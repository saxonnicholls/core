Detailed Description

snicholls::ml patches and positions for vision transformers: patch_grid, patchify_rows / unpatchify_rows for images, video tubelets and spectrograms, fixed sine-cosine position embeddings in two and three dimensions, axial RoPE, and gathered_rope for tokens at scattered positions.

Overview. A vision transformer reads an image as a sequence of patches (Dosovitskiy et al., 2021); I-JEPA (Assran et al., 2023) does, and V-JEPA (Bardes et al., 2024) reads a video as tubelets, a patch over a few frames. This header turns pixels into token rows and back, and gives each token its position.

  • patch_grid: a volume of frames x height x width x channels values (channels last: an image is one frame; a spectrogram is one frame of one channel, frequency by time, with rectangular patches, as Audio-JEPA reads one), cut into tubelets of tubelet x patch_height x patch_width. Its tokens are numbered in raster order, frame group, then row, then column: token = (gt · grid_height + gy) · grid_width + gx; a token's row is its values in the order (dt, dy, dx, c), as MAE's and I-JEPA's patchify lay them out ('nchpwq->nhwpqc').
  • patch_source(g, token, element): where element element of token token's row lives in the volume.
  • patchify_rows(b, g, volumes, tokens, samples): every token's row, each value read once from the volume (a gather: nothing is copied but the rows). unpatchify_rows is its inverse; the two are permutations, so each is the other's backward pass, to the bit. The patch embedding that follows is a linear_sequence (ml/linear.hpp), as a strided convolution of stride p is.
  • sincos_position_2d(dim, gh, gw, out, layout) and sincos_position_3d(dim, gt, gh, gw, out, uniform_power): the fixed sine-cosine embeddings of MAE, I-JEPA and V-JEPA, one row of dim per token. In one dimension, with h = d / 2 and ω_i = 1 / 10000^(i / h), the row of position p is [sin(p ω_0) .. sin(p ω_{h-1}), cos(p ω_0) .. cos(p ω_{h-1})]. In two, half the channels encode the row and half the column: [row, column] (sincos_layout::row_first, V-JEPA's get_2d_sincos_pos_embed) or [column, row] (column_first, as MAE's and I-JEPA's code order them, recalled, see Known issues). In three, [frame, row, column] with dim / 2, dim / 4, dim / 4 channels, or with uniform_power 2 · ceil(dim / 6) each, the row cut to dim (V-JEPA's get_3d_sincos_pos_embed). Computed in double and rounded once to T.
  • sincos_table_2d<T, Dim, Gh, Gw> and sincos_table_3d<T, Dim, Gt, Gh, Gw>: the same, built by a constexpr constructor, so a fixed grid's table is a constant the compiler holds (or is built at start-up when it exceeds the compiler's evaluation limits, as rope_table).
  • axial_rope_table<T, HeadDim, Gt, Gh, Gw>: RoPE in two or three dimensions (axial: each axis rotates its own share of the head's channel pairs by its own coordinate; Heo et al., 2024, "Rotary Position Embedding for Vision Transformer", and V-JEPA 2's 3-D RoPE, recalled). A rope_source by token index, so a configured attention layer rotates by it unchanged.
  • gathered_rope<R>: a rope_source over another one at a list of positions: the context encoder's tokens sit at their patches' positions, not at 0, 1, 2, .... Its sequence(s) gives sequence s of a batch its own list (ml/attention_layer.hpp asks for it).
// A 4 x 4 RGB image in patches of 2 x 2: 4 tokens of 12 values, raster order, each row (dy, dx, c)
constexpr ml::patch_grid image{.height = 4, .width = 4, .channels = 3, .patch_height = 2, .patch_width = 2};
static_assert(ml::valid(image) && image.tokens() == 4 && image.token_size() == 12);
std::vector<float> pixels(image.values());
for (std::size_t i = 0; i < pixels.size(); ++i)
pixels[i] = float(i); // pixel (y, x) channel c is ((y · 4 + x) · 3 + c)
std::vector<float> tokens(image.values()), back(image.values());
ml::patchify_rows(backend, image, std::span<const float>(pixels), std::span<float>(tokens));
ml::unpatchify_rows(backend, image, std::span<const float>(tokens), std::span<float>(back)); // the inverse, and the backward
// A video of 4 frames in tubelets of 2 x 2 x 2, and a 1-channel spectrogram (frequency x time) in 4 x 3 patches
constexpr ml::patch_grid video{.frames = 4, .height = 4, .width = 4, .channels = 3, .tubelet = 2, .patch_height = 2, .patch_width = 2};
constexpr ml::patch_grid spectrogram{.height = 8, .width = 12, .channels = 1, .patch_height = 4, .patch_width = 3};
// The fixed sine-cosine embedding of a 2 x 3 grid in 8 channels: [row, column], each [sin ..., cos ...]

const ml::gathered_rope<ml::axial_rope_table<double, 8, 1, 2, 3>> at_context{&rope, context, 2}; // two sequences of two

Relationships. ml/linear.hpp (the patch embedding), ml/rope.hpp (rope_source, rope_frequency), ml/gather.hpp and ml/masking.hpp (the tokens a model reads), ml/jepa.hpp. TRAINING.md T11. Group: snicholls-core.

Implementations. One each; patchify_rows and unpatchify_rows on the host for any backend, for a device library to overload (TRAINING.md T9).

Guarantees. constexpr, no allocation, linear in the values. patch_grid is trivially copyable and structural. patchify_rows then unpatchify_rows is the identity to the bit. A table built at compile time and the same function at run time agree within the last bits of math::sin and math::cos, which defer to <cmath> at run time.

Errors. Preconditions, asserted (valid(grid)): the frames, height and width divide by the tubelet and patch sizes; the sizes of the spans; an even share of channels per axis (dim a multiple of 4 in two dimensions, of 8 in three; even and at least 6 with uniform_power).

Performance. patchify_rows against the loops by hand (benchmarks/ml/patch_benchmark.cpp), 16 RGB images of 224 x 224 in patches of 16 and 4 videos of 16 frames in tubelets of 2 x 16 x 16: within 10%, about 4 GiB/s, a copy of each patch row (Xeon W-3245, Release, Apple clang 17, 2026-11-19, one thread, a machine at load average 60 to 80: differences within about 15% are noise). The tables are built once.

Tests and demos. tests/ml/patch_test.cpp, demos/ml/patch_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <cstddef>, <cstdint>, <span>, <type_traits>, snicholls/core/math/constexpr_math.hpp, ml/rope.hpp.

Known issues. MAE's get_2d_sincos_pos_embed (which I-JEPA copies) builds its grid as meshgrid(grid_w, grid_h) and gives its first half to that grid's first component, the column; V-JEPA's builds [row, column]. The layout of MAE and I-JEPA is recalled, not checked against their code here: pass the one the checkpoint was trained with. V-JEPA 2's split of a head among its axes (2 · ((head_dim / 3) / 2) channels each) is recalled; this header splits the pairs evenly, (HeadDim / 2) / axes each, the rest unrotated.

Status. Experimental, new in 0.16.0.
