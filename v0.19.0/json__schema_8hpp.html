Detailed Description

snicholls::ml JSON schema to GBNF: a practical subset of JSON Schema written as the grammar llama.cpp writes for it, so that generation emits only JSON that matches the schema.

Overview. Structured output (a tool call, an extraction into fields) is a JSON schema; json_schema_to_gbnf turns the schema's text into GBNF, which ml/grammar.hpp compiles and masks tokens with. The grammar is llama.cpp's (common/json-schema-to-grammar.cpp): the same rule names, the space rule, the primitive rules (value, object, array, string, char, number, integer, integral-part, decimal-part, boolean, null) and the rules sorted by name, so its output can be compared with llama.cpp's line for line.

Supported: type (one or a list: a list is an anyOf of the schema with each type), const, enum, anyOf / oneOf, allOf (merging the properties of object schemas, intersecting enums, intersecting integer ranges, as llama.cpp does), objects (properties in their written order, required, additionalProperties as a boolean or a schema, an object without properties accepting any object), arrays (items as a schema or a tuple, prefixItems, minItems, maxItems), strings (minLength, maxLength, format date, time, date-time and uuid; other formats are annotations), integers (minimum, maximum, exclusiveMinimum, exclusiveMaximum, as llama.cpp's digit-by-digit ranges), numbers, booleans, null, the empty schema (any value), and $ref to anywhere in the same document (#/$defs/..., #/definitions/...), recursive ones included. Annotations (title, description, default, examples, $schema, $id, ...) are ignored.

  • json_schema_to_gbnf(schema): the GBNF text, or a json_schema_error naming the keyword, its path (#/...) and, for a syntax error, the byte.
  • json_schema_grammar(schema): the schema straight to a compiled grammar.
  • json_schema_options{.strict = false}: llama.cpp's leniency instead, ignoring what is not implemented.
  • compile_json_schema<"...">(): at compile time, into a fixed_grammar, for a schema written in the program.
// The arguments of a weather tool: a city, and optionally a unit from a fixed set
constexpr const char* schema = R"({
"type": "object",
"properties": {
"city": {"type": "string", "minLength": 1},
"unit": {"enum": ["celsius", "fahrenheit"]}
},
"required": ["city"],
"additionalProperties": false
})";
const auto gbnf = ml::json_schema_to_gbnf(schema); // llama.cpp's grammar for it, rules sorted by name
const auto g = ml::json_schema_grammar(schema); // or straight to a compiled grammar
const bool good = ml::grammar_accepts(*g, R"({"city": "Oslo", "unit": "celsius"})");
const bool extra = ml::grammar_accepts(*g, R"({"city": "Oslo", "wind": 3})");
// What the subset does not implement is an error naming the keyword and where it is
const auto strict = ml::json_schema_to_gbnf(R"({"properties": {"zip": {"type": "string", "pattern": "^[0-9]{5}$"}}})");
// llama.cpp's leniency instead: the pattern is ignored and any string is accepted
const auto lenient = ml::json_schema_to_gbnf(R"({"properties": {"zip": {"type": "string", "pattern": "^[0-9]{5}$"}}})", {.strict = false});
// A schema written in the program, compiled to grammar tables by the compiler
constexpr auto yes_no = ml::compile_json_schema<R"({"type": "boolean"})">();
static_assert(ml::grammar_accepts(yes_no, "true") && !ml::grammar_accepts(yes_no, "yes"));

Relationships. ml/grammar.hpp compiles and matches the output. Group: snicholls-core.

Implementations. One, ported from llama.cpp at commit 39039aa: common/json-schema-to-grammar.cpp (build_repetition, build_min_max_int, PRIMITIVE_RULES, STRING_FORMAT_RULES, format_literal, gbnf_format_rule_name, common_chat_schema_converter::_add_rule, _not_strings, _resolve_ref, _build_object_rule, _add_primitive, _visit_all_of, visit, format_grammar) and common/json-schema.cpp (common_chat_schema_builder: which keywords make which kind of schema, in its order), checked against the expected grammars of tests/test-json-schema-to-grammar.cpp (tests/ml/json_schema_test.cpp).

Guarantees. constexpr throughout (compile_json_schema is consteval); no exceptions. The output always parses with parse_grammar (tested). Complexity: linear in the schema, plus the integer ranges' digits.

Errors. A json_schema_error for: malformed JSON (with its byte); a schema that is not an object; an unknown type; an empty or non-array enum, anyOf, oneOf or allOf; a negative or non-integer count; an unresolved or external $ref; an allOf whose integer ranges do not meet; nesting deeper than 128; and the keywords this subset does not implement, each named: pattern, patternProperties, propertyNames, not, if, contains, uniqueItems, multipleOf, minProperties, maxProperties, dependentRequired, dependentSchemas, unevaluatedProperties, unevaluatedItems, and minimum / maximum / exclusiveMinimum / exclusiveMaximum on a number (which llama.cpp ignores, so that its grammar admits numbers the schema rejects). Not strict, those are ignored as llama.cpp ignores them, and a pattern accepts any string.

Performance. Not benchmarked: a schema is converted once per request, its cost is small beside a forward pass.

Tests and demos. tests/ml/json_schema_test.cpp, demos/ml/json_schema_demo.cpp.

Dependencies. <algorithm>, <array>, <cstddef>, <cstdint>, <limits>, <string>, <string_view>, <utility>, <vector>, snicholls/core/ml/grammar.hpp, snicholls/core/result.hpp.

Known issues. Numbers in const and enum are written as they appear in the schema; llama.cpp re-prints them through its JSON library (1e2 becomes 100.0), so the two can differ for numbers not in canonical form. pattern (a regular expression) is not converted: llama.cpp converts a subset of regular expressions, or accepts any string with a warning; here it is an error. As in llama.cpp, the key rule of additionalProperties beside properties writes the property names' characters into classes unescaped, and refuses some keys that are proper prefixes of the declared names.

MSVC (19.52): compile_json_schema is wrong for a schema with an object inside an object (its properties). The compiler's constant evaluator loses the inner object as the reader builds it, and with that worked around, fails the conversion with "allocated storage not being deallocated". The run-time functions are right on MSVC; use json_schema_grammar there.

Status. Experimental, new in 0.17.0.
