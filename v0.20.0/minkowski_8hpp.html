Detailed Description

snicholls::metric::euclidean, manhattan, chebyshev, minkowski<P>, squared_euclidean and weighted_minkowski<P, W>: the coordinate-wise distances, on any point type.

Overview. The distances built from coordinate differences, each a small constexpr value with the full set of capabilities of metric/concepts.hpp: m(a, b), a reduced form for searching, a per-coordinate decomposition (so a k-d tree can prune with them), and is_metric.

| Metric | m(a, b) | Reduced form | is_metric | |—|—|—|—| | minkowski<P> (P ≥ 1) | (Σ |aᵢ - bᵢ|ᴾ)^(1/P) | Σ |aᵢ - bᵢ|ᴾ | yes | | euclidean = minkowski<2> | √Σ (aᵢ - bᵢ)² | Σ (aᵢ - bᵢ)² | yes | | manhattan = minkowski<1> | Σ |aᵢ - bᵢ| | the same | yes | | chebyshev | maxᵢ |aᵢ - bᵢ| | the same | yes | | squared_euclidean | Σ (aᵢ - bᵢ)² | the same | no (no triangle inequality) | | weighted_minkowski<P, W>{w} | (Σ wᵢ |aᵢ - bᵢ|ᴾ)^(1/P) | Σ wᵢ |aᵢ - bᵢ|ᴾ | yes, for wᵢ > 0 |

The exponent is a template argument, so |d|ᴾ is P multiplications, and the root is sqrt for P = 2 and nothing for P = 1. Points are anything point_traits reads, mixed freely (a std::array against a span), in their common floating type (double for integer coordinates). Both points must have the same dimension.

// The same metric between any two point kinds: an array of doubles, a vector of floats, a fixed_vector, a span
const std::array<double, 3> a{1, -2, 3};
const std::vector<float> b{4, 2, -1};
const auto c = la::fixed_vector<double, 3>{{1, -2, 3}};
const std::span<const float> bs(b);
// Differences (-3, -4, 4): values by hand, or python3 where marked
std::puts("Distances between (1, -2, 3) and (4, 2, -1)");
check(near(mt::euclidean{}(a, b), 6.4031242374328485), "euclidean = sqrt(41)", mt::euclidean{}(a, b));
check(mt::manhattan{}(a, bs) == 11.0, "manhattan = 3 + 4 + 4", mt::manhattan{}(a, bs));
check(mt::chebyshev{}(c, b) == 4.0, "chebyshev = max(3, 4, 4)", mt::chebyshev{}(c, b));
check(mt::squared_euclidean{}(c, bs) == 41.0, "squared_euclidean = 9 + 16 + 16", mt::squared_euclidean{}(c, bs));
check(near(mt::minkowski<3>{}(a, b), 5.371685354944832), "minkowski<3> = 155^(1/3) (python3)", mt::minkowski<3>{}(a, b));
check(near(mt::minkowski<64>{}(a, b), 4.04355714452557), "minkowski<64>, near chebyshev (numpy)", mt::minkowski<64>{}(a, b));
// A weighted metric holds its weights, one per axis: sqrt(1*9 + 2*16 + 0.5*16) = 7
const auto w = mt::weighted<2>(std::array<double, 3>{1, 2, 0.5});
check(w(a, b) == 7.0, "weighted<2>, weights (1, 2, 0.5) = 7", w(a, b));
// A search compares in the reduced form, which needs no root: is b within radius 6.5 of a?
const mt::euclidean e;
const double r2 = mt::contract(e, 6.5); // 42.25
const bool inside = mt::accumulate_within(e, a, b, r2) <= r2; // 9, 25, 41: never above 42.25
check(inside && e.reduced(a, b) == 41.0, "b within 6.5 of a, by reduced 41 <= 42.25", e.reduced(a, b));

Relationships. metric/concepts.hpp, math/constexpr_math.hpp. Used by containers/kd_tree.hpp, containers/ann_forest.hpp and metric/sets.hpp; tracking::euclidean and euclidean_weighted are the same distances on fixed_vectors. Group: snicholls-core.

Guarantees. constexpr, noexcept when the points' coordinate reads are, no allocation. Every metric is an empty value (or, weighted, holds its weights), trivially copyable.

Errors. None. Points of different dimensions are a precondition violation (the shorter's extent is not checked at run time).

Performance. Not benchmarked on their own: containers/kd_tree.hpp's and containers/ann_forest.hpp's benchmarks time them inside searches.

Tests and demos. tests/metric/minkowski_test.cpp, demos/metric/minkowski_demo.cpp.

Dependencies. <cstddef>, <type_traits>, math/constexpr_math.hpp, metric/concepts.hpp.

Known issues. None known.

Status. Experimental, new in 0.20.0.
