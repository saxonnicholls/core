Detailed Description

snicholls::ml transformer blocks composed from an attention part and an MLP part, either kind of each: x += attention(norm(x)); x += mlp(norm(x)), batched for training (returning the MLP's auxiliary losses) and token by token for decoding; DeepSeek-V3's block, multi-head latent attention with a mixture of experts, as latent_moe_block_* with its buffers' sizes and layouts.

Overview. Every pre-norm block is the same eight steps: keep the input, the first norm, the attention, the residual, keep it, the second norm, the MLP, the residual. Only the two parts vary: the attention is standard (ml/attention_layer.hpp) or multi-head latent (ml/latent_attention.hpp), the MLP dense (ml/mlp.hpp) or a mixture of experts (ml/moe.hpp). composed_block_weights<Attention, Mlp, T> holds one of each beside the norms, and the overloads here of block_forward_sequence, block_backward and block_forward run the steps with the parts chosen by their weights' types (an overload set, not a chain of type tests), so four kinds of block are one template rather than four headers. A new kind of attention or MLP is one overload of each part's step, not a new block.

A linear-time mixer is a third kind of attention part (TRAINING.md T15): mamba2_weights or gated_deltanet_weights (ml/mixer_layer.hpp), with mixer_activations and mixer_gradients. A hybrid stack is composed blocks of both kinds, layer i attention exactly when layer_is_attention(C, i) (Qwen3-Next's three gated-delta-rule layers then one attention layer; Jamba's one attention layer in eight); decoding goes through a hybrid_cache, its KV cache holding the attention layers alone (hybrid_attention_index) and its recurrent_cache the mixer layers' states (hybrid_mixer_index), or through a recurrent_cache for a stack of mixers alone.

  • block_forward_sequence<C>(backend, w, xs, rope_src, act, sequences) -> moe_losses<T>: the batched training pass, every step a backend call (TRAINING.md T9). It returns the mixture of experts' auxiliary losses (zero for a dense MLP), the sequences being the sequence-wise balance loss's groups.
  • block_backward<C>(backend, w, rope_src, act, dxs, grads, sequences): its backward pass, the auxiliary losses' gradients included.
  • block_forward<C>(w, x, pos, cache, layer, rope_src): one token, in place, through a kv_cache_view (standard attention) or a latent_kv_cache_view (latent), the MLP through mlp_forward (dense, or the overload for moe_weights).

DeepSeek-V3's block (DeepSeek-AI, 2024, sections 2.1 and 4.2) is latent attention with a mixture of experts: latent_moe_block_weights<T>, latent_moe_block_activations<T> and latent_moe_block_gradients<T>, sized by latent_moe_block_parameter_count, latent_moe_block_activation_values, latent_moe_block_activation_indices and latent_moe_block_gradient_work, laid out by latent_moe_block_weights_in, latent_moe_block_activations_in and latent_moe_block_gradients_in (the norms, then the attention in latent_attention_weights_in's order, then the mixture of experts in moe_weights_in's). Its node-limited routing is the configuration's expert_groups and group_top_k (ml/moe.hpp). A multi-token prediction module whose block is this one returns the block's losses (ml/multi_token_prediction.hpp).

constexpr auto C = v3_small;
constexpr std::size_t n = 6, sequences = 2, rows = n * sequences, d = C.d_model;
// Every buffer one allocation, sized by constant expressions and cut into views by the *_in functions
std::vector<float> params = noise(ml::latent_moe_block_parameter_count(C), 1, 0.3), grads(params.size()), selection(C.experts, 0.0f);
std::vector<float> values(ml::latent_moe_block_activation_values(C, rows)), work(ml::latent_moe_block_gradient_work(C, rows));
std::vector<u32> indices(ml::latent_moe_block_activation_indices(C, rows));
{
const auto w = ml::latent_moe_block_weights_in<C>(std::span<const float>(params));
for (const auto norm : {w.norm1_weight, w.norm2_weight, w.attention.q_norm, w.attention.kv_norm}) // norms start at 1
for (std::size_t i = 0; i < norm.size(); ++i)
params[std::size_t(norm.data() - params.data()) + i] = 1.0f;
}
const auto act = ml::latent_moe_block_activations_in<C>(std::span<float>(values), std::span<u32>(indices), rows);
const auto g = ml::latent_moe_block_gradients_in<C>(std::span<float>(grads), std::span<float>(work), rows);
static const ml::rope_table<float, 16, C.qk_rope_dim> rope{ml::rope_base_v<C, float>};
// Training: two sequences of 6 tokens, the block learning a fixed target; its auxiliary losses join the loss
const auto input = noise(rows * d, 2, 1.0), target = noise(rows * d, 3, 0.5);
std::vector<float> xs(rows * d);
auto step = [&] {
const auto w = ml::latent_moe_block_weights_in<C>(std::span<const float>(params), std::span<const float>(selection));
xs = input;
const auto aux = ml::block_forward_sequence<C>(backend, w, std::span<float>(xs), rope, act, sequences);
float loss = aux.balance + aux.z;
std::vector<float> dxs(rows * d);
for (std::size_t i = 0; i < xs.size(); ++i) {
const float e = xs[i] - target[i];
loss += 0.5f * e * e / rows;
dxs[i] = e / rows;
}
std::fill(grads.begin(), grads.end(), 0.0f);
ml::block_backward<C>(backend, w, rope, act, std::span<float>(dxs), g, sequences); // dxs: the input's gradient
for (std::size_t i = 0; i < params.size(); ++i)
params[i] -= 0.2f * grads[i];
ml::moe_update_bias<C>(backend, act.mlp.counts, std::span<float>(selection)); // auxiliary-loss-free balancing
return loss;
};
const float first = step();
float last = first;
for (int i = 0; i < 40; ++i)
last = step();
// Decoding: one token at a time, the attention absorbed over a latent cache (10 numbers a token), the experts
// through mlp_forward's overload for moe_weights; the training pass's outputs within rounding
const auto w = ml::latent_moe_block_weights_in<C>(std::span<const float>(params), std::span<const float>(selection));
xs = input;
ml::block_forward_sequence<C>(backend, w, std::span<float>(xs), rope, act, sequences);
ml::latent_kv_cache<C, float, 1, 16> cache;
float worst = 0.0f;
for (std::size_t t = 0; t < n; ++t) { // the first sequence
std::vector<float> x(input.begin() + std::ptrdiff_t(t * d), input.begin() + std::ptrdiff_t((t + 1) * d));
ml::block_forward<C>(w, x, t, cache.view(), 0, rope);
for (std::size_t i = 0; i < d; ++i)
worst = std::max(worst, std::abs(x[i] - xs[t * d + i]));
}

Relationships. ml/transformer_block.hpp (block_norm, block_norm_rows and their backward passes; the dense block), ml/moe_block.hpp and ml/latent_block.hpp (the standard-and-MoE and latent-and-dense blocks with their own field names, kept for their users; the composed block with the same parts gives their bits, tested), ml/attention_layer.hpp, ml/latent_attention.hpp, ml/mlp.hpp, ml/moe.hpp, ml/multi_token_prediction.hpp (a user). Group: snicholls-core.

Implementations. One skeleton; the parts are standard or latent attention or a mixer, and a dense or mixture-of-experts MLP.

Guarantees. constexpr, each step in a fixed order, so the bits do not depend on scheduling; no allocation (decoding keeps two rows of d_model and the parts' own fixed-size scratch). The batched passes are the existing blocks' steps with the parts' passes, to the bit: with standard attention and an MoE MLP it is ml/moe_block.hpp's block, with latent attention and a dense MLP ml/latent_block.hpp's, and latent attention with one expert chosen with weight 1 is the latent block's dense path (all tested). Decoding is the training pass within the latent attention's stated rounding (its absorbed form) and the MoE's (per-token products against the batched ones). Weight gradients are added into; dxs is replaced by the gradient in the block's input.

Errors. Preconditions, asserted, as the parts' and the norms' (empty or of d_model). Parts of no supported kind, or a configuration the parts reject (a dense one under a mixture of experts, a standard one under latent attention), are compile errors.

Performance. Not benchmarked as a whole: its parts are (ml/latent_attention.hpp, ml/moe.hpp, ml/transformer_block.hpp), and the skeleton adds the norms and residuals the other blocks have.

Tests and demos. tests/ml/composed_block_test.cpp, tests/ml/composed_block_hybrid_test.cpp (mixer blocks against central differences, hybrid stacks decoded against their batched passes, a hybrid stack trained), demos/ml/composed_block_demo.cpp, demos/ml/mixer_layer_demo.cpp.

Dependencies. <array>, <cassert>, <concepts>, <cstddef>, <cstdint>, <span>, <type_traits>, linalg/backend.hpp, ml/attention_layer.hpp, ml/latent_attention.hpp, ml/linear.hpp, ml/mixer_layer.hpp, ml/mlp.hpp, ml/moe.hpp, ml/row.hpp, ml/transformer_block.hpp, ml/transformer_config.hpp. It pulls in both attentions and both MLPs.

Known issues. The decoding MoE runs one token's experts one after another (mlp_forward's overload for moe_weights): a batch of tokens decoding together is the batched layer's job, through the backend.

Status. Experimental, new in 0.16.0; mixers as the attention part and hybrid caches new in 0.17.0.
