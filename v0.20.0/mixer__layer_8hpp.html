Detailed Description

snicholls::ml linear-time mixer layers in place of attention: Mamba-2's and the gated delta rule's (Qwen3-Next's), batched for training with their backward passes and one token at a time for decoding with a fixed-size state; their buffers' sizes and layouts; the caches of a hybrid stack.

Overview. A mixer layer maps the normalised residual rows to rows of d_model, as attention does, so it is a third kind of attention part for the composed block (ml/composed_block.hpp): a hybrid stack is composed blocks whose attention part is a mixer or attention, layer by layer as layer_is_attention says.

Mamba-2 (Dao and Gu, 2024, section 7.1 and 8.1; llama.cpp's build_mamba2_layer in src/models/mamba-base.cpp at commit 39039aa), with d_inner = H · P: [z | xBC | dt] = in_proj(h); xBC = silu(conv1d(xBC) + b) (ml/short_conv.hpp), split into x (d_inner), B and C (G · N each); dt = softplus(dt + dt_bias), A = -exp(A_log); y = SSD(x, dt, A, B, C) (ml/ssd.hpp, the chunked form); y = (y + D ⊙ x) ⊙ silu(z); an RMS norm over each group's d_inner / G channels with its weight (llama.cpp's grouped ssm_norm, mamba_ssm's RMSNormGated with norm_before_gate=False); out_proj.

The gated delta rule as Qwen3-Next's linear attention (llama.cpp's build_layer_attn_linear in src/models/qwen3next.cpp at commit 39039aa): [q | k | v | z | b | a] = in_proj(h) (G · N, G · N, H · P, H · P, H, H); qkv = silu(conv1d(qkv)) without a bias; q and k normalised per key head, x / sqrt(Σx² + eps) with the configuration's norm_eps (llama.cpp's build_gdn_l2_norm); β = sigmoid(b), g = -exp(A_log) · softplus(a + dt_bias); o = GatedDeltaRule(q, k, v, g, β) (ml/delta_rule.hpp, the chunked WY form); o = rms_norm(o) ⊙ silu(z) per head with one weight of P shared by the heads (build_norm_gated); out_proj. The projections are contiguous in that order: a checkpoint whose in_proj_qkvz interleaves them by key head is permuted when it is loaded.

  • mixer_forward_sequence<C>(backend, w, xs, act, out, sequences, states): the batched pass, saving act; with states it starts from them and leaves the final ones (a prompt prefilled for decoding).
  • mixer_backward<C>(backend, w, xs, act, dout, dxs, grads, sequences): dxs added into, every weight's gradient added into, for a forward pass from zero states.
  • mixer_forward<C>(w, x, state, out): one token, state of mixer_state_values(C) (the convolution's then the recurrence's), on core's reference backend.
  • mixer_parameter_count, mixer_activation_values, mixer_gradient_work, mixer_state_values size the buffers; mixer_weights_in, mixer_activations_in, mixer_gradients_in lay them out (the order of the weights' fields).
  • recurrent_cache<T> holds every mixer layer's state; hybrid_cache<KV, T> a KV cache for the attention layers beside it, indexed by hybrid_attention_index and hybrid_mixer_index.
// One buffer of parameters, laid out as the layer's weights
std::vector<double> params = wave(ml::mixer_parameter_count(C), 0.37, 0.3);
const auto w = ml::mixer_weights_in<C>(std::span<const double>(params));
// Prefill a prompt of 6 tokens with the batched pass, keeping the state it ends in
constexpr std::size_t prompt = 6, d = C.d_model;
const std::vector<double> tokens = wave((prompt + 2) * d, 0.11, 1.0);
std::vector<double> act(ml::mixer_activation_values(C, prompt, 1)), out(prompt * d), state(ml::mixer_state_values(C), 0.0);
ml::mixer_forward_sequence<C>(backend, w, std::span<const double>(tokens).first(prompt * d),
ml::mixer_activations_in<C>(std::span<double>(act), prompt, 1), std::span<double>(out), 1,
std::span<double>(state));
// Decode the next two tokens from that state: a fixed number of values, whatever the prompt's length. A stack keeps
// every mixer layer's state in a recurrent_cache (here a stack of one)
const ml::recurrent_cache<double> cache{std::span<double>(state), ml::mixer_state_values(C)};
std::vector<double> next(d), after(d);
ml::mixer_forward<C>(w, std::span<const double>(tokens).subspan(prompt * d, d), cache.layer(0), std::span<double>(next));
ml::mixer_forward<C>(w, std::span<const double>(tokens).subspan((prompt + 1) * d, d), cache.layer(0), std::span<double>(after));

Relationships. ml/ssd.hpp, ml/delta_rule.hpp, ml/short_conv.hpp, ml/norm.hpp, ml/linear.hpp, ml/composed_block.hpp (which takes these weights as its attention part), ml/transformer_config.hpp (the mixer fields, layer_is_attention). Group: snicholls-core.

Implementations. Mamba-2 and the gated delta rule, an overload each, chosen by the weights' type. Gated linear attention and RWKV have their ops (ml/gla.hpp, ml/rwkv.hpp) and no layer yet.

Guarantees. constexpr, no allocation, every step in a fixed order. Decoding one token at a time gives the batched pass's outputs within the chunked forms' rounding (tested at every position), and a prompt fed in pieces through states gives the whole prompt's. The products are the backend's (linear_sequence), so on core's reference backend the results are its bits.

Errors. Preconditions, asserted: the rows a multiple of d_model · sequences, every view of its size. A configuration without that mixer is a compile error.

Performance. Not benchmarked as a whole: its parts are (ml/ssd.hpp, ml/delta_rule.hpp, ml/short_conv.hpp, ml/linear.hpp).

Tests and demos. tests/ml/mixer_layer_test.cpp, demos/ml/mixer_layer_demo.cpp; the hybrid stacks in tests/ml/composed_block_test.cpp.

Dependencies. <array>, <cassert>, <cstddef>, <span>, <type_traits>, linalg/backend.hpp, linalg/reference.hpp (decoding), ml/activations.hpp, ml/delta_rule.hpp, ml/linear.hpp, ml/norm.hpp, ml/recurrence.hpp, ml/short_conv.hpp, ml/ssd.hpp, ml/transformer_config.hpp.

Known issues. The splits, gates and norms between the products run on the host (the products and the triangular solve are the backend's): a device library overloads mixer_forward_sequence and mixer_backward for its backend type. The backward pass is of a forward pass from zero states (training on whole sequences). Decoding keeps a row of each activation on the stack, so a very wide layer decodes through mixer_forward_sequence with one row instead.

Status. Experimental, new in 0.17.0.
