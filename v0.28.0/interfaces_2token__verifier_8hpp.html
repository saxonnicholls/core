Detailed Description

snicholls::token_verifier_interface: the pure virtual twin of token_verifier, and the adapters both ways.

Overview. When the verifier is chosen by configuration (a JWT verifier in production, the reference in a test), code holds a token_verifier_interface&. Its pure virtual verify is the operation of the concept token_verifier (concepts/token_verifier.hpp, where the contract and token_claims are documented), so the interface models the concept itself. token_verifier_adapter<V> puts any model behind the interface, owning it (V) or referring to it (V&); token_verifier_ref is a copyable, non-owning handle on the interface that models the concept.

token_verifier_adapter<memory_token_verifier&> adapter{reference}; // borrows
const token_verifier_interface& chosen = adapter;
const token_verifier_ref handle{chosen};
const auto who = handle.verify(token);

Relationships. concepts/token_verifier.hpp, interfaces/token_verifier_reference.hpp, interfaces/token_verifier_conformance.hpp. Group: snicholls-core.

Implementations / variants. token_verifier_adapter<V> over any model; an implementation above core may derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else; thread safety and exception safety are the wrapped implementation's.

Errors. As the contract.

Performance. One virtual call; the verifier's own cost dominates.

Tests and demos. tests/interfaces/token_verifier_test.cpp (the kit through every form, the adapters forward), demos/interfaces/token_verifier_demo.cpp.

Dependencies. <string_view>, <type_traits>, <utility>, concepts/token_verifier.hpp.

Known issues. None.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
