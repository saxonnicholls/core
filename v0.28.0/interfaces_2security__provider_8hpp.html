Detailed Description

snicholls::security_provider_interface: the pure virtual twin of security_provider, and the adapters both ways.

Overview. When the broker, custodian or registry is chosen per account, code holds a security_provider_interface&. Its pure virtual functions (capabilities, verify_webhook, resolve, statement, holdings) are the operations of the concept security_provider (concepts/security_provider.hpp, where the contract and its value types are documented), so the interface models the concept itself. security_provider_adapter<P> puts any model behind the interface, owning it (P) or referring to it (P&); security_provider_ref is a copyable, non-owning handle on the interface that models the concept.

memory_security_provider reference{secret<std::string>{"whsec_demo_only"}, manual_utc_clock{now}};
static_cast<void>(reference.execute("ord-7", money::from_units(vas, 40), -*parse_money(aud, "3916.00")));
webhook_event filled;
filled.source = "memory";
filled.event_id = "evt_7";
filled.kind = event_kind::security_updated;
filled.payment_id = "ord-7";
const owned_delivery delivery = reference.signed_webhook(filled);
std::unique_ptr<security_provider_interface> custodian =
std::make_unique<security_provider_adapter<memory_security_provider>>(std::move(reference)); // chosen at run time
const std::vector<security_fact> facts = on_delivery(*custodian, delivery.view());

Relationships. concepts/security_provider.hpp, interfaces/security_provider_reference.hpp, interfaces/security_provider_conformance.hpp; the sibling interfaces/payment_provider.hpp. Group: snicholls-core.

Implementations / variants. security_provider_adapter<P> over any model; an implementation above core may derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else; thread safety and exception safety are the wrapped implementation's.

Errors. As the contract.

Performance. One virtual call. Not benchmarked: the provider's own I/O dominates.

Tests and demos. tests/interfaces/security_provider_test.cpp (the kit through every form, the adapters forward), demos/interfaces/security_provider_demo.cpp.

Dependencies. <chrono>, <type_traits>, <utility>, <vector>, concepts/security_provider.hpp.

Known issues. None.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
