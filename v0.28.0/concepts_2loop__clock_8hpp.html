Detailed Description

snicholls::loop_clock_like: an event loop's sense of time, as a concept (C++20) and a trait (C++17).

Overview. An event loop that reads time through a clock can run its timers live, in replay at 0.01x or 100x, paused or single-stepped, and a test of a one-hour timeout costs no wall time. A loop clock answers:

  • now(): the current instant in the loop's timeline (std::chrono::steady_clock::time_point), noexcept;
  • block_for(until): how many real milliseconds the poller may block while the next deadline is until in the clock's timeline: -1 blocks until woken (a paused clock: that deadline is not coming), 0 does not block (a manual clock: only the program moves it), noexcept;
  • set_waker(f): the loop installs f, which a clock that moves on command calls when it moves, so a loop asleep in the poller looks at its timers again.

The pieces, as task_pool.hpp: is_loop_clock_like_v<C> (C++17 trait over the exact member types, const and noexcept), loop_clock_like<C> (the C++20 concept, under SNICHOLLS_HAS_CONCEPTS), SNICHOLLS_LOOP_CLOCK for a template head that is constrained under C++20 and typename under C++17.

manual_loop_clock clock;
const loop_time_point timer = clock.now() + 1h;
const long long before = poll_timeout(clock, timer); // 0: a manual clock is never waited for
clock.advance(1h); // an hour, in no wall time
const bool due = !(clock.now() < timer);

The contract (interfaces/loop_clock_conformance.hpp checks it): now() never goes backwards; block_for(t) is 0 once t is due, and never less than -1; set_waker accepts any callable and an empty one.

Relationships. The twin interfaces/loop_clock.hpp, the reference interfaces/loop_clock_reference.hpp (manual_loop_clock), the kit interfaces/loop_clock_conformance.hpp; concepts/task_pool.hpp (the macro SNICHOLLS_HAS_CONCEPTS). Group: snicholls-core.

Implementations. manual_loop_clock (single-threaded, deterministic). Above core, in ts-moveables: steady_clock_source, manual_clock (atomic) and scaled_clock (replay).

Guarantees. A trait and a concept: no code.

Errors. None: time is always available.

Performance. Not applicable. (ts-moveables' loop holds no clock by default and reads steady_clock directly.)

Tests and demos. tests/concepts/loop_clock_test.cpp, demos/concepts/loop_clock_demo.cpp.

Dependencies. <chrono>, <functional>, <type_traits>, <utility>, concepts/task_pool.hpp.

Known issues. A real sleep is the operating system's: every blocking clock lives above core.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
