Detailed Description

snicholls::task_pool_like: somewhere to submit work, as a concept (C++20) and a trait (C++17).

Overview. A task pool runs std::function<void()> tasks: submit(task) enqueues one, wait_idle() blocks until everything submitted (including what the tasks submitted) has run, worker_count() is the parallelism the algorithms may assume. Code that only needs "somewhere to run this" (a parallel for, a task graph, a benchmark that swaps pools) depends on this contract, not on one of the pools. Given a concrete pool, a template over task_pool_like calls it directly (inlined, devirtualised for a final pool); given a task_pool_interface& it goes through the vtable; the call site picks the dispatch and one algorithm serves both.

The pieces:

  • is_task_pool_like_v<P>: the members, with their exact types, const and noexcept, as a C++17 trait;
  • task_pool_like<P>: the same test as a C++20 concept, when the compiler has concepts (SNICHOLLS_HAS_CONCEPTS);
  • SNICHOLLS_TASK_POOL: template <SNICHOLLS_TASK_POOL Pool> is template <task_pool_like Pool> with concepts and template <typename Pool> without (check is_task_pool_like_v in a static_assert then);
  • is_pool_task_v<F> and pool_task<F>: a callable a pool can take as it is (no arguments, movable), with SNICHOLLS_POOL_TASK_TEMPLATE(F) for a pool's submit(F&&) beside its submit(task).
deferred_task_pool pool;
std::vector<int> squares(5);
parallel_for(pool, squares.size(), squares);

The contract (interfaces/task_pool_conformance.hpp checks it): every task submitted runs exactly once; when wait_idle() returns, every task submitted before it, and every task those submitted, has run; wait_idle() on an idle pool returns at once; worker_count() is at least 1 and does not throw. The concept is syntactic only: from which threads submit may be called is the implementation's to document.

Relationships. The twin interfaces/task_pool.hpp, the reference interfaces/task_pool_reference.hpp (deferred_task_pool), the kit interfaces/task_pool_conformance.hpp. Group: snicholls-core.

Implementations. deferred_task_pool (single-threaded, deterministic). Above core, in ts-moveables: the thread pools (one shared queue, sharded, work-stealing, dispatch, inline).

Guarantees. A trait and a concept: no code, no cost.

Errors. None in the contract; what a throwing task does is the implementation's.

Performance. Not applicable.

Tests and demos. tests/concepts/task_pool_test.cpp, demos/concepts/task_pool_demo.cpp.

Dependencies. <cstddef>, <functional>, <type_traits>, <utility>; <version> and <concepts> when available.

Known issues. C++17-clean by rule: no requires outside the SNICHOLLS_HAS_CONCEPTS block.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
