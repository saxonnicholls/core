Detailed Description

snicholls::ml gated linear units: ReGLU, GEGLU (tanh, erf and quick), SwiGLU, gpt-oss's clamped SwiGLU and SwiGLU with a clamp, for one element and over rows, forward and backward, all constexpr.

Overview. A gated MLP computes down(act(gate x) · up x) (Shazeer, 2020). The gate and the up projection are two rows of the same width; a GLU combines them element by element. ggml's GLU operations (ggml_reglu, ggml_geglu, ggml_geglu_erf, ggml_geglu_quick, ggml_swiglu, ggml_swiglu_oai, ggml_swiglu_clamp; ggml/src/ggml-cpu/ops.cpp and vec.h, llama.cpp 39039aa) are reproduced:

glu_kind h(g, u) Used by
reglu relu(g) · u T5 variants
geglu gelu_tanh(g) · u (ggml's ggml_gelu_f32 is the tanh form) Gemma
geglu_erf gelu(g) · u the exact GELU
geglu_quick gelu_quick(g) · u
swiglu silu(g) · u Llama, Qwen, DeepSeek
swiglu_oai x · sigmoid(α x) · (y + 1), x = min(g, limit), y = clamp(u, -limit, limit) gpt-oss (α 1.702, limit 7: src/llama-graph.cpp, LLM_FFN_SWIGLU_OAI_MOE)
swiglu_clamp silu(x) · y with the same clamps DeepSeek V4, GLM-5 (ggml_swiglu_clamp)
  • glu(kind, g, u, params) and glu_backward(kind, g, u, dh, params) for one element; the backward returns the gradients in g and u as dh · ∂h/∂g and dh · ∂h/∂u, multiplied in the order the MLP's SwiGLU always used, so mlp_forward and mlp_backward keep their bits.
  • glu_rows / glu_rows_backward over a gate row and an up row; glu_split over one row of 2n holding both halves, gate first unless swapped, as ggml's single-tensor form.
  • mlp_kind's gated kinds (ml/transformer_config.hpp) map to these, so the MLP, the mixture of experts and the blocks run every one of them.
// A gate row and an up row of four, through each gated linear unit
const std::array<float, 4> gate{-1.0f, 0.5f, 2.0f, 9.0f}, up{1.0f, -2.0f, 0.5f, 3.0f};
constexpr std::array kinds{ml::glu_kind::reglu, ml::glu_kind::geglu, ml::glu_kind::geglu_erf, ml::glu_kind::geglu_quick,
ml::glu_kind::swiglu, ml::glu_kind::swiglu_oai, ml::glu_kind::swiglu_clamp};
std::array<std::array<float, 4>, kinds.size()> out{};
for (std::size_t k = 0; k < kinds.size(); ++k)
ml::glu_rows(kinds[k], gate, up, out[k]); // gpt-oss's alpha 1.702 and limit 7 by default
// ggml's single-row form: one row of 2n, the gate first (or the up projection first when swapped)
const std::array<float, 8> both{-1.0f, 0.5f, 2.0f, 9.0f, 1.0f, -2.0f, 0.5f, 3.0f};
std::array<float, 4> split{}, swapped{};
ml::glu_split(ml::glu_kind::swiglu, both, split);
ml::glu_split(ml::glu_kind::swiglu, both, swapped, true);
// The backward pass: the gradients in the gate and the up rows, for a gradient of 1 in each output
const std::array<float, 4> dout{1.0f, 1.0f, 1.0f, 1.0f};
std::array<float, 4> dgate{}, dup{};
ml::glu_rows_backward(ml::glu_kind::swiglu_oai, gate, up, dout, dgate, dup);
std::array<float, 8> dboth{};
ml::glu_split_backward(ml::glu_kind::swiglu, both, dout, dboth);

Relationships. Built on ml/activations.hpp; used by ml/mlp.hpp and ml/moe.hpp through mlp_kind. Group: snicholls-core.

Implementations. One each; the kind is a run-time value or, in the MLP, a compile-time one (switch over an enumeration, never a chain over types).

Guarantees. constexpr, no allocation, linear in the row. The output may be the gate or the up row. At a clamp's edge the gradient passes (PyTorch's clamp: the bounds are inside).

Errors. Preconditions, asserted: the rows have one size (twice it for glu_split); limit is positive for the clamped kinds.

Performance. Against the same loops written by hand (benchmarks/ml/glu_benchmark.cpp, rows of 14,336): SwiGLU 113 million elements per second against 114, gpt-oss's SwiGLU 106 against 103 (Xeon W-3245, Release, Apple clang 17, 2026-11-19). The kind is resolved once per row, not per element.

Tests and demos. tests/ml/glu_test.cpp, demos/ml/glu_demo.cpp.

Dependencies. <cassert>, <concepts>, <cstddef>, <span>, <type_traits>, ml/activations.hpp, ml/row.hpp.

Known issues. ggml computes swiglu_oai as x / (1 + e^(-α x)) and GEGLU in float through a float16 table between -10 and 10 where GGML_GELU_FP16 is defined; here each is the activation of ml/activations.hpp, which agrees to a few units in the last place (stated in the tests). A NaN gate is not clamped (min keeps it).

Status. Experimental, new in 0.17.0.
