Detailed Description

snicholls::stats::systematic_resample, stratified_resample, multinomial_resample, residual_resample, effective_sample_size and log-weight normalisation: the resampling step of particle filters.

Overview. A particle filter's weights degenerate: after a few updates most particles carry almost no weight. Resampling draws M indices with probabilities proportional to the weights, so the heavy particles are copied and the light ones are dropped. The schemes differ in their variance and in how many random numbers they use:

Scheme Uniforms Variance of the copy counts
systematic_resample 1: uᵢ = (i + U) / M lowest in practice; the default
stratified_resample M: uᵢ = (i + Uᵢ) / M below multinomial's
multinomial_resample M + 1 (sorted by exponential spacings, no sort) the reference
residual_resample ⌊M wᵢ⌋ copies deterministically, the remainder by one of the above low

Weights need not be normalised: each function divides by their sum. effective_sample_size(w) is (Σ w)² / Σ w²; needs_resampling(w, fraction) says whether it has fallen below fraction · N (Stone Soup's ESSResampler). log_sum_exp and normalise_log_weights keep weights in log space without underflow.

The randomness is the caller's full_range_generator (wyrand and its stream(seed, k)), so a run reproduces on every platform, and a device thread can own a stream.

// Five particles after a measurement update, as log-likelihoods far below exp's range
std::array<double, 5> log_w{-1200.0, -1201.0, -1199.5, -1230.0, -1200.2};
const double log_evidence = st::normalise_log_weights<double>(log_w); // now Σ exp = 1
std::array<double, 5> w{};
for (std::size_t i = 0; i < 5; ++i)
w[i] = std::exp(log_w[i]);
// Resample (10 new particles from the 5) only when the effective sample size is below 3/4 of the count
const double ess = st::effective_sample_size<double>(w); // about 3.25
std::array<std::size_t, 10> picked{};
st::wyrand g(2026); // the caller's generator: the same draw on every platform
bool resampled = false;
if (st::needs_resampling<double>(w, 0.75))
resampled = st::systematic_resample<double>(w, picked, g);
// picked holds 10 indices in non-decreasing order; particle 3 (weight 2e-14) is never copied

Relationships. stats/random.hpp (uniform_real), math/constexpr_math.hpp (log, exp). The particle filters above core (and their device forms) use these. Group: snicholls-core.

Implementations. Each scheme walks the cumulative weights once against its increasing sequence of uniforms, O(N + M), with no sort and no allocation.

Guarantees. constexpr, noexcept when the generator is, no allocation. The indices come out in non-decreasing order (for residual_resample, the deterministic copies and the remainder are each in order). A particle of zero weight is never drawn.

Errors. None. With a zero, infinite or empty total weight, or any negative or NaN weight, no draw is possible: the functions return false and leave indices unspecified.

Performance. Systematic resampling of 2¹⁶ particles against the same walk written by hand, after checking every index agrees (benchmarks/stats/resample_benchmark.cpp; Release, Apple clang 17, Xeon W-3245, 2026-11-23): 77.0 million particles a second (by hand 79.3).

Tests and demos. tests/stats/resample_test.cpp, demos/stats/resample_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <limits>, <span>, math/constexpr_math.hpp, stats/random.hpp.

Known issues. Weights are summed in their own type; for millions of float weights, normalise in double.

Status. Experimental, new in 0.19.0.
