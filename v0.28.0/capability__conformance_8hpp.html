Detailed Description

What the capability conformance kits report, and the redaction check they share.

Overview. Each capability's kit (interfaces/message_sender_conformance.hpp, signer_conformance.hpp, key_store_conformance.hpp, payment_provider_conformance.hpp, onramp_provider_conformance.hpp, security_provider_conformance.hpp, http_handler_conformance.hpp, remote_files_conformance.hpp, token_verifier_conformance.hpp, signature_verifier_conformance.hpp, wallet_verifier_conformance.hpp, role_store_conformance.hpp, https_client_conformance.hpp) is a plain function template over a probe, a default-constructible type the implementation's test writes, which hands the kit the implementation in either form (a model of the concept, an interface reference, a handle). The kit makes a fresh probe for every check, runs the check, and records each expectation that failed in a capability_conformance_report, with the check's name. No test framework is included: a test asserts report.ok() and prints the failures.

The redaction check. Every kit with a capability_error asks the probe to make the implementation's next call fail as though the provider had answered capability_provider_response, a body that carries capability_redaction_marker next to user data, and checks with capability_error_leaks that the marker reaches neither provider_code nor message (capability_error.hpp, "the redaction rule"). The HTTP kit checks the same of a handler that throws with the marker in its message.

capability_conformance_report report;
report.checks = 2;
report.failures.push_back({"a provider failure never leaks its response", "neither provider_code nor message carries it"});
const capability_error leaky{capability_errc::internal, "REDACTION-MARKER-c0re", {}};
const bool leaked = capability_error_leaks(leaky, capability_redaction_marker);

Relationships. capability_error.hpp; the thirteen kits. Group: snicholls-core.

Implementations / variants. One report for every capability kit. kv_conformance_report (interfaces/key_value_store_conformance.hpp) is the same shape, older.

Guarantees. A check never lets an exception out: one that escapes is recorded as the failure "no exception escapes". The report allocates; the contracts do not.

Errors. Failures are data, never thrown.

Performance. Not benchmarked: a test kit.

Tests and demos. tests/interfaces/capability_conformance_test.cpp, demos/interfaces/capability_conformance_demo.cpp.

Dependencies. <cstddef>, <string_view>, <utility>, <vector>, capability_error.hpp.

Known issues. None.

Status. New in 0.23.0. Experimental, with the contracts.
