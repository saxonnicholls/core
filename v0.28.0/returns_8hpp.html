Detailed Description

Performance measures: time-weighted return (chained sub-periods), modified Dietz, money-weighted return and the internal rate of return, exact where the inputs allow and double where they cannot.

Overview. A fund, a wealth account or a mandate reports how it did. Two questions, two families of measure:

  • How did the manager do? The time-weighted return removes the effect of the investor's flows: the period is cut at every external flow into sub-periods, each sub-period's growth is end / (start + flow), and the growths are chained, TWR = prod(growth) - 1. period_return and time_weighted_return compute it exactly, as a finance::ratio, from money valuations; time_weighted_return(std::span<const double>) chains returns already in double. The modified Dietz return approximates it without a valuation at each flow: (V1 - V0 - sum F) / (V0 + sum w F), each flow weighted by the share of the period it was invested (w = (days in period - days before the flow) / days in period), also exact.
  • How did the investor do? The money-weighted return is the rate that discounts the investor's flows (the opening value and every contribution in, the closing value out) to zero: an internal rate of return. money_weighted_return gives it annualised (ACT/365 Fixed exponents, as a spreadsheet's XIRR); xirr takes dated flows; irr takes flows one period apart (numpy-financial's irr). A rate is a root of a polynomial in 1 / (1 + r), irrational in general: these are double, found with Brent's method (math/roots.hpp).

The root finder. The flows' sign changes bound the number of rates (Descartes' rule of signs, which holds for real exponents too). With none there is no rate (no_root). With one there is exactly one in (-1, inf): it is bracketed between r = 0 and the end of the range where the earliest or the latest flow dominates, and Brent's method closes on it. With more, the whole range is scanned for sign changes (1,024 steps in 1 / (1 + r) for r >= 0 and in 1 + r below) and each is closed with Brent; more than one is multiple_roots, and irr_roots lists them. The range is -0.999999 <= r <= 999,999.

// A quarter: $1m on 1 January; $500k in on 1 February; $200k out on 1 March; $1.32m at the end.
const valuation months[] = {
{cents(100'000'000), cents(0), cents(101'000'000)}, // January: +1%
{cents(101'000'000), cents(50'000'000), cents(153'000'000)}, // February, after the contribution
{cents(153'000'000), cents(-20'000'000), cents(132'000'000)}, // March, after the withdrawal
};
const auto twr = time_weighted_return(months); // exact
const cash_flow flows[] = {{sys_days{2026y / February / 1d}, cents(50'000'000)},
{sys_days{2026y / March / 1d}, cents(-20'000'000)}};
const sys_days start = sys_days{2026y / January / 1d}, end = sys_days{2026y / March / 31d};
const auto dietz = modified_dietz(cents(100'000'000), cents(132'000'000), flows, start, end); // exact
const auto mwr = money_weighted_return(cents(100'000'000), cents(132'000'000), flows, start, end); // annual
const double bond[] = {-950, 50, 50, 50, 50, 1050}; // bought at 95, 5% coupons, five years
const auto yield = irr(bond); // about 6.19% a period
const double two[] = {-100, 230, -132}; // worth zero at 10% and at 20%
double rates[4]{};
const std::size_t n = irr_roots(two, rates);
const xirr_flow dated[] = {{sys_days{2026y / January / 1d}, -10'000}, {sys_days{2026y / March / 1d}, 2'750},
{sys_days{2026y / October / 30d}, 4'250}, {sys_days{2027y / February / 15d}, 3'250},
{sys_days{2027y / April / 1d}, 2'750}};
const auto annual = xirr(dated);

Relationships. finance/ratio.hpp (the exact answers), money/money.hpp (the inputs), math/roots.hpp (brent), math/constexpr_math.hpp (pow). Above core: the fund library's performance reports. Group: snicholls-core.

Implementations / variants. Exact: period_return, time_weighted_return over valuations, modified_dietz. In double: time_weighted_return over returns, irr, irr_roots, xirr, money_weighted_return.

Guarantees. constexpr, noexcept, no allocation (the flows are spans; irr_roots writes into the caller's span). The exact functions return the exact value or an error, never a rounded one; amounts are minor units of one asset, so the asset's scale cancels.

Errors. returns_errc, through result: empty (no periods or flows); asset_mismatch (amounts in two assets); zero_capital (a sub-period, or Dietz's weighted capital, with nothing invested: zero or negative); out_of_range (an amount beyond 64 bits of minor units, or an exact answer that does not fit a ratio: use the double form); invalid_dates (an end before its start, a flow outside the period, dates out of order); no_root (no rate in range: flows of one sign, or a root beyond the range); multiple_roots (more than one rate: the IRR is not defined; read them with irr_roots).

Performance. Not benchmarked. One sign change (the usual case) costs two Brent searches over the flows; more cost a scan of 2,048 evaluations over the flows.

Tests and demos. tests/finance/returns_test.cpp, against numpy-financial 1.0.0's irr and an exact independent reference in Python's fractions and decimal (scripts/generate_returns_fixtures.py, tests/fixtures/finance/returns.txt, CTest generated.returns_fixtures_up_to_date); demos/finance/returns_demo.cpp.

Dependencies. <chrono>, <cstddef>, <cstdint>, <initializer_list>, <limits>, <optional>, <span>, finance/ratio.hpp, math/constexpr_math.hpp, math/roots.hpp, money/money.hpp, result.hpp.

Known issues. A double root (the NPV touches zero without crossing) has no sign change and is not found. Two rates closer together than a scan step are missed. A rate beyond the range is no_root. numpy-financial's irr returns one of several roots where this header says multiple_roots: deliberately, since the IRR is then not a return. The time-weighted return's flow is at the start of its sub-period; a flow at the end belongs to the next.

Status. New in 0.27.0. Experimental.
