Detailed Description

snicholls::fn::bind with placeholders arg<N> / _1 ... _9: arguments bound in any position, constexpr.

Overview. bind(f, a, _2, _1)(x, y) is f(a, y, x). Each bound argument is a value (stored, and passed to f), a placeholder arg<N> (the call's N-th argument, counting from one), or another bind (called with the same arguments, its result passed on):

// A short position's P&L is the long one with entry and exit swapped: reorder with placeholders.
constexpr auto long_pnl = fn::bind(pnl, _1, _2, _3);
constexpr auto short_pnl = fn::bind(pnl, _2, _1, _3);
static_assert(long_pnl(100.0, 110.0, 2.0) == 20.0);
static_assert(short_pnl(100.0, 110.0, 2.0) == -20.0);
// A value in the middle: one lot of 100.
constexpr auto per_lot = fn::bind(pnl, _1, _2, 100.0);
static_assert(per_lot(1.10, 1.12) > 1.99 && per_lot(1.10, 1.12) < 2.01);

Use bind when the arguments must be reordered or repeated, or a nested call made, and a lambda would be longer; use partial / partial_right (functional/curry.hpp) when only the leading or trailing arguments are bound. Never std::bind: it is not constexpr-friendly before C++20, not SFINAE-friendly, and it treats any std::is_bind_expression type specially.

Relationships. functional/curry.hpp (partial, curry), functional/combinators.hpp (the closures). Group: snicholls-core.

Implementations / variants. One. The placeholders are fn::arg<N>, and _1 ... _9 in snicholls::fn::placeholders, which is not pulled in by using namespace snicholls::fn: write using namespace snicholls::fn::placeholders; where they are wanted, so they never meet std::placeholders or another library's.

Guarantees. constexpr. Bound values are stored by value (decayed), passed as lvalues from an lvalue closure and moved from an rvalue one. A placeholder forwards its argument with the value category it was given; a nested bind sees the arguments as lvalues. Arguments no placeholder names are ignored, as std::bind does. The call is noexcept exactly when f's and the nested calls are; trivially copyable when the bound values are.

Errors. A placeholder beyond the number of arguments given makes the call ill-formed (std::is_invocable_v false).

Examples.

// A nested bind is called with the same arguments: the exit is the mid of a bid and an ask.
constexpr auto mid = fn::bind(std::divides<>{}, fn::bind(std::plus<>{}, _2, _3), 2.0);
constexpr auto mark_to_mid = fn::bind(pnl, _1, mid, 10.0);
static_assert(mark_to_mid(100.0, 101.0, 103.0) == 20.0); // (102 - 100) * 10

Performance. Not benchmarked separately: a call is f's call with the arguments rearranged, inlined, as the curry benchmark (benchmarks/functional/combinators_benchmark.cpp) shows for the same closures.

Tests and demos. tests/functional/bind_test.cpp, demos/functional/bind_demo.cpp.

Dependencies. <cstddef>, <functional>, <tuple>, <type_traits>, <utility> and snicholls/core/functional/combinators.hpp.

Known issues and gotchas. A placeholder named twice with an rvalue argument forwards it twice, so the second use may see a moved-from value; take it by const reference in f or pass an lvalue.

Status. Experimental, new in 0.27.0.
