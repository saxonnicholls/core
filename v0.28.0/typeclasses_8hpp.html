Detailed Description

Haskell's type classes as C++20 concepts with instance traits: Semigroup, Monoid, Functor, Applicative, Monad, Alternative, Bifunctor and Profunctor, and the functions over them, all constexpr.

Overview. A type class is a set of operations a type supports, with laws. Here each class is an instance trait, a class template a type specialises to join, and a concept that says whether it has; the operations are function objects that dispatch to the instance:

class instance trait operations here Haskell
Semigroup semigroup_instance<T> combine(a, b), sconcat(a, b, ...) <>, sconcat
Monoid monoid_instance<T> mempty<T>(), mconcat(seq) mempty, mconcat
Functor functor_instance<M> fmap(f, m), replace(x, m) fmap, <$
Applicative applicative_instance<M> pure<M>(x), ap(mf, mx), lift_a2(f, ma, mb) pure, <*>, liftA2
Monad monad_instance<M> mbind(m, k), and_then(k, m), mthen(ma, mb), join(mm), kleisli(f, g), kleisli_left(g, f), mreturn<M>(x) >>=, =<<, >>, join, >=>, <=<, return
Alternative alternative_instance<M> alt(a, b), mzero<M> <\|>, empty (MonadPlus: mplus, mzero)
Bifunctor bifunctor_instance<P> bimap(f, g, p), first(f, p), second(g, p) bimap, first, second
Profunctor (functions) dimap(f, g, h), lmap(f, h), rmap(g, h), contramap dimap, lmap, rmap

The monoid wrappers sum_of, product_of, min_of, max_of, first_of, last_of, all_of, any_of and endo choose which monoid a number, an optional or a function is meant to be, as Haskell's Sum, Product, Min, Max, First, Last, All, Any and Endo do.

The instances for the standard library's and core's types (std::optional, snicholls::result, std::tuple, std::pair, std::array, std::basic_string, std::vector) are in functional/instances.hpp; the Identity, Const, Reader, Writer and State monads in functional/state.hpp. A type of your own joins a class by specialising its trait in namespace snicholls::fn, with static constexpr bool defined = true; and the operations:

// A price with the venue it came from: a Functor maps the price and keeps the venue.
template <class T>
struct tagged {
T value;
char venue;
};
} // namespace
template <class T>
struct snicholls::fn::functor_instance<tagged<T>> {
static constexpr bool defined = true;
template <class F, class M>
static constexpr auto fmap(F&& f, M&& m)
{
return tagged<std::remove_cvref_t<std::invoke_result_t<F, T>>>{std::invoke(f, m.value), m.venue};
}
};

Use these when a calculation is generic over the carrier (written once for optionals, results and parsers), or when the laws are what you are relying on (a monoid folded in parallel and merged); call the carrier's own members (std::optional::value_or, result::map) when the carrier is fixed.

Relationships. functional/instances.hpp (the instances), functional/monad.hpp (lift, sequence, traverse, the monad helpers), functional/list.hpp (Foldable: fold_map, sum, ...), functional/state.hpp, functional/combinators.hpp. Group: snicholls-core.

Implementations / variants. A trait per class, so an instance can be partial (a result has alt but no mzero; an endo combines with an endo of another type). mreturn is pure; MonadPlus is Alternative (mplus is alt).

Guarantees. constexpr wherever the instance is. Every operation is a function object, so it can be passed, composed and curried. noexcept follows the instance's operation exactly (each dispatch is noexcept(noexcept(instance call))). The laws are the instance's promise; for core's instances they are tested at compile time (tests/functional/typeclasses_laws_test.cpp): Functor identity and composition, Monad left and right identity and associativity, Monoid identity and associativity.

Errors. An operation on a type with no instance is not invocable (std::is_invocable_v false).

Examples.

// One pass over the fills, three summaries at once: a tuple of monoids is a monoid.
constexpr std::array fills{120.0, -40.0, 15.0, 60.0};
constexpr auto summary = fn::fold_map([](double pnl) {
return std::tuple{fn::sum_of<double>{pnl}, fn::max_of<double>{pnl}, fn::all_of{pnl > -50.0}};
}, fills);
static_assert(std::get<0>(summary).value == 155.0);
static_assert(std::get<1>(summary).value == 120.0);
static_assert(std::get<2>(summary).value);

A parser over std::string_view joining Functor, Applicative and Alternative, and an order-ticket parser built from pieces with fmap, lift_a2, ap and alt, run by the compiler:

constexpr auto t = ticket_p.run("BUY 1000000 EUR/USD");
static_assert(t && t->first.buy && t->first.amount == 1'000'000 && t->first.base == "EUR" && t->first.quote == "USD");
static_assert(t->second.empty());
constexpr auto s = ticket_p.run("SELL 250 GBP/JPY rest");
static_assert(s && !s->first.buy && s->first.quote == "JPY" && s->second == " rest");
static_assert(!ticket_p.run("HOLD 5 EUR/USD")); // neither side parses
static_assert(!ticket_p.run("BUY lots EUR/USD")); // no quantity

Performance. Each operation is the instance's call, inlined; not benchmarked separately.

Tests and demos. tests/functional/typeclasses_test.cpp, tests/functional/typeclasses_laws_test.cpp, demos/functional/typeclasses_demo.cpp, demos/functional/typeclasses_parser_demo.cpp, demos/functional/typeclasses_map_reduce_demo.cpp (map-reduce with monoids).

Dependencies. <concepts>, <cstddef>, <functional>, <limits>, <optional>, <type_traits>, <utility>, functional/combinators.hpp, functional/curry.hpp, functional/fold.hpp.

Known issues and gotchas.

  • pure<M> and mzero<M> need the carrier named, as Haskell infers it from the context: pure<std::optional<int>>(3). The value type in M is only a key; the result holds decay_t of the argument.
  • A std::variant is not a Functor: nothing marks one alternative as the value. Use match (functional/match.hpp) or std::visit.
  • endo of different function types combine into a third type, so endo is a semigroup only in that looser sense; mconcat over a range of endo needs one function type.

Status. Experimental, new in 0.27.0.
