Detailed Description

Haskell's Data.List and OCaml's List over std::array (lists whose length is known at compile time) and, for the folds and searches, any input range; Foldable's length, null, elem, sum, product, maximum, minimum, fold_map; and fst, snd, map_tuple. All constexpr.

Overview. A std::array is a list with its length in its type, so each operation returns a type whose length the compiler knows: take<K> an array<T, K>, concat an array<T, N * M>, transpose an array<array<T, N>, M>. An operation whose length depends on the values (filter, nub, group, span) returns a containers::inplace_vector<T, N>, an array with a size, so nothing allocates:

constexpr std::array quantities{500, -200, 300, -100, 700};
// Split the book into buys and sells, keep their order.
constexpr auto split = fn::partition([](int q) { return q > 0; }, quantities);
static_assert(split.first.size() == 3 && split.second.size() == 2);
// Running position, and the largest fills first.
static_assert(fn::scanl([](int p, int q) { return p + q; }, 0, quantities) == std::array{0, 500, 300, 600, 500, 1200});
static_assert(fn::sort_on([](int q) { return -(q < 0 ? -q : q); }, quantities) == std::array{700, 500, 300, -200, -100});
// Ladders: zip prices with sizes, the first three levels.
constexpr auto ladder = fn::take<3>(fn::zip(std::array{1.0850, 1.0849, 1.0848, 1.0847}, std::array{5, 10, 20, 50}));
static_assert(ladder[2] == std::pair{1.0848, 20});
// A matrix of exposures, transposed from desks-by-currency to currency-by-desks.
constexpr auto by_ccy = fn::transpose(std::array{std::array{1, 2, 3}, std::array{4, 5, 6}});
static_assert(by_ccy[2] == std::array{3, 6});

foldl, foldr, foldl_of, foldr_of and unfold are in functional/fold.hpp; infinite lists (iterate, repeat, cycle, takeWhile on them) in functional/lazy.hpp. For lists known only at run time, std::views (transform, filter, take, drop, reverse) and <algorithm> are the tools; the searches and folds here accept any input range as well.

Relationships. functional/fold.hpp, functional/lazy.hpp, functional/instances.hpp (concat_map is the array monad's mbind), snicholls::fold_list (scanl calls it), snicholls::permutations (permutations calls it), containers::inplace_vector. Group: snicholls-core.

Implementations / variants. One each.

Guarantees. constexpr, allocation-free (C++20's std::sort-family algorithms are constexpr; sort_by is stable, an insertion sort, suited to the short lists that are sorted at compile time). Elements are copied out of the input, which is never modified. inplace_vector results need a default-constructible element type.

Errors. foldl1 / foldr1 of an empty array, and subsequences of more than 20 elements, do not compile. maximum / minimum of an empty range is a precondition violation (checked with assert).

Examples.

constexpr std::array venues{std::pair{'L', 1.0851}, std::pair{'E', 1.0852}, std::pair{'C', 1.0850}};
static_assert(fn::lookup('E', venues) == std::optional{1.0852});
static_assert(fn::find_index([](const auto& v) { return v.second < 1.0851; }, venues) == std::optional<std::size_t>{2});
static_assert(fn::all([](const auto& v) { return v.second > 1.08; }, venues));

Performance. Loops over the elements; nub and group_by are quadratic, as in Haskell. Not benchmarked separately.

Tests and demos. tests/functional/list_test.cpp, demos/functional/list_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <cstddef>, <functional>, <iterator>, <optional>, <ranges>, <tuple>, <type_traits>, <utility>, containers/inplace_vector.hpp, combinatorics/permutations.hpp, iterate.hpp and functional/instances.hpp.

Known issues and gotchas. fn::zip and fn::partition share their names with snicholls::zip (run-time ranges walked together) and with std::partition; with both namespaces opened, qualify them. permutations grows as N!: twelve elements are already half a billion lists.

Status. Experimental, new in 0.27.0.
