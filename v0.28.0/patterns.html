Patterns

How the pieces of snicholls-core fit together. Each pattern names the problem, the types that solve it, a compiled example (every snippet below is cut from a demo that runs as a CTest, so none of it can rot) and when not to use it. The per-header pages hold the detail; this page is the map. The programs in showcase/ put many of these patterns to work at once.

Principles behind every pattern

  • Decide at compile time. Tables, maps, attribution weights and stopping regions are built by the compiler (consteval constructors, constexpr functions); the hot path is a lookup or a few arithmetic operations.
  • Standard library only, header-only, C++20. Nothing here depends on a library above core.
  • Device-ready primitives. Pure constexpr functions, spans of plain data in, trivially copyable state, partial results that merge, randomness by stream or by index: callable from a GPU kernel, synthesizable for an FPGA in the fixed-size forms.
  • Zero overhead, proved. Anything with a run-time footprint carries static_asserts on its layout and a like-for-like benchmark against the hand-written equivalent.

Errors

Expected failure is a value: result<V, E>

Problem. A parse, a lookup or a call to a provider can fail in the ordinary course of things; bool plus an out-parameter loses the reason, and an exception hides the path.

Pieces. snicholls::result<V, E>, ok(v) / err(e), SNICHOLLS_TRY (Rust's ?), and the portable SNICHOLLS_TRY_ASSIGN / SNICHOLLS_TRY_VOID. A result of trivial types is trivially copyable and travels in registers.

// SNICHOLLS_TRY is Rust's `?`: the value, or return the error from this function.
snicholls::result<double, price_error> mid_price(std::string_view bid, std::string_view ask)
{
#if SNICHOLLS_RESULT_HAS_STATEMENT_EXPRESSIONS
const double b = SNICHOLLS_TRY(parse_price(bid));
const double a = SNICHOLLS_TRY(parse_price(ask));
#else
SNICHOLLS_TRY_ASSIGN(const double b, parse_price(bid)); // the portable statement form
SNICHOLLS_TRY_ASSIGN(const double a, parse_price(ask));
#endif
return snicholls::ok((b + a) / 2);
}
// result<void, E> is Rust's Result<(), E>; SNICHOLLS_TRY_VOID discards the value.
snicholls::result<void, price_error> validate_quote(std::string_view bid, std::string_view ask)
{
SNICHOLLS_TRY_VOID(parse_price(bid));
SNICHOLLS_TRY_VOID(parse_price(ask));
return snicholls::ok();
}

Not for the unexpected (a broken invariant): that stays an exception or an assertion.

Errors for logs: traced<E>

Problem. An error that reaches a log needs where it happened and what was going on, without paying for that on the success path.

Pieces. snicholls::traced<E>: the error plus a source location and lazily allocated context, fields and stack; error_sink and log_err(sink) hand it to the logger the program chose.

enum class io_error
{
not_found = 2,
};
using io_result = snicholls::result<std::string, snicholls::traced<io_error>>;
io_result read_file(std::string_view path)
{
if (path != "positions.csv")
return snicholls::traced_err(io_error::not_found); // records this file and line
return snicholls::ok(std::string("ES,10\nNQ,-4\n"));
}
snicholls::result<std::size_t, snicholls::traced<io_error>> load_positions(std::string_view account, std::string_view path)
{
// context() adds a frame at this line; SNICHOLLS_TRY adds a "propagated" frame with the expression text.
SNICHOLLS_TRY_ASSIGN(const std::string text, read_file(path).context("loading positions for {}", account));
return snicholls::ok(static_cast<std::size_t>(std::count(text.begin(), text.end(), '\n')));
}

Not for the wire: send error() or the report fields, never the trace. Never put a secret in context text.

Capabilities: a contract, its twin, a reference and a kit

Problem. A library needs "something that can sign", "a key-value store", "a source of random bytes" without depending on the library that implements it, and every implementation must behave the same.

Pieces. For each capability core holds four things:

  1. a concept (random_source_like), for static dispatch with no cost;
  2. a virtual twin (random_source_interface) with adapters both ways (random_source_adapter<Impl>, any_random_source), for when the implementation is chosen at run time;
  3. a reference implementation (test_random_source), deterministic and constexpr where it can be, for tests;
  4. a conformance kit (check_random_source), which every real implementation, in whichever library, must pass.

Failures are capability_errc, and nothing secret is ever written into an error.

// A 128-bit session token from any random source; the caller's failure is ours, never a weaker fallback
template <typename Source>
std::errc session_token(Source& source, std::array<std::byte, 16>& token) noexcept
{
static_assert(snicholls::is_random_source_like_v<Source>, "a cryptographic random source");
return source.fill(token.data(), token.size());
}
const bool testing = true; // a configuration decides which source the process uses
any_random_source source = testing ? any_random_source::of(test_random_source{7})
: any_random_source{}; // production: ts-moveables' source here
std::array<std::byte, 32> key{};
const std::errc e = source.fill(key.data(), key.size());
test_random_source a{1234}, b{1234}; // NOT cryptographic: the seed fixes every byte, for reproducible tests
std::array<std::byte, 24> x{}, y{};
(void)a.fill(x.data(), x.size());
(void)b.fill(y.data(), y.size());
unavailable_random_source unseeded; // proves a caller's failure path fails closed
test_random_source source{99};
const std::vector<std::string> problems = check_random_source(source); // empty: it conforms
for (const std::string& p : problems)
std::printf(" %s\n", p.c_str());
unavailable_random_source down;
const auto closed = check_random_source_fails_closed(down); // empty: it fails closed

The same shape serves the payment, on-ramp, signer, verifier, key store, key-value store, SQL, HTTP, message, remote-file, task-pool, clock, time-zone and UUID capabilities under interfaces/.

Not for a helper with one obvious implementation: write the function.

State machines

A machine is a table

Problem. Lifecycles (an order, a payment, a security, a session) are where bugs hide when written as flags and ifs.

Pieces. fsm/state_machine.hpp, in the style of Boost.SML: a transition table of state + event [guard] / action = next, checked by the compiler, with composite and orthogonal regions, history, deferral, logging and visitors.

struct release {};
struct ack {};
struct fin {};
struct timeout {};
const auto is_ack_valid = [](const ack&) { return true; };
const auto is_fin_valid = [](const fin&) { return true; };
const auto send_fin = [] { trace += "send_fin "; };
const auto send_ack = [] { trace += "send_ack "; };
struct hello_world {
auto operator()() const
{
using namespace snicholls::fsm;
return make_transition_table(
*"established"_s + event<release> / send_fin = "fin wait 1"_s,
"fin wait 1"_s + event<ack> [is_ack_valid] = "fin wait 2"_s,
"fin wait 2"_s + event<fin> [is_fin_valid] / send_ack = "timed wait"_s,
"timed wait"_s + event<timeout> / send_ack = X);
}
};
sm<hello_world> machine;
ok &= machine.is("established"_s);
ok &= machine.process_event(release{});
ok &= machine.is("fin wait 1"_s);
ok &= machine.process_event(ack{});
ok &= machine.is("fin wait 2"_s);
ok &= machine.process_event(fin{});
ok &= machine.is("timed wait"_s);
ok &= machine.process_event(timeout{});
ok &= machine.is(X); // released

Save, load and draw it

A machine's state saves and restores, so a lifecycle survives a restart; the same table draws itself.

sm<outer> machine;
ok &= machine.process_event(go{}) && machine.process_event(dig{});
const auto v1 = save(store, "job/7", machine, 0); // 0: a new key; the result is the version written
ok &= v1.is_ok() && *v1 == 1;
sm<outer> restored; // another process
const auto read = load(store, "job/7", restored); // every region, the sub-machine's included
ok &= read.is_ok() && *read == 1;
ok &= restored.is(state<inner>, "lights on"_s) && restored.is<inner>("deep"_s);
const auto stale = save(store, "job/7", restored, 0); // claims there was nothing: someone saved version 1
ok &= stale.is_err() && stale.unwrap_err_unchecked() == fsm_errc::stale;
ok &= save(store, "job/7", restored, *read).is_ok(); // with the version it read: version 2
const std::string mermaid = to_mermaid<lifecycle>(); // or to_mermaid(machine)

Lifecycles that read as the domain

sm<lifecycle> machine; // requested
payment p{12'50};
for (const auto step : {0, 1, 2}) {
const bool moved = step == 0 ? machine.process_event(submit{})
: step == 1 ? machine.process_event(confirm{})
: machine.process_event(settle{});
ok &= moved;
p.state = machine.current(); // pending, then confirmed, then settled
snicholls::println(p.state); // acout reads the state's label and colour
}

Machines, functionally

A machine is a function from state and event to state, so everything in functional/ applies to it.

  • A run is a fold, and its trace a scan:
constexpr std::array<input, 6> day{coin{}, push{}, push{}, coin{}, coin{}, push{}};
constexpr turn last = fn::foldl_of(step, machine{}, day).current(); // where the day ends
constexpr auto trace = fn::map(state_of, fn::scanl(step, machine{}, day)); // every state, the start included
static_assert(last == turn::locked);
static_assert(trace == std::array{turn::locked, turn::unlocked, turn::locked, turn::locked, turn::unlocked,
turn::unlocked, turn::locked});
  • Event sourcing is a law: a snapshot plus the remaining events equals the full replay, proved by static_assert:
// A snapshot is the lifecycle state and the money; resuming restores the machine (no action runs) and replays the rest.
struct snapshot {
account_state state;
long balance;
int refused;
};
constexpr snapshot take(const account& a) { return {a.life.current(), a.balance, a.refused}; }
constexpr account resume(const snapshot& s)
{
account a{machine{}, s.balance, s.refused};
static_cast<void>(a.life.restore(s.state));
return a;
}
// The law, for every split point k: replay(all) == replay(resume(take(replay(first k))), rest).
constexpr bool snapshots_are_safe()
{
const account whole = replay(account{}, history);
for (std::size_t k = 0; k <= history.size(); ++k) {
const std::span<const account_event> all{history};
const account resumed = replay(resume(take(replay(account{}, all.first(k)))), all.subspan(k));
if (!(resumed == whole)) return false;
}
return true;
}
static_assert(snapshots_are_safe());
  • A Mealy machine is the State monad: the same machine as a table and as fn::state, identical on every input:
// Every one of the 256 input sequences of length 8: the table and the monad emit the same eight outputs.
constexpr bool same_machine()
{
for (unsigned bits = 0; bits < 256; ++bits) {
const tape a = run_table(inputs_of(bits));
const tape b = run_monad(inputs_of(bits));
if (a.size != 8 || b.size != 8 || a.out != b.out) return false;
}
return true;
}
static_assert(same_machine());
  • Guards from combinators, transitions on the railway:
// Guards as values, built from pieces. A closure from fn goes into a table wrapped in fn::pointwise, and the pieces
// are combined here, outside the table: inside it, &&, || and ! are the table's own guard algebra, and combining two
// pointwise guards there would be ambiguous between the two.
constexpr bool at_most(long limit, long cents) { return cents <= limit; }
constexpr fn::pointwise amount{[](const authorise& a) { return a.cents; }};
constexpr auto authorisable = (amount > 0L) && (amount <= 50'000L); // a predicate
constexpr fn::pointwise refundable{fn::compose(fn::curry(at_most)(20'000L), &refund::cents)}; // curried, composed
static_assert(authorisable(authorise{1'000}) && !authorisable(authorise{0}) && !authorisable(authorise{90'000}));
static_assert(refundable(refund{5'000}) && !refundable(refund{25'000}));
// Each enters the table behind a lambda with the event's type: the table reads a guard's parameters from its
// signature, and Clang 18 crashes deducing them through pointwise's generic call operator.
constexpr auto authorisable_guard = [](const authorise& a) { return authorisable(a); };
constexpr auto refundable_guard = [](const refund& r) { return refundable(r); };
struct card_payment {
constexpr auto operator()() const
{
using namespace snicholls::fsm;
constexpr auto created = enum_state<payment::created>;
constexpr auto authorised = enum_state<payment::authorised>;
constexpr auto captured = enum_state<payment::captured>;
constexpr auto refunded = enum_state<payment::refunded>;
return make_transition_table(
*created + event<authorise> [authorisable_guard] = authorised,
authorised + event<capture> = captured,
captured + event<refund> [refundable_guard] = refunded);
}
};
// One track: card -> valid card -> authorised -> captured. Each and_then runs only on success.
constexpr outcome checkout(std::optional<card> c, long cents, int this_year)
{
snicholls::fsm::sm<card_payment> m;
int steps = 0;
auto r = option::ok_or(c, checkout_error::no_card)
.and_then([&](card k) -> snicholls::result<void, checkout_error> {
++steps;
if (k.expiry_year < this_year) return snicholls::err(checkout_error::expired);
return snicholls::ok();
})
.and_then([&] {
++steps;
return m.try_process_event(authorise{cents}).map_err(from_machine);
})
.and_then([&] {
++steps;
return m.try_process_event(capture{}).map_err(from_machine);
});
return {r, m.current(), steps};
}
  • Reachability is a fixed point of the transition relation:
// Reachable from draft: the least set R with draft in R and image(R) within R. Iterate R -> R | image(R).
constexpr auto reachable = snicholls::fixed_point([](set r) { return r | image(r); }, bit(order::draft), 64);
static_assert(reachable.converged && reachable.value == (set{1} << state_count) - 1); // every state is reachable
// Can still be delivered: the least set D with delivered in D and preimage(D) within D.
constexpr auto can_deliver = snicholls::fixed_point([](set d) { return d | preimage(d); }, bit(order::delivered), 64);
static_assert(can_deliver.value ==
(bit(order::draft) | bit(order::placed) | bit(order::paid) | bit(order::shipped) | bit(order::delivered)));
// Terminal states: no successors at all.
constexpr set terminal = [] {
set t = 0;
for (std::size_t s = 0; s < state_count; ++s)
if (next[s] == 0) t |= set{1} << s;
return t;
}();
static_assert(terminal == (bit(order::cancelled) | bit(order::refunded)));

Not for a two-state toggle: a bool is fine.

Presentation is an attribute of the type

Problem. Colour, labels, number formats and tooltips written at each call site drift apart, and P&L coloured by hand is eventually coloured wrong.

Pieces. A type or enumeration declares a constexpr function attributes in its own namespace returning attrs(...) (meta/attributes.hpp): colour, sign_colours, label, number_format (checked by the compiler), tooltip. acout, print_to, containers and stats::pivot read them, and write_enum_json exports them for a user interface, so each is written once.

enum class greek : std::uint8_t { delta, gamma, vega, vanna, volga, theta, rho };
struct column_width { // an attribute of the caller's own: any literal type
int characters;
};
// One set per greek, in enumerator order; leaving one out is a compile error.
constexpr auto attributes(greek g)
{
using namespace snicholls;
return per_enumerator(g, [] { return std::array{
attrs(colours::blue, label{"delta"}, tooltip{"dV/dS: P&L per unit move in the underlying"}, column_width{8}),
attrs(colours::cyan, label{"gamma"}, tooltip{"d2V/dS2: how delta changes as the underlying moves"}, column_width{8}),
attrs(colours::magenta, label{"vega"}, tooltip{"dV/dsigma: P&L per volatility point"}, column_width{8}),
attrs(colours::orange, label{"vanna"}, tooltip{"d2V/dS dsigma: delta's change with volatility"}, column_width{8}),
attrs(colours::yellow, label{"volga"}, tooltip{"d2V/dsigma2: vega's change with volatility"}, column_width{8}),
attrs(colours::grey, label{"theta"}, tooltip{"dV/dt: P&L from one day passing"}, column_width{8}),
attrs(rgb(0x953800), label{"rho"}, tooltip{"dV/dr: P&L per basis point of rates"}, column_width{8}),
}; });
}
// Green and red mean up and down, so no greek is green or red.
struct pnl { // P&L is green when up and red when down, wherever it prints

};
constexpr auto attributes(const pnl&) { return snicholls::attrs(snicholls::sign_colours{}, snicholls::number_format{"{:+.0f}"}); }
// Everything is known to the compiler.
static_assert(snicholls::attributes_of(greek::vanna).get<snicholls::tooltip>().text.starts_with("d2V/dS dsigma"));
static_assert(snicholls::attribute_or(greek::rho, snicholls::colours::red) == snicholls::rgb(0x953800));
static_assert(snicholls::attribute_or(3.0, column_width{12}).characters == 12); // a double has none
// P&L by greek: each greek in its colour, each P&L green or red, one message.
const std::array<std::pair<greek, pnl>, 7> by_greek{{{greek::delta, {12'500}}, {greek::gamma, {-3'200}}, {greek::vega, {4'100}},
{greek::vanna, {-900}}, {greek::volga, {350}}, {greek::theta, {-1'800}},
{greek::rho, {0}}}};
snicholls::acout out;
for (const auto& [g, p] : by_greek)
out << " " << g << '\t' << p << '\n';
snicholls::acout{} << today; // the same grid, in colour on a terminal

Rule. Green and red mean up and down, never an identity.

Printing

One message, one write

Problem. Lines from several threads interleave mid-line.

Pieces. acout{} << ..., acerr{}, print(...) / println(...): each message is built whole and written under one lock. Containers, tuples, optionals, variants and results print as they are, recursively.

// The one-line forms: a format string checked at compile time, written in one call.
snicholls::println(" {} of {} orders filled ({:.1f}%)", 7, 8, 87.5);
snicholls::print(stderr, " {}: {}\n", "warning", "stderr through fwrite");
// Into a message, mixed with streaming, emitted when it goes out of scope.
{
snicholls::acout message;
message << " order " << 42 << ": ";
message.print("{} @ {:.2f}", "AAPL", 189.25).println(" {}", "filled");
}
// Containers, pairs, tuples, optionals and type lists print as they are, recursively, through
// the same engine: into an acout always, onto a plain stream with the operator above in scope.
const std::map<std::string, std::vector<int>> book{{"bids", {100, 99}}, {"asks", {101, 102}}};
const std::vector<std::pair<std::string, std::optional<double>>> marks{{"AAPL", 189.25}, {"PRIV", std::nullopt}};
snicholls::acout{} << " book " << book << '\n';
snicholls::println(marks);
snicholls::acout{} << " types " << snicholls::meta::type_list<int, double>{} << '\n';
std::ostringstream shown;
shown << book << " " << std::tuple{1, 'a', "two"};

A type that prints itself

One member, void print(snicholls::acout&) const, and nothing else: no per-type operator<<.

// A type that prints itself: one member, and that is the whole contract. The classic form
// takes a stream ...
struct fill {
const char* symbol;
int quantity;
double price;
void print(std::ostream& os) const { os << symbol << " x" << quantity << " @ " << std::fixed << std::setprecision(2) << price; }
};
// ... and the better form takes the message: format strings inside, and the whole object is
// written in one call wherever it is streamed.
struct quote {
const char* symbol;
double bid;
double ask;
void print(snicholls::acout& out) const { out.print("{} {:.2f}/{:.2f}", symbol, bid, ask); }
};
// Plain streams get the operator by opting in, as with magic_enum's iostream_operators.
using snicholls::print_operators::operator<<;
// Through acout, print() is found by the concept; through a plain stream, by the operator above;
// println(value) is the one-liner.
const fill f{"AAPL", 100, 189.25};
const quote q{"AAPL", 189.20, 189.30};
snicholls::acout{} << " filled: " << f << " at " << q << '\n';
snicholls::println(q);
std::ostringstream plain;
plain << f << "; " << q;

Dispatch over types and values

Overload sets, never if constexpr chains

Problem. A chain of if constexpr over a type is hard to read and impossible to extend from outside.

Pieces. overloaded{...} for cases that do not overlap; first_match{...} with concept-constrained lambdas (meta/concepts.hpp) when they do: the first that accepts the argument runs, in the order written.

// The conditions of the chain are core's concepts (snicholls/core/meta/concepts.hpp).
std::string text(const auto& value); // the chain calls itself for the elements of a range
// A to_string written as one generic lambda has an if constexpr / else if constexpr
// chain inside it. Here every branch is its own callable and the order of the list is the
// chain: the first that accepts the value runs, and nothing is ambiguous. No if constexpr.
const auto text_chain = snicholls::first_match{
[](std::string_view s) { return std::string{s}; }, // std::string, const char*, string_view
[](std::same_as<bool> auto b) { return std::string{b ? "true" : "false"}; },
[](snicholls::character auto c) { return std::string(1, static_cast<char>(c)); },
[](snicholls::integer auto n) { return std::to_string(n); }, // not bool, not a character
[](std::floating_point auto x) { return std::format("{}", x); },
[](snicholls::enumeration auto e) { return std::to_string(static_cast<std::underlying_type_t<decltype(e)>>(e)); },
[](const snicholls::map_like auto& m) {
std::string out{"{"};
for (const auto& [key, value] : m)
out += (out.size() > 1 ? ", " : "") + text(key) + ": " + text(value);
return out + "}";
},
[](const std::ranges::input_range auto& r) { // after map_like: a map is a range too
std::string out{"["};
for (const auto& element : r)
out += (out.size() > 1 ? ", " : "") + text(element);
return out + "]";
},
[](const snicholls::streamable auto& x) { std::ostringstream os; os << x; return os.str(); },
[](const auto&) { return std::string{"?"}; }, // the else
};
std::string text(const auto& value) { return text_chain(value); }
using message = std::variant<int, double, std::string>;
const std::vector<message> inbox{42, 2.5, std::string{"hello"}};
const auto describe = snicholls::overloaded{
[](int n) { return "int " + std::to_string(n); },
[](const std::string& s) { return "string " + s; },
[](const auto&) { return std::string{"something else"}; }, // catch-all
};
for (const auto& m : inbox)
std::printf(" %s\n", std::visit(describe, m).c_str());

// A parser is a function from the input to a value and the rest, or nothing.
template <class F = void>
struct parser {
F run;
};
template <class F>
parser(F) -> parser<F>;
template <class T>
using parsed = std::optional<std::pair<T, std::string_view>>;
} // namespace
namespace snicholls::fn {
template <class F>
struct functor_instance<parser<F>> {
static constexpr bool defined = true;
template <class G, class P>
static constexpr auto fmap(G g, P p)
{
return parser{[g, p](std::string_view s) {
auto r = p.run(s);
using T = std::remove_cvref_t<decltype(g(r->first))>;
return r ? parsed<T>(std::pair{g(r->first), r->second}) : parsed<T>();
}};
}
};
template <class F>
struct applicative_instance<parser<F>> {
static constexpr bool defined = true;
template <class X>
static constexpr auto pure(X x)
{
return parser{[x](std::string_view s) { return parsed<X>(std::pair{x, s}); }};
}
template <class PF, class PX>
static constexpr auto ap(PF pf, PX px) // run the function's parser, then the value's on what is left
{
return parser{[pf, px](std::string_view s) {
auto f = pf.run(s);
using T = std::remove_cvref_t<decltype(f->first(px.run(s)->first))>;
if (!f) return parsed<T>();
auto x = px.run(f->second);
return x ? parsed<T>(std::pair{f->first(x->first), x->second}) : parsed<T>();
}};
}
};
template <class F>
struct alternative_instance<parser<F>> {
static constexpr bool defined = true;
template <class A, class B>
static constexpr auto alt(A a, B b) // the first that parses
{
return parser{[a, b](std::string_view s) {
auto r = a.run(s);
return r ? r : b.run(s);
}};
}
};

stats[p], std::span<float>(x).subspan(p * d, d), lnfw.g, lnfb.g);

const ml::block_gradients<float> grads{
b.n1w.g, b.n1b.g, b.n2w.g, b.n2b.g,
{dq, dk, dv, b.wq.g, b.wk.g, b.wv.g, b.wo.g, b.bq.g, b.bk.g, b.bv.g, b.bo.g, {}, {}},
{b.up.g, {}, b.down.g, b.bup.g, {}, b.bdown.g},
scratch};

}

}
std::vector<tensor*> all{&wte, &wpe, &lnfw, &lnfb};

for (tensor* e : all) {

// The extended Rosenbrock function: independent pairs, minimum 0 at all ones
double rosenbrock(cspan x, std::span<double> g)
{
double f = 0;
for (std::size_t i = 0; i + 1 < x.size(); i += 2) {
const double a = x[i + 1] - x[i] * x[i], b = 1 - x[i];
f += 100 * a * a + b * b;
g[i] = -400 * x[i] * a - 2 * b;
g[i + 1] = 200 * a;
}
return f;
}

// KKT for the LASSO: -∇ᵢ = μ sign(xᵢ) where xᵢ ≠ 0, |∇ᵢ| ≤ μ where xᵢ = 0
double kkt_violation(const std::array<double, n>& x)
{
const auto g = gradient(x);
double worst = 0;

}
return worst;

{

}

}

A recombining lattice (binomial, trinomial) is a fixed stencil, not a matrix: lattice_envelope<Steps> keeps one row, O(Steps) state in a std::array, and returns the value and the early-exercise boundary.

// A recombining lattice: node j of step t moves to j (down) or j + 1 (up), the same stencil at every node, so one
// row of storage carries the whole backward induction. A 64-step American put, S = K = 100, 4% a year, 20% vol.
constexpr std::size_t steps = 64;
constexpr double dt = 1.0 / steps, up = snicholls::math::exp(0.2 * snicholls::math::sqrt(dt));
constexpr double p = (snicholls::math::exp(0.04 * dt) - 1 / up) / (up - 1 / up);
constexpr auto put = [](std::size_t t, std::size_t j) {
const double s = 100 * snicholls::math::pow(up, 2 * static_cast<double>(j) - static_cast<double>(t));
return s < 100 ? 100 - s : 0.0;
};
constexpr auto tree = st::lattice_envelope<steps>(std::array{1 - p, p}, put, snicholls::math::exp(-0.04 * dt));
// Computed by the compiler: worth more than exercising now, and exercised early near expiry from the bottom node up
static_assert(tree.value > put(0, 0) && !tree.exercises(0) && tree.exercises(steps - 1) && tree.first_exercise[steps - 1] == 0);
