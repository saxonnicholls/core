Detailed Description

Rust's Option methods over std::optional (fn::rust::option), std::cmp's ordering helpers (fn::rust::cmp) and Into (fn::rust::into<T>), each the one Rust has and C++20 lacks. All constexpr.

Overview. snicholls::result already carries Rust's Result methods as members (map, map_err, map_or, map_or_else, and_then, or_else, and_, or_, inspect, inspect_err, is_ok_and, is_err_and, ok, err, flatten, transpose, unwrap_or, unwrap_or_else, unwrap_or_default, iter). C++20's std::optional has only value_or; this header gives it the rest of Rust's Option, as free functions taking the optional first, in Rust's argument order:

// A quote that may be missing, checked for freshness, turned into a mid price or an error.
const std::optional<quote> q = quote{99.5, 100.5, 40};
const auto fresh = option::filter(q, [](const quote& x) { return x.age_ms < 250; });
const snicholls::result<quote, quote_error> checked = option::ok_or(fresh, quote_error::stale);
const double mid = option::map_or(fresh, 0.0, [](const quote& x) { return (x.bid + x.ask) / 2; });

In a pipeline the receiver is bound last: o | fn::then(fn::partial_right(option::filter, p)), or a plain lambda. fn::rust::option is a namespace of function objects, so each can be passed and curried.

Ordering. Rust's Ordering is C++'s comparison categories (std::strong_ordering and friends, from <=>). cmp::then keeps the first non-equal ordering (the category is their common one), cmp::reverse flips one (0 <=> o), and cmp::comparing(key) builds a three-way comparator from a key, through snicholls::synth_three_way so a key with only < works:

// Highest priority first, then cheapest, then by id: Rust's a.cmp(b).then_with(...), as one comparator.
std::array<order, 4> book{{{1, 101.0, 7}, {2, 100.5, 3}, {2, 100.0, 9}, {1, 101.0, 2}}};
const auto best_first = cmp::lexicographic(cmp::reversed(cmp::comparing(&order::priority)), cmp::comparing(&order::price),
cmp::comparing(&order::id));
std::ranges::sort(book, cmp::as_less(best_first));

Relationships. snicholls::result (Rust's Result), functional/rust_iter.hpp (iterators and slices), functional/monad.hpp and functional/typeclasses.hpp (fmap, mbind, join), functional/ocaml.hpp (the same idea for OCaml), meta/compare.hpp, checked.hpp (numeric_cast). Group: snicholls-core.

Implementations / variants. One overload per value category of the optional: an lvalue is copied from, an rvalue moved from, as Rust's self by value moves.

Guarantees. constexpr. is_some_and, is_none_or, map_or, map_or_else, take, into and the cmp functions (but not the comparator lexicographic returns) are noexcept exactly when the calls and the copies or moves they make are; the others do not claim it. take, take_if, replace, insert and the get_or_insert family modify the optional they are given, as Rust's &mut self methods do; insert and get_or_insert* return a reference into it, valid while it holds that value.

Errors. None of their own: a callable's exception propagates, and the optional is then unchanged.

Examples.

// into<T> converts as Rust's Into does: implicitly and never narrowing.
const double widened = snicholls::fn::rust::into<double>(2.5f);
const std::string name = snicholls::fn::rust::into<std::string>("EURUSD");

Performance. A branch on has_value() and the call; not benchmarked.

Tests and demos. tests/functional/rust_test.cpp, demos/functional/rust_demo.cpp, demos/functional/rust_showcase_demo.cpp (Option, Result and iterator chains end to end).

Dependencies. <compare>, <concepts>, <cstddef>, <functional>, <optional>, <type_traits>, <utility>, snicholls/core/result.hpp (heavier than it looks: <string_view> and <stdexcept>), meta/compare.hpp, meta/concepts.hpp and functional/combinators.hpp.

Known issues and gotchas. and, or and xor are C++ keywords, so the functions are and_, or_ and xor_, as result's members are. fn::rust::option::zip is not snicholls::zip (ranges): qualify it. into<T> refuses a narrowing conversion by brace-initialisation's rules, as core's struct conversions do: double to int (Rust has no From<f64> for i32) and also int to double, which Rust allows.

Status. Experimental, new in 0.27.0.
