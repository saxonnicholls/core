Detailed Description

snicholls::basic_token<Chain, Address, Decimals, Symbol>: a token as a type, declared in one line and checked by the compiler.

Overview. A deployed token's chain, contract, decimals and symbol never change, so a token is a type. A product declares its own in one line, 

struct SAX : snicholls::basic_token<snicholls::chain::base, "0x...", 18, "SAX"> {};

and gets every member token_like asks for, all static constexpr:

  • chain(), a value of the chain type; contract(), the address as written; symbol();
  • scale(), the decimals;
  • code(), SYMBOL:chainid (SAX:8453), built at compile time, so that the same symbol on two chains is two assets.

The compiler checks the declaration: the address must be in its chain's canonical form (EIP-55 mixed-case hex for an EVM chain, verified with core's Keccak-256; base58check T... for TRON, verified with SHA-256), the decimals at most max_scale, and the code a valid asset code (so the symbol is capitals, digits and . - _). A mistyped address is a compile error, never a silent loss of funds.

An issuer's single-supply token, one asset across its chains, keeps its bare symbol: the deriving struct hides code() with its own (static constexpr std::string_view code() noexcept { return "SAX"; }).

// A product's token on Base (EIP-55's example address standing in). A typo in the address's case is a compile error.
struct SAX : snicholls::basic_token<snicholls::chain::base, "0x5aAeb6053F3E94C9b9A09f33669435E7Ef1BeAed", 18, "SAX"> {};
static_assert(SAX::code() == "SAX:8453");
// A single-supply issuer token, one asset on every chain, keeps its bare symbol.
struct GLD : snicholls::basic_token<snicholls::chain::arbitrum, "0xfB6916095ca1df60bB79Ce92cE3Ea74c37c5d359", 6, "GLD"> {
static constexpr std::string_view code() noexcept { return "GLD"; }
};

Relationships. concepts/token.hpp (the concept it models), interfaces/token.hpp, interfaces/token_conformance.hpp, token/tokens.hpp (the major tokens, declared with it), chain/chains.hpp, money/asset.hpp (asset_v<T> works on any token type). Group: snicholls-core.

Implementations. One template; each token is a struct deriving from it, so that its name is its own in diagnostics and documentation.

Guarantees. constexpr, noexcept, no state, no allocation; the code is a static array built once at compile time.

Precondition
Chain models evm_chain_like (an identifier is needed for the code: TRON's is 728126428).

Errors. Compile errors (static_assert) for a malformed or wrongly checksummed address, decimals above max_scale, or a symbol that makes an invalid asset code.

Performance. Nothing at run time; the address check is one Keccak-256 (or two SHA-256) per token type at compile time. Not benchmarked.

Tests and demos. tests/token/basic_token_test.cpp, demos/token/basic_token_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <string_view>, fixed_string.hpp, concepts/chain.hpp, concepts/token.hpp, money/asset.hpp, detail/token_checks.hpp (which includes hash/sha2.hpp and hash/sha3.hpp).

Known issues.

  • A chain with no EIP-155 identifier (Bitcoin, Solana) is not accepted: an SPL token's code has no rule yet.
  • The symbol must be an asset code's characters: USDC.e is written USDC.E, USD₮0 as USDT0.

Status. New in 0.23.0.
