Detailed Description

snicholls::ml RoPE as ggml names its modes: NORM and NEOX mapped to core's layouts, multimodal RoPE (Qwen2-VL's sections, Qwen3-VL's interleaved sections), vision RoPE in two dimensions, per-pair frequency factors (LongRoPE's short and long), the shift of a rotated key to a new position, and their angle tables, all constexpr.

Overview. ml/rope.hpp rotates a head by one position. Multimodal models rotate by several coordinates at once (time, height, width, and an extra one), and serving stacks name the layouts by ggml's modes. This header adds those on top of rope, rope_inverse and rope_frequency, as ggml computes them (ggml_rope_cache_init, ggml_mrope_cache_init and rotate_pairs in ggml/src/ggml-cpu/ops.cpp, llama.cpp 39039aa):

rope_mode ggml Pairs Angle of pair i
normal GGML_ROPE_TYPE_NORMAL (0) 2i, 2i + 1: rope_layout::interleaved p · f_i
neox GGML_ROPE_TYPE_NEOX (2) i, i + d/2: rope_layout::half p · f_i
mrope GGML_ROPE_TYPE_MROPE (8) as neox p_a · f_i, a the section of i mod S (Qwen2-VL)
imrope GGML_ROPE_TYPE_IMROPE (40) as neox a chosen by i mod 3 (Qwen3-VL's interleaved sections)
vision GGML_ROPE_TYPE_VISION (24) as neox, over the whole head p_a · base^(-2j / (d/2)), j the pair's index in its section

with f_i = base^(-2i/d) / factor_i and S = t + h + w + e the sections' pairs. A vision encoder with sections {d/4, d/4, ...} and positions (row, column) is the axial RoPE of ml/patch.hpp (axial_rope_table), to the bit.

  • rope_mode_layout(mode) and rope_mode_of(layout): ggml's names for core's rope_layout.
  • rope_section_axis(mode, sections, i): which coordinate pair i rotates by.
  • rope_mode_angles(position, cos, sin, base, mode, sections, factors, amplitude): one token's cosines and sines; rope_mode_table<T, Positions, HeadDim> holds many tokens' (built by a constexpr constructor, a rope_source by token index).
  • LongRoPE (Phi-3; llama.cpp's rope_long / rope_short tensors): factors divides each pair's frequency; longrope_factors(short, long, context, original) chooses as llama_model::get_rope_factors does (long when the context exceeds the trained one) and longrope_attention_factor(s, L) = sqrt(1 + ln s / ln L) is the amplitude the converter writes (conversion/phi.py).
  • Context shift: a key rotated at position p is moved to p + δ by rotating it by δ (the rotations compose), as llama.cpp's K-shift does (llama_kv_cache::build_rope_shift): rope_shift(x, delta, base, layout, factors). ml/kv_cells.hpp applies it to a cache.
  • Partial rotation (n_rot < head_dim, Phi-2, GLM): pass the head's first n_rot channels as the row; the rest are left alone, as ggml copies them.
// A GGUF's rope type names a core layout: NORM pairs adjacent channels, NEOX the halves
static_assert(ml::rope_mode_layout(ml::rope_mode::normal) == ml::rope_layout::interleaved);
static_assert(ml::rope_mode_of(ml::rope_layout::half) == ml::rope_mode::neox);
// Qwen2-VL: a head of 16 here, sections of 2, 3 and 3 pairs rotated by time, height and width
const ml::rope_sections qwen{2, 3, 3, 0};
std::array<float, 8> c{}, s{};
ml::rope_mode_angles(ml::rope_position{5, 2, 7, 0}, c, s, 10000.0f, ml::rope_mode::mrope, qwen);
std::array<float, 16> q{};
q.fill(1.0f);
ml::rope(q, c, s, ml::rope_mode_layout(ml::rope_mode::mrope));
// A vision encoder's table over a 2 x 3 grid of patches, positions (row, column), sections d/4 each
std::array<ml::rope_position, 6> grid{};
ml::vision_rope_positions(2, 3, grid);
constexpr std::size_t head = 16;
const ml::rope_mode_table<float, 6, head> vision(std::span<const ml::rope_position, 6>(grid), 10000.0f, ml::rope_mode::vision,
ml::rope_sections{head / 4, head / 4, head / 4, head / 4});
// LongRoPE (Phi-3): long factors past the trained context, and the amplitude its converter writes
const std::array<float, 8> shorts{1, 1, 1, 1, 1, 1, 1, 1}, longs{1, 1, 2, 4, 8, 16, 32, 64};
const auto factors = ml::longrope_factors<float>(shorts, longs, 131072, 4096);
const float amplitude = ml::longrope_attention_factor(32.0f, 4096);
ml::rope_mode_angles(ml::rope_position{1000}, c, s, 10000.0f, ml::rope_mode::neox, {}, factors, amplitude);
// Context shift: a key cached at position 40, moved to 32 after eight tokens before it were dropped
std::array<float, 8> key{0.5f, -1.0f, 0.25f, 2.0f, 1.0f, 0.0f, -0.5f, 1.5f}, fresh = key;
std::array<float, 4> kc{}, ks{};
ml::rope_angles(40, kc, ks);
ml::rope(key, kc, ks);
ml::rope_shift(key, -8, 10000.0f);
ml::rope_angles(32, kc, ks);
ml::rope(fresh, kc, ks);

Relationships. Built on ml/rope.hpp; ml/patch.hpp (axial_rope_table, the same angles in vision mode); ml/kv_cells.hpp (the K-shift over a cache). Group: snicholls-core.

Implementations. One each.

Guarantees. constexpr, no allocation, linear in the head. rope_mode_table is trivially copyable. Each angle is coordinate · rope_frequency(...) / factor with one call to rope_frequency per pair, so the neox and normal modes with no factors and amplitude 1 are rope_angles to the bit.

Errors. Preconditions, asserted: cos and sin have one size; factors is empty or has their size; for the sectioned modes at least one of t, h, w is set; the factors are positive.

Performance. Not benchmarked: a table read and rope's four multiplications per pair; the tables are built once.

Tests and demos. tests/ml/rope_modes_test.cpp, demos/ml/rope_modes_demo.cpp.

Dependencies. <array>, <cassert>, <concepts>, <cstddef>, <cstdint>, <span>, ml/rope.hpp, ml/row.hpp, snicholls/core/math/constexpr_math.hpp.

Known issues. ggml builds each frequency as a running product (theta *= theta_scale) in float; core calls rope_frequency (pow) per pair, so the angles agree to a few units in the last place, not to the bit. ggml's YaRN ramp inside rope_yarn is not repeated here: combine YaRN with rope_scaling in ml/rope.hpp. llama.cpp's K-shift of a multimodal cache rotates the whole head as neox by one position; rope_shift does the same.

Status. Experimental, new in 0.17.0.
