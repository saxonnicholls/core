Detailed Description

snicholls::ml convolutions of rank 1, 2 and 3: im2col / col2im, the convolution forward and backward (direct and through im2col), groups and depthwise, and the transposed convolution, all constexpr over the caller's spans.

Overview. The convolutions of vision and audio encoders (a ViT's patch embedding, Whisper's two 1-D convolutions, a U-Net's 2-D and transposed layers, a video model's 3-D stem), for one sample at a time. The rank is a template parameter: conv_shape<1>, <2> and <3> are the same code.

  • Layout, as PyTorch and ggml for one sample: the input [in_channels][spatial...], the output [out_channels][output...], the weights [out_channels][in_channels / groups][kernel...], every spatial index row-major (depth, height, width).
  • conv_shape<Rank>: channels, groups, and per dimension the input extent, kernel, stride, padding (both sides) and dilation. Its derived sizes are constexpr (output(), output_size(), column_size(), ...), so a constexpr conv_shape sizes std::array scratch at compile time. The output extent is ggml's and PyTorch's (in + 2p - d (k - 1) - 1) / s + 1.
  • im2col(shape, x, cols): the columns [output position][in_channels · kernel], channel-major then kernel, zero where the window reaches into the padding: ggml's ggml_im2col layout. col2im is its adjoint (overlapping entries summed).
  • conv_forward(shape, x, w, bias, y): the direct loop, no scratch. conv_forward_im2col(shape, x, w, bias, y, cols): im2col and the matrix product, the same sums in the same order, so the two agree to the bit.
  • conv_backward(shape, x, w, dy, dx, dw, db): dx written (col2im of Wᵀ dy), dw and db added (they sum over the samples of a batch). An empty span skips that gradient.
  • Groups: channel group g of groups convolves only with its own input channels. depthwise_shape(...) is a 2-D shape with groups == channels (ggml's ggml_conv_2d_dw).
  • conv_transpose_shape<Rank> and conv_transpose_forward / conv_transpose_backward: the transposed ("deconvolution") layer, output (in - 1) s - 2p + d (k - 1) + 1, weights [in_channels][out_channels / groups][kernel...] (PyTorch's ConvTranspose layout, ggml's ggml_conv_transpose_1d / _2d_p0 with padding 0 and dilation 1). It is exactly the adjoint, in its input, of the convolution as_conv() returns, so its forward is that convolution's data gradient and its backward that convolution's forward.
// A 3x3 convolution of one 4x4 channel into two, padding 1: the sizes are known to the compiler.
constexpr ml::conv_shape<2> s{.in_channels = 1, .out_channels = 2, .input = {4, 4}, .kernel = {3, 3}, .padding = {1, 1}};
static_assert(s.output() == std::array<std::size_t, 2>{4, 4} && s.column_size() == 16 * 9);
std::array<float, s.x_size()> x{};
for (std::size_t i = 0; i < x.size(); ++i)
x[i] = static_cast<float>(i);
std::array<float, s.weight_size()> w{};
w[4] = 1.0f; // filter 0: the identity (the centre tap)
for (std::size_t t = 9; t < 18; ++t) // filter 1: the 3x3 box sum
w[t] = 1.0f;
const std::array<float, 2> bias{0.0f, -1.0f};
std::array<float, s.y_size()> y{}, y2{};
std::array<float, s.column_size()> cols{};
ml::conv_forward(s, x, w, bias, y); // the direct loop
ml::conv_forward_im2col(s, x, w, bias, y2, cols); // im2col and a matrix product: the same bits
// The backward pass: dx written, dw and db added.
std::array<float, s.y_size()> dy{};
dy.fill(1.0f);
std::array<float, s.x_size()> dx{};
std::array<float, s.weight_size()> dw{};
std::array<float, 2> db{};
ml::conv_backward(s, x, w, dy, dx, dw, db);
// Depthwise: one 3x3 filter per channel, stride 2.
const auto dws = ml::depthwise_shape(3, 6, 6, 3, 3, 2, 1);
std::vector<float> dwx(dws.x_size(), 1.0f), dww(dws.weight_size(), 1.0f), dwy(dws.y_size());
ml::conv_forward(dws, dwx, dww, std::span<const float>{}, dwy);
// 1-D, Whisper's second stem convolution: kernel 3, stride 2, padding 1, 3000 frames to 1500.
constexpr ml::conv_shape<1> stem{.in_channels = 2, .out_channels = 2, .input = {3000}, .kernel = {3}, .stride = {2}, .padding = {1}};
static_assert(stem.output()[0] == 1500);
// A transposed convolution doubling a 2x2 map with a 2x2 kernel at stride 2.
constexpr ml::conv_transpose_shape<2> up{.in_channels = 1, .out_channels = 1, .input = {2, 2}, .kernel = {2, 2}, .stride = {2, 2}};
const std::array<float, 4> small{1, 2, 3, 4}, ones{1, 1, 1, 1};
std::array<float, up.y_size()> big{};
ml::conv_transpose_forward(up, small, ones, std::span<const float>{}, big);

Relationships. ml/row.hpp (the rows), ml/spatial.hpp (pooling, padding, upscaling), ml/patch.hpp (a stride-equals-kernel convolution is a patch embedding). Group: snicholls-core.

Implementations. Two forwards: direct (conv_forward, no scratch) and lowered (conv_forward_im2col, the columns in the caller's scratch, the form a GPU library replaces with its matrix product). They agree to the bit.

Guarantees. constexpr, no allocation, no exceptions. Each multiply and add is its own statement, summed per output in the order (input channel, kernel position) from 0, the bias added last. Complexity: out_channels · output_size · (in_channels / groups) · kernel_size multiply-adds for each pass. conv_shape is a structural aggregate (usable as a template argument).

Errors. Preconditions, asserted: shape.valid() (channels divisible by the groups, positive strides and dilations, a kernel that fits the padded input); every span the size the shape says, or empty for an optional bias or gradient.

Performance. Benchmarked against the 7-deep loop written by hand, same order of summation, with a fairness check to the bit (benchmarks/ml/conv_benchmark.cpp, BENCHMARKS.md): a 3x3 convolution, padding 1, of 64 channels of 32x32 floats into 64 runs 1.08 billion multiply-adds a second by hand, 1.02 billion through conv_forward_im2col and 0.89 billion through conv_forward, whose kernel extents are not known to the compiler (Xeon W-3245, -O3, Apple clang 17, 2026-11-19).

Tests and demos. tests/ml/conv_test.cpp, demos/ml/conv_demo.cpp.

Dependencies. <array>, <cassert>, <concepts>, <cstddef>, <span>, ml/row.hpp.

Known issues. ggml's transposed convolutions have no padding or dilation, and its CPU kernel sums over input channels first (a vector dot product) then over positions: the same value, possibly not the same last bit. No output_padding (PyTorch's extra row on one side of a transposed convolution): pad the output instead.

Status. Experimental, new in 0.17.0.
