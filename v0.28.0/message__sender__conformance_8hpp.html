Detailed Description

snicholls::run_message_sender_conformance: the conformance kit of the message_sender contract.

Overview. Drives any message_sender, in either form, through the contract of concepts/message_sender.hpp and reports which check failed (interfaces/capability_conformance.hpp). The probe is a default-constructible type with

  • auto& sender(): the implementation, a model of the concept (a sender, a message_sender_interface&, a message_sender_ref);
  • void provider_fails(capability_errc code, std::string_view response): the next send that would be accepted fails with code, as though the provider had answered response.

A fresh probe is made for every check. The checks: a valid message on a supported channel is accepted, an unsupported channel is unsupported, an invalid message is refused without echoing it, the same idempotency key sends once, a provider failure never leaks its response.

const capability_conformance_report report = run_message_sender_conformance<probe>();

Relationships. concepts/message_sender.hpp, interfaces/message_sender.hpp, interfaces/capability_conformance.hpp; run on memory_message_sender in every form by tests/interfaces/message_sender_test.cpp. Group: snicholls-core.

Implementations / variants. One kit for every form.

Guarantees. As interfaces/capability_conformance.hpp: no exception escapes a check.

Errors. Failures are data.

Performance. Not benchmarked: a test kit.

Tests and demos. tests/interfaces/message_sender_conformance_test.cpp (the kit catches broken senders), demos/interfaces/message_sender_conformance_demo.cpp.

Dependencies. <initializer_list>, <string>, <string_view>, <type_traits>, <utility>, concepts/message_sender.hpp, interfaces/capability_conformance.hpp.

Known issues. A sender that accepts nothing at all passes the acceptance check vacuously only if it supports no channel; it then fails nothing else either, which supports makes visible.

Status. New in 0.23.0.
