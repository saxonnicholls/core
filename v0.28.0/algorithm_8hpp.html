Detailed Description

snicholls::fill, fill_n, copy, copy_n, copy_backward, iota, equal, reverse and swap_ranges: the elementary algorithms as plain loops, usable in constant evaluation from C++17.

Overview. The handful of algorithms that build and compare fixed tables, as loops anyone can read in a minute: fill a table, count it up, copy one into another, reverse it, swap two, compare them. Each takes iterators as the standard's do and returns what the standard's returns; fill, iota and equal also take whole ranges (an std::array, a C array, a span, anything with begin and end).

// A lookup table built by the compiler: the first 16 cubes, then a copy of it reversed. C++17 or C++20 alike.
constexpr std::array<long, 16> cubes = [] {
std::array<long, 16> t{};
snicholls::iota(t, 0L);
for (auto& x : t)
x = x * x * x;
return t;
}();
constexpr std::array<long, 16> cubes_descending = [] {
std::array<long, 16> t{};
snicholls::copy(cubes.begin(), cubes.end(), t.begin());
snicholls::reverse(t.begin(), t.end());
return t;
}();
static_assert(cubes[3] == 27 && cubes_descending[0] == 3375 && cubes_descending[15] == 0);
static_assert(snicholls::equal(cubes, std::array<long, 16>{0, 1, 8, 27, 64, 125, 216, 343, 512, 729, 1000, 1331, 1728,
2197, 2744, 3375}));

Use them where <algorithm> is not what you want:

  • C++17 code that runs at compile time. std::fill, std::copy, std::iota, std::equal and the others are constexpr only from C++20; these are constexpr in C++17, so ts-moveables (C++17) builds tables with them. The header is compiled as C++17 by snicholls_core_cpp17_check.
  • Device code. A pure constexpr loop with no allocation and no library internals behind it is callable from a CUDA kernel under --expt-relaxed-constexpr and synthesises for an FPGA (bounded, no recursion).
  • Clearing a buffer without memset. GCC 13 and 15 report false -Wstringop-overflow on memset into a buffer whose size they misjudge; snicholls::fill is a loop, which the optimiser may still turn into a memset where that is right.

In C++20 host code the standard's algorithms are as good, and at run time std::copy is faster (see Performance).

Relationships. constexpr_for for loops whose index must be a constant expression; iterate.hpp and table<N>(f) for a table computed from its index; zip for walking ranges together.

Guarantees.

  • Every function is constexpr, and noexcept exactly when the iterator steps, compares and dereferences and the element assignments it performs are (std::string elements may throw; int elements never do).
  • Complexity is linear: one assignment (or compare) per element, reverse and swap_ranges three moves per swap.
  • Nothing allocates and nothing is owned: the caller's iterators are written through, never stored.
  • copy and copy_n write forwards, so the output may overlap the input only if it starts before it; copy_backward writes backwards, for an output that starts after the input. As in the standard.
  • equal over two ranges compares their lengths first, so ranges of different lengths are unequal (the three-iterator form, as the standard's, assumes the second range is long enough).

Errors. None reported: a precondition broken (an output too short, last before first) is undefined behaviour, as with the standard's algorithms, and a compile error in constant evaluation.

Performance. benchmarks/algorithm_benchmark.cpp, 4,096 doubles, Release -O3, Apple clang 17 on a Xeon W-3245, 2026-11-27: fill 526 ns, std::fill 540 ns, the hand-written loop 544 ns; copy 804 ns, the hand-written loop 801 ns, std::copy 563 ns. fill is the loop and as fast as anything. copy is the loop too, and the standard library turns std::copy of trivially copyable elements into memmove, about 1.4 times faster: for a large copy at run time in C++20 host code, use std::copy.

Tests and demos. tests/algorithm_test.cpp, demos/algorithm_demo.cpp.

Dependencies. <cstddef>, <iterator> (std::begin, std::end), <type_traits>, <utility> (std::move, std::declval).

Known issues. reverse and swap_ranges exchange elements by three moves, not by an ADL swap: a type whose swap does something a move does not is exchanged by its moves. Proxy iterators (std::vector<bool>) are not supported. The names are the standard's: call them qualified (snicholls::fill), as an unqualified call on standard iterators would also find std::fill by ADL and be ambiguous.

Status. Stable.
