Detailed Description

uniform_int<T, D>: a drop-in std::uniform_int_distribution whose draws are named, not left to the standard library: core's own, or libstdc++'s or libc++'s reproduced to the bit on every platform.

Overview. The standard specifies std::mt19937 to the bit but leaves std::uniform_int_distribution to each library, so the same seed picks different numbers under libstdc++ (GCC's, and Clang's on Linux), libc++ (Apple's, LLVM's) and MSVC. A program that must reproduce another program's choices - llama.cpp's HellaSwag selection, a published benchmark subset, a simulation built on Linux and checked on a Mac - cannot use the distribution its own library happens to ship. uniform_int<T, D> takes the algorithm as a template parameter:

  • draw::core (the default): uniform_index, Lemire's nearly divisionless draw over 64 bits; the fastest, and core's choice for anything new. It needs a full_range_generator (32 or 64 full bits).
  • draw::libstdcxx: libstdc++'s algorithm from GCC 11 on (Lemire's draw on 32- or 64-bit generators, two divisions on others, a composition of draws when the range is wider than the generator), as on a 64-bit target with __int128.
  • draw::libcxx: libc++'s algorithm (__independent_bits_engine: the fewest bits that cover the range, rejected until they fall inside it).

The choice is made once, at compile time: no flag, no branch on the hot path. When not to use it: for new work, draw::core or uniform_index directly; the library algorithms are for agreeing with code you do not own.

// llama.cpp picks HellaSwag tasks with std::mt19937(1) and std::uniform_int_distribution, so a Linux
// build and a Mac build pick different tasks. Name the library and the picks are the same everywhere.
std::mt19937 linux_rng(1), mac_rng(1);
stats::uniform_int<std::size_t, stats::draw::libstdcxx> as_on_linux(0, 99); // GCC's library
stats::uniform_int<std::size_t, stats::draw::libcxx> as_on_a_mac(0, 99); // Apple's, LLVM's
std::array<std::size_t, 6> linux_picks{}, mac_picks{};
for (std::size_t i = 0; i < 6; ++i) {
linux_picks[i] = as_on_linux(linux_rng);
mac_picks[i] = as_on_a_mac(mac_rng);
}
// For new work: core's own draw (the default), the fastest, and also the same everywhere.
stats::wyrand g(2026);
stats::uniform_int<int> die(1, 6);
const int roll = die(g);

Relationships. stats/random.hpp (uniform_index, wyrand, full_range_generator). Group: snicholls-core.

Guarantees. constexpr (with a constexpr generator such as wyrand), no allocation, noexcept exactly when the generator's call is. The same generator state gives the same draws on every platform and compiler. uniform_int is two Ts, trivially copyable, and stateless between draws: reset() does nothing, as in both libraries.

Errors. None. a <= b is a precondition (asserted), as for the standard distribution.

Performance. Not benchmarked: the library algorithms are there to agree, not to be fast.

Tests and demos. tests/stats/uniform_int_test.cpp checks each algorithm draw for draw against the real std::uniform_int_distribution of the library it reproduces, where the test is built with that library (macOS for libc++, Ubuntu's GCC and Clang for libstdc++), and against committed sequences everywhere else. demos/stats/uniform_int_demo.cpp.

Dependencies. <bit>, <cassert>, <concepts>, <cstddef>, <cstdint>, <limits>, <random> (the generator concept), <type_traits>, stats/random.hpp.

Known issues. libstdc++ before GCC 11 used two divisions everywhere, and on targets without __int128 still does for 64-bit generators: draw::libstdcxx reproduces GCC 11 and later on 64-bit targets (checked against GCC 13 and 15). MSVC's algorithm is not reproduced. T is one of the standard's eight short..unsigned long long; the standard does not allow char or bool either.

Status. New in 0.18.0.
