Detailed Description

snicholls::ml SentencePiece Unigram (T5, ALBERT, XLM-R, mT5, nomic-embed): the normaliser a Unigram vocabulary carries (its precompiled charsmap, read in place, and the whitespace rules), and the Viterbi segmentation over the vocabulary's log-probabilities.

Overview. A Unigram model scores every piece with a log-probability and tokenizes text as the segmentation whose scores sum highest. Two steps:

  1. unigram_normalize(text, charsmap, user_defined, options, out): each prefix of the input is replaced by the longest match in the model's precompiled charsmap (SentencePiece's normalisation rules, usually NFKC with case and width folding, compiled into a double array), user-defined pieces pass through untouched, invalid bytes become U+FFFD; then whitespace is escaped to "▁", a "▁" put in front (add_dummy_prefix), and runs of spaces merged (remove_extra_whitespaces), all as SentencePiece's Normalizer does. precompiled_charsmap is a view of the charsmap blob as GGUF (tokenizer.ggml.precompiled_charsmap) and tokenizer.json store it: nothing is decoded or copied.
  2. unigram_encode(normalized, vocab, score, kind, unknown, out, lattice): the Viterbi lattice over byte positions, each extended by every vocabulary piece that starts there (a walk of the token_trie); a code point no piece covers becomes the unknown token at the vocabulary's lowest score minus 10; consecutive unknowns become one. Scores are summed in double, as SentencePiece and llama.cpp sum them, so ties fall the same way.

Decode with sentencepiece_decode (ml/sentencepiece.hpp): "▁" is a space, the dummy prefix is dropped.

constexpr std::array<std::string_view, 6> pieces{"<unk>", "\xE2\x96\x81", "\xE2\x96\x81" "un", "do", "\xE2\x96\x81" "undo", "able"};
constexpr std::array<float, 6> scores{0, -3, -4, -4, -6, -3};
constexpr auto encode(std::string_view text)
{
std::array<std::uint32_t, 6> order{};
const std::size_t v = ml::build_token_index(pieces, order, [](std::uint32_t id) { return id != 0; }); // not <unk>
const ml::token_trie vocab{pieces, std::span<const std::uint32_t>(order).first(v)};
// No charsmap here; a model's comes from its file (tokenizer.ggml.precompiled_charsmap)
std::array<char, 64> norm{};
const std::size_t n = ml::unigram_normalize(text, {}, {}, {}, norm).unwrap(); // " undoable " -> "▁undoable"
std::array<std::uint32_t, 64> out{};
std::array<ml::unigram_lattice_entry, 65> lattice{};
const ml::unigram_unknown unknown{0, ml::unigram_unknown_score(-6)};
const std::size_t k = ml::unigram_encode(std::string_view(norm.data(), n), vocab, [](std::uint32_t id) { return scores[id]; },
[](std::uint32_t) { return ml::token_kind::normal; }, unknown, out, lattice)
.unwrap();
return std::pair{out, k};
}
// "▁undo" + "able" scores -9, beating "▁un" + "do" + "able" at -11
static_assert(encode(" undoable ").second == 2 && encode(" undoable ").first[0] == 4 && encode(" undoable ").first[1] == 5);

Relationships. ml/token_trie.hpp (the vocabulary: build it over the normal, user-defined and unused tokens, as SentencePiece does), ml/sentencepiece.hpp (decoding, escaped_space), ml/unicode.hpp. Group: snicholls-core.

Implementations. One, llama.cpp's llm_tokenizer_ugm_session (itself SentencePiece's optimised Viterbi): the best path to each byte offset, extended forward one code point at a time.

Guarantees. constexpr when the callables are. No allocation: the caller's output and lattice. Pure. Complexity: normalising O(n · L) for charsmap matches of up to L bytes; encoding O(n · L · log V) for pieces of up to L bytes in a vocabulary of V. The charsmap view checks every index it reads against the blob: a truncated or corrupt blob stops a match, it never reads out of bounds.

Errors. unigram_error::output_too_small (normalising: fewer than the normalised bytes, at most unigram_normalized_size(text.size(), charsmap); encoding: fewer than normalized.size() slots), lattice_too_small (fewer than normalized.size() + 1 entries), bad_charsmap (a blob too short to hold its own header).

Performance. benchmarks/ml/unigram_benchmark.cpp, the nomic-embed fixture's normalised texts (Release, Apple clang 17, Xeon W-3245, 2026-11-19, one thread on a loaded machine (ratios held across runs)): 10.6 MiB/s, against 25.9 MiB/s for llama.cpp's Viterbi written out with its node trie: the difference is the trie walk (ml/token_trie.hpp), 2.4 times slower; the lattice itself costs the same.

Tests and demos. tests/ml/unigram_test.cpp: the charsmap view over double arrays built by the tests, the normaliser's whitespace rules, Viterbi against the definition on random texts, unknown runs, the errors. tests/ml/tokenizer_test.cpp: token for token llama.cpp on nomic-embed's XLM-R vocabulary (ggml-vocab-nomic-bert-moe.gguf), on a committed subset with the charsmap entries its strings reach rebuilt as a small double array (the fixture generator checks, on the whole vocabulary and the whole 237 KB charsmap, that core and llama.cpp agree). demos/ml/unigram_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <span>, <string_view>, snicholls/core/result.hpp, ml/sentencepiece.hpp, ml/token_trie.hpp, ml/unicode.hpp.

Known issues. NFC applied before the charsmap (llama.cpp's normalizer.nfc, for vocabularies without a charsmap) is not provided: a caller that needs it composes the text first. SentencePiece's treat_whitespace_as_suffix is supported as llama.cpp supports it, by appending the space.

Status. Experimental, new in 0.17.0.
