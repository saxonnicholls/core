Detailed Description

snicholls::token_like: a token deployed on a chain, as a concept.

Overview. A token is an asset that a contract on a chain issues: USDC on Ethereum, USDT on TRON. Beyond asset_like's code() and scale() (its decimals) it answers:

  • chain(), a chain_like value: the chain it is deployed on;
  • contract(), the contract's address in its chain's canonical text: EIP-55 checksummed hex for an EVM chain, base58check (T...) for TRON;
  • symbol(), the symbol the issuer gives it (USDC).

Its asset code is SYMBOL:chainid (USDC:1, USDC:56, USDT:728126428), so that one symbol on two chains is two assets in one book; an issuer's single-supply token may keep its bare symbol. The concept is written over object expressions, so it is modelled by compile-time types (snicholls::token::ethereum::USDC, a product's own basic_token<...>) and by any object behind the virtual twin token_interface (interfaces/token.hpp).

// Where to send a deposit of this token: the chain's identifier and the contract to watch.
template <snicholls::token_like T>
constexpr bool is_on_chain(const T& t, std::uint64_t id, std::string_view contract)
{
return t.chain().chain_id() == id && t.contract() == contract;
}
static_assert(snicholls::token_like<snicholls::token::base::USDC>);
static_assert(!snicholls::token_like<snicholls::native::ETH>); // a native asset has no contract
