Detailed Description

snicholls::containers::ann_forest<Point, D, Metric>: approximate nearest neighbours by a forest of random-projection trees (the algorithm of Spotify's Annoy), under any metric, in flat storage the caller owns.

Overview. In tens or hundreds of dimensions (embeddings), exact trees degrade to a linear scan. A forest of random-projection trees trades a little recall for orders of magnitude in speed. Each tree splits its points recursively by a hyperplane between two centroids found by a short two-means on a sample. A query walks all the trees best-first by how near it is to each split, gathers a budget of candidates from the leaves it reaches, and re-ranks them exactly with the metric. More trees and a larger candidate budget buy recall.

  • Point is any metric::point of dimension D; Metric is any metric (distance_for). The split is chosen by the metric (ann_default_split): hyperplanes between centroids for the Minkowski metrics (ann_euclidean_split), hyperplanes through the origin between unit-length centroids for angular, cosine_distance, angle and inner_product (ann_angular_split), and random bits for hamming (ann_bit_split). A metric of the caller's specialises ann_default_split, or names the split explicitly.
  • build(points, trees, leaf_size, nodes, items, normals, g): builds into the caller's storage (sized by suggested_storage) with the caller's generator, so a seed reproduces the index exactly.
  • The index is three flat arrays of trivially copyable values (ann_nodes, item indices and split normals) linked by indices, not pointers, plus an ann_layout. A consumer can therefore write them to a file and map them back, sharing one index between processes as Annoy does. The constructor from a layout and spans attaches to storage without rebuilding.
  • query(q, out, candidates, frontier): the out.size() nearest found, nearest first, with their exact distances. candidates is the budget of points examined (Annoy's search_k: trees · k is a reasonable start); frontier is the best-first queue's storage.
// Storage the caller owns, sized for 10 trees with leaves of at most 16 points
using forest = ct::ann_forest<embedding, D>; // euclidean by default; the split follows the metric
const ct::ann_storage size = forest::suggested_storage(points.size(), 10, 16);
std::vector<ct::ann_node> nodes(size.nodes);
std::vector<std::uint32_t> items(size.items);
std::vector<float> normals(size.normals);
st::wyrand g(7); // the caller's generator: the same seed builds the same index
const auto built = forest::build(points, 10, 16, nodes, items, normals, g);
if (!built)
return 1;
const forest index = built.unwrap();
// The ten nearest of one query, examining at most 1,000 candidates; every distance returned is exact
std::array<ct::ann_neighbour, 10> ten{};
std::vector<std::uint32_t> candidates(1000);
std::array<ct::ann_frontier, 512> frontier{};
const std::size_t found = index.query(queries[0], ten, candidates, frontier);
// The index is three flat arrays and a layout: write them out, map them back, attach without rebuilding
const ct::ann_layout layout = index.layout();
const std::vector<ct::ann_node> saved_nodes(index.nodes().begin(), index.nodes().end());
const std::vector<std::uint32_t> saved_items(index.items().begin(), index.items().end());
const std::vector<float> saved_normals(index.normals().begin(), index.normals().end());
const forest attached(layout, points, saved_nodes, saved_items, saved_normals);

Relationships. metric/ (every metric plugs in), containers/kd_tree.hpp (exact, for a few dimensions), stats/random.hpp (the generator), result.hpp. After Bernhardsson's Annoy (github.com/spotify/annoy). Group: snicholls-core.

Implementations. Splits: two-means of 200 steps over random members of the node's points (Annoy's two_means), centroids weighted by their counts. When a split leaves one side empty, the points are shuffled and halved and the split's normal is zero, so a query explores both sides. Queries: a binary max-heap on min(parent priority, ±margin), every root starting at +∞; candidates are sorted, de-duplicated and re-ranked. Build is breadth-first over the node array (the array is the queue); query is iterative.

Guarantees. constexpr, no allocation, no recursion. Build O(trees · n log n) expected; query O(candidates · D). Deterministic for a given generator state. noexcept is not claimed (the caller's metric and generator decide). The results are approximate: every returned distance is exact, but a closer point may be missed.

Errors. ann_error::out_of_storage: the node or normal storage was too small for the trees built (rebuild with more; suggested_storage is generous for typical data). ann_error::invalid_parameters: no points, no trees, a leaf size of zero, more than 2³¹ points, an item span shorter than points · trees, or points of the wrong dimension.

Performance. Not yet benchmarked: a benchmark against brute force (recall and speed) and against Annoy itself on the same data is planned.

Tests and demos. tests/containers/ann_forest_test.cpp, demos/containers/ann_forest_demo.cpp.

Dependencies. <algorithm>, <array>, <cstddef>, <cstdint>, <limits>, <span>, <type_traits>, math/constexpr_math.hpp, metric/angular.hpp, metric/binary.hpp, metric/concepts.hpp, metric/minkowski.hpp, result.hpp, stats/random.hpp.

Known issues. inner_product (maximum inner product search) uses the angular split without Annoy's extra norm dimension, so its recall is lower for vectors of very different lengths; normalise them, or append √(max |x|² - |x|²) as a last coordinate yourself. A full frontier drops further entries (lower recall, never a wrong distance).

Status. Experimental, new in 0.20.0.
