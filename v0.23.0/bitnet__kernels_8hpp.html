Detailed Description

snicholls::ml BitNet's packed ternary layouts: I2_S (2 bits a weight, multiply-add kernels) and the lookup-table formats TL1 (pairs of weights, 4-bit indices) and TL2 (triples, 4-bit magnitude and a sign bit), byte for byte as bitnet.cpp writes them, with reference kernels, all constexpr.

Overview. bitnet.cpp (microsoft/BitNet 0b341e5) runs ternary weights two ways. I2_S stores each weight as t + 1 in two bits and multiplies by int8 activations; TL1 and TL2 replace the multiplications with table lookups: for each pair (TL1) or triple (TL2) of activations, the sums of every ternary combination of them are built once, and each weight group's index picks its sum.

Layout Group Code Bits per weight Source
I2_S 1 t + 1 in {0, 1, 2}; block b of Block weights in Block / 4 bytes, weight j in byte j % (Block / 4), bits 6 - 2 (j / (Block / 4)) 2 quantize_i2_s, src/ggml-bitnet-mad.cpp
TL1 2 3 w0 + w1 + 4 in [0, 8] 2 preprocess_weights_tl1, utils/convert-hf-to-gguf-bitnet.py

| TL2 | 3 | |9 w0 + 3 w1 + w2| in [0, 13] and a sign bit (1 when negative) | 5/3 | preprocess_weights_tl2, same file |

Block is 128 on x86 and 64 on ARM (QK_I2_S); the float scale follows the codes at byte n / 4, in a 32-byte tail. The TL layouts also tile the matrix for the SIMD kernels (lut_tiles: BM rows, BK columns, bm rows a kernel step, from a model's kernel_config.ini); tl1_pack and tl2_pack write those bytes exactly.

// A ternary matrix (absmean_quantize's codes) with its scale, and a token's activations
std::vector<std::int8_t> t(rows * cols);
for (std::size_t i = 0; i < t.size(); ++i)
t[i] = static_cast<std::int8_t>(int((i * 2654435761u >> 7) % 3) - 1);
std::vector<float> x(cols);
for (std::size_t j = 0; j < cols; ++j)
x[j] = std::sin(0.37f * float(j));
// The kernels' activations: one scale for the tensor
std::vector<std::int8_t> a(cols);
const float s = ml::lut_activation_quantize(x, a);
// I2_S: two bits a weight, 128 to a block on x86, the scale after the codes; one row's dot product
std::vector<std::uint8_t> i2(ml::i2_s_bytes(rows * cols));
ml::pack_i2_s(t, 0.02f, i2);
const std::int32_t row0 = ml::i2_s_dot(std::span<const std::uint8_t>(i2).first(cols / 4), a);
// TL1 (pairs) and TL2 (triples): tables of activation sums, one lookup per weight group
std::vector<std::uint8_t> c1(rows * cols / 2);
std::vector<ml::tl2_code_t> c2(rows * cols / 3);
ml::tl1_encode(t, c1);
ml::tl2_encode(t, c2);
std::vector<std::array<std::int16_t, 16>> l1(cols / 2), l2(cols / 3);
std::vector<std::int32_t> y1(rows), y2(rows);
ml::tl1_gemv(c1, rows, cols, a, l1, y1);
ml::tl2_gemv(c2, rows, cols, a, l2, y2);
const float out0 = float(y1[0]) / s * ml::i2_s_scale(i2, rows * cols); // the kernels' epilogue
// The converter's tiled bytes for a kernel configuration (BM, BK, bm)
std::vector<std::uint8_t> tl1(ml::tl1_packed_bytes(rows, cols));
ml::tl1_pack(t, rows, cols, {32, 128, 32}, tl1);
  • quantize_i2_s(w, out): bitnet.cpp's quantiser, which takes a matrix already ternary times a scale (as absmean_quantize leaves it): |w| < 1e-6 is 0, otherwise the sign; the scale stored is max |w|. pack_i2_s(t, scale, out) packs codes directly. i2_s_dot_raw is ggml_vec_dot_i2_i8_s_1x1, the sum of (t + 1) · a; i2_s_dot subtracts sum a, giving the ternary dot product.
  • tl1_code / tl2_code, tl1_lut(a0, a1) / tl2_lut(a0, a1, a2): the codes, and the tables the kernels build (lut_ctor in utils/codegen_tl1.py, three_lut_ctor in the TL2 kernels): entry c is the sum of the combination tl1_weights[c] / tl2_weights[c], tables the compiler builds.
  • tl1_gemv, tl2_gemv: the lookup-table matrix-vector product over unpacked codes, the kernels' arithmetic in plain order: exactly ternary_dot row by row.
  • lut_activation_quantize(x, q): the kernels' per-tensor activations, s = 127 / max |x|, round to nearest even (vcvtnq, _mm256_round_ps), no clamp; the output is acc / s · weight_scale.

Relationships. ml/bitnet.hpp (absmean weights, per-token activations, BitLinear, ternary_dot); ml/quant_ternary.hpp (ggml's TQ1_0 and TQ2_0). Group: snicholls-core.

Implementations. One each: the reference the SIMD and GPU kernels reorder.

Guarantees. constexpr, no allocation, linear. Integer sums are exact (int32). I2_S bytes and i2_s_dot_raw equal bitnet.cpp's quantize_i2_s and ggml_vec_dot_i2_i8_s_1x1 on every row of tests/fixtures/ml/bitnet_i2s_fixture.txt (built from BitNet's C++, x86); TL1 and TL2 bytes equal the converter's on tests/fixtures/ml/bitnet_lut_fixture.txt (its Python, transcribed), for real model tilings; the LUT GEMVs equal the plain ternary product (tested).

Errors. Preconditions, asserted: sizes (n a multiple of Block; the tiling dividing the matrix as the converter requires: M % BM, K % BK, BM % bm, TL1's BK % (256 / bm), TL2's bm == 32). bitnet.cpp's quantiser treats NaN as a negative weight, as here.

Performance. Against plain loops (benchmarks/ml/bitnet_kernels_benchmark.cpp); numbers in BENCHMARKS.md.

Tests and demos. tests/ml/bitnet_kernels_test.cpp, demos/ml/bitnet_kernels_demo.cpp.

Dependencies. <array>, <bit>, <cassert>, <cstddef>, <cstdint>, <limits>, <span>, <type_traits>, ml/bitnet.hpp, ml/row.hpp.

Known issues. bitnet.cpp's AVX2 I2_S kernel sums up to 32 blocks in 16-bit lanes before widening, which wraps for adversarial activations (|partial sum| above 32767 in a lane); the reference here is exact, so it agrees with the kernel wherever the kernel does not wrap (every fixture row). The x86 non-ACT_PARALLEL I2_S form (four rows interleaved a byte, quantize_i2_s_1x4) is not here. The I2_S matrix product's correction by sum a and its scaling are done in bitnet.cpp's llama.cpp fork, which the clone does not include: i2_s_dot and the acc / s · scale epilogue are recalled from it and agree with the GPU kernel's epilogue (gpu/bitnet_kernels/bitnet_kernels.h). TL2's padded size is the converter's formula, which assumes K >= 256.

Status. Experimental, new in 0.17.0.
