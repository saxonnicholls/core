Detailed Description

snicholls::ml LoRA: a trainable low-rank update y = W x + (α/r) B A x beside a frozen base (dense, bfloat16 or NF4 for QLoRA), forward and backward for one row, a sequence and attention's heads, its initialisation, merge and unmerge, and the optimiser's view of the adapter alone.

Overview. Low-rank adaptation (Hu et al. 2021) fine-tunes a model by freezing each weight W (rows x cols) and learning ΔW = s · B A, A of r x cols, B of rows x r, r small, s = α / r (TRAINING.md T13). Only A and B have gradients and optimiser state, so a model of billions of weights is tuned with a few million. QLoRA (Dettmers et al. 2023, eq. 5) stores W in NF4 (ml/nf4.hpp) and dequantises it as it is read.

  • lora_weights<W, T>{base, a, b, rank, scaling}: the view; W is dense_weights<S> (any storage linear reads, float, double, bfloat16) or nf4_weights.
  • lora_linear(w, x, y, u, bias): u = A x (kept for the backward), y = W x + b + s · B u.
  • lora_linear_backward(w, x, u, dy, dx, da, db, du): du = s · Bᵀ dy, dB += s · dy uᵀ, dA += du xᵀ, dx += Wᵀ dy + Aᵀ du. No gradient reaches W.
  • lora_sequence / lora_sequence_backward: the same over n rows through a linalg backend: the base by linear_sequence (any storage with an overload), the adapter as three matrix products.
  • lora_heads / lora_heads_backward: the outputs head by head over a batch of sequences, as linear_heads lays out attention's queries, keys and values; the base dense in the sequence's type.
  • lora_initialise(a, b, cols, g, kind): B = 0, so a new adapter changes nothing, and A Kaiming-uniform (the bound 1/√cols of PyTorch's nn.Linear, PEFT's default) or Gaussian with standard deviation 1/r (PEFT's "gaussian"), from the caller's stats::wyrand.
  • lora_merge / lora_unmerge: W ± s · B A into a dense matrix for inference, and back.
  • lora_parameters<T>: the adapter's two tensors and their gradients, as the spans an optimiser steps (adamw_step on each), so nothing of the base is touched.
// A frozen base, an adapter A (r x cols, Kaiming-uniform) and B (rows x r, zero): at first the layer is the base
std::vector<float> a(rank * cols), b(rows * rank), da(a.size()), db(b.size());
ml::lora_initialise<float>(a, b, cols, g);
const ml::lora_weights<ml::dense_weights<float>, float> lw{{w, rows, cols}, a, b, rank, ml::lora_scaling(4.0f, rank)};
const ml::lora_parameters<float> adapter{a, b, da, db}; // what the optimiser sees: A and B, nothing of W
std::vector<float> ma(a.size()), va(a.size()), mb(b.size()), vb(b.size());
for (std::uint64_t t = 1; t <= 200; ++t) {
step(lw, xs, targets, da, db);
ml::adamw_step(adapter.parameters()[0], adapter.gradients()[0], ma, va, t, ml::adamw_config<float>{.learning_rate = 0.01f});
ml::adamw_step(adapter.parameters()[1], adapter.gradients()[1], mb, vb, t, ml::adamw_config<float>{.learning_rate = 0.01f});
}

Relationships. ml/linear.hpp (linear, linear_sequence, linear_heads, the products), ml/nf4.hpp (the quantised base), ml/optim.hpp (adamw_step), stats/random.hpp (wyrand). Group: snicholls-core.

Implementations. One. The products go through the backend, so a device library runs them; the base's input gradient is linear_sequence_backward_input, overloaded per storage.

Guarantees. constexpr, no allocation (the caller's u and du, r a row). Linear in rows · cols for the base plus r · (rows + cols) for the adapter. Gradients da, db, dx are added into; u and du written. With B = 0 the output is the base's to the bit (the adapter adds 0). Merge then unmerge returns each weight within 2 ε (|w| + |s · (BA)_ij|) of itself (each is one rounding of a sum and one of a difference; the product (BA)_ij is computed identically both times), and exactly when the update is exact.

Errors. Preconditions, asserted: a has rank · cols, b rows · rank, the rows and scratch their sizes.

Definitions. The update, s = α / r, zero B: from the LoRA paper (recalled, not re-read) and QLoRA's eq. 5 (checked). The initialisations are PEFT's, recalled.

Performance. lora_linear and lora_linear_backward (rank 16 on a 1024 x 1024 base, 8 rows) against the same loops by hand, after a bit-for-bit check (benchmarks/ml/lora_benchmark.cpp): 10.4 ms against 10.2 ms, medians of three, level (Xeon W-3245, -O2, Apple clang 17, 2026-11-19, one thread, CPU time, load average about 100: a record, not a quiet-machine figure). The adapter adds 2r / rows of the base's work forward and about as much backward.

Tests and demos. tests/ml/lora_test.cpp, demos/ml/lora_demo.cpp.

Dependencies. <array>, <cassert>, <cstddef>, <cstdint>, <span>, <type_traits>, linalg/backend.hpp, math/constexpr_math.hpp, ml/linear.hpp, ml/nf4.hpp, ml/row.hpp, stats/random.hpp.

Known issues. DoRA, rsLoRA's α/√r and other variants are not here (scaling is the caller's, so rsLoRA is one argument). Merging into bfloat16 or NF4 storage is the caller's (merge in float, then round).

Status. Experimental, new in 0.16.0.
