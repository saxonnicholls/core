Detailed Description

snicholls::memory_payment_provider: the standard-library reference payment_provider; pull (card) and push (bank transfer by reference) collections, payouts, refunds, quotes, credits, signed webhooks and facts, in memory.

Overview. It plays both shapes the contract was made for, so a product's tests cover the pull path and the push path without a network:

  • a card collection returns a redirect and waits; the test calls complete (the payer paid) or decline;
  • a bank transfer collection returns bank details and a reference and waits; the test calls receive_credit (money arrived quoting a reference), which completes the matching collection, or leaves an unmatched credit for the caller's suspense handling.

Webhooks are signed the way Stripe signs them: a Memory-Signature: t=<unix seconds>,v1=<hex> header, the tag HMAC-SHA256 (core's hmac<sha256>) under the webhook secret over <t>.<raw body>, several v1 accepted during a secret rotation, and a 300-second window. signed_webhook makes a delivery for a test; verify_webhook checks one in constant time and fails closed. The body is key=value lines (source, provider_account, id, fact_id, kind, type, payment_id, our_reference, reference, occurred_at in unix seconds, needs_lookup), the kind by its enumerator's name: no amount, because amounts come only from resolve and statement, which read the balance transactions it recorded. fail_next(code, response) makes the next collect, payout or refund fail as though the provider had answered response.

auto provider = make_provider();
webhook_event e;
e.source = "memory";
e.event_id = "evt_42";
e.kind = event_kind::credit_received;
e.needs_lookup = true;
owned_delivery d = provider.signed_webhook(e); // Memory-Signature: t=...,v1=<HMAC-SHA256>
const auto verified = provider.verify_webhook(d.view());
d.body[0] = 'X'; // one byte changed
const auto tampered = provider.verify_webhook(d.view());

Relationships. Models payment_provider (concepts/payment_provider.hpp); passes interfaces/payment_provider_conformance.hpp in every form. Group: snicholls-core.

Implementations / variants. Card and bank transfer; bank debit is unsupported.

Guarantees. Not thread-safe. Ids are deterministic (mem_pay_1, mem_cr_2, ...). Amounts are exact. Errors follow the redaction rule: a decline keeps the provider's code only.

Errors. As the contract, and whatever fail_next armed.

Performance. verify_webhook: benchmarks/interfaces/payment_provider_reference_benchmark.cpp, against the same HMAC check written by hand. Not yet quoted from a quiet machine: make benchmarks records them in BENCHMARKS.md.

Tests and demos. tests/interfaces/payment_provider_reference_test.cpp, demos/interfaces/payment_provider_reference_demo.cpp.

Dependencies. <algorithm>, <charconv>, <chrono>, <cstdint>, <functional>, <map>, <optional>, <set>, <string>, <string_view>, <system_error>, <utility>, <vector>, hash/hmac.hpp, hash/secure.hpp, hash/sha2.hpp, meta/enums.hpp, secret.hpp, interfaces/payment_provider.hpp.

Known issues. Bank debit (mandates) is unsupported.
