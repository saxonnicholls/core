Detailed Description

snicholls::ml small tensor operations: the sinusoidal timestep embedding, arange, cumsum and its backward, a stable argsort, the top-k mask, triangular fill and the lower-triangular solve with its backward, all constexpr over the caller's spans.

Overview. The building blocks that diffusion models, state-space and linear-attention layers and samplers ask of a tensor library, as ggml defines them:

  • timestep_embedding(t, dim, out, max_period): each timestep's row [cos(t f_0) ... cos(t f_{h-1}), sin(t f_0) ... sin(t f_{h-1})] with h = dim / 2, f_j = exp(-ln(max_period) · j / h), cosines first and a trailing 0 for an odd dim (ggml's ggml_timestep_embedding, the diffusion models' timestep_embedding).
  • arange_count(start, stop, step) and arange(start, step, out): start + step · i, ceil((stop - start) / step) values (ggml's ggml_arange).
  • cumsum(x, y): the running sum y_i = y_{i-1} + x_i (ggml's ggml_cumsum, in place allowed); cumsum_backward is the reverse running sum.
  • argsort(x, indices, order): the indices that sort a row ascending or descending, equal values in index order (stable), so the result is the same everywhere; top_k_mask(x, k, y, scratch) keeps the k largest and sets the rest to -infinity, ties to the lower index.
  • tri(kind, rows, cols, x, y, fill): keep the lower or upper triangle of each matrix, with or without the diagonal, fill elsewhere (ggml's ggml_tri and its ggml_tri_type, which fills with 0).
  • solve_tri(a, b, x, n, k): A X = B for a lower-triangular n x n A and k right-hand sides, by forward substitution in ggml's order (ggml_solve_tri); solve_tri_backward gives dB = A⁻ᵀ dX and adds dA = -dB Xᵀ on the lower triangle.
// Two timesteps embedded in 6 channels: three cosines, then three sines.
std::array<float, 12> embedding{};
ml::timestep_embedding(std::array<float, 2>{0.0f, 10.0f}, 6, embedding);
// arange(0, 1, 0.25) and the running sum of it; cumsum's backward is the running sum from the end.
std::array<float, ml::arange_count(0.0f, 1.0f, 0.25f)> steps{};
ml::arange(0.0f, 0.25f, steps);
std::array<float, steps.size()> sums{}, back{};
ml::cumsum(steps, sums);
ml::cumsum_backward(std::array<float, 4>{1, 1, 1, 1}, back);
// The indices that sort a row (ties in index order), and the row with all but its two largest masked.
const std::array<float, 5> logits{0.5f, 2.0f, -1.0f, 2.0f, 1.0f};
std::array<std::size_t, 5> order{}, scratch{};
ml::argsort(logits, order, ml::sort_order::descending);
std::array<float, 5> kept{};
ml::top_k_mask(logits, 2, kept, scratch);
// A causal mask: 0 on and below the diagonal, -infinity above.
std::array<float, 9> mask{};
ml::tri(ml::tri_kind::lower_diag, 3, 3, mask, mask, -std::numeric_limits<float>::infinity());
// Solve L x = b for a lower-triangular L, then the gradients of sum(x).
const std::array<double, 9> L{2, 0, 0, 1, 1, 0, 1, 1, 1};
const std::array<double, 3> b{2, 3, 6};
std::array<double, 3> x{}, db{};
std::array<double, 9> dL{};
ml::solve_tri(L, b, x, 3, 1);
ml::solve_tri_backward(L, x, std::array<double, 3>{1, 1, 1}, dL, db, 3, 1);

Relationships. ml/sampling.hpp (a top-k of its own, with values), ml/row.hpp. Group: snicholls-core.

Implementations. One each.

Guarantees. constexpr, no allocation, no exceptions. Each multiply and add is its own statement. argsort and top_k_mask are O(n log n) through std::sort with the index as the tie-break; solve_tri O(n² k).

Errors. Preconditions, asserted: spans of the sizes the arguments imply; a nonzero step; k at most the row; a nonzero diagonal for solve_tri.

Performance. Not benchmarked: one pass, or a sort.

Tests and demos. tests/ml/tensor_ops_test.cpp, demos/ml/tensor_ops_demo.cpp.

Dependencies. <algorithm>, <cassert>, <concepts>, <cstddef>, <limits>, <span>, <type_traits>, snicholls/core/math/constexpr_math.hpp, ml/row.hpp.

Known issues. ggml's argsort uses std::sort, which does not keep equal values in order; here they are, so rows with ties can order differently from ggml's. arange_count rounds (stop - start) / step up in the row's type, as ggml does in float: a step that does not divide the range exactly may give one value more than in exact arithmetic.

Status. Experimental, new in 0.17.0.
