Detailed Description

snicholls::ml control vectors: a direction per layer added to the residual stream after layers il_start to il_end, in llama.cpp's layout, with the sum of several at given strengths and the backward pass for training one.

Overview. Representation engineering (Zou et al., 2023; "steering vectors") shifts a model's behaviour by adding a fixed direction to the residual stream between blocks. llama.cpp applies one after each block's output (build_cvec after ffn_out, src/models/llama.cpp), for the layers from il_start to il_end inclusive (llama_adapter_cvec::tensor_for and apply_to, src/llama-adapter.cpp, llama.cpp 39039aa). Its buffer holds n_embd values for each layer from 1 on (layer 0 has none: "never present"), and common_control_vector_load sums several files, each scaled by its strength.

  • control_vector_view<T>{data, width, layer_start, layer_end}: llama.cpp's buffer and range; direction(il) gives layer il's row, or an empty span outside the range or the buffer.
  • apply_control_vector(cv, il, rows): x += direction(il) for every row of a batch, after block il.
  • add_control_vector(sum, data, strength): sum += strength · data, to combine vectors before use.
  • control_vector_backward(cv, il, drows, ddirection): the gradient passes unchanged to the block's output, and the direction's gradient is the sum of the rows' (training a steering vector).
// llama.cpp's layout: width 2, layers 1 to 3 (layer 0 has no entry)
const std::array<float, 6> happy{0, 0, 1, 1, 2, 2}, formal{0, 0, 1, -1, 0, 0};
std::array<float, 6> combined{};
ml::add_control_vector(std::span<float>(combined), happy, 0.5f);
ml::add_control_vector(std::span<float>(combined), formal, 1.0f);
const ml::control_vector_view<float> cv{combined, 2, 2, 3}; // applied after layers 2 and 3
std::array<float, 4> residual{1, 1, 1, 1}; // two tokens
for (std::int32_t il = 0; il < 4; ++il)
ml::apply_control_vector(cv, il, std::span<float>(residual)); // between block_forward calls
// Training a steering direction: its gradient is the sum of the rows' gradients
std::array<float, 2> ddirection{};
ml::control_vector_backward(cv, 2, std::array<float, 4>{1, 0, 1, 0}, std::span<float>(ddirection));

Relationships. Applied between block_forward calls (ml/transformer_block.hpp); ml/lora.hpp is the other adapter llama.cpp loads. Group: snicholls-core.

Implementations. One.

Guarantees. constexpr, no allocation, linear in the rows. A disabled vector (layer_start -1, as llama_adapter_cvec::apply with no data) changes nothing.

Errors. Preconditions, asserted: width > 0; the rows a multiple of width; sum and data the same size.

Performance. Not benchmarked: one addition per value.

Tests and demos. tests/ml/control_vector_test.cpp, demos/ml/control_vector_demo.cpp.

Dependencies. <cassert>, <cstddef>, <cstdint>, <span>, snicholls/core/math/constexpr_math.hpp.

Known issues. llama.cpp's loader also accepts vectors with fewer layers than the model (the rest are zero); direction returns an empty span past the buffer, the same effect.

Status. Experimental, new in 0.17.0.
