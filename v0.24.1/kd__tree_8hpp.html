Detailed Description

snicholls::containers::kd_tree<Point, K, Metric>: a balanced k-d tree built in place over the caller's points, under any coordinate-wise metric, with nearest, k-nearest, radius and box queries, iterative and allocation-free.

Overview. A scan brings hundreds of detections and a tracker asks, for each track, which detections lie near its prediction. A k-d tree answers that in about log n per query instead of n. This one is built once over a span of points the caller owns, and stores nothing but a permutation of their indices (the caller's span, too). The tree is implicit: the median of each index range is its node, split on axis depth mod K. So there are no node objects and no pointers, and a rebuild per scan costs O(n log n).

  • Point is any metric::point (fixed_vector, std::array, a struct of the caller's with point_traits). Queries may be any compatible point type.
  • Metric is any metric::decomposable metric (euclidean by default; manhattan, chebyshev, minkowski<P>, weighted_minkowski, a mahalanobis made coordinate-wise by whitening the points first, or the caller's own): a single coordinate's term bounds the whole, which is what lets a subtree be skipped.
  • nearest(q): the closest point and its distance, or nothing for an empty tree.
  • k_nearest(q, out): the out.size() closest, nearest first.
  • for_each_within(q, r, f): f(index, distance) for every point within distance r.
  • for_each_in_box(lo, hi, f): f(index) for every point with lo ≤ p ≤ hi on every axis.

Distances are reported in the metric's own units (expand of the reduced form the search compares in).

// One scan: index the detections (the tree keeps only a permutation, in storage the caller gives it)
std::vector<std::uint32_t> order(detections.size());
const ct::kd_tree<xy, 2> tree(detections, order);
const xy track{500, 500}; // a track's predicted position
const auto closest = tree.nearest(track); // index and distance, in metres
std::array<ct::kd_neighbour, 5> five{};
const std::size_t found = tree.k_nearest(track, five); // nearest first
std::vector<std::uint32_t> gated; // every detection within 40 m
tree.for_each_within(track, 40.0, [&](std::uint32_t i, double) { gated.push_back(i); });
std::vector<std::uint32_t> boxed; // every detection in the gate's bounding box
tree.for_each_in_box(xy{460, 460}, xy{540, 540}, [&](std::uint32_t i) { boxed.push_back(i); });
// The metric is a template parameter: the same scan, gated by city-block distance
std::vector<std::uint32_t> order_l1(detections.size());
const ct::kd_tree<xy, 2, mt::manhattan> by_blocks(detections, order_l1);
const auto closest_l1 = by_blocks.nearest(track);

Relationships. metric/concepts.hpp and metric/minkowski.hpp, intrusive_avl_tree.hpp (the same policy style), containers/ann_forest.hpp (approximate search for high dimensions, where k-d trees lose their edge). Stone Soup's DetectionKDTreeNN and KDTreePDA associators are built on it in the framework above core. Group: snicholls-core.

Implementations. Build: an explicit stack of index ranges, each partitioned at its median by std::nth_element (constexpr since C++20). Queries: an explicit stack of at most 64 frames, near child first, each carrying a lower bound on its points' reduced distance (the larger of its parent's and the splitting plane's term), skipped when the bound exceeds the best so far. Candidate distances are accumulated with an early exit at the current bound.

Guarantees. constexpr, no allocation, no recursion. Build O(n log n) expected; queries O(log n) expected for well-spread points in a few dimensions. The tree reads the points through the span: they must not change or move while the tree is in use. noexcept when the points' coordinate reads and the callbacks are.

Errors. None. An index span shorter than the points builds a tree over the first indices.size() points.

Performance. Not yet benchmarked.

Tests and demos. tests/containers/kd_tree_test.cpp, demos/containers/kd_tree_demo.cpp.

Dependencies. <algorithm>, <array>, <cstddef>, <cstdint>, <limits>, <optional>, <span>, <utility>, metric/concepts.hpp, metric/minkowski.hpp.

Known issues. Up to 2³² points (the indices are std::uint32_t), and depth at most 64, which a balanced tree of fewer than 2⁶³ points never reaches. Changed in 0.20.0: the metric is a template parameter, points are read through metric::point_traits (the kd_point_traits parameter is gone), kd_neighbour::distance is the metric's distance (it was distance2, the squared Euclidean distance), and for_each_within takes a radius (it took its square).

Status. Experimental, new in 0.19.0; generic over the metric in 0.20.0.
