Detailed Description

The identifiers of the capability contracts: bounded inplace_strings, one alias per kind of id, and make_id, which refuses an id that does not fit.

Overview. A contract owns no std::string: an identifier a provider returns or a ledger books is an inplace_string<N> (trivially copyable, no allocation, refused rather than truncated), and a free-form payload (a message body, a webhook body, a request) is borrowed for the call as std::string_view or std::span<const std::byte>. Time is utc_s, core's utc<std::chrono::seconds> (time/utc.hpp). The bounds:

Alias Capacity For Why that bound
provider_id 96 an id a provider assigns: a payment, order, withdrawal, quote, message, key, cursor, transaction hash an EVM transaction hash is 66 characters, a Stripe Checkout session id about 66, an SES message id about 60, a UUID 36, OKX and Twilio ids under 35
fact_id 128 what a ledger books once <chain id>:<transaction hash>:<log index> is at most 98 with a 20-digit chain id, plus a suffix such as :reversed or :dispute_loss
event_id 64 a webhook delivery, the dedup key Stripe evt_... is about 28, Wise's X-Delivery-Id a UUID
provider_account 64 the opaque id of our account at a provider Stripe acct_... is 21, a Wise profile id a number
client_id 64 an id we choose: an idempotency key, a client order id, a client reference OKX clOrdId allows 32; ours are UUIDs (36) or shorter
provider_name 32 which provider: "stripe", "wise", "okx", "chain" a name
short_text 255 a short field a provider returns: a label, a name, a payment reference, an address SEPA's remittance text is 140 characters, an account name 70

Stripe documents its ids as up to 255 characters, but none it issues today comes near 96; an implementation that meets a longer one answers capability_errc::internal rather than cut it (an id cut short is another id).

const auto key = make_id<client_id>("order-2026-11-24-0001"); // our idempotency key: at most 64
const auto hash = make_id<provider_id>("0x" + std::string(64, 'f')); // a transaction hash: 66 of 96
const auto too_long = make_id<event_id>(std::string(65, 'e')); // refused, never cut short

Relationships. containers/inplace_string.hpp, capability_error.hpp, time/utc.hpp; every contract under concepts/ that names an id. Group: snicholls-core.

Implementations / variants. Aliases; make_id<Id> for any of them.

Guarantees. Every alias is trivially copyable, standard layout and structural. make_id is constexpr and noexcept, and never truncates.

Errors. make_id returns capability_errc::invalid_argument ("identifier too long") when the text does not fit.

Performance. Not benchmarked: a bounded copy (containers/inplace_string.hpp has the numbers).

Tests and demos. tests/capability_ids_test.cpp, demos/capability_ids_demo.cpp.

Dependencies. <chrono>, <string_view>, capability_error.hpp, containers/inplace_string.hpp, time/utc.hpp.

Known issues. A URL (a hosted checkout's) is a payload, not an id: it stays a std::string (concepts/payment_provider.hpp).

Status. New in 0.23.0. Experimental, with the contracts.
