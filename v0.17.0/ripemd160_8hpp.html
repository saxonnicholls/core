Detailed Description

RIPEMD-160 (Dobbertin, Bosselaers and Preneel, 1996), usable at compile time: Bitcoin's hash160.

Overview. RIPEMD-160 with the incremental interface of every hash in core and a one-shot hash, returning a digest<20>. It survives in one place that matters: hash160(x) = RIPEMD-160(SHA-256(x)) names Bitcoin addresses (P2PKH, P2SH, P2WPKH) and the BIP-32 key fingerprint, and Cosmos derives account addresses the same way. Two parallel lines of 80 rounds over 64-byte blocks, little-endian words. For anything new use SHA-256 or BLAKE2.

// hash160 = RIPEMD-160(SHA-256(x)): Bitcoin's address payload, and BIP-32's key fingerprint (its first 4 bytes)
template <snicholls::hash_input Key>
constexpr snicholls::digest<20> hash160(const Key& public_key) noexcept
{
return snicholls::ripemd160::hash(snicholls::sha256::hash(public_key));
}
// The compressed public key of private key 1 (the secp256k1 generator)
constexpr std::array<std::uint8_t, 33> generator = {
0x02, 0x79, 0xbe, 0x66, 0x7e, 0xf9, 0xdc, 0xbb, 0xac, 0x55, 0xa0, 0x62, 0x95, 0xce, 0x87, 0x0b, 0x07,
0x02, 0x9b, 0xfc, 0xdb, 0x2d, 0xce, 0x28, 0xd9, 0x59, 0xf2, 0x81, 0x5b, 0x16, 0xf8, 0x17, 0x98};
static_assert(hash160(generator).hex().view() == "751e76e8199196d454941c45d1b3a323f1433bd6");

Relationships. md_hash and digest<N> (hash/digest.hpp); sha256 (hash/sha2.hpp) for hash160. Group: snicholls-core.

Guarantees. Every member is constexpr and noexcept; no allocation; a hasher is a trivially copyable value. Complexity: one compression (160 steps) per block.

Errors. None.

Examples. Above; demos/hash/ripemd160_demo.cpp.

Performance. benchmarks/hash/ripemd160_benchmark.cpp, against a hand-written loop, after a fairness check. Release, Apple clang 17, Xeon W-3245 (a shared machine), 2026-11-20, 16 KiB / 64-byte messages: core 189 / 90 MB/s, the hand loop 172 / 81.

Tests and demos. tests/hash/ripemd160_test.cpp (the designers' published vectors, including a million a, Python's hashlib on random lengths, every split), demos/hash/ripemd160_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, hash/digest.hpp.

Known issues. OpenSSL 3 moved RIPEMD-160 to its legacy provider, so some systems' hashlib lack it; the committed fixture does not depend on it at test time.

Status. New in 0.17.0. Experimental.
