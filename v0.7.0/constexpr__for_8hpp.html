Detailed Description

constexpr_for, constexpr_nest, unrolled_for: compile-time loop unrolling.

Overview. constexpr_for<Start, End, Inc> expands into exactly the calls it needs and leaves no loop at all: the bounds are template parameters, so there is no counter, no compare and no branch. The body is handed std::integral_constant<T, I>, not a bare T, so I.value is a constant expression inside the body and can index a tuple or be a template argument, while I still converts to its value for ordinary arithmetic:

// The index is a type, so it can index a tuple: no plain loop can do this
const auto row = std::make_tuple(std::string{"BTC"}, 64000.0, 3);
std::string line;
snicholls::constexpr_for<std::tuple_size_v<decltype(row)>>([&](auto I) {
if constexpr (I.value > 0)
line += ", ";
if constexpr (std::is_same_v<std::decay_t<decltype(std::get<I.value>(row))>, std::string>)
line += std::get<I.value>(row);
else
line += std::to_string(std::get<I.value>(row));
});

constexpr_nest<E0, E1, ...> unrolls nested loops to any depth, row-major, with a constant index per level. unrolled_for<Unroll>(first, last, body) walks a run-time range with the body emitted Unroll times per iteration and a tail.

Relationships. For iterating values (an index range, a tuple-like by index). To operate on a pack of types, use type_list (CLAUDE.md "Idioms").

Guarantees. Expansion is a fold over an index_sequence, depth 1 whatever the count, so there is no instantiation-depth cliff. The iteration count is computed in long long, so a negative step against unsigned bounds cannot wrap. A step of 0 is a compile error. Trailing arguments reach every call as lvalues, never forwarded, so a body cannot move from the same object twice.

Performance. At -O2 compilers already unroll simple counted loops, and doing it by hand can lose. Reach for constexpr_for when the body must be instantiated per index; reach for unrolled_for only with a benchmark in hand. Not benchmarked in core; ts-moveables' make bench-parallel compares them.

Tests and demos. tests/constexpr_for_test.cpp, demos/constexpr_for_demo.cpp.

Dependencies. <cstddef>, <type_traits>, <utility>.

Known issues. constexpr_nest<8, 8, 8> is 512 copies of the body: for small fixed extents, not whole arrays.

Status. Stable.
