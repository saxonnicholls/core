Detailed Description

snicholls::hash_combine: mix one hash value into a running seed, in 64 bits on every platform.

Overview

The building block for hashing a composite value from the hashes of its parts. A hash of a struct is hash_combine applied to each member's hash in declaration order, starting from seed 0.

It is the Boost.ContainerHash 1.81+ hash_combine, so the same chain gives the same answer as Boost's on a 64-bit platform: seed = mix(seed + 0x9e3779b9 + h), where mix is a 64-bit xor-shift / multiply finaliser with full avalanche (constant 0xe9846af9b1a615d).

Relationships
  • A std::hash written as this chain over an object's fields gives the same value as a hand-written hash of the equivalent struct.
  • Module: snicholls-core.
Implementations and variants

None: a single implementation.

Guarantees and contracts
  • constexpr and noexcept; O(1).
  • A chain from a fixed seed is order-sensitive, because every step mixes the running seed: permuted values hash differently. A single step is not: it adds seed and h before mixing, so hash_combine(1, 2) == hash_combine(2, 1), as in Boost.
  • Computed in 64 bits whatever the width of std::size_t, then narrowed to it.
Errors

None.

Examples

A hash for a plain struct, usable as an std::unordered_set key:

struct quote_key {
std::string symbol;
char side;
long level;
bool operator==(const quote_key&) const = default;
};
struct quote_key_hash {
std::size_t operator()(const quote_key& k) const noexcept
{
std::size_t seed = 0; // every member, in declaration order, from seed 0
seed = snicholls::hash_combine(seed, std::hash<std::string>{}(k.symbol));
seed = snicholls::hash_combine(seed, std::hash<char>{}(k.side));
seed = snicholls::hash_combine(seed, std::hash<long>{}(k.level));
return seed;
}
};
std::unordered_set<quote_key, quote_key_hash> seen;

Known issues and gotchas
  • Not portable across builds when fed std::hash values: std::hash of the leaves is implementation-defined (libc++ and libstdc++ differ for strings and doubles), so never persist, transmit or compare such hashes across builds. hash_combine itself is deterministic.
