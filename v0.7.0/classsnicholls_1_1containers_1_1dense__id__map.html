Detailed Description

template<class Value>
class snicholls::containers::dense_id_map< Value >

Maps ids to pointers with one array lookup when ids are dense and increasing (exchange order refs).

Overview

Feeds such as NASDAQ ITCH number orders sequentially per day, so an order id is almost an array index. This map keeps a window [base, base + size) of slots indexed by id - base; a lookup is one subtraction, one compare and one load - no hashing, no probing, no growth rehash of the whole table (the window grows by doubling and copies slots, never re-inserts). Ids outside the window, or too far ahead of it (max_window), go to a snicholls::containers::flat_id_map, so arbitrary ids still work.

Profiling limit order books showed id-map growth at about 20% of a large book's add path; this map is the fix for sequential feeds. For random ids (client order ids, UUID-derived) use flat_id_map directly.

Relationships
  • Same interface as snicholls::containers::flat_id_map (find, insert, erase, contains, clear, size), so the order books take either (id_index in the book policy, lob/book_core.hpp).
  • Module: snicholls-core.
Implementations and variants
Map Choose it when
flat_id_map<V> ids arbitrary
dense_id_map<V> ids mostly increasing and dense (exchange order refs)
Guarantees and contracts
  • Thread safety: none internal.
  • Exception safety: insert is strong (growth allocates before changing anything); the rest is noexcept.
  • Complexity: O(1) in the window; expected O(1) in the fallback; growth amortised O(1).
  • Memory: one pointer per id in the window, including ids already erased below the highest live id; the window start moves up (compact) when its first half is empty.
  • Invariants: a null slot means absent, so Value must be a pointer type; empty_key is never stored.
Errors

std::bad_alloc from growth. Inserting an existing key returns false.

Examples
snicholls::containers::dense_id_map<int*> ids(1024);
for (std::uint64_t id = 5'000'000; id < 6'000'000; ++id) { // a day of ITCH order refs
ids.insert(id, &orders[id % 1024]);
if (id >= 5'000'512) ids.erase(id - 512); // ~512 live orders at any time
}
ids.insert(42, &orders[0]); // an outlier id: hash fallback
Performance

Inside a ladder book on sequential-id workloads: 1.3x-2.3x the flat_id_map book (Ubuntu Release, 2026-10-18). In core, benchmarks/containers/dense_id_map_benchmark.cpp compares it like for like with std::unordered_map, after a fairness check; not yet measured in Release.

Tests and demos

Dependencies

CMake target snicholls::core; standard library only.

Known issues and gotchas
  • Pointers returned by find are invalidated by insert (growth) and erase/compact.
