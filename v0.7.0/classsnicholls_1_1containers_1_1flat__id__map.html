Detailed Description

template<class Value>
class snicholls::containers::flat_id_map< Value >

A hash map from std::uint64_t ids to trivially copyable values, stored in one flat array.

Overview

Order books look orders up by exchange id on every cancel, execute and replace. std::unordered_map allocates a node per insert (the reference implementations pay a heap allocation per order for it). This map keeps {key, value} pairs in one power-of-two array, finds them by linear probing from a Fibonacci hash (which spreads the sequential ids exchanges assign), and deletes by backward shifting, so there are no tombstones and lookups never degrade after many erases. The load factor stays at or below one half.

Use it for integer ids mapped to pointers or indices. Not for string keys, or values that are not trivially copyable (they are moved by bitwise assignment during probing and growth).

Relationships
  • Used by limit order books (order id -> order node).
  • Module: snicholls-core.
Implementations and variants

None: a single implementation.

Guarantees and contracts
  • Thread safety: none internal; one writer, or many readers with no writer.
  • Exception safety: insert and reserve are strong (growth allocates a new array before touching the old one); find, erase, clear are noexcept.
  • Complexity: expected O(1) for find, insert and erase; growth O(n), amortised O(1).
  • Ownership and lifetime: pointers returned by find are invalidated by any insert (growth) or erase (backward shift).
  • Invariants: size() <= capacity() / 2; the key empty_key (UINT64_MAX) is never stored. The reserved key empty_key is never stored: insert of it returns false, and find, contains and erase of it report "absent".
Errors

std::bad_alloc from growth. Inserting an existing key returns false and changes nothing.

Examples
snicholls::containers::flat_id_map<int> ids(1024); // room for 1024 ids before growing
ids.insert(1'000'001, 7);
const bool again = ids.insert(1'000'001, 8); // duplicate: refused, value unchanged
int* found = ids.find(1'000'001);
ids.erase(1'000'001);
Performance

Measured inside limit order books. In core, benchmarks/containers/flat_id_map_benchmark.cpp compares it like for like with std::unordered_map, after a fairness check; not yet measured in Release.

Tests and demos
  • Tests: tests/containers/flat_id_map_test.cpp (model-checked against std::unordered_map).
  • Demo: demos/containers/flat_id_map_demo.cpp.
  • Benchmark: benchmarks/containers/flat_id_map_benchmark.cpp.
Dependencies

CMake target snicholls::core; standard library only.

Known issues and gotchas
  • UINT64_MAX is reserved; a feed that uses it as an id must remap it.
