Detailed Description

snicholls::ml quantised weights: ggml's Q8_0 and Q4_0 blocks and the OCP MXFP4 block, byte for byte as ggml lays them out, with quantisation, dequantisation and the integer dot products, plus symmetric int8 rows.

Overview. A quantised model stores its weights in blocks of 32 numbers, each block with one scale. These are the formats llama.cpp and gpt-oss ship, so a GGUF tensor of one of them is an array of these structs, read in place:

Block Scale Elements Bytes Bits per weight
block_q8_0 float16 d = amax / 127 int8 round(x / d) 34 8.5
block_q4_0 float16 d = (the signed value of largest magnitude) / -8 4-bit x / d + 8, element j in the low nibble of byte j, j + 16 in the high 18 4.5
block_mxfp4 E8M0 exponent e = floor(log2 amax) - 2 + 127 FP4 E2M1, the nearest of ±{0, 0.5, 1, 1.5, 2, 3, 4, 6} · 2^(e - 127), packed as Q4_0 17 4.25
  • quantize<Block>(x, blocks) and dequantize(blocks, x): rows of 32 · blocks.size() floats.
  • dot(x, y): the dot product of a Q8_0, Q4_0 or MXFP4 row with a Q8_0 row (the activations, quantised on the fly), in integers within a block and one multiplication by the scales per block, as ggml's matrix-vector products do. Each gives ggml's scalar reference result bit for bit.
  • quantize_int8(x, q) and dequantize_int8(q, scale, x): one symmetric scale for a whole row (per-channel or per-tensor int8), the same rounding as Q8_0.
// One row of 64 weights and 64 activations: two blocks of 32 each
std::array<float, 64> w{}, a{};
for (std::size_t i = 0; i < 64; ++i) {
w[i] = 0.05f * std::sin(0.7f * static_cast<float>(i));
a[i] = std::cos(0.3f * static_cast<float>(i));
}
// The weights in three formats, byte for byte as a GGUF file stores them
std::array<ml::block_q8_0, 2> w8{};
std::array<ml::block_q4_0, 2> w4{};
std::array<ml::block_mxfp4, 2> wm{};
ml::quantize(w, std::span(w8));
ml::quantize(w, std::span(w4));
ml::quantize(w, std::span(wm));
// The activations quantised on the fly to Q8_0, then integer dot products, one multiplication per block
std::array<ml::block_q8_0, 2> a8{};
ml::quantize(a, std::span(a8));
const float d8 = ml::dot(std::span<const ml::block_q8_0>(w8), a8);
const float d4 = ml::dot(std::span<const ml::block_q4_0>(w4), a8);
const float dm = ml::dot(std::span<const ml::block_mxfp4>(wm), a8);

Relationships. ml/minifloat.hpp (float16, and the FP8, FP6 and FP4 element formats of the other MX blocks); ml/row.hpp. Group: snicholls-core.

Implementations. One per block. The blocks are the formats; the dot products are the scalar reference, which a SIMD or GPU kernel reorders.

Guarantees. constexpr, no allocation, linear in the row. The blocks are trivially copyable, have ggml's sizes and no padding (static_asserted). Quantised bytes equal ggml's quantize_row_*_ref and dot products equal ggml's ggml_vec_dot_*_generic on every input of the committed fixture (tests/fixtures/ml/quant_fixture.txt, from scripts/generate_quant_fixture.cpp built against ggml). Each multiplication and each addition is its own statement, so no compiler fuses them into an FMA and the result is the same on every machine.

Errors. Preconditions, asserted: the row has 32 · blocks.size() elements; the rows of a dot product have the same number of blocks. NaN and infinity in a block are not representable in these formats; the result is unspecified, as in ggml.

Performance. Against ggml's scalar loops written out by hand (benchmarks/ml/quantize_benchmark.cpp), rows of 4,096: the three dot products level, 1.9 to 2.6 billion weights per second; Q8_0 quantisation 2x faster than ggml's loop (590 against 300 million per second), from rounding without roundf (Xeon W-3245, Release, Apple clang 17, 2026-11-11, one thread, scalar code; SIMD kernels are the libraries' above).

Tests and demos. tests/ml/quantize_test.cpp, demos/ml/quantize_demo.cpp.

Dependencies. <array>, <bit>, <cassert>, <cstddef>, <cstdint>, <span>, <type_traits>, snicholls/core/math/constexpr_math.hpp, ml/minifloat.hpp, ml/row.hpp.

Known issues. ggml computes MXFP4's exponent as floorf(log2f(amax)), which depends on the C library and can round up for an amax a few units in the last place below a power of two; core reads the exponent from the bits, as the OCP specification defines it. An amax below 2^-125 gives exponent 0 (ggml's conversion there is undefined). A dot product over infinities is a NaN whose sign is the hardware's (negative on x86, positive on ARM), so results are bit-identical across platforms except for the sign of a NaN. Each multiply and add is its own statement, which Clang never fuses, but GCC fuses across statements by default in C++ (-ffp-contract=fast), so on a target with FMA (every ARM64) the last bit can differ: compile with -ffp-contract=off for ggml's bits.

Status. Experimental, new in 0.7.0.
