Detailed Description

snicholls::uint256: a 256-bit unsigned integer, constexpr, exact, for amounts that do not fit a uint64_t.

Overview. Every EVM token amount is a 256-bit unsigned integer; one token with 18 decimals is 10^18 base units, and a std::uint64_t overflows at 18.4 of them. A double holds 15 to 17 significant digits and silently rounds the rest. uint256 is the native type: four 64-bit limbs, little-endian, every operation constexpr, and arithmetic that behaves like the built-in unsigned types (modulo 2^256) with checked forms beside it that report overflow instead of wrapping:

// 10,000 USDT on an 18-decimal chain is 1e22 base units: no uint64 holds it, and that
// is the deposit that once overflowed std::stoull after the bill had been issued.
const std::optional<uint256> deposit = uint256::from_decimal("10000000000000000000000");
const std::optional<uint256> fee = uint256::from_decimal("2500000000000000000"); // 2.5 tokens
const uint256 one_token = uint256::pow10(18);
// The ledger works in base units, exactly.
const uint256 net = *deposit - *fee;
const auto [whole, fraction] = net.divmod(one_token);
// Human units only at the leaf, from the amount and its decimals together.
const std::string human = net.format_units(18); // 9997.500000000000000000, exactly
// USDT has 6 decimals, and Binance quotes eight places: parse_units takes both, and rounds nothing.
const std::optional<uint256> withdrawal = uint256::parse_units("250.12000000", 6); // 250,120,000 base units
// The ABI word for the call that moves it.
const std::string word = net.to_abi_word(); // 64 hex digits, zero-padded
// Overflow and bad input are refused, never wrapped and never thrown.
const std::optional<uint256> too_much = uint256::checked_mul(uint256::max(), 2);
const std::optional<uint256> not_a_number = uint256::from_decimal("10,000");

A token amount as people write it goes through parse_units("250.12", 6) and format_units(6): 6 decimals for USDT and USDC, 18 for ETH, any count up to 77. Digits past the token's decimals are accepted only when they are zeros (Binance's eight-place strings for a 6-decimal token), so nothing is ever rounded away.

Parsing never throws: from_decimal and from_hex return std::nullopt on any bad input or overflow, because a money path must be able to refuse bad input without unwinding through a half-completed transaction. Rendering is exact: to_string is the full decimal, to_hex the minimal 0x form, to_abi_word the 64-nibble word an ABI encoder wants.

Relationships. detail/wide_mul.hpp for the 128-bit products; hash_combine for std::hash; wyhash where a uint256 is a key across machines. Scaling to human units is the caller's, from the amount and its decimals together (pow10). Group: snicholls-core.

Guarantees. A literal type of exactly 32 bytes, trivially copyable, standard layout. Every operation is constexpr; everything but division and the string renderings is noexcept. +, -, *, <<, >> wrap modulo 2^256 like unsigned; the checked_ forms return std::nullopt instead. Division by zero is a precondition violation (asserted); checked_div and checked_divmod return std::nullopt for it. Shifts by 256 or more give 0. Decimal and hexadecimal round trips are exact.

Errors. None thrown by the arithmetic. to_string, to_hex and to_abi_word allocate and can throw std::bad_alloc. The parsers and the checked operations report through std::optional: this header deliberately does not include result.hpp, so that a numeric vocabulary type stays light; wrap the optional in a result at the call site where the reason matters.

Performance. Benchmarked in benchmarks/uint256_benchmark.cpp: addition and multiplication against the same limb loops written out by hand, after a fairness check; division and to_string alone, since their hand-written equivalents are the same algorithms. Release, Apple clang 17, Xeon W-3245, 2026-11-06, 4,096 pairs of every width: addition 2.0 ns through the class and 2.0 ns by hand, multiplication 4.3 ns and 4.4 ns, divmod 45 ns (Knuth D, base 2^32), to_string 540 ns (nine digits per 32-bit division, plus the string building). Zero overhead on the operators.

Tests and demos. tests/uint256_test.cpp, demos/uint256_demo.cpp.

Dependencies. <array>, <bit>, <cassert>, <compare>, <cstddef>, <cstdint>, <functional>, <optional>, <ostream>, <string>, <string_view>, <utility>, detail/wide_mul.hpp and hash/hash_combine.hpp. print(std::ostream&) const makes it a snicholls::printable for acout.hpp without including it.

Known issues. Construction is from std::uint64_t only; a negative int converts to a large value as it would for unsigned. There is no conversion to or from floating point: scale to human units by division and to_string, which is exact, and convert the text if a double is really wanted.

Status. New in 0.5.0.
