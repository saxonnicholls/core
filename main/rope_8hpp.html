Detailed Description

snicholls::ml rotary position embedding: the frequencies, a table of cosines and sines the compiler can build, and the rotation of a head, forward and inverse.

Overview. RoPE (Su et al., 2021), as LLaMA, GPT-NeoX and nanochat use it: each pair of channels of a query or key head is rotated by the angle pos · base^(-2i/d), so that the dot product of a query and a key depends on their distance only.

  • rope_frequency<T>(i, d, base): base^(-2i/d), the angular frequency of pair i of a head of d channels.
  • rope_angles(pos, cos, sin, base): one position's row of d/2 cosines and sines.
  • rope_table<T, Positions, HeadDim>: every position's rows, built by a constexpr constructor: in a constexpr variable for a table the compiler holds (a fixed context on an FPGA, a float table a GPU kernel reads), or at start-up for a long context, which would exceed the compiler's evaluation limits.
  • rope(x, cos, sin, layout) rotates a head by +θ; rope_inverse by -θ. The rotation is orthogonal, so the backward pass of rope is rope_inverse applied to the gradient, and the other way round.
  • rope_layout::half pairs channel i with i + d/2 (GPT-NeoX, Hugging Face LLaMA, nanochat); rope_layout::interleaved pairs 2i with 2i + 1 (Meta's LLaMA, GPT-J).
// A context of 16 positions and heads of 8 channels: the compiler builds the whole table, in float as a kernel reads it
constexpr ml::rope_table<float, 16, 8> table{};
static_assert(table.cos[0][0] == 1.0f && table.sin[0][0] == 0.0f); // position 0 does not rotate
float score(std::array<float, 8> q, std::size_t pq, std::array<float, 8> k, std::size_t pk, ml::rope_layout layout)
{
ml::rope(q, table.cos_at(pq), table.sin_at(pq), layout);
ml::rope(k, table.cos_at(pk), table.sin_at(pk), layout);
float s = 0.0f;
for (std::size_t i = 0; i < 8; ++i)
s += q[i] * k[i];
return s;
}

Relationships. ml/attention.hpp takes the rotated queries and keys; ml/row.hpp (the rows). Group: snicholls-core.

Implementations. One.

Guarantees. constexpr, no allocation, linear in the head. rope_table is trivially copyable. A rotation keeps a pair's length up to rounding.

Errors. Preconditions, asserted: the head has an even number of channels, and cos and sin have half as many. Position 0 is the identity.

Performance. Not benchmarked: four multiplications and two additions per pair, against a table read.

Tests and demos. tests/ml/rope_test.cpp, demos/ml/rope_demo.cpp.

Dependencies. <array>, <cassert>, <concepts>, <cstddef>, <span>, snicholls/core/math/constexpr_math.hpp, ml/row.hpp.

Known issues. nanochat's apply_rotary_emb rotates by -θ (y1 = x1 cos + x2 sin): its forward pass is rope_inverse here. Either direction is a valid RoPE as long as queries and keys agree. LLaMA 3's long-context rescaling of the frequencies is not built in; scale the table's angles yourself.

Status. Experimental, new in 0.7.0.
