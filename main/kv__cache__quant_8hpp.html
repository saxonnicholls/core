Detailed Description

snicholls::ml quantised KV caches: keys and values stored as Q8_0, Q4_0 or MXFP4 rows, attention that reads them as ggml's flash attention does, and the K-shift of quantised keys.

Overview. A cache of float keys and values is the largest buffer of long-context inference. llama.cpp stores them quantised (--cache-type-k q8_0 --cache-type-v q4_0): each head's row of head_dim values is head_dim / 32 blocks of ml/quantize.hpp. Its CPU flash attention (ggml_compute_forward_flash_attn_ext_f16_one_chunk, ggml/src/ggml-cpu/ops.cpp, llama.cpp 39039aa) quantises the query once to the key type's dot-product partner (Q8_0 for every block type here), scores each key with the block dot product (kq_vec_dot), and dequantises each value row (v_to_float) into the running sum. This header does the same:

  • quantized_kv_cache_view<C, KBlock, VBlock>: views over the caller's blocks, laid out as kv_cache_view's [layer][kv_head][slot][block], with append(layer, pos, k, v) quantising each head (slot pos % capacity, a ring under a sliding window), key_blocks and value_blocks by slot; quantized_kv_cache<C, Layers, Capacity, ...> owns fixed-size arrays.
  • attend_quantized(cache, layer, kv_head, q, keys, out): one query head over the keys keys (a key_range of positions, which may wrap the ring), with the configuration's scale and soft cap, in attend's recurrence.
  • kv_shift_quantized_keys<C>(cache, layers, cells): llama.cpp's K-shift on a quantised cache: each moved key is dequantised, rotated by its shift and quantised again (as ggml's graph does with a cast around ggml_rope).
// One layer, one key-value head of 64 channels, 16 slots: keys as Q8_0, values as Q4_0 (owning arrays)
constexpr ml::transformer_config c{.d_model = 64, .n_heads = 1, .n_kv_heads = 1, .head_dim = 64, .d_ff = 64, .rope = ml::rope_kind::half};
ml::quantized_kv_cache<c, 1, 16, ml::block_q8_0, ml::block_q4_0> cache;
const auto view = cache.view();
std::vector<float> fk, fv; // the same rows in float, to compare
for (std::size_t p = 0; p < 16; ++p) {
std::array<float, 64> k{}, v{};
for (std::size_t i = 0; i < 64; ++i) {
k[i] = std::sin(0.1f * float(i) + float(p));
v[i] = std::cos(0.05f * float(i * p));
}
view.append(0, p, k, v); // quantised on the way in
fk.insert(fk.end(), k.begin(), k.end());
fv.insert(fv.end(), v.begin(), v.end());
}
std::array<float, 64> q{}, out{}, exact{};
for (std::size_t i = 0; i < 64; ++i)
q[i] = std::sin(0.3f * float(i));
ml::attend_quantized(view, 0, 0, q, ml::key_range{0, 16}, out); // q to Q8_0, block dot products, values dequantised
ml::attend(q, fk, fv, exact, 1.0f / 8.0f);
// The K-shift on quantised keys: positions 8 to 15 move back by 8 after the first 8 are dropped
ml::kv_cells<16> cells;
for (std::size_t p = 0; p < 16; ++p)
cells.place(p, ml::kv_pos(p), 0);
cells.seq_rm(0, 0, 8);
cells.seq_add(0, 8, -1, -8);
ml::kv_shift_quantized_keys(view, cells);

Relationships. ml/quantize.hpp (the blocks, quantize, dequantize, dot); ml/kv_cache.hpp (the layout and key_range); ml/kv_cells.hpp (positions, sequences and shifts). Group: snicholls-core.

Implementations. One, for any quant_block keys and values.

Guarantees. constexpr, no allocation: the quantised query and one dequantised value row are fixed-size arrays on the stack. The scores and the recurrence are those of a loop that quantises the query, takes dot per key and adds each dequantised value to an attention_accumulator, to the bit (tested). Bytes per cached value: 1.0625 (Q8_0), 0.5625 (Q4_0), 0.53125 (MXFP4), against 4 for float.

Errors. Preconditions, asserted: head_dim a multiple of 32 (a compile error otherwise); the block spans required_blocks' size; the rows kv_size floats; the range no longer than the capacity.

Performance. Not benchmarked here: the block dot products are ml/quantize.hpp's, benchmarked there against ggml's scalar loops.

Tests and demos. tests/ml/kv_cache_quant_test.cpp, demos/ml/kv_cache_quant_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <cstddef>, <limits>, <span>, ml/activations.hpp, ml/attention.hpp, ml/kv_cache.hpp, ml/kv_cells.hpp, ml/quantize.hpp, ml/rope.hpp, ml/transformer_config.hpp.

Known issues. ggml accumulates the values in float16 (VKQ16) when V is float16, and in float otherwise; here always in float. The block formats of the quantisation track (K-quants, IQ) plug in once they model quant_block. A quantised K-shift requantises, so each shift adds a rounding of the key (ggml's does too).

Status. Experimental, new in 0.17.0.
