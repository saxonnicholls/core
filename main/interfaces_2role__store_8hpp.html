Detailed Description

snicholls::role_store_interface: the pure virtual twin of role_store, and the adapters both ways.

Overview. When the store is chosen by configuration (Postgres in production, the reference in a test), code holds a role_store_interface&. Its pure virtual functions are the operations of the concept role_store (concepts/role_store.hpp, where the contract and role_grant are documented), so the interface models the concept itself. role_store_adapter<S> puts any model behind the interface, owning it (S) or referring to it (S&); role_store_ref is a copyable, non-owning handle on the interface that models the concept.

role_store_adapter<memory_role_store&> adapter{reference}; // borrows
role_store_interface& chosen = adapter;
role_store_ref roles{chosen};
static_cast<void>(roles.grant({alice, "acme", "admin", alice, "bootstrap", now, std::nullopt}, ""));
const auto members = roles.members("acme", now);

Relationships. concepts/role_store.hpp, interfaces/role_store_reference.hpp, interfaces/role_store_conformance.hpp. Group: snicholls-core.

Implementations / variants. role_store_adapter<S> over any model; an implementation above core may derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else; thread safety and exception safety are the wrapped implementation's.

Errors. As the contract.

Performance. One virtual call; the store's own cost dominates.

Tests and demos. tests/interfaces/role_store_test.cpp, demos/interfaces/role_store_demo.cpp.

Dependencies. <string_view>, <type_traits>, <utility>, <vector>, concepts/role_store.hpp.

Known issues. None.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
