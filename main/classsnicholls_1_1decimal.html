Detailed Description

An exact decimal mantissa x 10^exponent, normalised so that equal numbers are equal objects.

Overview

Strikes, tick sizes, lot sizes and multipliers must round-trip exactly through text (CME:LOZ26 P72.5, a tick of 0.0000001); double cannot promise that. A decimal holds up to 18 significant digits and an exponent in [-18, 18]. It is always normalised (the mantissa has no factor of ten; zero is 0 x 10^0), so the defaulted == is numeric equality and the canonical text is unique: "6930", "72.5", "0.0000001", "-5.25", "0" - no exponent notation, no trailing fractional zeros, no "+", no "-0". It is not an arithmetic type: S1 only needs exact identity, ordering and text.

Relationships
  • Used for option strikes and instrument definitions in symbology.
  • Group: snicholls-core.
Implementations and variants

None: a value type.

Guarantees and contracts
  • Trivially copyable, 16 bytes, every member function constexpr and noexcept.
  • parse(to_text(d)) == d for every decimal, and to_text(*parse(t)) == t for every canonical t.
  • <=> is exact (no conversion through double).
Errors

from_parts and parse return std::nullopt for out-of-range or malformed input; nothing throws.

Examples
const auto strike = decimal::parse("72.5"); // canonical text only: no "72.50", no "+"
const auto tick = decimal::parse("0.0000001");
const auto plain = decimal::parse("72.50", decimal_syntax::plain); // venue input may carry trailing zeros
static_assert(*decimal::parse("6930") == *decimal::from_parts(69300, -1)); // normalised: equal numbers are equal
Performance

Parse and format are a single pass over at most 40 characters; not benchmarked in core.

Tests and demos
  • Tests: tests/decimal_test.cpp.
  • Demo: demos/decimal_demo.cpp.
Dependencies

CMake target snicholls::core; standard library only.

Known issues and gotchas
  • to_double() is for display and maths, not identity: 0.1 has no exact double.
