Detailed Description

snicholls::ml::merge_encode: byte-pair encoding driven by a priority over pairs (Hugging Face's and GGUF's merge lists, or SentencePiece's scores), with byte fallback; the merge list as a sorted index; and GPT-2's byte-to-unicode map, built at compile time.

Overview. ml/bpe.hpp is tiktoken's merge, where a token's rank decides. Hugging Face's tokenizer.json and GGUF instead list merges, pairs left right in priority order, and the pair decides: the same bytes may be mergeable from one split and not from another. merge_encode is that algorithm, as Hugging Face's BPE::merge_word and llama.cpp's llm_tokenizer_bpe_session run it:

  1. Optionally, if the whole piece is a token, that token (ignore_merges, which Llama 3's tokenizer sets).
  2. Start from the piece's units: its bytes, or its UTF-8 code points.
  3. Repeatedly merge the adjacent pair with the best priority, the leftmost on ties, until no adjacent pair has one.
  4. Each part that is a token is that token; a part that is not becomes one token per byte (byte fallback: per byte of the part, or with byte_level per byte its code points spell in GPT-2's alphabet).

The priority is the caller's: priority(left, right) -> Key, lower is better, merge_never<Key> for a pair that does not merge. A merge list gives its rank (merge_table); ml/sentencepiece.hpp gives minus the score of the merged piece, which is SentencePiece's BPE. The token lookup and the byte fallback are callables too.

  • Byte-level BPE (GPT-2, Llama 3, Qwen, DeepSeek, ...): the vocabulary is written in GPT-2's byte-to-unicode alphabet, each byte one printable code point. byte_level_encode(piece, out) maps a pre-tokenised piece into that alphabet, merge_encode runs on its code points against the vocabulary as stored, and byte_level_decode maps decoded pieces back to bytes. The two 256- and 324-entry tables are computed by the compiler (byte_to_unicode, unicode_to_byte).
  • SentencePiece-style BPE (Gemma 4, byte_encode = false in llama.cpp): spaces already escaped to U+2581, code points as units, <0xNN> byte tokens for the fallback.
// A vocabulary as a byte-level tokenizer file writes it: " " is "Ġ" (U+0120) in GPT-2's alphabet
constexpr std::array<std::string_view, 7> pieces{"l", "o", "w", "\xC4\xA0", "lo", "low", "\xC4\xA0low"};
constexpr std::array<std::pair<std::string_view, std::string_view>, 3> merges{
{{"l", "o"}, {"lo", "w"}, {"\xC4\xA0", "low"}}}; // in priority order: "l o" first
constexpr auto encode(std::string_view raw)
{
std::array<std::uint32_t, 7> order{};
ml::build_token_index(pieces, order);
const ml::token_trie vocab{pieces, order};
std::array<std::uint32_t, 3> merge_order{};
ml::build_merge_index(merges, merge_order);
const ml::merge_table table{merges, merge_order};
// Map the piece into the alphabet, then merge its code points
std::array<char, 32> mapped{};
const std::size_t m = ml::byte_level_encode(raw, mapped).unwrap();
std::array<std::uint32_t, 16> out{};
std::array<ml::merge_entry<std::uint32_t>, ml::merge_scratch_size(32)> scratch{};
const auto bytes = [&](unsigned char b) { // each byte's own token, by its spelling in the alphabet
char s[4]{};
return vocab.find(std::string_view(s, ml::encode_utf8(ml::byte_to_unicode[b], s)));
};
const std::size_t n = ml::merge_encode(std::string_view(mapped.data(), m), table, vocab, bytes, out, scratch,
{ml::merge_units::code_points, false, true}).unwrap();
return std::pair{out, n};
}
static_assert(encode(" low").second == 1 && encode(" low").first[0] == 6); // l o -> lo, lo w -> low, Ġ low
static_assert(encode("owl").second == 3); // no merge applies: o w l

Relationships. ml/bpe.hpp (tiktoken's rank-of-bytes merge, and bpe_error), ml/pretokenize.hpp (the pieces), ml/token_trie.hpp (a token lookup), ml/sentencepiece.hpp (the score priority). Group: snicholls-core.

Implementations. One: candidate pairs in a binary heap ordered by (priority, start), the pair a part starts being current while the part is alive and its pair still ends where it did; O(n log n) for a piece of n units, so a long piece (Gemma 4's whole lines) costs no more per byte than a short one.

Guarantees. constexpr when the callables are. No allocation: the caller's output and scratch. Pure. Complexity: O(n log n) heap steps and O(n) priority lookups (at most three per merge).

Errors. bpe_error::output_too_small (fewer than piece.size() slots), scratch_too_small (fewer than merge_scratch_size(piece.size()) entries), unknown_bytes (a part is not a token and one of its bytes has no byte token; out may then be partly written). byte_level_encode / byte_level_decode return output_too_small, and byte_level_decode unknown_bytes for a code point outside the alphabet.

Performance. benchmarks/ml/bpe_merges_benchmark.cpp, the Llama 3 fixture's pieces in GPT-2's alphabet (Release, Apple clang 17, Xeon W-3245, 2026-11-19, one thread on a loaded machine (ratios held across runs)): 744,000 pieces/s, against 556,000 for llama.cpp's loop written out (a std::priority_queue of bigrams holding std::strings, merges in a std::map, the vocabulary in a std::unordered_map): 1.3 times faster, with no allocation.

Tests and demos. tests/ml/bpe_merges_test.cpp: against the merge rule written directly on random pieces and merge lists; ties; the pair that decides; both fallbacks; the byte map's 256 entries; the errors. tests/ml/tokenizer_test.cpp: token for token llama.cpp's test vectors (models/ggml-vocab-*.gguf.inp/.out) for GPT-2, Llama 3, Qwen 2 and 3.5, DeepSeek LLM and Coder, Falcon, StarCoder, Refact, Command R, MPT and Gemma 4, on committed subsets of those vocabularies (tests/fixtures/ml/tokenizers/, written by scripts/generate_tokenizer_fixtures.cpp), and decoding back. demos/ml/bpe_merges_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <limits>, <span>, <string_view>, <type_traits>, <utility>, ml/bpe.hpp, ml/unicode.hpp.

Known issues. Code-point units decode strictly (decode_utf8): an invalid byte is a unit of its own. llama.cpp takes a unit's length from its lead byte alone, and its byte-level path replaces an invalid byte by U+FFFD before encoding; Hugging Face cannot be given invalid UTF-8. A piece is at most 2^32 - 1 bytes.

Status. Experimental, new in 0.17.0.
