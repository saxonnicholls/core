Detailed Description

template<class T, std::size_t ChunkSize = 4096>
class snicholls::containers::object_pool< T, ChunkSize >

A pool of T slots allocated in fixed-size chunks, with an intrusive free list.

Overview

Hot paths that create and destroy many small objects (orders, price levels) pay for new/delete and lose locality. The pool allocates ChunkSize slots at a time, hands them out in address order, and recycles released slots last-in first-out through a free list threaded through the slots themselves (no side vector, unlike the reference implementations' ObjectPool). Addresses are stable for the pool's lifetime, so intrusive containers may link the objects.

Use it for many objects of one type whose lifetimes end in arbitrary order. Not for objects that must be returned to the operating system individually (memory is released only by release_all() or destruction).

Relationships
  • Used by limit order books (orders, stop levels and price levels).
  • Module: snicholls-core.
Implementations and variants

None: a single implementation.

Guarantees and contracts
  • Thread safety: none internal; one owner thread.
  • Exception safety: create is strong: if a chunk allocation or T's constructor throws, the pool is unchanged (the slot goes back to the free list). destroy is noexcept when T's destructor is.
  • Complexity: create / destroy O(1); a new chunk every ChunkSize live objects.
  • Ownership and lifetime: the pool owns the memory. Neither release_all() nor the destructor runs the destructors of live objects: destroy them first, or use a trivially destructible T.
  • Invariants: live() == created - destroyed.
Errors

std::bad_alloc when a new chunk cannot be allocated; whatever T's constructor throws.

Examples
snicholls::containers::object_pool<order, 1024> pool;
order* a = pool.create(1, 100); // constructed in place in a pooled slot
order* b = pool.create(2, 200);
pool.destroy(a); // slot goes back to the free list
order* c = pool.create(3, 300); // ... and is reused first
Performance

Measured inside limit order books. In core, benchmarks/containers/object_pool_benchmark.cpp compares it like for like with new / delete, after a fairness check; not yet measured in Release.

Tests and demos
  • Tests: tests/containers/object_pool_test.cpp.
  • Demo: demos/containers/object_pool_demo.cpp.
  • Benchmark: benchmarks/containers/object_pool_benchmark.cpp.
Dependencies

CMake target snicholls::core; standard library only.

Known issues and gotchas
  • Destroying the pool with live non-trivially-destructible objects leaks their resources (their destructors do not run); a debug assertion is deliberately absent so the pool stays usable as an arena.
  • A double destroy(p) is not detected: it runs the destructor twice and puts the slot on the free list twice, so two later create calls return the same address. destroy only objects this pool created, once each.
