Detailed Description

snicholls::deferred_task_pool: the standard-library reference task pool; single-threaded and deterministic.

Overview. Core has no threads, so its pool runs nothing until asked: submit queues a task, and wait_idle runs the queue on the caller's thread, in submission order, until it is empty (tasks a task submits run in the same call). run_one() runs only the next, so a test can step through work and look between tasks; pending() says how many wait. Code written against task_pool_like is tested with it and gets the same interleaving on every run. (ts-moveables' inline_task_pool runs a task inside submit; this one defers it.)

deferred_task_pool pool;
std::string log;
pool.submit([&] { log += 'a'; pool.submit([&] { log += 'c'; }); });
pool.submit([&] { log += 'b'; });
const bool stepped = pool.run_one(); // runs "a" only
const std::string after_one = log;
pool.wait_idle(); // then "b", then "c" that "a" submitted

Relationships. Models task_pool_like (concepts/task_pool.hpp); passes interfaces/task_pool_conformance.hpp directly and through interfaces/task_pool.hpp. Group: snicholls-core.

Implementations / variants. One.

Guarantees. Not thread-safe: submit from the thread that waits. FIFO. A task that throws leaves wait_idle (or run_one) with its exception, already removed from the queue; the rest stay queued. C++17-clean.

Errors. A task's exception, as it is.

Performance. Not benchmarked: a test double (one std::deque push and pop per task).

Tests and demos. tests/interfaces/task_pool_reference_test.cpp, demos/interfaces/task_pool_reference_demo.cpp.

Dependencies. <cstddef>, <deque>, <utility>, interfaces/task_pool.hpp.

Known issues. None.
