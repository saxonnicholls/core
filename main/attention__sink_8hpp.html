Detailed Description

snicholls::ml::attend_with_sink and its backward pass: attention for one query with a learnable sink logit, a virtual key every query attends to that carries no value (gpt-oss), with keys and values of different widths.

Overview. A softmax must give its whole mass to the keys, so a head with nothing to attend to still has to attend somewhere; trained models dump that mass on the first tokens ("attention sinks", Xiao et al., 2023). A learnable sink gives it a place of its own: one logit σ per head, appended to the scaled scores before the softmax and dropped after, so the weights sum to 1 - e^(σ - lse) (gpt-oss's sdpa, QK = cat([QK, S]); W = softmax(QK)[..., :-1]; the sink is not scaled): 

out = Σ_j e^(s_j - lse) v_j,   lse = log(Σ_j e^(s_j) + e^σ),   s_j = scale · q·k_j
  • attend_with_sink(q, keys, values, out, scale, sink): the keys are n rows of q.size() channels, the values n rows of out.size(), so a head whose keys and values differ in width (multi-head latent attention's 192 and 128) is one call. Returns lse, the sink included. A sink of -infinity is plain attention: attend's bits when the widths agree.
  • attend_with_sink_backward(...): writes dq, adds into dkeys and dvalues, and returns the gradient in the sink, -e^(σ - lse) · (dout·out), which the caller adds into the head's sink gradient.
  • attention_sink_weight(lse, sink): the mass the sink took, e^(σ - lse).

The recurrence is attend's (one pass, flash attention's running softmax, the sink folded last), and it is written once, over a score and a value per key given by the caller (detail::attention_sink::forward and backward), so the latent and sparse attentions (ml/latent_attention.hpp, ml/sparse_attention.hpp) are the same code.

StreamingLLM's kept tokens (Xiao et al., 2023, section 3.2) are the other form of a sink: a cache of the first four tokens plus a rolling window, positions counted within the cache. Here that is the caller's choice of keys: the first tokens' rows and the window's (attention_window) passed as one block, or two attention_accumulators merged; re-rotating cached keys to their positions in the cache needs the keys cached before RoPE. It is not a function of its own.

// Keys of 4 channels, values of 2: four positions whose value is their position
constexpr std::size_t dk = 4, dv = 2, n = 4;
const std::array<float, dk> q{0.2f, -0.1f, 0.4f, 0.3f};
std::array<float, n * dk> keys{};
std::array<float, n * dv> values{};
for (std::size_t j = 0; j < n; ++j) {
for (std::size_t i = 0; i < dk; ++i)
keys[j * dk + i] = std::cos(static_cast<float>(j + i));
values[j * dv] = values[j * dv + 1] = static_cast<float>(j);
}
const float scale = 0.5f, sink = 1.0f; // the head's learned sink logit (not scaled)
std::array<float, dv> out{};
const float lse = ml::attend_with_sink(q, keys, values, out, scale, sink);
const float to_sink = ml::attention_sink_weight(lse, sink); // the attention that went nowhere
// Without a sink (-infinity) it is plain attention
std::array<float, dv> plain{};
ml::attend_with_sink(q, keys, values, plain, scale, -std::numeric_limits<float>::infinity());
// Training: the sink has a gradient like any weight
const std::array<float, dv> dout{1.0f, 0.0f};
std::array<float, dk> dq{};
std::array<float, n * dk> dkeys{};
std::array<float, n * dv> dvalues{};
const float dsink = ml::attend_with_sink_backward(q, keys, values, out, dout, lse, scale, sink, dq, dkeys, dvalues);

Relationships. ml/attention.hpp (attend, whose recurrence this is), ml/latent_attention.hpp and ml/sparse_attention.hpp (the users), transformer_config::attention_sinks. Group: snicholls-core.

Implementations. One.

Guarantees. constexpr, no allocation, O(n · (Dk + Dv)). With a sink of -infinity the result is attend's and attend_backward's to the bit (the widths equal). The weights sum to 1 - attention_sink_weight.

Errors. Preconditions, asserted: keys is a whole number of rows of q.size(), values the same number of rows of out.size(); the gradients have their inputs' sizes. A sink of +infinity is not allowed.

Performance. Not benchmarked on its own: attend's loop plus one fold.

Tests and demos. tests/ml/attention_sink_test.cpp, demos/ml/attention_sink_demo.cpp.

Dependencies. <algorithm>, <cassert>, <concepts>, <cstddef>, <limits>, <span>, <type_traits>, ml/attention.hpp, ml/row.hpp.

Known issues. gpt-oss keeps its sinks in bfloat16; here they are the caller's T.

Status. Experimental, new in 0.16.0.

The backward pass of attend_with_sink: writes dq, adds into dkeys and dvalues.

With p_j = e^(s_j - lse) and D = dout·out: dv_j += p_j dout, ds_j = p_j (dout·v_j - D), dq = scale Σ ds_j k_j, dk_j += scale ds_j q, and the sink's gradient -e^(σ - lse) D.
