Detailed Description

The standard-library-only backend: naive, correct, constexpr, deterministic. Models linalg::backend.

Members take the canonical views of linalg::backend (strided, const for inputs) and assume the extents were checked: call them through linalg::lu_factor(linalg::reference, ...) and the other free functions, which check.

◆ relative_tolerance

double snicholls::linalg::reference_backend::relative_tolerance = 1.0

The multiple of pivot_tolerance(n, scale) below which a pivot counts as zero: 1 by default; 0 for LAPACK's rule, where only an exact zero (or a NaN) is a singular pivot.

The default judges a matrix and its multiple by 1e-30 alike but rejects one whose rows or columns differ in scale by more than about 1 / (n epsilon): diag(1e16, 1) is reported singular. Equilibrate such a matrix first (scale its rows and columns so their largest elements are 1, solve, and scale the solution back), or construct the backend with reference_backend{.relative_tolerance = 0}.

A negative value or a NaN is clamped to 0, so no setting lets a zero pivot through (an unclamped -1 made lu_factor accept diag(1, 0) and lu_solve return infinities); infinity reports every matrix singular.

It governs the zero-pivot tests only. LDLT's growth check (ldlt_growth_limit) applies in every mode, including 0: it guards the accuracy of a nonsingular matrix ([[1e-6, 1, 0], [1, 0, 1], [0, 1, 1]] would be solved to 2e-10), which no tolerance on pivots expresses, so LAPACK's rule is not a licence to answer inaccurately. Solve such a matrix with LU.
