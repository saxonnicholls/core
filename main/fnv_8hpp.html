Detailed Description

FNV-1a hashing, usable at compile time and the same on every machine.

Overview. The Fowler-Noll-Vo FNV-1a hash in its 32- and 64-bit forms. It is not cryptographic and not the fastest hash for long inputs, but it is tiny, constexpr, and specified byte for byte, so a hash computed by the compiler on a Mac equals one computed at run time on a Raspberry Pi. That is what the family uses it for: names in compile-time dispatch tables, switch labels on strings, and structural signatures that two machines must agree on.

using namespace snicholls::literals;
// Labels are hashed by the compiler; the subject at run time. Check the string
// too when a collision would matter: here the cases are a fixed known set.
const char* verb(std::string_view method)
{
switch (snicholls::fnv1a_64(method)) {
case "GET"_fnv64: return "read";
case "POST"_fnv64: return "create";
case "DELETE"_fnv64: return "remove";
default: return "unknown";
}
}

fnv1a_64_append folds an integer into a running hash through its little-endian bytes, so composite hashes do not depend on the host's byte order either.

Relationships. hash_combine mixes std::hash values for unordered containers, where only one process needs to agree; use FNV-1a where a hash crosses a process or machine boundary or must be a constant expression.

Guarantees. Every function is constexpr and noexcept. The values are the published FNV-1a test vectors (see the tests), and never change between versions.

Errors. None.

Performance. One multiply and one xor per byte. Not benchmarked; for hashing large buffers at run time use a modern non-cryptographic hash instead.

Tests and demos. tests/hash/fnv_test.cpp, demos/hash/fnv_demo.cpp.

Dependencies. <cstdint>, <string_view>, <type_traits>, and endian.hpp.

Status. Experimental.
