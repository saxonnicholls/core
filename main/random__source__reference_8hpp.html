Detailed Description

Test doubles for random_source_like: test_random_source, deterministic from a seed, and unavailable_random_source, which always fails. Never for secrets..

Overview. Core does no I/O, so it holds no real source of entropy (that is ts-moveables'). What it holds are the doubles every consumer's tests need:

  • test_random_source{seed} writes a deterministic stream (SplitMix64 in counter mode), so a test that generates a key, a nonce or a UUID is reproducible. It is not cryptographic: anyone who knows or guesses the seed knows every byte. Its name says so on purpose.
  • unavailable_random_source{code} always fails with code (default resource_unavailable_try_again, as an unseeded system source reports), so a consumer can prove its own failure path fails closed.
test_random_source a{1234}, b{1234}; // NOT cryptographic: the seed fixes every byte, for reproducible tests
std::array<std::byte, 24> x{}, y{};
(void)a.fill(x.data(), x.size());
(void)b.fill(y.data(), y.size());
unavailable_random_source unseeded; // proves a caller's failure path fails closed

Relationships. concepts/random_source.hpp, interfaces/random_source.hpp, interfaces/random_source_conformance.hpp. Group: snicholls-core.

Implementations. The two doubles above.

Guarantees. fill is noexcept and allocation-free; test_random_source fills any length, chunk by chunk, and the same seed gives the same stream across platforms and runs (little-endian bytes of each 64-bit word). Trivially copyable. C++17-clean.

Errors. unavailable_random_source only.

Performance. Not benchmarked: a test double.

Tests and demos. tests/interfaces/random_source_reference_test.cpp, demos/interfaces/random_source_reference_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <system_error>, concepts/random_source.hpp.

Known issues. None: it is a test double by design.

Status. New in 0.27.0.
