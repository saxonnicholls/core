Detailed Description

snicholls::ml ternary blocks: ggml's TQ1_0 (1.6875 bits per weight, five trits a byte) and TQ2_0 (2.0625 bits, four 2-bit codes a byte), byte for byte as ggml lays them out, with quantisation, dequantisation and the dot products with Q8_K activations, all constexpr.

Overview. A ternary model (BitNet b1.58, TriLMs) stores each weight as -1, 0 or +1 times one scale per 256. ggml packs those trits two ways:

Block Elements Scale Codes Bytes Bits per weight
block_tq1_0 256 float16 amax five trits a byte in qs (240 weights), four in qh (16) 54 1.6875
block_tq2_0 256 float16 amax q + 1 in 2 bits, four a byte 66 2.0625

A trit is lroundf(x / amax) + 1 in {0, 1, 2}. TQ1_0 writes five of them as the base-3 number t0 t1 t2 t3 t4 scaled to a byte, ceil(n · 256 / 243), so trit k comes back as ((uint8_t)(b · 3^k) · 3) >> 8 with no division; ternary_pow3 is that table, built by the compiler. The 240 weights of qs run in strides: byte m of the first 32 holds weights m, m + 32, ..., m + 128, byte 32 + m of the last 16 holds weights 160 + m, 176 + m, ..., 224 + m, and qh[j] holds 240 + j, 244 + j, 248 + j, 252 + j (four trits, shifted one place up). TQ2_0's byte 32 g + m holds weights 128 g + m + 32 l in bits 2l.

// 512 weights already ternary times 1/32 (as a BitNet b1.58 checkpoint holds them), and 512 activations
std::array<float, 512> w{}, a{};
for (std::size_t i = 0; i < 512; ++i) {
w[i] = 0.03125f * float(int(i * 7 % 5 % 3) - 1);
a[i] = std::sin(0.1f * float(i));
}
// Two layouts of the same trits: five a byte, or four
std::array<ml::block_tq1_0, 2> t1{};
std::array<ml::block_tq2_0, 2> t2{};
ml::quantize(w, std::span(t1));
ml::quantize(w, std::span(t2));
// The activations as Q8_K, then integer dot products with one multiplication per 256 weights
std::array<ml::block_q8_k, 2> a8{};
ml::quantize(a, std::span(a8));
const float d1 = ml::dot(std::span<const ml::block_tq1_0>(t1), std::span<const ml::block_q8_k>(a8));
const float d2 = ml::dot(std::span<const ml::block_tq2_0>(t2), std::span<const ml::block_q8_k>(a8));
  • quantize_row(x, importance, blocks): ggml's quantize_tq1_0 / quantize_tq2_0 (which ignore the importance matrix, as here);
  • dequantize_row(blocks, x): dequantize_row_tq*_0;
  • dot(weights, activations): ggml_vec_dot_tq*_0_q8_K_generic, an integer sum per block and one multiplication by the scales.

Relationships. ml/quantize.hpp (the contract: quantized_block, block_traits, quantize, dequantize, block_q8_k); ml/bitnet.hpp (BitNet's own absmean ternary quantisation and its I2_S, TL1 and TL2 layouts). Group: snicholls-core.

Implementations. One per block, the scalar reference.

Guarantees. constexpr, no allocation, linear in the row. The blocks are trivially copyable, ggml's sizes, no padding (static_asserted). Bytes and dot products equal ggml's on every row of the committed fixture (tests/fixtures/ml/quant_ternary_fixture.txt, from scripts/generate_quant_ternary_fixture.cpp built against ggml, llama.cpp 39039aa).

Errors. Preconditions, asserted: the row has 256 · blocks.size() numbers; the rows of a dot product have the same number of blocks. NaN and infinity are not representable; the result is ggml's on x86 (see Known issues).

Performance. Against ggml's scalar loops written by hand (benchmarks/ml/quant_ternary_benchmark.cpp); numbers in BENCHMARKS.md.

Tests and demos. tests/ml/quant_ternary_test.cpp, demos/ml/quant_ternary_demo.cpp.

Dependencies. <array>, <cassert>, <cstddef>, <cstdint>, <limits>, <span>, ml/quantize.hpp.

Known issues. ggml rounds with lroundf, whose result C leaves undefined for NaN and infinity (an infinite inverse scale meets them when the amax is subnormal); core gives what ggml gives where the fixture was made, whose lroundf saturates (+inf to LONG_MAX, whose low 32 bits make the trit 0; -inf and NaN to LONG_MIN, trit 1). A C library that returns LONG_MIN for every invalid input gives other bytes for such a block in ggml. ggml's TQ2_0 code 3 (never written by its quantiser) decodes to +2, as here.

Status. Experimental, new in 0.17.0.
