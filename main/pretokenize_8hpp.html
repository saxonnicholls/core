Detailed Description

snicholls::ml pre-tokenisers: the split patterns of GPT-2, Llama 3, Qwen 2 and 3.5, GPT-4o (o200k), DeepSeek V3, LLM and Coder, Falcon, StarCoder and Gemma 4 as hand-written constexpr matchers over Unicode categories (no regex engine), the splits that compose them, and the added-token split.

Overview. Before a byte-pair or SentencePiece model sees text, the tokenizer cuts it into pieces with a regular expression, and a merge never crosses a cut. Each pattern here is that expression written out as code that walks UTF-8 and asks ml/unicode.hpp for categories: what the regex engine would match, alternative by alternative and with its backtracking, decided per code point and without allocating.

  • A pattern is a callable p(text, at) -> std::size_t: the length in bytes of its match starting at byte at, or 0. gpt2_pattern, llama3_pattern, qwen2_pattern, qwen35_pattern, gpt4o_pattern, deepseek_v3_pattern and the smaller ones (digits_pattern<Max>, cjk_pattern, newline_pattern, ...) are documented with the expression each one implements.
  • split_isolated(text, pattern, emit) is a regex split that keeps both the matches and the text between them as pieces (Hugging Face's Split with Isolated, and llama.cpp's unicode_regex_split). split_sequence applies several patterns in turn, each to the pieces of the last (Hugging Face's Sequence).
  • pretokenize(kind, text, emit) runs a tokenizer family's whole split by name (pretokenizer), and pretokenizer_for(name) maps GGUF's tokenizer.ggml.pre strings to it.
  • split_added_tokens(text, added, on_text, on_token) cuts out the added tokens (special and user-defined tokens matched in the raw text before anything else), leftmost and longest first.

Every piece is a std::string_view into the caller's text.

// Llama 3's split at compile time: contractions, a lead joined to letters, digits three at a time
constexpr std::size_t pieces(std::string_view text)
{
std::size_t n = 0;
ml::pretokenize(ml::pretokenizer::llama3, text, [&](std::string_view) { ++n; });
return n;
}
static_assert(pieces("I'm 12345 ok!\n") == 7); // I, 'm, " ", 123, 45, " ok", "!\n"

Relationships. ml/unicode.hpp (categories), ml/token_trie.hpp (the added tokens), and the models that consume the pieces: ml/bpe.hpp (tiktoken's merge), ml/bpe_merges.hpp (Hugging Face's and GGUF's merges), ml/sentencepiece.hpp. Group: snicholls-core.

Implementations. The patterns follow the expressions in Hugging Face's tokenizer.json files and tiktoken, not llama.cpp's adaptations: GPT-4o's case classes are the real \p{Lu}/\p{Ll}, where llama.cpp approximates them by "not a-z" and "not A-Z", and the case-insensitive contractions accept U+017F (ſ), which folds to s. Where llama.cpp itself runs a sequence of expressions (DeepSeek, Falcon, StarCoder) the sequence is llama.cpp's, which is what its test vectors were checked against.

Guarantees. constexpr; no allocation; the pieces cover the text exactly, in order, none empty. Complexity: linear in the text for every pattern but gpt4o_pattern, whose case classes backtrack over one letter run (linear in the run). An invalid byte is one unit with U+FFFD's category (other symbol), as llama.cpp decodes it, so a split never stalls.

Errors. pretokenizer_for returns pretokenize_error::unknown_name for a name it does not know.

Performance. benchmarks/ml/pretokenize_benchmark.cpp, the Llama 3 split over the fixtures' texts (Release, Apple clang 17, Xeon W-3245, 2026-11-19, one thread on a loaded machine (ratios held across runs)): 72 MiB/s, against 1.2 MiB/s for std::regex on the same expression over text with every code point collapsed to a byte for its category (llama.cpp's general technique, the collapse included): sixty times faster.

Tests and demos. tests/ml/pretokenize_test.cpp: every pattern against Python's regex module running the original expression, on committed fixtures (tests/fixtures/ml/pretokenize_fixture.txt, written by scripts/generate_pretokenize_fixture.py), and each family's split through the token-for-token tests of tests/ml/tokenizer_test.cpp against llama.cpp's vocabulary test vectors. demos/ml/pretokenize_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <initializer_list>, <span>, <string_view>, snicholls/core/result.hpp, ml/unicode.hpp, ml/token_trie.hpp.

Known issues. Unicode 16.0 categories; Python's regex and llama.cpp may be older, which matters only for code points assigned since. Overlapping added tokens are resolved leftmost-longest, as Hugging Face's Aho-Corasick does; llama.cpp splits by one added token at a time, longest first, which differs only when a shorter one starts earlier inside a longer one's match. Added tokens' lstrip / rstrip are not applied.

Status. Experimental, new in 0.17.0.
