Detailed Description

template<class T>
class snicholls::containers::offset_ptr< T >

A pointer to T held as the byte offset from the offset_ptr itself to its target.

Overview

A linked structure (a list, a tree, a hash table with chains) built inside a memory-mapped file breaks when the file is mapped at another address: every stored pointer still names the old one. An offset_ptr stores target - this instead, which stays correct when the whole region, pointer and target together, is mapped, copied or shared at any address. Dereferencing costs one addition.

Use it for links inside one region that moves as a whole. Not for a pointer from outside the region into it (the offset would change whenever the region moved), and not where an index into an array will do: index_pool's indices are half the size and trivially copyable.

Relationships
  • index_pool, the index-addressed alternative for fixed-size records.
  • ts-moveables' mapped_memory_resource, which allocates the nodes such a structure links.
  • Module: snicholls-core.
Implementations and variants

None.

Guarantees and contracts
  • Thread safety: as a raw pointer.
  • Exception safety: everything is noexcept.
  • Complexity: O(1); get() is one addition and one comparison.
  • Ownership and lifetime: non-owning, as T*.
  • Invariants: get() returns what was last assigned, as long as the offset_ptr and its target have moved together (or not at all).
Errors

None.

Examples
struct node
{
int value;
offset_ptr<node> next; // the distance to the next node, not its address
};
alignas(node) static std::byte region[3 * sizeof(node)];
node* n = reinterpret_cast<node*>(region);
::new (&n[0]) node{1, nullptr};
::new (&n[1]) node{2, nullptr};
::new (&n[2]) node{3, nullptr};
n[0].next = &n[2];
n[2].next = &n[1];
alignas(node) static std::byte moved[sizeof region];
std::memcpy(moved, region, sizeof region); // the region is now somewhere else
int sum = 0, steps = 0;
for (const node* p = std::launder(reinterpret_cast<node*>(moved)); p; p = p->next.get()) {
sum = sum * 10 + p->value;
++steps;
}
Performance

benchmarks/containers/offset_ptr_benchmark.cpp walks a linked list through offset_ptr against the same list through T*, after a fairness check: 4,096 nodes in shuffled order. Release, Apple Clang 17, Intel Xeon W-3245 (macOS 26), 2026-11-12, median of 5 on a loaded machine: 16.4 µs against 13.1 µs, about 0.8 ns more per hop, the null test and the addition on the critical path of a pointer chase.

Dependencies

Standard library only.

Known issues and gotchas
  • Not trivially copyable: copying one recomputes the offset for its new address, which is what makes a = b work. A byte-for-byte copy of a whole region keeps every link; a byte-for-byte copy of one object to somewhere else does not.
  • Null is stored as offset 1 (a one-byte offset cannot name an aligned T other than a char), so an offset_ptr<char> cannot point at the byte just past itself; 0 means "points at itself", which is allowed.
  • Not constexpr: the offset is computed from integer addresses.
  • Both addresses must be in one object or one mapping for the distance to mean anything, which is how it is used.
