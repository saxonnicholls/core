Detailed Description

snicholls::time_zone_interface: the pure virtual twin of time_zone, and the adapters both ways.

Overview. When the zone is chosen at run time (by an exchange, from a user's settings, from the IANA database), code holds a time_zone_interface& (crtp's interface of the same name). Its pure virtual functions are the operations of the concept time_zone (concepts/time_zone.hpp, where the contract and the conversions are documented), so the interface models the concept and from_local, to_local and offset_at take it as they are. time_zone_adapter<Z> puts any model behind the interface, owning it (Z) or referring to it (Z&); time_zone_ref is a copyable, non-owning handle on the interface that models the concept.

std::unique_ptr<time_zone_interface> chosen = std::make_unique<time_zone_adapter<two_rule_zone>>(sydney_like_zone());
time_zone_ref zone{*chosen}; // copyable, models the concept
const utc_s t{sys_days{year{2026} / January / 15}};
const auto local = to_local(zone, t);

Relationships. concepts/time_zone.hpp, interfaces/time_zone_reference.hpp, interfaces/time_zone_conformance.hpp. Group: snicholls-core.

Implementations / variants. time_zone_adapter<Z> over any model; a database's zones above core derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else. A zone is immutable once made, so a shared one may be read from any thread when the implementation is.

Errors. None from the members.

Performance. One virtual call; not benchmarked.

Tests and demos. tests/interfaces/time_zone_test.cpp (the kit through every form), demos/interfaces/time_zone_demo.cpp.

Dependencies. <chrono>, <string_view>, <type_traits>, <utility>, concepts/time_zone.hpp.

Known issues. None.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
