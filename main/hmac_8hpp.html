Detailed Description

HMAC (RFC 2104, FIPS 198-1) over any hash in core, usable at compile time.

Overview. hmac<H> is the keyed message authentication code built from a hash H: H((K ^ opad) || H((K ^ ipad) || message)), with a key longer than H's block first hashed. It is the MAC to reach for when a protocol names one (JWT's HS256, AWS Signature V4, TOTP, webhooks' signatures, BIP-32's HMAC-SHA512("Bitcoin seed", seed)) and the building block of hkdf_* and pbkdf2_hmac (hash/kdf.hpp). The incremental interface of the hashes (update, finish), a one-shot mac, and verify, which compares in constant time.

// A webhook carries HMAC-SHA256(secret, body); check it in constant time, never with ==
bool authentic(const std::string& secret, const std::string& body, const snicholls::digest<32>& signature)
{
return snicholls::hmac<snicholls::sha256>::verify(secret, body, signature);
}
// RFC 4231 test case 2, at compile time
static_assert(snicholls::hmac<snicholls::sha256>::mac("Jefe", "what do ya want for nothing?").hex().view() ==
"5bdcc146bf60754e6a042426089575c75a003f089d2739839dec58b964ec3843");

H is any hash_function: sha256, sha512, sha1 (HMAC-SHA1 is still sound: HMAC does not need collision resistance), sha3_256 (block size the rate, as FIPS 202 specifies), blake2b<N>. BLAKE2 and BLAKE3 have keyed modes of their own that are cheaper than HMAC around them.

Relationships. hash_function, digest<N> (hash/digest.hpp); constant_time_equal and secure_wipe (hash/secure.hpp); hkdf_extract, hkdf_expand, pbkdf2_hmac (hash/kdf.hpp), scrypt (hash/scrypt.hpp). Group: snicholls-core.

Guarantees. Every member is constexpr and noexcept; no allocation. The padded key is wiped with secure_wipe once the two inner states are primed; the object then holds two hash states and no key. An hmac<H> is a copyable value: copying a keyed object and updating the copy reuses the key's two compressions, which is how PBKDF2 runs at two compressions per iteration. verify takes time independent of where the tags differ.

Errors. None. Any key length is accepted, including empty (RFC 2104).

Examples. Above; demos/hash/hmac_demo.cpp.

Performance. Two hash computations, and two extra compressions for the key, which a copied object does not repeat. Benchmarked through PBKDF2 in benchmarks/hash/kdf_benchmark.cpp (see hash/kdf.hpp): at the hand loop's speed.

Tests and demos. tests/hash/hmac_test.cpp (RFC 4231's test cases 1 to 7 for SHA-224/256/384/512, RFC 2202 for SHA-1, Python's hmac on random keys and lengths over SHA-1, SHA-2 and SHA-3, every split, verify), demos/hash/hmac_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <span>, hash/digest.hpp, hash/secure.hpp.

Known issues. None known.

Status. New in 0.17.0. Experimental.
