Detailed Description

snicholls::holiday_calendar_interface: the pure virtual twin of the holiday_calendar concept, and the adapters between them.

Overview. A server holds one calendar per market, loaded at run time, and picks one per trade. holiday_calendar_interface is is_business_day behind a virtual call; holiday_calendar_model<T> adapts any holiday_calendar to it, and the interface models the concept, so the adjustment rules of finance/business_day.hpp accept either form.

struct set_calendar { // a market's holidays, loaded at start-up
std::set<sys_days> holidays;
bool is_business_day(sys_days d) const noexcept { return snicholls::is_business_day(d) && !holidays.contains(d); }
};
std::map<std::string, std::unique_ptr<holiday_calendar_interface>> calendars;
calendars["XLON"] = std::make_unique<holiday_calendar_model<set_calendar>>(set_calendar{{sys_days{2026y / December / 25d}, sys_days{2026y / December / 28d}}});
calendars["weekends"] = std::make_unique<holiday_calendar_model<finance::weekend_calendar>>();
const holiday_calendar_interface& london = *calendars.at("XLON"); // from the trade's terms
const auto pay = finance::adjust(sys_days{2026y / December / 25d}, finance::business_day_convention::modified_following, london);

Relationships. concepts/holiday_calendar.hpp, finance/business_day.hpp, interfaces/holiday_calendar_conformance.hpp. Group: snicholls-core.

Implementations. holiday_calendar_model<T> for every holiday_calendar T.

Guarantees. is_business_day is noexcept: a calendar answers from data it already holds. The adapter holds its T by value and is usable in constant expressions when T is.

Errors. None.

Performance. One virtual call; not benchmarked.

Tests and demos. tests/interfaces/holiday_calendar_test.cpp, demos/interfaces/holiday_calendar_demo.cpp.

Dependencies. <chrono>, <utility>, concepts/holiday_calendar.hpp.

Known issues. The adapted calendar's is_business_day should not throw: the interface's is noexcept, so an exception would end the program.

Status. New in 0.23.0.
