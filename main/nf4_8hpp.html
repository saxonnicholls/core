Detailed Description

snicholls::ml QLoRA's 4-bit NormalFloat weights with double quantisation: quantise, dequantise, and products that dequantise on the fly.

Overview. QLoRA (Dettmers et al. 2023) fine-tunes a model whose frozen base weights are stored in 4 bits and read back to the compute type as they are used, with LoRA adapters trained in full precision beside them (ml/lora.hpp; TRAINING.md T13). Its storage, nf4_weights, is three levels:

  • NormalFloat4 codes, two a byte (the first of a pair in the high nibble). Each code indexes nf4_values, the sixteen values of the paper's appendix E: the quantiles of a standard normal, asymmetric so that 0 is exact (its eq. 4), normalised to [-1, 1]. A block of 64 weights shares one scale, its absolute maximum c2, and a weight is nf4_values[code] · c2. A weight's code is the value nearest w / c2, ties to the lower code.
  • Double quantisation of the block scales (the paper's §3): their mean is subtracted, and each group of 256 block scales is stored as 8-bit floats (OCP E4M3, float8_e4m3) of (c2 - mean) / s1, s1 = max|c2 - mean| / 448 the group's float scale. The scales cost 8.5 bits a block of 64 instead of 32, about 0.13 bits a weight.
  • The mean, one float.

linear(nf4, x, y, bias), linear_backward_input and the sequence forms dequantise each weight as they read it, in float, and add the products in the order of a dense linear: a product through nf4_weights equals linear through the dense matrix nf4_dequantize gives, to the bit. There is no linear_backward into NF4 weights: they are frozen (TRAINING.md T4).

// Quantise: 4-bit codes, one E4M3 scale per 64 weights, one float per 256 scales, and their mean
std::vector<std::uint8_t> codes(ml::nf4_code_bytes(n));
std::vector<ml::float8_e4m3> block_scales(ml::nf4_block_count(n));
std::vector<float> group_scales(ml::nf4_group_count(n));
const float mean = ml::nf4_quantize(w, codes, block_scales, group_scales);
const ml::nf4_weights q{codes, block_scales, group_scales, mean, rows, cols};
// y = W x, each weight dequantised as it is read
std::vector<float> x(cols, 0.5f), y(rows);
ml::linear(q, ml::prepare_input<cols>(q, x), y);

Relationships. ml/lora.hpp (the adapters over a frozen base), ml/linear.hpp (the same prepare_input / linear seam), ml/quantize.hpp (ggml's formats, for inference), ml/minifloat.hpp (float8_e4m3). Group: snicholls-core.

Implementations. One, on the host. A device library overloads linear_sequence and linear_sequence_backward_input for its backend (TRAINING.md T9).

Guarantees. constexpr, no allocation, noexcept. Quantising is linear in the weights (three passes); a product is one multiply and one add a weight, plus one scale a block.

Errors. Preconditions, asserted: cols is a multiple of 64 (a block never crosses a row); the spans have the sizes nf4_code_bytes, nf4_block_count and nf4_group_count give.

Definitions. nf4_values checked digit for digit against the paper's appendix E (arXiv 2305.14314), and reproduced in the tests from the normal quantiles by bitsandbytes' construction (recalled: offset 0.9677083, 8 and 9 quantiles, normalised). The block of 64, the double quantisation to 8-bit floats in groups of 256 after subtracting the mean: checked against the paper. Not checked, and not bitsandbytes' bytes: bitsandbytes stores the second level in its own dynamic 8-bit code, where core uses E4M3, and its nibble order is recalled.

Performance. linear through NF4 against the same loop by hand over the same bytes, after a bit-for-bit check (benchmarks/ml/nf4_benchmark.cpp), 1024 x 1024, one row: 2.5 ms against 2.7 ms, level; the dense product of the dequantised matrix takes 1.2 ms, so dequantising on the fly costs about twice the product on the host (Xeon W-3245, -O2, Apple clang 17, 2026-11-19, one thread, CPU time, load average about 100: a record, not a quiet-machine figure). It saves memory, not time; a device dequantises in registers.

Tests and demos. tests/ml/nf4_test.cpp, demos/ml/nf4_demo.cpp.

Dependencies. <array>, <cassert>, <concepts>, <cstddef>, <cstdint>, <ranges>, <span>, ml/minifloat.hpp, ml/row.hpp.

Known issues. The products are in float, as QLoRA computes in a 16-bit type; a bfloat16 compute path is the caller's, after nf4_dequantize.

Status. Experimental, new in 0.16.0.
