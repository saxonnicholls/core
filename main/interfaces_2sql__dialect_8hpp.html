Detailed Description

snicholls::sql_dialect_interface: the pure virtual twin of sql_dialect, and the adapters both ways.

Overview. When the engine is chosen at run time (configuration names SQLite or PostgreSQL), code holds a const sql_dialect_interface&, which a connection returns from dialect(). Its pure virtual functions are the operations of the concept sql_dialect (concepts/sql_dialect.hpp, where the contract and the generators are documented), so the interface models the concept and the generators take it as they are. sql_dialect_adapter<D> puts any model behind the interface, owning it (D) or referring to it (const D&); sql_dialect_ref is a copyable, non-owning handle on the interface that models the concept.

const bool use_postgres = argc < 2; // configuration, at run time
std::unique_ptr<sql_dialect_interface> d;
if (use_postgres)
d = std::make_unique<sql_dialect_adapter<postgres_dialect>>(postgres_dialect{});
else
d = std::make_unique<sql_dialect_adapter<sqlite_dialect>>(sqlite_dialect{});
const sql_dialect_ref handle{*d}; // copyable, models the concept
const auto insert = sql_insert(handle, sql_table{"t", {{"k", sql_type::uuid, false}}, {0}, false});

Relationships. concepts/sql_dialect.hpp, interfaces/sql_dialect_reference.hpp, interfaces/sql_dialect_conformance.hpp, interfaces/sql_connection.hpp. Group: snicholls-core.

Implementations / variants. sql_dialect_adapter<D> over any model; crtp's dialects may derive from the interface directly.

Guarantees. The adapters add one virtual call; dialects are immutable, so a shared one is safe from any thread.

Errors. None from the members.

Performance. One virtual call; not benchmarked.
