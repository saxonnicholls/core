Detailed Description

snicholls::tracking::pda_weights, pda_update and jpda_marginals: probabilistic data association, which updates a track with every detection weighted by the chance it is the target's, rather than committing to one.

Overview. In clutter, or where targets cross, committing each track to its nearest detection swaps identities. Probabilistic data association keeps every hypothesis, weighted.

  • pda_weights(log_likelihoods, pd, pg, clutter_density, weights): one track's hypothesis weights, Stone Soup's PDAHypothesiser normalised. Missed detection gets 1 - P_D P_G; detection i gets P_D N(νᵢ; 0, S) / λ. A detection outside the gate has log-likelihood -∞ and weight 0.
  • pda_update(prediction, mp, innovations, weights): the moment-matched posterior (Bar-Shalom and Tse): x + K ν̄, and β₀ P + (1 - β₀) (P - K S Kᵀ) + K (Σ βᵢ νᵢ νᵢᵀ - ν̄ ν̄ᵀ) Kᵀ, with ν̄ = Σ βᵢ νᵢ.
  • jpda_marginals<MaxTracks, MaxDetections>(likelihoods, tracks, detections, marginals): joint PDA over a cluster. It enumerates every feasible joint event (each detection to at most one track), weights each by the product of its tracks' entries, and returns each track's marginal probability of each detection (column 0: missed), Stone Soup's JPDA. The enumeration is exact and grows exponentially, so it is for small clusters.
  • gate_volume(threshold, S): the volume of the gate {ν : νᵀ S⁻¹ ν ≤ γ}, for a clutter density from a count.
// A constant-velocity track (x, vx, y, vy) and a sensor that measures position
const tr::gaussian<double, 4> prediction{vec4{{0, 1, 0, 1}}, mat4{{2, 0.3, 0, 0, 0.3, 0.5, 0, 0, 0, 0, 2, 0.3, 0, 0, 0.3, 0.5}}};
const tr::linear_gaussian<double, 4, std::array{0, 2}> sensor{mat2{{0.5, 0, 0, 0.5}}};
const auto mp = tr::predict_measurement(prediction, sensor);
// Clutter: 2 false alarms expected inside the 99% gate, so a density of 2 / gate volume
const double gate = tr::gate_threshold(0.99, 2);
const double volume = tr::gate_volume(gate, mp.covariance).unwrap();
const double clutter_density = 2 / volume;
// Four detections: three inside the gate, one far outside (log-likelihood -∞, weight 0)
const std::array<vec2, 4> detections{vec2{{0.4, -0.3}}, vec2{{-1.5, 1.0}}, vec2{{2.0, 2.2}}, vec2{{30.0, -25.0}}};
std::array<vec2, 4> innovations{};
std::array<double, 4> log_likelihoods{};
for (std::size_t i = 0; i < detections.size(); ++i) {
innovations[i] = detections[i] - mp.mean;
const double d2 = tr::squared_mahalanobis(innovations[i], mp.covariance).unwrap();
log_likelihoods[i] = tr::in_gate(d2, gate) ? tr::log_likelihood(innovations[i], mp.covariance).unwrap() : -std::numeric_limits<double>::infinity();
}
std::array<double, 5> weights{}; // missed detection first
const bool formed = tr::pda_weights<double>(log_likelihoods, 0.9, 0.99, clutter_density, weights);
const auto posterior = tr::pda_update<double, 4, 2>(prediction, mp, innovations, weights);
// Two tracks, two detections: rows (missed, detection 1, detection 2), unnormalised; track 1 cannot see detection 1
const std::array<double, 6> likelihoods{0.1, 2.0, 1.0,
0.1, 0.0, 3.0};
std::array<double, 6> marginals{};
const bool joint = tr::jpda_marginals<4, 4, double>(likelihoods, 2, 2, marginals);

Relationships. tracking/gaussian.hpp (log_likelihood), tracking/kalman.hpp (measurement_prediction, kalman_update gives each detection's log_likelihood and innovation), combinatorics/assignment.hpp (the hard-decision alternative). Group: snicholls-core.

Implementations. Weights are formed in log space and normalised by log_sum_exp. jpda_marginals walks the joint events depth first, iteratively, with a stack of partial products; a detection already used is skipped, and so is a zero entry.

Guarantees. constexpr, noexcept for the standard floating-point types, no allocation, no recursion. Weights sum to 1 and each track's marginals sum to 1.

Errors. pda_weights returns false when weights is not one longer than the likelihoods or no hypothesis has weight. pda_update returns linalg::error::not_positive_definite for an S without a Cholesky factor. jpda_marginals returns false for sizes beyond its maxima, spans too short, or no feasible event with weight.

Performance. Not benchmarked. jpda_marginals costs the number of feasible joint events, which for t tracks all gating d detections is Σₖ C(t, k) d! / (d - k)!.

Tests and demos. tests/tracking/association_test.cpp, demos/tracking/association_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <limits>, <numbers>, <span>, linalg/fixed.hpp, math/constexpr_math.hpp, result.hpp, stats/resample.hpp (log_sum_exp), tracking/gaussian.hpp, tracking/kalman.hpp.

Known issues. Loopy belief propagation and the efficient hypothesis management tree (Stone Soup's JPDAwithLBP and JPDAwithEHM) are not here yet.

Status. Experimental, new in 0.19.0.
