Detailed Description

template<class V, class E>
class snicholls::result_throws::result< V, E >

Rust's Result<V, E>: either a success value V or an error E, with zero runtime overhead.

Overview

A function that can fail returns snicholls::result<V, E>: return snicholls::ok(v); or return snicholls::err(e);. The caller tests it (is_ok, if (r)), transforms it (map, and_then, or_else ...), propagates it with SNICHOLLS_TRY (Rust's ?), or unwraps it (unwrap, expect, unwrap_or ...). The whole of Rust's Result API is here, in Rust's names (and_ / or_ because and / or are C++ keywords), with ref-qualified overloads so values move out without copies. snicholls::result<void, E> is the Result<(), E> specialisation.

Use it for expected failures that the caller should handle: parsing, validation, lookups, I/O. Use exceptions for failures nobody nearby can handle, and try_invoke to turn one into the other at a boundary. Errors are any object type: an enum or std::error_code costs nothing; snicholls::traced<E> (snicholls/core/traced.hpp) adds a source location, a context chain, fields and an optional stack trace for logging, paying only on the error path.

Relationships
  • snicholls::ok, snicholls::err, snicholls::ok_t, snicholls::err_t: the constructors (Rust's Ok / Err).
  • snicholls::traced, snicholls::error_sink: detailed errors and logging (snicholls/core/traced.hpp); context(), with_field(), with_stack(), trace() and log_err() here are their entry points.
  • snicholls::try_invoke, snicholls::result_from_exceptions, rethrow(), value_or_throw(), snicholls::throw_error, snicholls::error_exception: the bridge to and from exceptions.
  • SNICHOLLS_TRY, SNICHOLLS_TRY_ASSIGN, SNICHOLLS_TRY_VOID: propagation.
  • std::expected (C++23): to_expected() and a constructor, under __cpp_lib_expected.
  • Module: snicholls-core.
Implementations and variants

Guarantees and contracts
  • Layout: no allocation, no virtual function, no RTTI. Trivially copyable / destructible (and each special member trivial) exactly when it is for both V and E. Proven by static_asserts in tests/result_test.cpp.
  • noexcept exactly when the operations performed are (copies, moves, the callables). unwrap, expect, unwrap_err and expect_err are noexcept under SNICHOLLS_RESULT_THROW=0, where they terminate instead.
  • constexpr: every operation except the error paths of unwrap/expect/rethrow.
  • Assignment between the two states gives the strong guarantee (std::expected's rule); it exists when V or E is nothrow move constructible.
  • Not thread-safe beyond the usual value-type rules: concurrent const access is safe.
  • Precondition
    operator*, operator->, unwrap_unchecked() need is_ok(); unwrap_err_unchecked() needs is_err() (asserted in debug builds, undefined behaviour otherwise, as in Rust).
    Errors
  • unwrap() / expect(msg) on an error throw snicholls::bad_result_access<E> (bad_result_access<void> when E is not copyable); unwrap_err() / expect_err(msg) on a success throw snicholls::bad_result_access<void>. With SNICHOLLS_RESULT_THROW=0 each prints its message and calls std::terminate.
  • rethrow(), rethrow_if_err(), value_or_throw() throw the error as its own exception (snicholls::throw_error).
  • Everything else throws only what the callables and the copies / moves of V and E throw.
Examples
enum class price_error : std::uint8_t
{
empty = 1,
not_a_number = 2,
negative = 3,
};
// A function that can fail returns snicholls::result: ok(value) or err(error). No allocation, no exception.
snicholls::result<double, price_error> parse_price(std::string_view text) noexcept
{
if (text.empty())
return snicholls::err(price_error::empty);
double value = 0;
double scale = 0;
for (const char c : text)
{
if (c == '.' && scale == 0)
scale = 1;
else if (c >= '0' && c <= '9')
{
value = value * 10 + (c - '0');
scale *= 10;
}
else
return snicholls::err(c == '-' ? price_error::negative : price_error::not_a_number);
}
return snicholls::ok(scale > 0 ? value / scale : value);
}
// SNICHOLLS_TRY is Rust's `?`: the value, or return the error from this function.
snicholls::result<double, price_error> mid_price(std::string_view bid, std::string_view ask)
{
#if SNICHOLLS_RESULT_HAS_STATEMENT_EXPRESSIONS
const double b = SNICHOLLS_TRY(parse_price(bid));
const double a = SNICHOLLS_TRY(parse_price(ask));
#else
SNICHOLLS_TRY_ASSIGN(const double b, parse_price(bid)); // the portable statement form
SNICHOLLS_TRY_ASSIGN(const double a, parse_price(ask));
#endif
return snicholls::ok((b + a) / 2);
}
// result<void, E> is Rust's Result<(), E>; SNICHOLLS_TRY_VOID discards the value.
snicholls::result<void, price_error> validate_quote(std::string_view bid, std::string_view ask)
{
SNICHOLLS_TRY_VOID(parse_price(bid));
SNICHOLLS_TRY_VOID(parse_price(ask));
return snicholls::ok();
}
// unwrap() on an error throws snicholls::bad_result_access<E> (or terminates with SNICHOLLS_RESULT_THROW=0).
try
{
(void)parse_price("abc").expect("price from the feed");
check(false, "expect() of an error throws");
}
catch (const snicholls::bad_result_access<price_error>& e)
{
check(e.error() == price_error::not_a_number, std::string("expect() threw: ") + e.what());
}
// Exceptions in, results out: try_invoke catches into std::exception_ptr ...
auto risky = snicholls::try_invoke([] { return std::stoi("not a number"); });
check(risky.is_err() && snicholls::error_text(risky.unwrap_err()).find("stoi") != std::string::npos, "try_invoke caught std::invalid_argument");
// ... and rethrow() throws the original exception again.
try
{
risky.rethrow();
}
catch (const std::invalid_argument&)
{
check(true, "rethrow() threw the original std::invalid_argument");
}
// An exception mapped to your own error type.
auto mapped = snicholls::result_from_exceptions([] { return std::stoi("99999999999999999999"); },
[](std::exception_ptr) { return std::make_error_code(std::errc::result_out_of_range); });
check(mapped == snicholls::err(std::make_error_code(std::errc::result_out_of_range)), "result_from_exceptions with a map");

Known issues and gotchas
  • SNICHOLLS_TRY returns a proxy that converts to the enclosing function's snicholls::result: the function needs a declared result return type (not auto).
  • SNICHOLLS_TRY(expr) is a GNU statement expression (GCC, Clang); elsewhere use SNICHOLLS_TRY_ASSIGN / SNICHOLLS_TRY_VOID.
  • There is no implicit construction from a bare V or E (as some Result types have): write snicholls::ok(v) / snicholls::err(e). A result whose V and E are similar types (result<double, int>) is never ambiguous.
  • rethrow() of a snicholls::traced<X> throws X: the context chain is not in the exception. Log first (log_err).
  • Equality and hashing of snicholls::traced errors use the inner error only (the context is diagnostics).
  • The && overloads that hand out the value or the error return it by value, moved out (std::move(r).unwrap() is a V, not a V&&), so for (auto x : make().unwrap()) and const auto& v = make().unwrap(); are safe. On an lvalue they return references, as before.
  • A niche result (snicholls::result_niche) reads a moved-from V that equals the niche value as an error.
