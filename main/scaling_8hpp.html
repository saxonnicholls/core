Detailed Description

snicholls::optim::ruiz_equilibrate: modified Ruiz equilibration of a quadratic program's data, as OSQP does it, and of a single matrix, as SCS does it, with the scaling and unscaling of solutions, all constexpr, in place.

Overview. First-order and Krylov solvers converge at a rate set by the conditioning of their data. A portfolio QP mixes weights near 1e-2, notionals near 1e8 and risk numbers near 1e-6; left alone, ADMM crawls. Equilibration rescales rows and columns so that every row and column of the KKT matrix has ∞-norm near 1 (Ruiz, "A scaling algorithm to equilibrate both rows and columns norms in matrices", 2001), which is cheap (a few passes over the non-zeros) and changes neither the solution nor the sparsity.

The quadratic program, the form of OSQP: 

minimise ½ xᵀ P x + qᵀ x   subject to   l ≤ A x ≤ u,     P (n x n) symmetric PSD, A (m x n)

is replaced by its scaled form, with D = diag(d) (variables, n), E = diag(e) (constraints, m) and the cost scale c > 0: 

P̄ = c D P D,   q̄ = c D q,   Ā = E A D,   l̄ = E l,   ū = E u,   x = D x̄,   y = E ȳ / c,   z = A x = E⁻¹ z̄

where y is the multiplier of the constraints with the sign of P x + q + Aᵀ y = 0, and the scaled objective is c times the original. ruiz_equilibrate(P, A, q, d, e, c, iterations, work) computes d, e, c and rewrites P, A and q in place (P as its upper triangle); scale_bounds rewrites l and u. After solving the scaled problem, unscale_solution (or unscale_primal, unscale_dual, unscale_constraint, unscale_objective) gives the original's; scale_primal and scale_dual take a warm start the other way; unscale_data restores P, A and q.

Each iteration (all from the current, already scaled, data):

  1. The KKT matrix [P Aᵀ; A 0]'s column ∞-norms: δⱼ = max(‖P₍:,ⱼ₎‖∞, ‖A₍:,ⱼ₎‖∞) for the variables (P's full symmetric column), εᵢ = ‖A₍ᵢ,:₎‖∞ for the constraints.
  2. Each norm limited (limit(v) = 1 if v < min_scaling, max_scaling if v > max_scaling, else v), then δ̂ⱼ = 1 / sqrt(limit(δⱼ)), ε̂ᵢ = 1 / sqrt(limit(εᵢ)) (rounded to the nearest power of two in the geometric sense when power_of_two).
  3. P ← Δ̂ P Δ̂, A ← Ê A Δ̂, q ← Δ̂ q, d ← Δ̂ d, e ← Ê e.
  4. When scale_cost: γ = 1 / limit(max(mean ‖P₍:,ⱼ₎‖∞, limit(‖q‖∞))) (rounded likewise), P ← γ P, q ← γ q, c ← γ c.

d, e and c start at 1. A zero row or column (norm below min_scaling) is left unscaled. This is OSQP's procedure (Stellato et al., "OSQP: an operator splitting solver for quadratic programs", 2020, section 5.1), and its defaults: 10 iterations, limits 1e-4 and 1e4.

ruiz_equilibrate_rectangular(A, r, s, iterations, work) is the same iteration for one m x n matrix, rows and columns at once: Ā = R A S, R = diag(r) (rows, m), S = diag(s) (columns, n), r̂ᵢ = 1 / sqrt(limit(‖A₍ᵢ,:₎‖∞)), ŝⱼ = 1 / sqrt(limit(‖A₍:,ⱼ₎‖∞)) from the current matrix each iteration. It is the equilibration SCS applies to its data matrix (O'Donoghue et al., 2016, section 5; SCS's D is r, its E is s), and what a Krylov method on AᵀA wants. For a system A x = b: solve Ā x̄ = R b, then x = S x̄.

// minimise ½ (1e4 x₁² + 1e-2 x₂²) subject to x₁ + 1e3 x₂ = 1 (l = u = 1)
std::array<std::int32_t, 3> pp{0, 1, 2}, pi{0, 1}, ap{0, 1, 2}, ai{0, 0};
std::array<double, 2> pv{1e4, 1e-2}, av{1, 1e3}, q{0, 0};
const sp::csc_view<double> p{2, 2, pp, pi, pv}, a{1, 2, ap, ai, av};
const auto before = kkt_norms<2, 1>(p, a);
std::array<double, 2> d{};
std::array<double, 1> e{}, l{1}, u{1};
std::array<double, op::ruiz_workspace(2, 1)> work{};
double c = 0;
if (!op::ruiz_equilibrate(p, a, q, d, e, c, 10, work))
return false;
op::scale_bounds(std::span<const double>(e), l, u);
const auto after = kkt_norms<2, 1>(p, a);
// Solve the scaled KKT system [P̄ Āᵀ; Ā 0] [x̄; ȳ] = [-q̄; l̄] (symmetric indefinite) by MINRES
const std::array<double, 9> kkt{pv[0], 0, av[0], 0, pv[1], av[1], av[0], av[1], 0};
const std::array<double, 3> rhs{-q[0], -q[1], l[0]};
std::array<double, 3> sol{};
std::array<double, la::minres_workspace(3)> mw{};
const auto r = la::minres(la::make_dense_operator(std::span<const double>(kkt), 3, 3), rhs, sol, mw, {1e-14});
// Back to the original problem: x = D x̄, y = E ȳ / c
std::array<double, 2> x{sol[0], sol[1]};
std::array<double, 1> y{sol[2]};
op::unscale_solution(std::span<const double>(d), e, c, x, y);

Relationships. sparse/csc.hpp (scale, column_inf_norms, row_inf_norms, symmetric_upper_inf_norms), linalg/krylov.hpp (solve after equilibrating), math/constexpr_math.hpp (sqrt). Group: snicholls-core.

Implementations. Plain passes over the CSC arrays: one per norm, one per scale. The power-of-two variant rounds each factor to 2ᵏ, so every scaling and unscaling is exact in binary floating point (no rounding, barring overflow and underflow); its norms then approach 1 only to within a factor of √2 or so.

Guarantees. constexpr, noexcept for arithmetic T and integer I, no allocation, no recursion. The patterns of P and A are unchanged; only values change. d, e and c are positive and finite. Complexity: O(iterations · (nnz(P) + nnz(A) + n + m)).

Errors. sparse::sparse_error::dimension_mismatch: P not n x n, A not m x n, q, d or e of the wrong length. sparse::sparse_error::insufficient_capacity: work shorter than ruiz_workspace(n, m) (or ruiz_rectangular_workspace(m, n)). On an error nothing is written.

Performance. Not benchmarked: it runs once per problem, before the solve.

Tests and demos. tests/optim/scaling_test.cpp, demos/optim/scaling_demo.cpp.

Dependencies. <cstddef>, <span>, <type_traits>, sparse/csc.hpp, linalg/types.hpp, math/constexpr_math.hpp, result.hpp.

Known issues. Without power_of_two, scaling then unscaling a value returns it to within an ulp or two, not exactly. Equilibration is a heuristic: it brings norms near 1 and conditioning down in practice, without a bound on the condition number. Infinite bounds stay infinite through scale_bounds.

Status. Experimental, new in 0.21.0.
