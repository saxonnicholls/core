Detailed Description

Wolfram's Subsets and Tuples at compile time: combinations, power sets and every tuple, as tables or one at a time.

Overview.

Wolfram here count
Subsets[list, {k}] subsets<k>(list), for_each_combination<n, k> C(n, k)
Subsets[list] for_each_subset<n> (by size, then in order) 2^n
Tuples[list, k] tuples<k>(list), for_each_tuple<n, k> n^k

Rows come in Wolfram's order: combinations lexicographic by position, subsets by size and then lexicographically, tuples lexicographically with the last position varying fastest. The for_each forms visit index rows and store nothing; the table forms build every row at compile time. For types, meta::subsets_t and meta::cartesian_power_t.

// Subsets[hedges, {2}]: every pair of hedges to test together, in order, computed by the compiler.
constexpr std::array<std::string_view, 4> hedges{"puts", "vix", "gold", "duration"};
constexpr auto pairs = snicholls::subsets<2>(hedges);
static_assert(pairs.size() == 6 && pairs[5][0] == "gold" && pairs[5][1] == "duration");
// Tuples[shocks, 3]: every path of three daily shocks, down, flat or up.
constexpr auto paths = snicholls::tuples<3>(std::array{-1, 0, 1});
static_assert(paths.size() == 27);

Relationships. combinatorics/permutations.hpp, combinatorics/partition.hpp; game/coalition.hpp enumerates subsets as bit masks; meta/type_list.hpp. Group: snicholls-core.

Guarantees. constexpr, allocation-free; an element type need only be copyable. Visiting is O(1) amortised per row.

Errors. A count too large for std::size_t is a compile error with a message.

Performance. Not benchmarked: compile time, or a few increments per row.

Tests and demos. tests/combinatorics/subsets_test.cpp, demos/combinatorics/subsets_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <limits>, <optional>, <utility>.

Known issues. A compiler's constant-evaluation budget limits the size of a table; use the for_each forms at run time above it.

Status. New in 0.5.0.
