Detailed Description

reference_key_value_store: the std-only in-memory store, which tests use as their fake.

Overview. A std::map of byte vectors under unsigned byte-wise order, modelling every key-value capability in core: key_value_store (concepts/key_value_store.hpp), kv_health, kv_backup and kv_cas (0.27.0). It is the contract's executable definition, the store a unit test hands to the code under test, and the baseline of the benchmark. As a fake it can fail on purpose: inject_failure(e, n) makes the write n writes from now fail with e (inside a batch: the batch fails at that write and changes nothing), and set_unavailable(true) makes every operation answer kv_errc::unavailable, as a lost connection would.

reference_key_value_store fake;
fake.inject_failure(kv_errc::io); // the next write fails, once
ok &= save_order(fake, "1", "2 x AAPL").is_ok() && *kv_count(fake) == 1; // the retry succeeded
fake.inject_failure(kv_errc::io, 1); // a batch fails at its second write ...
kv_write_batch batch;
batch.put("order/2", "1 x MSFT").put("order/3", "5 x NVDA");
ok &= fake.apply(batch).is_err() && *kv_count(fake) == 1; // ... and changes nothing
fake.set_unavailable(true); // as a lost connection would
ok &= save_order(fake, "4", "x").unwrap_err() == kv_errc::unavailable;
fake.set_unavailable(false);

Not for production data: nothing persists, and it is not synchronised.

Relationships. Models the concepts directly (static dispatch); behind the virtual interfaces through key_value_store_adapter, kv_health_adapter, kv_backup_adapter. Its snapshots are reference_kv_snapshot. Passes run_kv_conformance, run_kv_health_conformance and run_kv_backup_conformance (interfaces/key_value_store_conformance.hpp). Group: snicholls-core.

Implementations / variants. This is the one implementation in core.

Guarantees.

  • Everything the contract promises (the kit checks it).
  • Strong exception safety, and no exception out: a call that fails changes nothing, std::bad_alloc included, which it reports as kv_errc::out_of_memory. Only a visitor's own exception leaves a call.
  • Copy-on-write: a snapshot, a checkpoint and a copy of the store share the data; the first write after one copies the map (O(n)), so taking them is O(1) and reading them is free.
  • Complexity: read, contains, put, insert, erase O(log n) unless a snapshot is shared; scan O(log n + k); apply O(n + b log n) (it builds the next state and swaps it in); diagnostics and verify O(n).
  • Thread safety: none; like a standard container, one thread at a time (snapshots included, since they share the data and its reference count with the store).
  • Sequence: starts at 0 and rises by one per call that changed the store.

Errors. kv_errc::unavailable while set_unavailable(true); the injected error; kv_errc::conflict for a batch insert of a present key; kv_errc::invalid_argument for an empty or used checkpoint name; kv_errc::out_of_memory.

Examples. See the overview, and demos/interfaces/key_value_store_reference_demo.cpp.

Performance. See benchmarks/interfaces/key_value_store_benchmark.cpp and BENCHMARKS.md.

Tests and demos. tests/interfaces/key_value_store_reference_test.cpp (the fake's controls, sharing, checkpoints), the kit in tests/interfaces/key_value_store_test.cpp, demos/interfaces/key_value_store_reference_demo.cpp.

Dependencies. <algorithm>, <cstddef>, <cstdint>, <iterator>, <map>, <memory>, <new>, <optional>, <span>, <string>, <string_view>, <utility>, <vector>, and the four capability concepts.

Known issues. apply copies the map, so a fake holding many entries pays O(n) per batch.

Status. New in 0.22.0; compare_and_swap (kv_cas) in 0.27.0. Experimental.
