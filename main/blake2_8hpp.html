Detailed Description

BLAKE2b and BLAKE2s (RFC 7693), keyed or not, with any output length, usable at compile time.

Overview. BLAKE2b (64-bit words, 128-byte blocks, 1 to 64 bytes of output) and BLAKE2s (32-bit words, 64-byte blocks, 1 to 32 bytes), each a class template over its output length: blake2b<32> is BLAKE2b-256, blake2b<64> BLAKE2b-512. Faster than SHA-2 in software, and keyed directly: blake2b<32>{key} is a MAC with no HMAC around it (RFC 7693 2.9). The incremental interface of every hash in core (update, finish) and a one-shot hash; every function is constexpr.

// The output length is part of the type: BLAKE2b-256 is not BLAKE2b-512 truncated
constexpr auto short_id = snicholls::blake2b<16>::hash("order 42");
static_assert(short_id.size() == 16);
// Keyed: a MAC in one pass, no HMAC around it
snicholls::digest<32> tag(const std::string& key, const std::string& message)
{
return snicholls::blake2b_256::keyed_hash(key, message);
}

Where it is used: Polkadot and Substrate (SS58 addresses, storage keys), Zcash, Argon2's internals, libsodium's crypto_generichash, WireGuard (BLAKE2s), and anywhere a fast keyed hash is wanted.

Relationships. digest<N> and hash_input (hash/digest.hpp); blake3 (hash/blake3.hpp), its faster successor; hmac (hash/hmac.hpp) is unnecessary with BLAKE2's own key but works. Group: snicholls-core.

Implementations / variants. blake2_hash<Traits, N> is the one class; blake2b<N> and blake2s<N> its alias templates, and blake2b_256, blake2b_512, blake2s_256 the common lengths.

Guarantees. Every member is constexpr; the unkeyed constructor, update, finish and hash are noexcept. No allocation; a hasher is a trivially copyable value. Complexity: one compression (12 rounds for BLAKE2b, 10 for BLAKE2s) per block. The last block is held back until finish, as the algorithm requires.

Precondition
1 <= N <= 64 (BLAKE2b) or <= 32 (BLAKE2s): a compile error otherwise.

Errors. The keyed constructor throws std::length_error for a key longer than 64 (BLAKE2b) or 32 (BLAKE2s) bytes; in a constant expression that is a compile error.

Examples. Above; demos/hash/blake2_demo.cpp.

Performance. benchmarks/hash/blake2_benchmark.cpp: BLAKE2b-512 and BLAKE2s-256 against a hand-written loop and OpenSSL (when installed), after a fairness check. Release, Apple clang 17, Xeon W-3245 (a shared machine), 2026-11-20, 16 KiB / 64-byte messages: BLAKE2b-512 core 633 / 267 MB/s, hand 630 / 310, OpenSSL 829 / 106; BLAKE2s-256 core 386 / 319, hand 381 / 377, OpenSSL 542 / 114. Portable code only: the AVX2 and NEON versions of libb2 or libsodium are faster.

Tests and demos. tests/hash/blake2_test.cpp (RFC 7693 Appendices A and B, the reference's keyed vectors, Python's hashlib keyed and unkeyed on random lengths and output lengths, every split), demos/hash/blake2_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <stdexcept>, hash/digest.hpp.

Known issues. The salt and personalisation fields of the BLAKE2 paper's parameter block (which RFC 7693 leaves out) are not provided, nor the tree modes or BLAKE2bp / BLAKE2sp.

Status. New in 0.17.0. Experimental.
