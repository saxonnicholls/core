Detailed Description

containers::md_array<T, E...> and md_span<T, Rank, Layout>: multi-dimensional storage and views, zero-overhead indexing.

Overview. A 3-, 4- or 5-dimensional table (scenario x tenor x strike, currency x book x day) is one contiguous block indexed by a row-major offset. With the extents in the type, md_array<T, E...> holds the block in place and its strides are constants, so a(i, j, k) compiles to the arithmetic a hand-written a[(i * J + j) * K + k] does; with the extents known only at run time, md_span<T, Rank, Layout> is a view over storage someone else owns. for_each_index visits every index in row-major order, unrolled at compile time for an md_array through constexpr_nest.

// 3 scenarios x 4 tenors x 5 strikes, one block, strides known to the compiler.
snicholls::containers::md_array<double, 3, 4, 5> pnl{};
snicholls::containers::md_array<double, 3, 4, 5>::for_each_index([&](auto s, auto t, auto k) {
pnl(s(), t(), k()) = 10.0 * static_cast<double>(s) - static_cast<double>(t) + 0.5 * static_cast<double>(k);
});

A view's layout says how indices map to an offset, as std::mdspan's does:

Layout Offset of (i0, ..., iR-1) Typical storage
layout_right (the default) row-major: the last index is contiguous C arrays, NumPy's default
layout_left column-major: the first index is contiguous Fortran, BLAS / LAPACK, Eigen's default
layout_stride sum(i_d * stride(d)), any strides a slice, a transpose, padded rows, a batch with gaps
// The same six numbers, read as a 2 x 3 matrix three ways.
std::array<double, 6> storage{1, 2, 3, 4, 5, 6};
const md_span<double, 2> rows(storage.data(), {2, 3}); // row-major: 1 2 3 / 4 5 6
const md_span<double, 2, layout_left> columns(storage.data(), {2, 3}); // column-major: 1 3 5 / 2 4 6
const md_span<double, 2, layout_stride> transpose(storage.data(), {3, 2}, {1, 3}); // rows, transposed
const md_span<const double, 2, layout_stride> any = columns; // converts, as std::mdspan's do

submdspan(s, slices...) takes a sub-view: an index fixes a dimension (the rank drops by one), full_extent keeps it, and a std::pair{first, last} keeps [first, last). The result is a layout_stride view of the same storage, so one system of a batch, a row or a column is a view, never a copy.

// Three 2 x 2 systems, stored one after another; the second system, its first column, and a block of rows.
std::array<double, 12> batch_storage{};
for (std::size_t i = 0; i < batch_storage.size(); ++i)
batch_storage[i] = static_cast<double>(i);
const md_span<double, 3> batch(batch_storage.data(), {3, 2, 2});
const auto second = submdspan(batch, 1, full_extent, full_extent); // md_span<double, 2, layout_stride>
const auto first_column = submdspan(second, full_extent, 0);
const auto last_two = submdspan(batch, std::pair<std::size_t, std::size_t>{1, 3}, full_extent, full_extent);

Relationships. constexpr_for.hpp's constexpr_nest; C++23's std::mdspan, whose spellings md_span keeps wherever it costs nothing (extent, stride, rank, size, empty, data_handle, mapping, extents, is_exhaustive, layout_right / layout_left / layout_stride, full_extent, submdspan), so moving to the standard type is a rename. linalg/ takes its matrices and batches as md_spans. Group: snicholls-core.

Guarantees. constexpr; md_array is sizeof(T) * E0 * E1 * ... and trivially copyable when T is; indexing is unchecked (md_array::at checks); an md_span is a pointer plus Rank extents and Rank strides, trivially copyable, and never owns. Views convert implicitly to a view of const elements and from layout_right or layout_left to layout_stride, as std::mdspan's do.

Errors. md_array::at throws std::out_of_range; nothing else throws.

Performance. benchmarks/containers/md_array_benchmark.cpp: a 16 x 16 x 16 x 16 grid summed in order, Release, Apple clang 17, Xeon W-3245, 2026-11-07: 65.3 us through a(i, j, k, l), 65.0 us through the offsets written by hand. The same file times an md_span in each layout against its offsets written by hand (see BENCHMARKS.md).

Tests and demos. tests/containers/md_array_test.cpp, demos/containers/md_array_demo.cpp.

Dependencies. <array>, <concepts>, <cstddef>, <span>, <stdexcept>, <tuple>, <type_traits>, <utility>, constexpr_for.hpp.

Known issues. Differences from std::mdspan, each chosen to stay small: extents are always run-time values (a mapping is mapping<Rank> where the standard's is mapping<Extents>), extents() returns a std::array, elements are read with operator() (C++20 has no multi-argument operator[]), there is no accessor policy, and submdspan always returns a layout_stride view and takes no strided_slice.

Status. New in 0.5.0; layouts and submdspan new in 0.6.0.
