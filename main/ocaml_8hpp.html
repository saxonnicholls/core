Detailed Description

OCaml's standard modules over core's types: fn::ocaml::option (Option), fn::ocaml::result (Result) and fn::ocaml::list (List), with OCaml's names and argument orders; and the idioms for |>, @@, labelled and optional arguments and functors. All constexpr.

Overview. For code read by people who think in OCaml, the same operations under OCaml's names:

OCaml here
x \|> f \|> g x \| fn::then(f) \| fn::then(g)
f @@ x fn::call(f, x)
Option.map / bind / join / fold ocaml::option::map(f, o), bind(o, f), join(o), fold(none, some, o)
Option.value ~default, get, is_some, is_none, some, none the same names
Result.map / map_error / bind / join / fold ocaml::result::map(f, r), map_error(f, r), bind(r, f), join(r), fold(ok, error, r)
Result.value ~default, get_ok, get_error, is_ok, is_error, to_option the same names
List.map / filter / fold_left / fold_right / rev / length / mem / exists / for_all / find_opt / assoc_opt / partition / combine / split / sort / init ocaml::list::...
// OCaml: [1.0850; 1.0852; 1.0849] |> List.map to_bp |> List.filter wide |> List.length
constexpr auto to_bp = [](double x) { return x * 10'000.0; };
constexpr auto n = std::array{1.0850, 1.0852, 1.0849}
| fn::then(fn::partial(oc::list::map, to_bp))
| fn::then(fn::partial(oc::list::filter, [](double bp) { return bp > 10'850.0; }))
| fn::then(oc::list::length);
static_assert(n == 1);
// f @@ x
static_assert(fn::call(to_bp, 0.0001) == 1.0);

Labelled and optional arguments. OCaml's f ~rate ~spread ?(floor = 0.) price is a designated-initialiser struct in C++20: the labels are member names, the optional ones have default member initialisers, and the call reads f({.rate = 1.085, .spread = 25}, price). The compiler checks the names and their order; an omitted member takes its default:

// OCaml: let quote ~rate ~spread_bp ?(floor = 0.) price = ...
struct quote_args {
double rate; // labelled, required: no default
double spread_bp; // labelled, required
double floor = 0.0; // optional, with its default
};
constexpr double quote(const quote_args& a, double price)
{
const double q = price * a.rate * (1 + a.spread_bp / 1e4);
return q < a.floor ? a.floor : q;
}

Functors. An OCaml functor is a module parameterised by a module: module Make (Ord : ORDERED) = struct ... end. In C++ the module type is a concept, the module a struct of static functions and types, and the functor a class template constrained by the concept: template <ordered Ord> struct make_set { ... };, applied as make_set<by_price>. The demo works one through:

// module type ORDERED = sig type t val compare : t -> t -> int end
template <class M>
concept ordered = requires(const typename M::t& a) {
{ M::compare(a, a) } -> std::convertible_to<int>;
};
// module Make_best (Ord : ORDERED) = struct let best xs = ... end
template <ordered Ord>
struct make_best {
template <std::size_t N>
static constexpr typename Ord::t best(const std::array<typename Ord::t, N>& xs)
{
return snicholls::fn::foldl1([](const auto& a, const auto& b) { return Ord::compare(b, a) > 0 ? b : a; }, xs);
}
};
// Two modules of the module type, and the functor applied to each.
struct by_price {
struct t { double price; int size; };
static constexpr int compare(const t& a, const t& b) { return a.price < b.price ? -1 : (b.price < a.price ? 1 : 0); }
};
struct by_size {
using t = by_price::t;
static constexpr int compare(const t& a, const t& b) { return a.size - b.size; }
};
using best_price = make_best<by_price>;
using best_size = make_best<by_size>;

Relationships. functional/typeclasses.hpp, functional/monad.hpp, functional/list.hpp (the operations underneath), snicholls::result. Group: snicholls-core.

Implementations / variants. The modules are namespaces of function objects; most are the functional/ ones under another name, a few adapt the argument order (fold_right f l init).

Guarantees. Those of the operations they name: constexpr, allocation-free.

Errors. option::get and result::get_ok / get_error of the wrong case are precondition violations (OCaml raises Invalid_argument); they are checked with assert.

Examples. See the overview.

Performance. That of the operations underneath; not benchmarked separately.

Tests and demos. tests/functional/ocaml_test.cpp, tests/functional/ocaml_modules_test.cpp, demos/functional/ocaml_demo.cpp, demos/functional/ocaml_pipes_demo.cpp (programs in |> style).

Dependencies. <cassert>, <optional>, <utility>, functional/monad.hpp and functional/list.hpp.

Known issues and gotchas. fn::ocaml::result is a namespace, so with using namespace snicholls::fn::ocaml; and using namespace snicholls; both open, result is ambiguous: name the type snicholls::result. OCaml's List is a linked list; here it is std::array (and ranges for the searches), so cons and pattern matching on :: are left out.

Status. Experimental, new in 0.27.0.
