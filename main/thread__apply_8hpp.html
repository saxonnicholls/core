Detailed Description

thread_apply and outer: Mathematica's Thread and Outer over tuples and arrays, resolved per element at compile time.

Overview. Thread[f[{a, b}, x]] is {f[a, x], f[b, x]}: f is applied across its list arguments position by position, and an argument that is not a list is repeated. thread_apply is that for tuple-like values, so the elements may have different types, and each call is resolved on its own: an overloaded or first_match picks a branch per element.

// Thread[f[{a, b}, {x, y}]] is {f[a, x], f[b, y}]: corresponding elements, whatever their types.
constexpr auto add = [](auto a, auto b) { return a + b; };
static_assert(snicholls::thread_apply(add, std::tuple{1, 2.5}, std::tuple{10, 20}) == std::tuple{11, 22.5});
// Thread[f[{a, b}, x]] is {f[a, x], f[b, x]}: an argument that is not a list is repeated.
static_assert(snicholls::thread_apply(add, std::tuple{1, 2}, 10) == std::tuple{11, 12});
// One overload per element's type, chosen at compile time.
std::string log;
snicholls::thread_apply(snicholls::overloaded{
[&log](int qty, const char* venue) { log += std::string(venue) + " qty " + std::to_string(qty) + "; "; },
[&log](double px, const char* venue) { log += std::string(venue) + " px " + std::to_string(px) + "; "; },
},
std::tuple{100, 189.25}, "NYSE");
// whole() repeats a tuple rather than threading it.
constexpr auto second_plus = [](int a, const std::tuple<int, int>& t) { return a + std::get<1>(t); };
static_assert(snicholls::thread_apply(second_plus, std::array{1, 2}, snicholls::whole(std::tuple{0, 5})) == std::tuple{6, 7});
Wolfram here
Thread[f[{a, b}]] thread_apply(f, std::tuple{a, b})
Thread[f[{a, b}, x]] thread_apply(f, std::tuple{a, b}, x)
Thread[f[{a, b}, {x, y}]] thread_apply(f, tuple_ab, tuple_xy)
Thread[f[x]], no list to thread thread_apply(f, x), which is f(x)

Wolfram's position specifications are for types (meta::thread_t); here, whole(t) marks one tuple to be repeated rather than threaded.

outer(f, a, b) is Outer[f, a, b]: every combination rather than corresponding elements.

// Outer[f, {a, b}, {x, y}] is {{f[a, x], f[a, y]}, {f[b, x], f[b, y]}}: every combination, row-major.
constexpr auto notional = [](double price, int quantity) { return price * quantity; };
constexpr auto grid = snicholls::outer(notional, std::array{189.25, 420.50}, std::array{100, 200, 300});
static_assert(grid[1][2] == 420.50 * 300);

Relationships. meta/type_list.hpp for meta::thread_t; overloaded.hpp for the callables; zip.hpp for ranges whose length is known only at run time. Group: snicholls-core.

Guarantees. constexpr, no allocation of its own. Calls are made in order, left to right. A repeated argument reaches f as a const lvalue, every time. A threaded rvalue tuple's elements are moved out, each once. The result is a std::tuple of the results by value, or void if every call returns void. A tuple-like is anything std::tuple_size knows: std::tuple, std::pair, std::array.

Errors. Compile errors with a message: tuples of different lengths, and a mix of void and non-void results. Exceptions are whatever f throws.

Performance. Not benchmarked: it expands to the calls written out.

Tests and demos. tests/thread_apply_test.cpp, demos/thread_apply_demo.cpp.

Dependencies. <array>, <cstddef>, <functional>, <tuple>, <type_traits>, <utility>.

Known issues. It threads one level, as Thread does; nested tuples reach f whole.

Status. New in 0.5.0.
