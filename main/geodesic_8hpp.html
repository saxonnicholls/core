Detailed Description

snicholls::metric::haversine: the great-circle distance between two (latitude, longitude) points on a sphere.

Overview. Positions on the Earth are compared along its surface. haversine{r} takes points whose first two coordinates are latitude and longitude in radians (a fixed_vector from geometry::ecef_to_lla, an std::array<double, 2>, a struct of the caller's through point_traits) and returns 2 r asin √(sin²(Δφ/2) + cos φ₁ cos φ₂ sin²(Δλ/2)), in the units of r. The default radius is the Earth's mean radius, 6371008.8 m (IUGG). A third coordinate (height) is ignored.

It is a metric, so trees that prune by the triangle inequality can use it. It is exact on a sphere and within about 0.5% on the WGS 84 ellipsoid; for survey work, convert with geometry::local_frame and use euclidean.

// (latitude, longitude) in radians; the Earth's mean radius by default, so the answer is in metres
const std::array<std::array<double, 2>, 4> cities{degrees(51.5074, -0.1278), degrees(48.8566, 2.3522), degrees(40.7128, -74.0060),
degrees(-33.8688, 151.2093)};
const char* names[] = {"London", "Paris", "New York", "Sydney"};
const me::haversine earth{};
const double london_paris = earth(cities[0], cities[1]);
// The nearest city to a ship at sea, given with its height (the third coordinate is ignored)
const la::fixed_vector<double, 3> ship{{45.0 * pi / 180, -30.0 * pi / 180, 25.0}};
std::size_t nearest = 0;
for (std::size_t i = 1; i < cities.size(); ++i)
if (earth(ship, cities[i]) < earth(ship, cities[nearest]))
nearest = i;
// Any sphere: radius 1 gives the central angle, Mars its own radius
const double angle = me::haversine{1.0}(cities[0], cities[3]);
const double on_mars = me::haversine{3389500.0}(cities[0], cities[3]);

Relationships. metric/concepts.hpp, geometry/geodetic.hpp (ecef_to_lla, local_frame), geometry/angle.hpp (radians), math/constexpr_math.hpp. Group: snicholls-core.

Guarantees. constexpr, noexcept when the coordinate reads are, no allocation. The haversine form is accurate for small distances, where the spherical law of cosines loses digits; the argument of asin is clamped to [0, 1], so antipodal points give π r, never NaN.

Errors. None.

Performance. Not benchmarked: five trigonometric calls and a square root.

Tests and demos. tests/metric/geodesic_test.cpp, demos/metric/geodesic_demo.cpp.
