Detailed Description

snicholls::key_store: anything that creates, rotates, retires and destroys signing keys, and never exports one.

Overview. A key store manages the life of signing keys; a signer (concepts/signer.hpp) uses them. The two are separate capabilities because a product may sign through a KMS it does not administer. Neither exports private key material: there is no operation that could. This is the concept half of a pair; the pure virtual half is key_store_interface (interfaces/key_store.hpp), with key_store_adapter<K> and key_store_ref.

The life of a key: create makes version 1, active. rotate makes the next version active and retires the one before it (retired versions still verify, so a JWKS keeps publishing them until their tokens expire). retire stops the whole key signing. destroy removes every version; nothing verifies afterwards.

The contract (interfaces/key_store_conformance.hpp checks it): an unknown id is not_found; an algorithm the store cannot hold is unsupported; a label longer than 255 characters (short_text) is invalid_argument; rotate of a retired or destroyed key is conflict; info returns the current version; list returns every version not destroyed, by key id, then version; ids are unique and never reused, even after destroy. Errors follow the redaction rule of capability_error.hpp.

memory_key_store store = memory_key_store::deterministic();
const auto v2 = rotate_jwt_key(store);
const auto all = store.list(); // version 1 retired (still verifies), version 2 active

Relationships. concepts/signer.hpp (the algorithms), capability_error.hpp, capability_ids.hpp, time/utc.hpp; the twin interfaces/key_store.hpp, the reference interfaces/key_store_reference.hpp, the kit interfaces/key_store_conformance.hpp. Group: snicholls-core.

Implementations. memory_key_store (interfaces/key_store_reference.hpp; HS256 only, for tests). Above core: a KMS server, AWS KMS.

Guarantees. A concept: no code, no cost. Thread safety is the implementation's.

Errors. capability_error, as the contract says.

Performance. Not benchmarked: key management is not a hot path.

Tests and demos. tests/concepts/key_store_test.cpp, demos/concepts/key_store_demo.cpp.

Dependencies. <concepts>, <cstdint>, <string_view>, <vector>, capability_error.hpp, capability_ids.hpp, concepts/signer.hpp, time/utc.hpp.

Known issues. Envelope encryption (data keys under a master key) needs AES-GCM and is not part of the contract.

Status. New in 0.23.0. Experimental until two real implementations pass the kit.
