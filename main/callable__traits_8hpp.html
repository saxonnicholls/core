Detailed Description

snicholls::callable_traits: the result, arguments and arity of a callable with one signature.

Overview. Given a callable type, say what it takes and what it returns: for a function type, a function pointer or reference, a pointer to member function with any const, volatile, &, && or noexcept qualification, a std::function, or a class with exactly one non-template operator() (every non-generic lambda). The arguments come as a meta::type_list, so the type-level algorithms apply to them:

// A handler's parameter list, read from its type: a registry can record what each one takes.
template <snicholls::single_signature_callable F>
std::string describe(const F&)
{
using traits = snicholls::callable_traits<F>;
std::string out = std::to_string(traits::arity) + " argument(s)";
snicholls::meta::for_each_type<typename traits::arguments>([&]<typename Argument>() {
out += std::string{", "} + typeid(Argument).name();
});
out += traits::is_noexcept ? ", noexcept" : "";
return out;
}
struct account {
double balance(const std::string& currency) const noexcept;
};

single_signature_callable<F> is the concept: true exactly when callable_traits<F> is defined. A generic lambda or an overloaded operator() has no single signature, and invoke_with uses this concept to say so with a message.

Relationships. snicholls::invoke_with reads parameter lists through it; snicholls::function_ref and overloaded are what it is usually pointed at; meta::type_list carries the arguments. Group: snicholls-core.

Guarantees. Compile time only. callable_traits<F> strips const, volatile and references from F first, so the traits of a const lambda object are the lambda's. result_type and arguments are the declared types, references and all; arity counts the arguments. For a pointer to member function class_type is the class and is_member is true; for a function object is_member is false and class_type is the object's type.

Errors. None. callable_traits<F> for a type without a single signature is an empty struct, so naming its members is a compile error and the concept is false, never a hard error inside a constraint.

Performance. Not applicable.

Tests and demos. tests/meta/callable_traits_test.cpp, demos/meta/callable_traits_demo.cpp.

Dependencies. <cstddef>, <type_traits> and meta/type_list.hpp.

Known issues. A C-variadic function (int(const char*, ...)) has no traits. A class whose operator() is itself inherited through using from two bases is ambiguous and has none either.

Status. New in 0.5.0.
