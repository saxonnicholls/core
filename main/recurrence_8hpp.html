Detailed Description

snicholls::ml recurrences over a sequence: a step and its backward pass give the sequence forward with checkpoints, the backward pass through time from them, and decoding one token at a time with a fixed-size state.

Overview. Every linear-time sequence mixer (ml/ssd.hpp, ml/gla.hpp, ml/rwkv.hpp, ml/delta_rule.hpp) is a recurrence: a state of a fixed size, updated by each token, from which the token's output is read. Written once here, a mixer supplies only its step and the step's backward pass, and gets

  • recurrence_forward(r, n, sequences, chunk, states, checkpoints): every token of sequences sequences of n tokens laid end to end, each from its own initial state (written back as its final state), saving the state at the start of every chunk of chunk tokens;
  • recurrence_backward(r, n, sequences, chunk, checkpoints, dstates, work): backpropagation through time, one chunk at a time from the last: the chunk's states are recomputed from its checkpoint (so memory is n / chunk + chunk states, not n), then the step's backward pass runs from the chunk's last token to its first;
  • decoding: r.step on one token with the sequence's state, which is the forward pass's own step, so decoding gives the forward pass's bits at every position.

A recurrence (concept recurrence) is a small object over the caller's views with state_size and work_size (static constexpr), step(row, state) (the output of global row row, the state updated in place), advance(row, state) (the update alone, for recomputation) and step_backward(row, previous, dstate, work) (with previous the state before the row and dstate the gradient in the state after it, replaced by the gradient in the state before it; the gradients in the row's inputs written, those in the mixer's own parameters added into).

// s <- a s + x_t, y_t = s: the state is one number; a is a parameter
struct moving_average
{
using value_type = double;
static constexpr std::size_t state_size = 1, work_size = 0;
std::span<const double> x{};
double a = 0.5;
std::span<double> y{};
std::span<const double> dy{}; // the backward pass's views
std::span<double> dx{};
double* da = nullptr;
constexpr void advance(std::size_t t, std::span<double> s) const { s[0] = a * s[0] + x[t]; }
constexpr void step(std::size_t t, std::span<double> s) const
{
advance(t, s);
y[t] = s[0];
}
constexpr void step_backward(std::size_t t, std::span<const double> prev, std::span<double> ds, std::span<double>) const
{
const double d = ds[0] + dy[t]; // the gradient in s_t: from the output and from the next state
dx[t] = d;
*da += d * prev[0];
ds[0] = d * a; // into s_{t-1}
}
};

Relationships. The mixers above; their chunked forms write the same checkpoints, so either forward pass feeds recurrence_backward. Group: snicholls-core.

Implementations. One driver; the mixers are the implementations of the concept.

Guarantees. constexpr, no allocation (the caller owns the states, checkpoints and work), the order of every operation fixed, so the bits do not depend on scheduling. Sequences are independent and could run in parallel; tokens are sequential (the chunked forms are the parallel ones). The checkpoints of a forward pass with any chunk are its states at those tokens, so the backward pass's result does not depend on chunk (tested to the bit).

Errors. Preconditions, asserted: the states sequences · state_size, the checkpoints sequences · recurrence_checkpoints(n, chunk) · state_size (or empty in the forward pass: none saved), work recurrence_backward_work<R>(chunk).

Performance. The driver adds a copy of the state per chunk forward and per token backward to the steps' own work; the mixers' benchmarks measure it against loops by hand: benchmarks/ml/ssd_benchmark.cpp (1.96 ms against 1.96 ms, (Release, AppleClang 17, Intel Xeon W-3245, macOS, 2026-11-19)) and the others in BENCHMARKS.md.

Tests and demos. tests/ml/recurrence_test.cpp, demos/ml/recurrence_demo.cpp.

Dependencies. <algorithm>, <cassert>, <concepts>, <cstddef>, <span>, <type_traits>.

Known issues. Backpropagation through time is sequential in the tokens: a device runs the chunked backward pass of each mixer instead and checks it against this one.

Status. Experimental, new in 0.17.0.
