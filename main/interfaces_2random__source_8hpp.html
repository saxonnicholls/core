Detailed Description

snicholls::random_source_interface, the virtual twin of random_source_like, and the adapters both ways.

Overview. The run-time form of a source of cryptographically secure random bytes, for code that chooses its source at run time (the operating system's in production, a seeded test source in tests). random_source_adapter puts any random_source_like type behind the interface, held by value or, for a reference type, borrowed; any_random_source owns an interface and is itself random_source_like, so a function written against the concept accepts either form.

const bool testing = true; // a configuration decides which source the process uses
any_random_source source = testing ? any_random_source::of(test_random_source{7})
: any_random_source{}; // production: ts-moveables' source here
std::array<std::byte, 32> key{};
const std::errc e = source.fill(key.data(), key.size());

Relationships. concepts/random_source.hpp (the concept), interfaces/random_source_reference.hpp, interfaces/random_source_conformance.hpp. Group: snicholls-core.

Implementations. random_source_adapter<Impl>; ts-moveables' operating-system source derives from the interface or is adapted.

Guarantees. fill is noexcept in every form and fails closed: an error leaves no claim that any byte is random. C++17-clean. An any_random_source that holds nothing reports std::errc::operation_not_permitted.

Errors. Whatever the source reports, passed through unchanged.

Performance. One virtual call per fill; not benchmarked, the source's system call dominates.

Tests and demos. tests/interfaces/random_source_test.cpp, demos/interfaces/random_source_demo.cpp.

Dependencies. <cstddef>, <memory>, <system_error>, <type_traits>, <utility>, concepts/random_source.hpp.

Known issues. None.

Status. New in 0.27.0.
