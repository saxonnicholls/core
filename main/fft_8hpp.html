Detailed Description

snicholls::signal fast Fourier transforms of any length, at compile time and at run time: complex and real, forward and inverse, in one dimension, over rows and over N axes, with their backward passes.

Overview. The discrete Fourier transform X_k = sum_j x_j e^(-2 pi i jk / n) in O(n log n) for every n:

  • Mixed radix when every prime factor of n is at most fft_max_radix (31): a Stockham autosort transform, one pass per factor, radix 4 and 2 by hand for the powers of two and a generic butterfly for 3, 5, 7, ..., 31. Stockham needs no bit reversal: each pass reads one buffer and writes the other in natural order.
  • Bluestein's chirp z-transform for any other n (a large prime factor): the transform as a convolution of length m, the power of two at least 2n - 1, done with three transforms of length m.
  • In place, radix 2, with a bit-reversal table, for a power of two known at compile time (static_fft_plan<T, N>::forward_in_place): no second buffer, the form an FPGA pipeline takes.

A plan holds what does not depend on the data: the factorisation and the twiddle factors (and, for Bluestein, the chirp and the spectrum of its kernel). fft_plan<T> is built at run time over memory the caller gives it (fft_plan<T>::storage_size(n) elements) and never allocates; static_fft_plan<T, N> is built by a consteval constructor into std::arrays, so for a size known when the program is written every table is computed by the compiler. Both are usable in constant evaluation, so a whole transform can be a static_assert. Executing a plan takes a work buffer of work_size() elements from the caller; nothing allocates.

Real input: rfft gives the n / 2 + 1 bins of the half spectrum (the rest is their conjugate), through one complex transform of length n / 2 when n is even; irfft is its inverse, and uses only the real parts of bin 0 and, for even n, bin n / 2, as numpy does. fft_rows transforms a batch of contiguous rows; fftn any number of axes of a row-major array (fft2 for two).

Normalisation, as numpy's and PyTorch's norm: fft_norm::backward (the default: the forward transform is unscaled, the inverse divides by n), fft_norm::forward (the forward divides by n), fft_norm::ortho (both divide by sqrt(n), so the transform is unitary), and fft_norm::none (neither is scaled). The inverse is x_j = s sum_k X_k e^(+2 pi i jk / n) with that scale s.

Gradients. For a real loss of a complex output, with the gradient written g = dL/d re + i dL/d im (PyTorch's convention), the backward pass of each transform is its adjoint: fft_backward is the inverse transform with the forward's scale, ifft_backward the forward with the inverse's, rfft_backward and irfft_backward the corresponding real transforms with the bins between 0 and n / 2 halved or doubled for the half spectrum.

// A cosine of two cycles in 16 samples: its transform, computed by the compiler, is 8 at bins 2 and 14.
constexpr auto x = [] {
std::array<cd, 16> v{};
for (std::size_t i = 0; i < 16; ++i)
v[i] = {m::cos(2 * m::pi * 2.0 * static_cast<double>(i) / 16.0), 0.0};
return v;
}();
constexpr auto X = s::fft(x); // the plan (twiddles, bit reversal) and the transform, all in constant evaluation
static_assert(m::near(X[2].re, 8.0, 1e-13) && m::near(X[14].re, 8.0, 1e-13) && m::near(s::abs(X[5]), 0.0, 1e-13));
// A plan for a length known when the program is written: tables as std::arrays, written by a consteval constructor.
static constexpr s::static_fft_plan<float, 1024> plan1024{};
// Real input: the half spectrum.
constexpr auto H = s::rfft(std::array<double, 8>{1, 1, 1, 1, 0, 0, 0, 0});
static_assert(H.size() == 5 && H[0].re == 4.0);
// Run-time plans over memory the caller owns; nothing allocates while transforming.
const std::size_t n = 1000; // 4 x 2 x 5 x 5 x 5: mixed radix
std::vector<cd> storage(s::fft_plan<double>::storage_size(n)), work(s::fft_plan<double>::work_size(n)), data(n);
const s::fft_plan<double> plan(n, storage);
for (std::size_t i = 0; i < n; ++i)
data[i] = {i == 3 ? 1.0 : 0.0, 0.0}; // an impulse at 3
s::fft(plan, std::span<cd>(data), std::span<cd>(work)); // X_k = e^(-2 pi i 3k / n)
const cd bin1 = data[1];
s::ifft(plan, std::span<cd>(data), std::span<cd>(work)); // back to the impulse
// A prime length runs through Bluestein's algorithm; the call is the same.
std::vector<cd> st_p(s::fft_plan<double>::storage_size(1009)), w_p(s::fft_plan<double>::work_size(1009)), d_p(1009, cd{1, 0});
const s::fft_plan<double> prime(1009, st_p);
s::fft(prime, std::span<cd>(d_p), std::span<cd>(w_p), s::fft_norm::ortho); // a constant: sqrt(n) at DC
// Real samples: n / 2 + 1 bins through a complex transform of half the length.
std::vector<cd> st_r(s::rfft_plan<double>::storage_size(12)), w_r(s::rfft_plan<double>::work_size(12)), half(7);
const s::rfft_plan<double> rplan(12, st_r);
std::vector<double> samples(12), back(12);
for (std::size_t i = 0; i < 12; ++i)
samples[i] = m::sin(2 * m::pi * static_cast<double>(i) / 12.0);
s::rfft(rplan, std::span<const double>(samples), std::span<cd>(half), std::span<cd>(w_r)); // -6i at bin 1
s::irfft(rplan, std::span<const cd>(half), std::span<double>(back), std::span<cd>(w_r));

Relationships. signal/complex.hpp (the element type and twiddle); signal/stft.hpp, signal/dct.hpp, signal/convolve.hpp and signal/hilbert.hpp run on these plans. Group: snicholls-core.

Implementations. Mixed-radix Stockham (radix 4, 2 and a generic odd prime up to 31), Bluestein for the rest, and in-place radix-2 decimation in time with a bit-reversal table for static_fft_plan of a power of two. The generic butterfly costs p complex multiplications per output, so a factor of 31 is about eight times a radix-4 pass; Bluestein costs about six transforms of length m <= 4n, so a prime n runs roughly ten times slower than a power of two near it. Pad or choose a smooth length where the length is yours to choose.

Guarantees. constexpr throughout; no allocation, no recursion, every loop bounded by the length. Plans are immutable after construction and may be shared by any number of threads; a transform touches only its data and its work buffer. fft_plan is trivially copyable (a layout and a span). Tables built at compile time and at run time agree to a few units in the last place (math's compile-time sine and cosine against <cmath>'s), and each is deterministic: the same plan gives the same result to the bit on every call.

Accuracy, against the direct transform in long double (tests/signal/fft_test.cpp: every length from 1 to 300, the powers of two to 2^16 and primes to 10007 bin by bin, float and double): max_k |X_k - X*_k| <= 2 eps ceil(log2 L) ||x||_2, eps the element type's epsilon and L the length the passes run at (n, or Bluestein's m); measured, the worst case is a third of that. Round trips (ifft(fft(x))) return x within the same bound, and Parseval holds to it.

Errors. Preconditions, asserted: the data's length is the plan's; the work buffer is at least work_size(); the storage given to a plan is at least storage_size(n). A plan of length 0 transforms nothing.

Performance. benchmarks/signal/fft_benchmark.cpp: the transform against the same Stockham passes written out by hand (bit-identical, a fairness check) and against the direct O(n^2) DFT. Intel Xeon W-3245, AppleClang 17, Release, 2026-11-20, on a shared machine under load (BENCHMARKS.md): double, 1,024 points 8.0 us (by hand 8.2 us; the direct DFT 1.3 ms), 4,096 points 34 us, 65,536 points 0.94 ms; 1,000 points (radices 4 2 5 5 5) 38 us; 1,009 (Bluestein) 44 us; rfft of 1,024 4.2 us; the in-place radix-2 pass of static_fft_plan<double, 1024> 8.1 us.

Tests and demos. tests/signal/fft_test.cpp, demos/signal/fft_demo.cpp.

Dependencies. <array>, <cassert>, <cstddef>, <cstdint>, <span>, <type_traits>, snicholls/core/math/constexpr_math.hpp, signal/complex.hpp.

Known issues. The generic butterfly (radix 3, 5, 7, ...) is not written out, so a length of 1,000 costs about four times a power of two per point. Constant evaluation has a step limit: Clang's default (-fconstexpr-steps, about a million) allows a static_fft_plan of a few thousand points and a transform of about a thousand; GCC's is larger. The generic butterfly keeps its p inputs on the stack (at most 31 complex numbers).

Status. Experimental, new in 0.17.0.
