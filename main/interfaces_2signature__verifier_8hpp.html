Detailed Description

snicholls::signature_verifier_interface: the pure virtual twin of signature_verifier, and the adapters both ways.

Overview. When the verifier is chosen at run time (crypto's in production, the HS256 reference in a test), code holds a signature_verifier_interface&. Its pure virtual verify is the operation of the concept signature_verifier (concepts/signature_verifier.hpp, where the contract and verify_request are documented), so the interface models the concept itself. signature_verifier_adapter<V> puts any model behind the interface, owning it (V) or referring to it (V&); signature_verifier_ref is a copyable, non-owning handle on the interface that models the concept.

signature_verifier_adapter<memory_signature_verifier&> adapter{reference}; // borrows
const signature_verifier_interface& chosen = adapter;
const signature_verifier_ref handle{chosen};
const auto checked = handle.verify({signature_algorithm::hs256, kid, 1, {}, message, tag->bytes});

Relationships. concepts/signature_verifier.hpp, interfaces/signature_verifier_reference.hpp, interfaces/signature_verifier_conformance.hpp. Group: snicholls-core.

Implementations / variants. signature_verifier_adapter<V> over any model; an implementation above core may derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else; thread safety and exception safety are the wrapped implementation's.

Errors. As the contract.

Performance. One virtual call; the verification's own cost dominates.

Tests and demos. tests/interfaces/signature_verifier_test.cpp, demos/interfaces/signature_verifier_demo.cpp.

Dependencies. <type_traits>, <utility>, concepts/signature_verifier.hpp.

Known issues. None.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
