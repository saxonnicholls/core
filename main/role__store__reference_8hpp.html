Detailed Description

snicholls::kv_role_store<S>, the reference role_store over any key_value_store, and memory_role_store, it over core's reference_key_value_store.

Overview. Grants and their history as rows of a key-value store, so the same code runs over the in-memory reference in a test and over any store a product persists to. Each grant and revoke is one atomic batch: the current grant (put or erased), the event, and the next sequence number. The rows (keys length-prefixed, so a tenant's rows are one prefix and never another tenant's):

Key Value
g tenant-length tenant party(16 bytes) role the grant
e tenant-length tenant sequence(8 bytes, big-endian) the event, in order within the tenant
s the next sequence number

Values are length-prefixed fields with times as big-endian Unix seconds. S is the store by value (owned) or a reference to one (borrowed). fail_next(code, response) makes the next call fail as though the backend had answered response; a failure of the store itself is unavailable (or conflict, internal) with a fixed message.

reference_key_value_store kv; // or any key_value_store a product persists to
kv_role_store<reference_key_value_store&> roles{kv};
static_cast<void>(roles.grant({bob, "acme", "member", alice, "joined", now, std::nullopt}, ""));
static_cast<void>(roles.grant({bob, "acme", "admin", alice, "promoted", now, std::nullopt}, "Grant admin to bob in acme"));
static_cast<void>(roles.revoke(bob, "acme", "member", alice, "admin covers it", now));
const kv_role_store<reference_key_value_store&> after_restart{kv};
const auto history = after_restart.history("acme"); // grant, grant, revoke: oldest first

Relationships. Models role_store (concepts/role_store.hpp); passes its kit in every form; stores through kv_writable (concepts/key_value_store.hpp), by default reference_key_value_store (interfaces/key_value_store_reference.hpp). Group: snicholls-core.

Implementations / variants. kv_role_store<S> over any store; memory_role_store.

Guarantees. Strong: a call that fails changes nothing (one batch per write). Not thread-safe: synchronisation is the caller's (or ts-moveables'). Rows a product wrote before a restart are read back by a new store over the same backend.

Errors. As the contract; invalid_argument for a confirmation, reason or id that does not fit its bound; internal ("a stored grant is malformed") for a row it cannot decode.

Performance. Not benchmarked: a prefix scan per read, one batch per write.

Tests and demos. tests/interfaces/role_store_reference_test.cpp, demos/interfaces/role_store_reference_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <optional>, <string>, <string_view>, <type_traits>, <utility>, <vector>, concepts/key_value_store.hpp, interfaces/key_value_store_reference.hpp, interfaces/role_store.hpp.

Known issues. members and history scan the whole tenant.
