Detailed Description

snicholls::asset: what an amount is of, a code and a scale, as a type or as a 26-byte value.

Overview. An amount of money is a count of minor units of one asset: cents of AUD, wei of ETH, the smallest unit of a token. The asset is its code and its scale, the number of decimal places a minor unit stands for (AUD 2, ETH 18, USDC 6). Both are known when the program is written and never change, so they are compile-time first:

  • as a type. Every ISO 4217 currency is a type (snicholls::currency::AUD, generated from the SIX lists, money/iso4217.hpp), every native chain asset too (snicholls::native::ETH, money/native.hpp), and a product declares its own tokens the same way: a struct with static constexpr member functions code() and scale() (and, for a currency, name() and numeric()). The concepts are snicholls::asset_like and snicholls::currency_like (concepts/asset.hpp);
  • as a value. snicholls::asset, 26 bytes, trivially copyable and structural, for data that names its asset at run time (a ledger row, a message). asset_v<T> is a type's value, checked by the compiler; make_asset("USDC:56", 18) builds one at run time and refuses a malformed code.

A code is 1 to 24 characters: capitals, digits, and : . - _ (AUD, ETH, USDC:56, EEAU2029). A code is unique within a book: a token that exists on several chains is told apart by its code (USDC:1, USDC:56); the registry that assigns those codes is the server's, not core's. The scale is at most max_scale (36), which leaves room in 256 bits for a rate's product.

Use it for money, balances and prices; use decimal for a bounded rate or quantity within 18 digits, and uint256 for a raw on-chain integer that has no asset.

struct eeau { // a product's token, declared as a type
static constexpr std::string_view code() noexcept { return "EEAU"; }
static constexpr std::uint8_t scale() noexcept { return 18; }
};
constexpr asset aud = asset_v<currency::AUD>; // checked by the compiler
constexpr asset token = asset_v<eeau>;
constexpr asset gold = asset_v<with_scale<currency::XAU, 18>>; // ISO gives XAU no minor units
const auto usdc_bsc = make_asset("USDC:56", 18); // at run time, from data
constexpr asset usdc_base = checked_asset("USDC:8453", 6); // a bad code here would not compile
std::array held{checked_asset("USDC:56", 6), usdc_base, asset_v<currency::AUD>};
std::ranges::sort(held); // by code, then scale: deterministic reports

Relationships. concepts/asset.hpp (the concepts), interfaces/asset.hpp (the virtual interface and its adapters), money/iso4217.hpp, money/native.hpp, money/money.hpp. Group: snicholls-core.

Implementations. The value asset is the capability's reference implementation; every currency and native type is another, and interfaces/asset.hpp adapts any of them to asset_interface.

Guarantees. constexpr throughout, noexcept, no allocation. asset is trivially copyable, standard layout and structural (usable as a template argument); equality compares code and scale.

Errors. make_asset returns std::nullopt for an empty, over-long or malformed code, or a scale above max_scale. asset_v<T> of a type with a bad code or scale is a compile error.

Performance. Equality is a 26-byte compare. Not benchmarked separately: money/money.hpp's benchmarks include it.

Tests and demos. tests/money/asset_test.cpp, demos/money/asset_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <optional>, <string_view>, concepts/asset.hpp.

Known issues. None.
