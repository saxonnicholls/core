Detailed Description

synth_three_way: compare two values with <=> if they have it, otherwise with <, as std::tuple does.

Overview. A generic operator<=> over members (a tuple-like, a reflected aggregate, a key of several parts) must compare members that may have <=> or only <. The standard specifies how, for std::tuple and std::pair, as synth-three-way: the member's own <=> when it has one, otherwise a std::weak_ordering built from two <. It never names the function; this does.

// A key of two parts, ordered as std::tuple would order them: the first part that differs decides.
struct key {
std::string venue;
legacy_id id;
friend std::weak_ordering operator<=>(const key& a, const key& b)
{
if (const auto c = snicholls::synth_three_way(a.venue, b.venue); c != 0)
return c;
return snicholls::synth_three_way(a.id, b.id); // only <, so a weak ordering from two of them
}
friend bool operator==(const key& a, const key& b) { return (a <=> b) == 0; }
};
const bool earlier = key{"LSE", {7}} < key{"LSE", {9}};

Relationships. meta/concepts.hpp; objects with fields can compare through it. Group: snicholls-core.

Guarantees. constexpr; noexcept exactly when the comparison it makes is. The result type is the member's own ordering, or std::weak_ordering when synthesised.

Errors. None: a type with neither <=> nor < does not satisfy synth_three_way_comparable.

Performance. The comparison it makes; not benchmarked.
