Detailed Description

Retry backoff with full jitter, as a pure function of the attempt: the caller owns the clock and the sleep.

Overview. When a connection drops, every client that lost it at the same moment must not retry at the same moment, or the server that just came back is knocked over by the herd. Full jitter answers that: the delay before attempt n is uniform in [0, min(max, min * 2^n)], so the herd spreads over the whole window while the window still grows exponentially. The attempt count resets only after a session that lasted session_grace, so a server that accepts and drops at once does not make its clients spin at min.

constexpr snicholls::backoff_policy policy{.min = 100ms, .max = 5s, .session_grace = 30s};
std::mt19937_64 rng{2026}; // the caller owns the randomness, the clock and the sleep
// Six connections that drop at once, then one that stays up: the attempt count resets.
std::uint32_t attempt = 0;
for (int connection = 0; connection < 7; ++connection) {
const auto ceiling = snicholls::backoff_ceiling(policy, attempt);
const auto delay = snicholls::backoff_delay(policy, attempt, rng); // uniform in [0, ceiling]
const auto session = connection < 6 ? 50ms : 2min; // how long it then stayed up
std::printf(" attempt %u: ceiling %5lld ms, sleep %5lld ms, session %6lld ms\n", attempt,
static_cast<long long>(ceiling.count()), static_cast<long long>(delay.count()),
static_cast<long long>(std::chrono::duration_cast<std::chrono::milliseconds>(session).count()));
ok &= delay >= 0ms && delay <= ceiling;
attempt = snicholls::next_attempt(policy, attempt, session);
}

Everything here is a function of its arguments: the caller draws the random number, reads the clock and sleeps. That is what makes the schedule provable in a unit test, overflow included, without breaking a database to see it.

Relationships. The reconnect loops in ts-moveables and in consumers' network layers; a supervisor's restart policy. Group: snicholls-core.

Guarantees. backoff_ceiling and next_attempt are constexpr and noexcept, and never overflow: the doubling stops at max, and the attempt count saturates. backoff_delay with a fraction is constexpr and noexcept too; with a generator it is as noexcept as the generator and performs one draw. No state, no allocation.

Errors. None. A fraction outside [0, 1) is clamped; a policy with max < min behaves as if max == min.

Performance. A loop of at most 32 doublings and one draw. Not benchmarked: there is no abstraction here to have a cost.

Tests and demos. tests/backoff_test.cpp, demos/backoff_demo.cpp.

Dependencies. <algorithm>, <chrono> (durations only; no clock), <cstdint>, <random> (the generator concept and the uniform distribution).

Known issues. std::uniform_int_distribution is not specified bit for bit across standard libraries, so the same seed gives a different schedule on libc++ and libstdc++; the fraction form is the one to pin in a test.

Status. New in 0.5.0.
