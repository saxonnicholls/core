Detailed Description

snicholls::signal convolution and correlation of real sequences, direct and through the FFT, in scipy's full, same and valid modes, and block filtering by overlap-add and overlap-save.

Overview. convolve(a, b, out, mode) is scipy.signal.convolve: full gives na + nb - 1 values c_k = sum_j a_j b_(k-j); same the na values centred on it (starting at (nb - 1) / 2); valid the max - min + 1 values where one sequence covers the other. correlate is scipy.signal.correlate, c_k = sum_j a_(j+k) b_j, the convolution with b reversed (lags from -(nb - 1) in full mode).

  • convolve / correlate: direct, O(na nb), the reference and the fast path for short kernels; constexpr.
  • fft_convolve / fft_correlate: one complex transform of both real inputs packed as a + i b, the product of the two spectra separated from it, and one inverse; the plan's length must be at least na + nb - 1.
  • overlap_add(plan, h, x, out): the full convolution of a long signal with a filter of L taps, in blocks of plan.size() - L + 1 samples, each block's tail added to the next.
  • overlap_save(plan, h, x, out): the causal filter output y_n = sum_k h_k x_(n-k), x.size() samples, each block transformed with the L - 1 samples before it and the wrapped part discarded.
// A three-point moving average, direct (also at compile time) and through the FFT.
static constexpr std::array<double, 6> x{3, 6, 9, 3, 0, 3};
static constexpr std::array<double, 3> avg{1.0 / 3, 1.0 / 3, 1.0 / 3};
constexpr auto full = [] {
std::array<double, s::convolve_size(6, 3, s::convolve_mode::full)> out{};
s::convolve<double>(x, avg, out);
return out;
}();
std::vector<double> same(6), valid(4), fast(8);
s::convolve<double>(x, avg, same, s::convolve_mode::same);
s::convolve<double>(x, avg, valid, s::convolve_mode::valid);
std::vector<cd> storage(s::fft_plan<double>::storage_size(8));
const s::fft_plan<double> plan(8, storage); // at least 6 + 3 - 1
std::vector<cd> work(s::fft_convolve_work_size(plan));
s::fft_convolve(plan, std::span<const double>(x), std::span<const double>(avg), std::span<double>(fast), std::span<cd>(work));
// Where does a pattern occur? Correlation peaks at its lag.
const std::vector<double> signal{0, 0, 0, 1, 2, 1, 0, 0}, pattern{1, 2, 1};
std::vector<double> corr(10), corr_fft(10);
s::correlate<double>(signal, pattern, corr); // lag = index - (pattern.size() - 1)
std::vector<cd> st16(s::fft_plan<double>::storage_size(16));
const s::fft_plan<double> p16(16, st16);
std::vector<cd> w16(s::fft_convolve_work_size(p16));
s::fft_correlate(p16, std::span<const double>(signal), std::span<const double>(pattern), std::span<double>(corr_fft), std::span<cd>(w16));

Relationships. signal/fft.hpp (the plans); signal/fir.hpp (filters to apply); signal/resample.hpp. Group: snicholls-core.

Implementations. Direct; FFT of the full length; overlap-add and overlap-save over blocks. For a kernel of fewer than about 32 taps the direct form is faster; above, overlap-save wins, and the full-length transform for two long sequences.

Guarantees. constexpr; no allocation (work buffers from the caller: fft_convolve_work_size(plan), block_filter_work_size(plan)). The FFT forms agree with the direct one within 4 eps ceil(log2 n) ||a||_2 ||b||_2. Complexity: O(n log n) for fft_convolve, O(N log n) for a signal of N samples through the block forms.

Errors. Preconditions, asserted: the output's size is the mode's; the plan is long enough (na + nb - 1, or more than the filter for the block forms); correlate in valid mode needs na >= nb. Empty inputs give empty outputs.

Performance. benchmarks/signal/convolve_benchmark.cpp: convolve against the same loop by hand (bit-identical), and fft_convolve and overlap_save against it, on 16,384 samples. Intel Xeon W-3245, AppleClang 17, Release, 2026-11-20, a shared machine under load, so the pairs vary by 30% from run to run (BENCHMARKS.md): 16 taps, direct 0.19 ms, overlap-save (blocks of 64) 0.42 ms; 64 taps, direct 0.81 ms, overlap-save 0.36 ms; 512 taps, direct 8.5 ms, overlap-save 0.43 ms, fft_convolve 0.9 ms at every length.

Tests and demos. tests/signal/convolve_test.cpp (scipy's values for every mode, the FFT and block forms against the direct one, compile-time use), demos/signal/convolve_demo.cpp.

Dependencies. <cassert>, <cstddef>, <span>, <type_traits>, signal/fft.hpp.

Known issues. Real sequences only. The block forms transform one block per pass; packing two real blocks into one complex transform would halve their cost.

Status. Experimental, new in 0.17.0.
