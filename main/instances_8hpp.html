Detailed Description

The type-class instances of functional/typeclasses.hpp for std::optional (Maybe), snicholls::result (Either), std::tuple and std::pair (products), std::array (fixed lists), std::basic_string, std::vector and containers::inplace_vector (what functional/list.hpp's filter and partition return), all constexpr.

Overview.

type Semigroup / Monoid Functor Applicative / Monad Alternative Bifunctor
std::optional<T> (Maybe) lifts T's semigroup; nullopt the value pure = engaged; short-circuits first engaged; nullopt -
result<V, E> (Either) the first success (no mempty) the value pure = ok; the first error wins first success value and error
std::tuple<Ts...> element by element every element - - pair, 2-tuples
std::pair<A, B> element by element both elements - - first and second
std::array<T, N> element by element every element Haskell's list: cartesian, N * M - -
std::basic_string concatenation; "" - - - -
std::vector<T> concatenation; {} every element - - -
containers::inplace_vector<T, N> - every element, into inplace_vector<R, N> - - -
// Maybe: a mid needs both sides; the first missing one stops the calculation.
constexpr auto mid = [](double b, double a) { return (b + a) / 2; };
constexpr std::optional<double> bid = 1.0850, ask = 1.0852, stale{};
static_assert(fn::lift_a2(mid, bid, ask).has_value() && !fn::lift_a2(mid, bid, stale).has_value());
// Either: the error says why.
enum class why { crossed };
using quote = snicholls::result<double, why>;
constexpr auto checked = [](double b) { return b > 1.0 ? quote(ok(b)) : quote(err(why::crossed)); };
static_assert(fn::mbind(quote(ok(1.2)), checked).is_ok());

A std::array is a list whose length is in its type, so its Monoid cannot be concatenation (the length would change): it is the product monoid, element by element. Its Monad is the list monad, with the length multiplied: mbind(array<T, N>, T -> array<U, M>) is an array<U, N * M>. An inplace_vector<T, N> (the bounded list filter, partition, span and group return) maps into an inplace_vector<R, N> of the same size and capacity, so fmap(f, partition(p, xs).first) stays at compile time; it has no Monoid, because concatenation could pass the capacity.

// A bounded list (what fn::filter and fn::partition return) maps too, still at compile time.
constexpr snicholls::containers::inplace_vector<double, 4> longs{120.0, 80.0};
constexpr auto doubled = fn::fmap([](double q) { return 2 * q; }, longs); // inplace_vector<double, 4>
static_assert(doubled.size() == 2 && doubled[1] == 160.0);

A tuple's Functor maps every element (with one generic function), not only the last as Haskell's does, because C++'s tuple is a product of equals; bimap over a pair is the Haskell one.

Relationships. functional/typeclasses.hpp (the classes), functional/state.hpp (Identity, Const, Reader, Writer, State), functional/monad.hpp, snicholls::result. Group: snicholls-core.

Implementations / variants. One instance per type, partially specialised on the template.

Guarantees. constexpr (C++20's std::optional, std::tuple, std::array, std::string and std::vector, and core's result, are). The carrier's value category is kept (an rvalue optional moves its value into f). noexcept exactly when f and the copies are, except that the standard library's string and vector operations allocate and are never noexcept. The laws hold and are tested at compile time (tests/functional/typeclasses_laws_test.cpp).

Errors. None of their own; results propagate their first error.

Examples.

// The array monad is Haskell's list monad: every scenario through every shock.
constexpr std::array spot{100.0, 110.0};
constexpr auto shocked = fn::mbind(spot, [](double s) { return std::array{s * 0.99, s, s * 1.01}; });
static_assert(shocked.size() == 6);
// ap: every function applied to every value.
constexpr auto grid = fn::ap(std::array{+[](double x) { return x + 1; }, +[](double x) { return x * 2; }}, std::array{1.0, 2.0});
static_assert(grid == std::array{2.0, 3.0, 2.0, 4.0});

Performance. A branch and the call for Maybe and Either; the elements' calls for products and arrays. Not benchmarked separately.

Tests and demos. tests/functional/instances_test.cpp, tests/functional/instances_edge_test.cpp, tests/functional/typeclasses_laws_test.cpp, demos/functional/instances_demo.cpp, demos/functional/instances_list_monad_demo.cpp (the list monad's searches).

Dependencies. <array>, <concepts>, <cstddef>, <functional>, <optional>, <string>, <tuple>, <type_traits>, <utility>, <vector>, snicholls/core/result.hpp, snicholls/core/meta/concepts.hpp, containers/inplace_vector.hpp and functional/typeclasses.hpp.

Known issues and gotchas. result<void, E> has the Functor and Monad of its own map / and_then; it is not an Applicative here (there is no value to apply). An optional's fmap stores f's result by value.

Status. Experimental, new in 0.27.0.
