Detailed Description

snicholls::memory_sql_connection: the standard-library reference sql_connection, an in-memory table store that runs the statements core's generators write.

Overview. A test double for code written against sql_connection: its tables live in memory, its dialect is sqlite_dialect ($N placeholders are read too), and it runs exactly the shapes of SQL that concepts/sql_dialect.hpp generates, which is what the kit and engine-neutral code send:

  • CREATE TABLE [IF NOT EXISTS] "t" ("c" TYPE [NOT NULL], ..., PRIMARY KEY (...)) [WITHOUT ROWID] and DROP TABLE [IF EXISTS] "t";
  • INSERT INTO "t" (...) VALUES (?1, ...) [ON CONFLICT (...) DO NOTHING | DO UPDATE SET "c" = excluded."c", ...];
  • SELECT "c", ... | count(*) FROM "t" [WHERE "c" = ?n AND "c" >= ?n AND "c" < ?n] [ORDER BY "c" [DESC], ...] [LIMIT n] and DELETE FROM "t" [WHERE ...];
  • BEGIN [IMMEDIATE], COMMIT, ROLLBACK.

Anything else is syntax_error: it is not an SQL engine, and a test that needs one uses SQLite. Values are typed as PostgreSQL types them (text into an integer column is type_mismatch), with SQLite's integer booleans; NOT NULL and the primary key are enforced. Statements are parsed once and cached by text (prepare). A transaction is a snapshot of every table, restored on rollback; a batch is all or nothing the same way. break_connection() makes every later call connection_lost, to test a caller's recovery.

memory_sql_connection db;
const sql_table ticks{"tick", {{"ts", sql_type::int64, false}, {"px", sql_type::float64, false}}, {0}, true};
static_cast<void>(sql_execute(db, *sql_create_table(db.dialect(), ticks)));
const auto n = db.execute_batch(*sql_insert(db.dialect(), ticks), 2, 100, sql_row_filler([](std::size_t row, std::span<sql_param> p) {
p[0] = static_cast<std::int64_t>(row);
p[1] = 100.0 + static_cast<double>(row) / 10;
}));
sql_select window;
window.range_column = 0;
window.has_from = true;
window.has_to = true;
window.order_by = {0};
std::vector<std::int64_t> seen;
static_cast<void>(sql_query(db, *sql_select_rows(db.dialect(), ticks, window), {std::int64_t{10}, std::int64_t{13}},
[&seen](const sql_row& r) { seen.push_back(*r.get_int64(0)); }));

Relationships. Models sql_connection (concepts/sql_connection.hpp); passes interfaces/sql_connection_conformance.hpp directly and through interfaces/sql_connection.hpp; interfaces/sql_dialect_reference.hpp. Group: snicholls-core.

Implementations / variants. One.

Guarantees. Not thread-safe (one per test). Strong exception safety for a failed statement: the tables are as they were. Error messages are literals: no value, table or column name reaches one.

Errors. As the contract: syntax_error, undefined_object, type_mismatch, constraint_violation, unique_violation, misuse (parameter count, nested or missing transaction), connection_lost.

Performance. Not benchmarked: a test double; every lookup is a scan.

Tests and demos. tests/interfaces/sql_connection_reference_test.cpp, demos/interfaces/sql_connection_reference_demo.cpp.

Dependencies. <algorithm>, <cctype>, <cstddef>, <cstdint>, <functional>, <map>, <optional>, <span>, <string>, <string_view>, <utility>, <vector>, interfaces/sql_connection.hpp, interfaces/sql_dialect_reference.hpp.

Known issues. Only the statements above; no joins, expressions, indexes or functions but count(*).

Status. New in 0.27.0. A test double.
