Detailed Description

Checked and saturating integer arithmetic, numeric_cast that refuses a lossy conversion, and parse_number.

Overview. A money path must not wrap silently. checked_add, checked_sub and checked_mul return std::nullopt instead of overflowing; saturating_* clamp to the type's range; numeric_cast<To> gives std::nullopt unless the value survives the conversion exactly; parse_number<T> reads a whole string with std::from_chars and returns the reason it could not. Integers use the compiler's overflow builtins, one instruction and a flag, and a portable form during constant evaluation and on MSVC.

// Adding a fill to a position: an overflow is refused, never wrapped.
const std::int64_t position = 9'000'000'000'000'000'000;
const auto after = snicholls::checked_add<std::int64_t>(position, 500'000'000'000'000'000);
// A quantity from the wire: the whole string, a whole number, and it must fit in 32 bits.
const auto lots = snicholls::parse_number<std::int32_t>("1500");
const auto rubbish = snicholls::parse_number<std::int32_t>("15e2");
// A price that must be an exact number of ticks before it becomes an integer.
const auto ticks = snicholls::numeric_cast<std::int32_t>(1234.0);

Relationships. uint256.hpp for 256-bit amounts, which checks the same way; result.hpp; meta/assignable.hpp for refusing narrowing at compile time. Group: snicholls-core.

Guarantees. constexpr and noexcept, but parse_number, which is noexcept and not constexpr for floating point.

Errors. std::nullopt, or a std::errc in the result: invalid_argument for text that is not a number or has trailing characters, result_out_of_range for one that does not fit.

Performance. Not benchmarked: a builtin and a branch.

Tests and demos. tests/checked_test.cpp, demos/checked_demo.cpp.

Dependencies. <algorithm>, <array>, <cerrno>, <charconv>, <cstdlib>, <concepts>, <limits>, <optional>, <string_view>, <system_error>, <type_traits>, <utility>, result.hpp.

Known issues. Integers only for the arithmetic; floating point has its own infinities. Where the standard library lacks floating-point std::from_chars (Xcode 16's libc++ and older), parse_number of a floating-point type uses the C library: the same syntax, but the decimal point follows LC_NUMERIC if the program changes it, and text over 255 characters is refused.

Status. New in 0.5.0.
