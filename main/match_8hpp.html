Detailed Description

snicholls::fn::match: pattern matching over values, std::variant and snicholls::result, with guards, exhaustiveness checked at compile time, and destructuring of tuples and plain aggregates.

Overview. match(value, cases...) runs the first case, in the order written, that accepts the value and whose guard (if it has one) holds:

// An order event is one of three; the match is checked for exhaustiveness by the compiler.
using event = std::variant<fill, cancel, reject>;
constexpr auto notional = [](const event& e) {
return fn::match(e,
fn::guard([](const fill& f) { return f.quantity > 1'000'000; },
fn::destructure([](double, long) { return -1.0; })), // too large: flagged
fn::destructure([](double px, long qty) { return px * static_cast<double>(qty); }),
[](const cancel&) { return 0.0; },
fn::otherwise([](const auto&) { return 0.0; })); // anything else
};
static_assert(notional(event{fill{1.25, 1000}}) == 1250.0);
static_assert(notional(event{fill{1.25, 5'000'000}}) == -1.0);
static_assert(notional(event{reject{42}}) == 0.0);
case accepts Haskell / OCaml
a callable [](T x) {...} what it can be called with (a variant's alternative, the value) T x -> ...
guard(p, case) what case accepts, when p of it holds x \| p x -> ..., when
on_ok(f), on_err(f) a result's value, a result's error Right v, Left e, Ok v
unpack(f) a tuple, pair or array, f of its elements (a, b) -> ...
destructure(f) a plain aggregate, f of its members {x; y}, record patterns
otherwise(f) anything ([](const auto&) {...}) _ -> ...

A std::variant is matched by its alternative and a result by its side; anything else is matched as itself. Exhaustiveness is a compile-time check: every alternative (both sides of a result, or the value) must be accepted by some case without a guard, or the match does not compile, with "snicholls::fn::match: not exhaustive". The cases that come after it can never run for that alternative, as in Haskell, and are allowed. The match's result type is that of the first unguarded case for the first alternative; every case that runs must return something convertible to it.

Sum types are std::variant (with match in place of std::visit plus overloaded), product types are plain aggregates (destructured by destructure through snicholls::tie), Maybe is std::optional and Either is snicholls::result.

Relationships. snicholls::first_match (the same first-accepting rule, without guards or exhaustiveness), snicholls::overloaded and std::visit, snicholls::tie (reflect/struct_tuple.hpp), functional/combinators.hpp. Group: snicholls-core.

Implementations / variants. One: the cases are tried in order by overloads, never an if constexpr chain.

Guarantees. constexpr. The value is passed to the cases as an lvalue (of the constness given); nothing is copied. A case that does not accept an alternative is never instantiated with it.

Errors. "snicholls::fn::match: not exhaustive" when an alternative has no unguarded case. Not noexcept: the guards and cases may throw.

Examples.

// A result is matched by side; a guard can look at the value.
using placed = snicholls::result<long, order_error>;
constexpr auto status = [](const placed& r) {
return fn::match(r, fn::guard([](long id) { return id == 0; }, fn::on_ok([](long) { return 'T'; })), // a test order
fn::on_ok([](long) { return 'P'; }), // placed
fn::guard([](order_error e) { return e == order_error::market_closed; }, fn::on_err([](order_error) { return 'C'; })),
fn::on_err([](order_error) { return 'R'; })); // rejected
};
static_assert(status(ok(17L)) == 'P' && status(ok(0L)) == 'T');
static_assert(status(err(order_error::market_closed)) == 'C' && status(err(order_error::insufficient_margin)) == 'R');

Performance. A variant's std::visit, a result's branch, then the guards in order; not benchmarked.

Tests and demos. tests/functional/match_test.cpp, tests/functional/match_patterns_test.cpp, demos/functional/match_demo.cpp, demos/functional/match_evaluator_demo.cpp (an expression evaluator).

Dependencies. <cstddef>, <functional>, <tuple>, <type_traits>, <utility>, <variant>, snicholls/core/result.hpp, snicholls/core/reflect/struct_tuple.hpp (heavier than it looks: the generated member binders) and functional/combinators.hpp.

Known issues and gotchas. "Accepts" is std::is_invocable, so implicit conversions count, as in first_match: a [](double) case accepts an int alternative. Constrain a case ([](std::same_as<int> auto)) or order the exact cases first.

Status. Experimental, new in 0.27.0.
