Detailed Description

ISO 3166-1: every country as a type (snicholls::country::AU) and as a constexpr table, from Unicode CLDR, with its currencies from SIX and its E.164 calling code from core's own table.

Overview. Country codes change only when ISO 3166 is revised, so they are compiled in. Each country is a type in snicholls::country, named by its alpha-2 code in capitals (AU, GB, DO; lowercase would make do and in keywords). Each type has static constexpr member functions:

  • alpha2(), alpha3(), numeric();
  • name(), CLDR's English name ("Australia", "Hong Kong SAR China");
  • currencies(), the ISO 4217 codes in use, from SIX's list one with the funds left out, sorted: exactly the inverse of the currencies' countries() (money/iso4217.hpp);
  • calling_code(), the E.164 country calling code, read from detail/e164_country_codes.hpp (the table phone_number.hpp uses), 0 where none is assigned (Antarctica, Bouvet Island).

Every type models country_like (concepts/country.hpp). The same data is a sorted table for codes that arrive at run time: find_country("AU"), find_country("AUS"), find_country(36). The literal "AU"_country is checked by the compiler.

The table is generated by scripts/generate_iso3166.py from the subset of CLDR committed under scripts/data/cldr/ (its release is iso3166_cldr_version, its licence scripts/data/cldr/LICENSE). ISO 3166-1 is CLDR's regular regions with an alpha-3 and a numeric code below 900: not the exceptional reservations (AC, CP, DG, EA, IC, TA) nor the user-assigned XK.

static_assert(country::AU::alpha3() == "AUS" && country::AU::calling_code() == 61);
static_assert(country::CH::currencies()[0] == "CHF");
constexpr country_entry nz = "NZ"_country; // a compile error for an unknown code
const country_entry* gb = find_country("GBR"); // alpha-3 that arrives at run time
const country_entry* by_number = find_country(std::uint16_t{392});

Relationships. concepts/country.hpp, interfaces/country.hpp, money/iso4217.hpp, phone_number.hpp. Group: snicholls-core.

Implementations. One generated type per country, and the generated table.

Guarantees.

  • constexpr, noexcept, no allocation.
  • The table is sorted by alpha-2; alpha-3 and numeric codes are unique, and are searched through sorted permutations.

Errors. find_country returns nullptr for an unknown code; "ZZ"_country is a compile error.

Performance. Binary search over 249 rows, at compile time where the code is a constant. Not benchmarked.

Tests and demos. tests/country_test.cpp (checked against pycountry, babel and phonenumbers through tests/fixtures/countries/countries.tsv, CTest generated.country_fixtures_up_to_date; the table against its sources by generated.iso3166_up_to_date), demos/country_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <span>, <string_view>, detail/iso3166_table.hpp (249 types and rows: heavier than it looks, so include it only where needed).

Known issues.

  • A platform macro of two capitals hides its country type: <windows.h> defines IN, Objective-C's <objc/objc.h> defines NO. Use find_country("IN") there, or include this header first and #undef the macro.
  • Names are CLDR's English names, not ISO's short names ("Palestinian Territories", "U.S. Outlying Islands").
  • Currencies are SIX's: where CLDR 47 lags (Bulgaria's euro of 2026) or adds unofficial ones (GBP in South Georgia), the test lists the differences from babel.

Status. New in 0.23.0.
