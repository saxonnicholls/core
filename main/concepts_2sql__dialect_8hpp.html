Detailed Description

snicholls::sql_dialect: the SQL text one engine needs, and the statements written once over any dialect.

Overview. A dialect turns a database-neutral description of a table (sql_table) into the text one engine understands, and executes nothing. The concept is what differs between engines:

  • d.name(): "sqlite", "postgres";
  • d.column_type(t): the engine's name for a sql_type (INTEGER, BIGINT, BYTEA), or std::nullopt;
  • d.append_identifier(out, id): id quoted, so any name is valid and keeps its case ("a""b"); false for an empty name or one with a NUL;
  • d.append_placeholder(out, n): the 1-based parameter n (?1, $1);
  • d.begin_transaction(): the statement that starts a read-write transaction (BEGIN, SQLite's BEGIN IMMEDIATE);
  • d.clustered_suffix(): what follows a table stored in primary-key order (SQLite's WITHOUT ROWID).

Over it, the statements every engine runs: sql_create_table, sql_drop_table, sql_insert (with sql_conflict: fail, ignore, upsert), sql_select_rows, sql_count and sql_delete (with sql_select: equality on columns, a half-open range on one, an order and a limit). Parameters are numbered in the order each documents; callers bind sql_params in that order (sql_value.hpp).

const sql_table quotes{"quote", {{"series", sql_type::text, false}, {"ts", sql_type::timestamp, false}, {"px", sql_type::decimal, false}}, {0, 1}, true};
const std::string sqlite = ddl(sqlite_dialect{}, quotes);
const std::string postgres = ddl(postgres_dialect{}, quotes);
sql_select latest;
latest.equal = {0};
latest.order_by = {1};
latest.descending = true;
latest.limit = 1;
const auto select = sql_select_rows(postgres_dialect{}, quotes, latest);

The contract (interfaces/sql_dialect_conformance.hpp checks it): every sql_type has a name; an identifier is always quoted, with an embedded quote doubled, and an empty one or one with a NUL is refused; placeholders are distinct for distinct numbers; the transaction statement begins with BEGIN.

Relationships. sql_value.hpp; the twin interfaces/sql_dialect.hpp, the references interfaces/sql_dialect_reference.hpp (sqlite_dialect, postgres_dialect), the kit interfaces/sql_dialect_conformance.hpp; the engines' contract concepts/sql_connection.hpp. Group: snicholls-core.

Implementations. sqlite_dialect and postgres_dialect, standard library only and constexpr where the language allows. Above core: crtp's dialects add their engines' extras.

Guarantees. Dialects are stateless and immutable, so one instance serves every connection and thread. The generators allocate the text they return and nothing else.

Errors. The generators return sql_errc::misuse for a table with no name or no columns, a column index past the table, an identifier that cannot be quoted, an upsert without a primary key, and a type the dialect cannot name.

Performance. Not benchmarked: generate a table's statements once and keep them (prepared statements are cached by text).

Tests and demos. tests/concepts/sql_dialect_test.cpp (golden SQL for both dialects), demos/concepts/sql_dialect_demo.cpp.

Dependencies. <concepts>, <cstddef>, <optional>, <string>, <string_view>, <vector>, sql_value.hpp.

Known issues. Identifiers are always quoted, so they are case-sensitive: "Price" and "price" are two columns.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
