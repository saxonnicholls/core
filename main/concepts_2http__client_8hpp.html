Detailed Description

snicholls::http_client: anything that sends an HTTP request and returns the response.

Overview. The client half of HTTP, beside http_handler (concepts/http_handler.hpp): c.send(request) returns the server's http_response (any status, a 404 or a 503 included, is a response) or a capability_error when there is no response at all: unavailable (DNS, connect, TLS, a reset), timeout, or invalid_argument for a request that cannot be sent (no path, a header with a line break). Code that calls a provider's API takes an http_client and is tested against a handler through loopback_http_client (interfaces/http_client_reference.hpp) with no network at all. http_get(c, target) builds a GET from path?query.

loopback_http_client api{price_api()};
const auto bhp = price(api, "BHP");
const auto missing = http_get(api, "/nowhere"); // a 404 is a response

The contract (interfaces/http_client_conformance.hpp checks it): a request reaches the server and its response comes back as it is; an error status is a response, never an error; no response is an error that carries nothing of what the transport received (capability_error.hpp's redaction rule); a malformed request is refused before anything is sent; HEAD comes back without a body.

Relationships. concepts/http_handler.hpp (the values), capability_error.hpp; the twin interfaces/http_client.hpp, the reference interfaces/http_client_reference.hpp, the kit interfaces/http_client_conformance.hpp. Group: snicholls-core.

Implementations. loopback_http_client<H> (over any handler, in memory). Above core: crtp's cpp-httplib client and ts-moveables' client.

Guarantees. validate_request is noexcept and allocation-free. Thread safety is the implementation's.

Errors. capability_error, as the contract says.

Performance. Not benchmarked: a client is I/O bound.

Tests and demos. tests/concepts/http_client_test.cpp, demos/concepts/http_client_demo.cpp.

Dependencies. <concepts>, <string>, <string_view>, <utility>, <vector>, capability_error.hpp, concepts/http_handler.hpp.

Known issues. Streaming bodies and WebSocket clients are not in the contract (crtp's websocket_client_interface stays crtp's).

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
