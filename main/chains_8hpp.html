Detailed Description

The major blockchains as types: snicholls::chain::ethereum, base, arbitrum, bsc, tron, ...

Overview. A chain's identity changes rarely, and a recompile is cheap, so each chain is a type. Each answers:

  • name() and kind();
  • native_asset(), a value of the native asset's type (native::ETH, native::BTC, ...);
  • for an EVM chain, chain_id(), its EIP-155 identifier, the one wallets and RPC nodes report.

The types model chain_like (and evm_chain_like). A wallet, a token registry or a deposit monitor is written once, as a template over the concept, or once over chain_interface when the choice is made at run time. Testnets are here too, so that a test network is a type and never a magic number.

static_assert(chain::ethereum::chain_id() == 1 && chain::base::chain_id() == 8453);
using native = decltype(chain::bsc::native_asset()); // BNB
static_assert(native::scale() == 18);

Relationships. concepts/chain.hpp, interfaces/chain.hpp, money/native.hpp. Group: snicholls-core.

Implementations. One type per chain.

Guarantees. constexpr, noexcept, no state.

Errors. None.

Performance. Not applicable.

Tests and demos. tests/chain/chains_test.cpp checks every EIP-155 identifier and native asset against the chain registry (ethereum-lists/chains); demo demos/chain/chains_demo.cpp.

Dependencies. <cstdint>, <string_view>, concepts/chain.hpp, money/native.hpp.

Known issues.

  • TRON reports the EIP-155-style identifier 728126428 (0x2b6653dc) through its JSON-RPC, but its kind is tron, since its addresses and transactions are not Ethereum's.
  • Bitcoin and Solana have no EIP-155 identifier.

Status. New in 0.22.0.
