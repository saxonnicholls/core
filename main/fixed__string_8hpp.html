Detailed Description

snicholls::basic_fixed_string and snicholls::fixed_string: compile-time strings usable as template parameters.

Overview. A fixed-capacity string, usable as a non-type template parameter, modelled on std::basic_string and std::string_view conventions and on https://github.com/unterumarmung/fixed_string, but written fresh to be small and dependency-free:

constexpr snicholls::fixed_string greeting = "hello";
static_assert(greeting.size() == 5);
static_assert(greeting == "hello");
static_assert((greeting + snicholls::fixed_string(", world")) == "hello, world");
static_assert(greeting.substr<1, 3>() == "ell");

As a template parameter, the reason the type exists:

// A type parameterised by a name, with no run-time string anywhere
template <snicholls::basic_fixed_string Name>
struct field {
static constexpr std::string_view name = Name;
double value = 0;
};
using price = field<"price">;
using quantity = field<"quantity">;

N is the logical length, excluding the trailing '\0', matching std::string: fixed_string("abc").size() == 3. Deduction from a string literal drops the literal's terminator, so fixed_string("abc") is a string of 3 characters.

Implementations / variants. basic_fixed_string<CharT, N> is the type to name as a template parameter (template <basic_fixed_string Name>). The convenience wrappers fixed_string, wfixed_string, u8fixed_string, u16fixed_string and u32fixed_string mirror the standard character-type family; each derives from basic_fixed_string and carries its own deduction guide. They are class templates rather than alias templates because alias-template CTAD (P1814) is not supported by every Clang release, so fixed_string("abc") must deduce through a real class template.

Guarantees. Every operation is constexpr; every operation but construction from a literal is noexcept. The character storage elems is a public member because a non-type template parameter type must be structural: treat it as read-only. Comparisons go through std::basic_string_view, so a fixed string compares with another fixed string of any length, a string_view, a std::string or a literal. std::hash is specialised, so a fixed string can key an unordered container.

Errors. substr<Pos, Count>() out of range is a compile error. operator[], front() and back() are unchecked, as for std::string_view; front() and back() on an empty string are undefined.

Known issues. std::hash is specialised for basic_fixed_string, not for the wrappers (fixed_string<N>, ...): key an unordered container with basic_fixed_string<CharT, N>, or pass the base's hash. (As moved from base-encode-decode, comparing two fixed strings with each other was ambiguous under C++20 and rejected by MSVC; the fixed-to-fixed operators fixed that.)

Tests and demos. tests/fixed_string_test.cpp, demos/fixed_string_demo.cpp.

Dependencies. <compare>, <cstddef>, <functional>, <string_view>.

Status. Stable.
