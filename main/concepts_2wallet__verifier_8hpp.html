Detailed Description

snicholls::wallet_verifier: did this wallet sign this sign-in message (EIP-191 personal_sign)?

Overview. The seam between Sign-In with Ethereum (EIP-4361) and the two ways a wallet proves a signature:

  • an externally owned account: secp256k1 ecrecover of the EIP-191 hash (personal_sign_hash, which is keccak256("\x19Ethereum Signed Message:\n" + decimal length + message)), compared with the address; high-s refused (EIP-2), v 27 or 28 (0 or 1 mapped);
  • a smart-contract wallet: ERC-1271 isValidSignature(hash, signature) returning 0x1626ba7e on the chain the message names, and ERC-6492 for a wallet not yet deployed (the counterfactual wrapper, magic suffix 0x6492...6492).

This is the concept half of a pair; the pure virtual half is wallet_verifier_interface (interfaces/wallet_verifier.hpp), with wallet_verifier_adapter<V> and wallet_verifier_ref.

The contract (interfaces/wallet_verifier_conformance.hpp checks it):

  • ok() exactly when address signed message; any other signer, a tampered message, or a malformed or empty signature is capability_errc::signature_invalid;
  • address is lowercase 0x and 40 hex digits (is_lowercase_evm_address); anything else is capability_errc::invalid_argument;
  • a chain the verifier cannot reach for ERC-1271 is capability_errc::unavailable (retryable) or capability_errc::unsupported;
  • errors follow the redaction rule of capability_error.hpp: no message, signature, address or node response in them.
// Sign-In with Ethereum's last step: any verifier, the address the message names, the message, the signature.
template <wallet_verifier V>
capability_result<void> sign_in(const V& v, std::uint64_t chain, std::string_view address, std::string_view siwe_message,
std::span<const std::byte> signature)
{
if (!is_lowercase_evm_address(address))
return fail(capability_errc::invalid_argument, {}, "not a lowercase EVM address");
return v.verify({chain, address, siwe_message, signature});
}

Relationships. hash/sha3.hpp (keccak256), capability_error.hpp, capability_ids.hpp (wallet_address); the twin interfaces/wallet_verifier.hpp, the reference interfaces/wallet_verifier_reference.hpp, the kit interfaces/wallet_verifier_conformance.hpp. Group: snicholls-core.

Implementations.

  • memory_wallet_verifier (interfaces/wallet_verifier_reference.hpp): test wallets whose "signature" is keyed HMAC-SHA256 over personal_sign_hash, standard library only, for tests only.
  • Above core: servers' crypto_wallet_verifier (auth/crypto_verifiers.hpp): an EOA through crypto's secp256k1::recover_ethereum(hash, rsv, high_s::reject), the address the last 20 bytes of core's keccak256(key.xy()); ERC-1271 and ERC-6492 through an eth_call on the message's chain (servers' EVM client). secp256k1 is crypto's, never core's.

Guarantees. is_lowercase_evm_address and personal_sign_hash are constexpr, noexcept and allocation-free. wallet_signature_request borrows everything for the call. Thread safety is the implementation's.

Errors. capability_error, as the contract says.

Performance. Not benchmarked: one per sign-in.

Tests and demos. tests/concepts/wallet_verifier_test.cpp (personal_sign_hash against published vectors, checked with an independent Keccak), demos/concepts/wallet_verifier_demo.cpp.

Dependencies. <array>, <concepts>, <cstddef>, <cstdint>, <span>, <string_view>, capability_error.hpp, hash/digest.hpp, hash/sha3.hpp.

Known issues. The address is compared as text: a checksummed (EIP-55) address must be lowercased first.

Status. New in 0.27.0, lifted from servers. Experimental until two real implementations pass the kit.
