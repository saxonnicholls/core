Detailed Description

Day-count conventions as types: ACT/360, ACT/365 Fixed, 30/360, 30E/360 and ACT/ACT ISDA, each with an exact year fraction.

Overview. Each convention of the 2006 ISDA Definitions (section 4.16) that a money-market or swap leg names is an empty type modelling snicholls::day_count_convention:

  • act_360 (4.16(e)): actual days / 360;
  • act_365_fixed (4.16(d)): actual days / 365;
  • thirty_360 (4.16(f), "30/360, 360/360, Bond Basis"): a start on the 31st counts from the 30th; an end on the 31st counts to the 30th when the start is the 30th or 31st;
  • thirty_e_360 (4.16(g), "30E/360, Eurobond Basis"): either date on the 31st counts as the 30th;
  • act_act_isda (4.16(b)): the days in common years / 365 plus the days in leap years / 366.

day_count(start, end) is the days the convention counts, year_fraction(start, end) the exact finance::year_fraction. A convention is chosen at compile time by naming its type, or at run time through day_count_interface (interfaces/day_count.hpp).

const sys_days start = sys_days{2023y / December / 31d}, end = sys_days{2024y / March / 31d};
constexpr year_fraction money_market = act_360::year_fraction(sys_days{2024y / January / 2d}, sys_days{2024y / April / 2d});
static_assert(money_market == year_fraction{91, 360});
const auto bond = thirty_360::day_count(start, end); // 31st -> 30th at both ends: 90 days
const auto euro = thirty_e_360::day_count(start, end); // 90 days
const auto isda = act_act_isda::year_fraction(start, end); // 1/365 + 90/366, exactly

Relationships. concepts/day_count.hpp, interfaces/day_count.hpp, finance/year_fraction.hpp, finance/business_day.hpp (rolling a date onto a business day before counting), time/civil.hpp. Group: snicholls-core.

Implementations. The five above. Not provided: 30E/360 ISDA and 30/360 US, which need the maturity date or an end-of-February rule; ACT/ACT ICMA, which needs the coupon schedule; BUS/252, which needs a calendar.

Guarantees. constexpr, noexcept, O(1), no allocation; every convention is an empty, trivially copyable type. day_count(a, a) and year_fraction(a, a) are zero. The ACT conventions are antisymmetric (f(b, a) == -f(a, b)); the 30/360 family applies its rules to the dates as given, start first, as ISDA and QuantLib do, and so is not.

Errors. None.

Performance. benchmarks/finance/day_count_benchmark.cpp: 4,096 date pairs up to 30 years apart, Release, Apple clang 17, Xeon W-3245, 2026-11-23: act_act_isda::year_fraction 273 us against 260 us for the same arithmetic written by hand, thirty_360::year_fraction 193 us against 203 us (about 65 and 47 ns a pair).

Tests and demos. tests/finance/day_count_test.cpp, against fixtures from QuantLib 1.44 (scripts/generate_finance_fixtures.py, tests/fixtures/finance/day_count.txt); demos/finance/day_count_demo.cpp.

Dependencies. <chrono>, <cstdint>, <string_view>, concepts/day_count.hpp, finance/year_fraction.hpp, time/civil.hpp.

Known issues. QuantLib's Thirty360(ISDA) is 30E/360 ISDA, not this header's thirty_360; QuantLib's Thirty360(BondBasis) is.

Status. New in 0.23.0.
