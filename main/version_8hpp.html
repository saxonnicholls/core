Detailed Description

Which version of snicholls-core you are compiling against.

CMake knows the version and exports it for find_package, but a header-only library is also consumed by people who copy the headers into a tree with no build system at all, and they have no CMake to ask. Without these macros there is no way for them to find out what they have, or to write code that works against two versions:

#if SNICHOLLS_CORE_VERSION >= SNICHOLLS_CORE_VERSION_CHECK(0, 2, 0)
// use something that only exists from 0.2 onwards
#endif

A consumer that needs a minimum says so once, where the compiler can see it:

SNICHOLLS_CORE_REQUIRE_VERSION(0, 5, 0);
SNICHOLLS_CORE_REQUIRE_VERSION
#define SNICHOLLS_CORE_REQUIRE_VERSION(major, minor, patch)
Fail to compile unless snicholls-core is at least major.minor.patch.

That is the compile-time half of the diamond rules in CMakeLists.txt; the CMake half is snicholls_core_require(x.y.z). The number here, the project(... VERSION) in CMakeLists.txt and the release tag are three copies of one fact, checked against each other by scripts/check_version.py on every CI job. Three places holding one number is exactly how a number goes quietly wrong.

// Three views of one number: macros for the preprocessor, constexpr
// functions for templates and static_assert, a string for people.
std::printf(" version %s\n", SNICHOLLS_CORE_VERSION_STRING);
std::printf(" major.minor.patch %d.%d.%d\n",
snicholls::core::version_major(),
snicholls::core::version_minor(),
snicholls::core::version_patch());
std::printf(" encoded %d\n", snicholls::core::version());
// Gate code on a minimum at compile time, in either language
#if SNICHOLLS_CORE_VERSION >= SNICHOLLS_CORE_VERSION_CHECK(0, 5, 0)
std::printf(" at least 0.5.0 yes, says the preprocessor\n");
#endif
static_assert(snicholls::core::version() >= SNICHOLLS_CORE_VERSION_CHECK(0, 5, 0));
SNICHOLLS_CORE_REQUIRE_VERSION(0, 5, 0);
