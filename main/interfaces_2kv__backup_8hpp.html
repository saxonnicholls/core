Detailed Description

The backup capability, virtual form: kv_backup_interface and kv_backup_adapter.

Overview. checkpoint(destination) and verify() as pure virtual functions, for a store chosen at run time. The interface models the concept kv_backup (concepts/kv_backup.hpp); kv_backup_adapter<S> puts any model of the concept behind the interface, owning it or referring to it (S&).

// Before a migration: the data must verify, and a checkpoint must exist to go back to.
bool checkpoint_before_migration(kv_backup_interface& backup, std::string_view name)
{
const auto check = backup.verify();
if (check.is_err() || !check->ok())
return false;
const auto taken = backup.checkpoint(name);
std::printf(" %.*s: %s\n", static_cast<int>(name.size()), name.data(),
taken.is_ok() ? "checkpoint taken" : "no checkpoint, migration refused");
return taken.is_ok();
}

Relationships. The concept and its reports: concepts/kv_backup.hpp. The store contract: key_value_store_interface (interfaces/key_value_store.hpp); a backend derives from both. Group: snicholls-core.

Implementations / variants. kv_backup_adapter<S>; backends above core derive directly.

Guarantees. Those of the concept. The adapter lets no exception of the model through: std::bad_alloc becomes kv_errc::out_of_memory, anything else kv_errc::backend.

Errors. As the concept.

Examples. See the overview.

Performance. Not benchmarked: backend-specific.

Tests and demos. tests/interfaces/kv_backup_test.cpp, demos/interfaces/kv_backup_demo.cpp.

Dependencies. <string_view>, <type_traits>, <utility>, and concepts/kv_backup.hpp, interfaces/key_value_store.hpp (for the exception translation).

Known issues. None known.

Status. New in 0.22.0. Experimental.
