Detailed Description

containers::inplace_vector<T, N>: a vector of at most N elements stored in place, never allocating, constexpr.

Overview. On a hot path an allocation is the cost to avoid: the legs of an order, the levels of a book snapshot, the fills of one message are bounded by a number known when the program is written. inplace_vector<T, N> holds up to N elements inside itself, behaves like a std::vector up to that capacity, and is constexpr, so tables of variable length can be built at compile time.

// At most four legs per order, held inside the order: no allocation on the hot path.
struct leg {
int instrument = 0;
double quantity = 0;
};
snicholls::containers::inplace_vector<leg, 4> legs;
legs.push_back({101, 5});
legs.push_back({102, -5});
const bool room = legs.try_push_back({103, 1}); // false only when full

Past capacity, push_back and emplace_back throw std::length_error (C++26's std::bad_alloc would mislead: nothing is allocated); try_push_back returns false instead and is noexcept.

Relationships. C++26's std::inplace_vector, whose interface this follows where it can; containers/static_map.hpp; the other containers. Group: snicholls-core.

Guarantees. No allocation, ever. sizeof is N * sizeof(T) plus the size, rounded to alignment; trivially copyable when T is. Every operation is constexpr; iterators are pointers; erasure moves later elements down, keeping order.

Errors. std::length_error past capacity (push_back, emplace_back, resize, insert); std::out_of_range from at.

Performance. benchmarks/containers/inplace_vector_benchmark.cpp: 16 doubles per message for 4,096 messages, Release, Apple clang 17, Xeon W-3245, 2026-11-07: 64.8 us, against 64.6 us for a plain array written by hand and 85.8 us for a reserved and reused std::vector.

Tests and demos. tests/containers/inplace_vector_test.cpp, demos/containers/inplace_vector_demo.cpp.

Dependencies. <algorithm>, <array>, <compare>, <concepts>, <cstddef>, <iterator>, <stdexcept>, <type_traits>, <utility>.

Known issues. T must be default-constructible: the unused capacity holds default-constructed elements, which is what makes the container constexpr in C++20 (C++26's uses raw storage).

Status. New in 0.5.0.
