Detailed Description

Shapley attribution of a game, exactly or by sampling, and the attribution methods it is compared with.

Overview. An investment process has n features (signals, constraints, risk factors), and a performance measure v(S) for every set S of them switched on, from a backtest, a pricer or a model: a game. Attribution splits v(all) - v(none) among the features. The Shapley attribution is the only split with full attribution, the correct baseline, fairness and monotonicity (Young 1985); it is the average, over all n! orders of switching features on, of each feature's lift when it is switched on.

// Bacon's return attribution (the paper's table 3): country allocation is feature 0, stock
// selection feature 1, and each backtest's return is a table entry indexed by the features on.
constexpr std::array<double, 4> returns{6.4, 5.2, 9.4, 8.3};
const auto backtests = game::from_table(returns);
const auto shapley = game::shapley<2>(backtests); // fair and full
const auto brinson = game::one_at_a_time<2>(backtests); // leaves 0.1 unattributed
const auto off_the_top = game::sequential<2>(backtests); // full, but favours feature 0
// Ten features and an expensive backtest: sample orders, and see the error of each estimate.
std::mt19937_64 rng(2021);
const auto quadratic = [](game::coalition s) { return static_cast<double>(game::coalition_size(s) * game::coalition_size(s)); };
const auto estimate = game::shapley_sampled<10>(game::memoized(quadratic), rng, {.permutations = 200});

shapley_interactions gives the Shapley interaction index of every pair: which features act together. For a game that is cheap to tabulate, harsanyi.hpp gives the same values from the dividends; for features in groups, owen.hpp.

Relationships. game/coalition.hpp for games; game/harsanyi.hpp, game/owen.hpp, game/properties.hpp, game/tabular.hpp (models over a dataset), game/change.hpp (explaining a change of inputs). Group: snicholls-core.

Guarantees. The exact methods are constexpr, evaluate each coalition once, and take O(n 2^n) arithmetic after that. A value type need only be a game_value, so several metrics can be attributed together. The sampling methods take a floating-point value, report a standard error per feature, and draw from the caller's generator: the same generator state gives the same attribution on every platform, which std::shuffle does not promise.

Errors. None of their own: limits on n are preconditions (static_assert where n is a template argument, assert otherwise). Whatever the game throws propagates.

Performance. benchmarks/game/shapley_benchmark.cpp, exact Shapley of a 16-player game from its table against formula (3) of the paper written out, after a fairness check. Release, Apple clang 17, Xeon W-3245, 2026-11-07: 481 us through shapley against 1,405 us for the formula written out, agreeing to 1e-12 of the total. A game is a table lookup here; with a real backtest the 2^n evaluations dominate, and memoized or sampling is the lever.

Tests and demos. tests/game/shapley_test.cpp, with the paper's tables 1, 3 and 4 and its quadratic example; demos/game/shapley_demo.cpp.

Dependencies. <array>, <cassert>, <cmath>, <concepts>, <cstddef>, <cstdint>, <limits>, <ostream>, <random> (for the generator concept only), <span>, <vector>, meta/concepts.hpp, stats/random.hpp, game/coalition.hpp, combinatorics/permutations.hpp.

Known issues. The paper writes its formulas (3) and (4) with "- b" at the end and gives 2P1 as the attribution of x'Px; neither agrees with its own tables or with full attribution, and this header follows the tables: no - b, and P1. The tests pin both.

Status. New in 0.5.0, experimental.
