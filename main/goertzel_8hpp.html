Detailed Description

snicholls::signal Goertzel detectors: one frequency of a block without a full FFT, its coefficient computed by the compiler when the frequency is known when the program is written; a streaming state of two values, the generalised (non-integer bin) form, windows, and a bank of K frequencies in one pass.

Overview. The Goertzel algorithm computes one term of the discrete-time Fourier transform of a block of n samples, X(w) = sum_j x_j e^(-i w j), with the second-order recurrence 

s_j = x_j + 2 cos(w) s_(j-1) - s_(j-2)

one real multiplication and two additions per sample, and a final step X(w) = e^(-i w n) (e^(i w) s_(n-1) - s_(n-2)) once per block. With w = 2 pi k / n for an integer k it is bin k of the DFT, and the phase factor e^(-i w n) is 1; with any other w (a frequency between bins: the generalised Goertzel algorithm) it is the transform at exactly that frequency, aligned to the block's first sample. The power |X|^2 is (cos w s_(n-1) - s_(n-2))^2 + (sin w s_(n-1))^2, no complex arithmetic: the same four multiplications as the textbook s_(n-1)^2 + s_(n-2)^2 - 2 cos w s_(n-1) s_(n-2), without that form's cancellation at DC and Nyquist.

Use it to test for a handful of frequencies: DTMF's eight tones, a pilot tone, a mains-hum check, a carrier. Prefer signal/fft.hpp when most of the spectrum is wanted: K detectors cost K n real multiply-adds, a real FFT about (n / 2) log2(n / 2) complex ones, so the detectors win while K is below about log2 n. That is the count of operations; measured (Performance, below) one detector is bound by the latency of its recurrence, so a bank of 8 costs only about 1.3 times one detector, and at 1,024 points it still takes 0.6 of the real FFT's time. The detectors also stream: they need no buffer of the block, and the answer is ready the sample the block ends.

Three forms, one state:

  • static_goertzel<T, Frequency, SampleRate, N, Window>: the frequency, sample rate and block length are template parameters, so the bin, cos w, sin w and the coefficient 2 cos w are static constexpr members computed by the compiler with snicholls::math (no trigonometry at run time: a GPU or FPGA kernel reads a constant), and so is the window's table when there is one. The object is the state alone.
  • goertzel<T>: the same detector for a frequency chosen at run time (its constructor is constexpr, so a constexpr goertzel<float> also has its coefficient computed by the compiler).
  • goertzel_bank<T, K>: K frequencies over the same block, every state updated by each sample in one pass.

The constants are goertzel_coefficients<T> (at_frequency, at_bin, at_fractional_bin), and the recurrence is goertzel_state<T>, for a caller who keeps its own layout (one state per channel, a structure of arrays on a device).

// A 1 kHz pilot tone at 8 kHz over blocks of 64: bin 8, the coefficient 2 cos(pi / 4) computed by the compiler.
using pilot = s::static_goertzel<float, 1000.0, 8000.0, 64>;
static_assert(pilot::bin_index == 8.0f);
constexpr float coeff = pilot::coeff; // a constant: no trigonometry at run time
static_assert(sizeof(pilot) == sizeof(s::goertzel_state<float>)); // the object is the state alone
pilot d;
for (const float x : tones(1000.0, 0.0, 64, 8000.0))
d.push(x);
const bool present = d.complete() && d.magnitude() > 0.25f * 64 / 2; // A n / 2 = 16 for A = 0.5
// A frequency chosen at run time, between bins (60 Hz mains hum at 1 kHz over 250 samples: bin 15), streamed in
// two halves, with a Hann window from window.hpp.
const double hum = 60.0, fs = 1000.0;
s::goertzel<double> mains(hum, fs, 250);
std::vector<double> x(250);
for (std::size_t j = 0; j < x.size(); ++j)
x[j] = 0.2 * m::cos(2 * pi * hum * static_cast<double>(j) / fs) + 0.01 * m::cos(2 * pi * 213.0 * static_cast<double>(j) / fs);
const auto window = s::make_window<double, 250>(s::hann{});
mains.update(std::span<const double>(x).first(100), window);
mains.update(std::span<const double>(x).subspan(100), window);
const s::complex<double> X = mains.bin(); // the generalised Goertzel's final step: fft(x * w)[15]
const double amplitude = 2 * mains.magnitude() / 125.0; // sum(hann) = n / 2
// A DTMF decoder: eight detectors in one pass over 205 samples at 8 kHz, their coefficients computed by the compiler.
constexpr std::array<double, 8> hz{697, 770, 852, 941, 1209, 1336, 1477, 1633};
constexpr s::goertzel_bank<float, 8> dtmf(hz, 8000.0, 205);
constexpr char keys[4][5] = {"123A", "456B", "789C", "*0#D"};
auto decode = [&](const std::vector<float>& block) {
auto bank = dtmf; // a copy: the constants and a zeroed state
bank.update(block);
const std::size_t r = bank.strongest(0, 4), col = bank.strongest(4, 8);
for (std::size_t i = 0; i < bank.size(); ++i) // every other tone well below both
if (i != r && i != col && bank.power(i) * 10 > (bank.power(r) < bank.power(col) ? bank.power(r) : bank.power(col)))
return '?';
return keys[r][col - 4];
};
std::string dialled;
for (const char key : std::string("0123456789*#ABCD"))
for (std::size_t r = 0; r < 4; ++r)
for (std::size_t col = 0; col < 4; ++col)
if (keys[r][col] == key)
dialled += decode(tones(hz[r], hz[4 + col], 205, 8000.0));

Template parameters. Frequency and SampleRate are double non-type template parameters, which C++20 admits and GCC 13, Clang 18 and Apple clang 17 compile (Clang from 18; checked for this header), so static_goertzel<float, 1209.0, 8000.0, 205> reads as it is written and a frequency that is not a whole number of hertz (59.94, 1633.5) needs no scaled integer. A rational frequency in integers would have compiled on older compilers too, but at the cost of a numerator and denominator per frequency, and the ratio is reduced in the compute type anyway. Window is a window value of signal/window.hpp (signal::hann{}, signal::kaiser{8.6}), a structural class type, so its parameters are part of the type as well.

Scaling: the same as fft.hpp's bin. No normalisation is applied, so bin() is fft(x)[k] with fft_norm::backward (the default) for an integer k, and power() is its squared magnitude: the two are compared directly (the tests do, for every k). A tone A cos(2 pi k j / n + phi) on an integer bin gives |X_k| = A n / 2 and phase phi; with a window w, A sum(w) / 2. Divide by n (or sum(w)) for fft_norm::forward's scale.

Relationships. signal/fft.hpp (the full transform it is checked against), signal/window.hpp (the windows), signal/complex.hpp (the bin's type and the exact integer-bin twiddle), math/constexpr_math.hpp (the compile-time cosine and sine). Group: snicholls-core.

Implementations. One recurrence. The coefficients of an integer bin come from the octant-reduced root of unity that fft.hpp's tables use, so cos w and sin w are the same constants the FFT multiplies by; a frequency whose bin k = f n / fs is within 4 eps n of an integer is snapped to that bin. A non-integer bin, reduced into [0, n), computes cos and sin of 2 pi k / n and the block phase from frac(k). Constants are computed in compute_t<T> (double for float) and rounded once; the recurrence runs in T (a float detector is all float, as a device kernel is), written s_j = (x_j - s_(j-2)) + coeff s_(j-1) so that the subtraction is off the recurrence's critical path (one multiplication and one addition of latency per sample: 1.6 times the textbook order's speed, measured). Constants built at compile time use math's own sine and cosine, those built at run time <cmath>'s; the two may differ in the last place, so a detector built at run time and one built by the compiler for the same frequency agree within an ulp of their coefficients, not always to the bit.

Guarantees. Every function is constexpr and noexcept; nothing allocates and nothing recurses. goertzel_state, goertzel_coefficients, goertzel, static_goertzel and goertzel_bank are trivially copyable and standard layout; static_goertzel is the state alone (two Ts and a count). A detector is not synchronised: one per thread, or one per channel. push is O(1), update O(samples), a bank's O(samples K); the final step is O(1) per frequency.

Numerical behaviour. The recurrence is a resonator with both poles on the unit circle, so rounding errors are not damped: in the tests' worst case over random blocks, |X - X*| <= eps n ||x||_2 / max(|sin w|, 1 / n), a bound that grows with n where the FFT's grows with log2 n, and fastest near w = 0 and w = pi, where sin w is small (at DC the states grow as n^2 and the final difference cancels); measured, the worst case is 0.8 of the bound. In float over 4,096 samples a mid-band bin is good to about 1e-4 relative to ||x||; a long block in single precision near DC or Nyquist is where to use double (or shorter blocks, which detection usually wants anyway). power() is within 2 d (|X| + d) of |X|^2, d that bound, and is norm(bin()) to the bit for an integer bin.

Errors. None thrown. Preconditions, asserted: a block length of at least 1 and a positive sample rate; a window table at least as long as the samples pushed through it. A frequency outside [0, fs) aliases into it (a negative one is fs minus it), as sampling does. Samples pushed past the block length extend the sum: bin() is then the transform of everything pushed since reset() (its phase factor computed at run time).

Performance. benchmarks/signal/goertzel_benchmark.cpp: one detector and a bank of eight against the same recurrence written out by hand (bit-identical, a fairness check), and against fft.hpp's full real transform of the block reading the same bins (agreeing within the bound above). Intel Xeon W-3245, AppleClang 17, Release, 2026-11-24, on a shared machine under heavy load (load average 24 to 50 on 32 hardware threads; BENCHMARKS.md), so the numbers are indicative: double, a block of 1,024: one bin 2.0 us (by hand 2.0 us), a bank of 8 bins 2.6 us (by hand 2.7 us), the real FFT of the block 4.2 us; 4,096: 8.2 us, 10.6 us, the FFT 18.3 us; a block of 205 (DTMF at 8 kHz): one bin 0.39 us, 8 bins 0.52 us, the FFT 9.9 us (205 is 5 x 41, a Bluestein length); float, 1,024: one bin 2.0 us, 8 bins 2.3 us, the FFT 3.3 us. One detector runs at about 500 million samples a second, the latency of a multiplication and an addition per sample; the bank's eight independent recurrences overlap.

Tests and demos. tests/signal/goertzel_test.cpp (every integer bin against fft.hpp in three types, numpy's DTFT at non-integer bins and with windows from tests/fixtures/signal/goertzel.txt, tones, noise, DC, Nyquist, the 16 DTMF digits, compile-time constants), demos/signal/goertzel_demo.cpp.

Dependencies. <array>, <cassert>, <cstddef>, <span>, <type_traits>, snicholls/core/math/constexpr_math.hpp, signal/complex.hpp, signal/window.hpp.

Known issues. A static_goertzel with a window builds its table of N values at compile time, within the compiler's constant-evaluation limit (Clang's default admits a few thousand points of a cosine window; a Kaiser window costs more per point). MSVC accepts double template parameters from Visual Studio 2019 16.8.

Status. Experimental, new in 0.24.0.
