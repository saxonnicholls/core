Detailed Description

snicholls::ml::mlp_forward and mlp_backward: a transformer's MLP for one token, down(act(up x)) or a gated unit's down(glu(gate x, up x)) (SwiGLU's silu(gate x) · up x, ReGLU, the GEGLUs, gpt-oss's clamped SwiGLU), as the configuration says, and its backward pass; moe_gate and its backward.

Overview. The feed-forward half of a transformer block. transformer_config::mlp chooses the form: GELU (exact or tanh, GPT-2; quick, CLIP), ReLU² (nanochat) or a gated linear unit (ml/glu.hpp: SwiGLU, Llama; ReGLU; GEGLU, Gemma; gpt-oss's clamped SwiGLU). The weights are mlp_weights, views over any weight_matrix storage, so the same call runs on float, bfloat16 or quantised weights. The input is prepared once for up and gate.

For training, mlp_forward(w, x, y, save) also writes the pre-activations into mlp_activations (the output is the same to the bit), and mlp_backward reads them back: it recomputes the hidden row, then adds the gradients into mlp_gradients and the input's. Only dense weights train; a quantised MLP's backward is a compile error. mlp_forward_sequence and mlp_backward_sequence are the batched pair over a sequence: each product one gemm through a linalg backend, the hidden rows saved (mlp_activations::hidden), the backward's working space in mlp_gradients::scratch.

For a mixture of experts, moe_gate<K>(router_logits) picks the K experts a token goes to and their weights (a softmax over the K largest router logits, as Mixtral); the token's output is the weighted sum of those experts' mlp_forwards, each expert's weights a mlp_weights of its own. moe_gate_backward takes the gradient in those weights back to the router logits.

constexpr ml::transformer_config relu2{.d_model = 2, .n_heads = 1, .n_kv_heads = 1, .head_dim = 2, .d_ff = 2, .mlp = ml::mlp_kind::relu_squared};
constexpr ml::transformer_config swiglu{.d_model = 2, .n_heads = 1, .n_kv_heads = 1, .head_dim = 2, .d_ff = 2, .mlp = ml::mlp_kind::swiglu};
const std::array<float, 4> up{1, 0, 0, 1}, gate{1, 1, -1, -1}, down{1, 0, 1, 1}; // 2 x 2 each
const std::array<float, 2> x{2.0f, -1.0f};
std::array<float, 2> a{}, b{};
ml::mlp_forward<relu2>(ml::mlp_weights<W>{W{up, 2, 2}, W{}, W{down, 2, 2}}, x, a); // down(relu(up x)²)
ml::mlp_forward<swiglu>(ml::mlp_weights<W>{W{up, 2, 2}, W{gate, 2, 2}, W{down, 2, 2}}, x, b); // down(silu(gate x) · up x)
// The other gated units run through the same MLP: GEGLU (Gemma) and gpt-oss's clamped SwiGLU, its limit lowered to
// 1 here so the clamp shows; mlp_glu is one hidden element, mlp_glu_backward its gradients
constexpr ml::transformer_config geglu{.d_model = 2, .n_heads = 1, .n_kv_heads = 1, .head_dim = 2, .d_ff = 2, .mlp = ml::mlp_kind::geglu};
constexpr ml::transformer_config oai{.d_model = 2, .n_heads = 1, .n_kv_heads = 1, .head_dim = 2, .d_ff = 2,
.mlp = ml::mlp_kind::swiglu_oai, .glu_limit = 1};
std::array<float, 2> c{}, d{};
ml::mlp_forward<geglu>(ml::mlp_weights<W>{W{up, 2, 2}, W{gate, 2, 2}, W{down, 2, 2}}, x, c); // down(gelu_tanh(gate x) · up x)
ml::mlp_forward<oai>(ml::mlp_weights<W>{W{up, 2, 2}, W{gate, 2, 2}, W{down, 2, 2}}, x, d);
const auto grads = ml::mlp_glu_backward<oai>(1.0f, 2.0f, 1.0f); // gate x = 1, up x = 2 (clamped to 1): d/dup is 0
// Training: the forward pass saves its pre-activations, the backward pass reads them back
std::array<float, 2> saved_up{}, y{};
const ml::mlp_weights<W> relu_w{W{up, 2, 2}, W{}, W{down, 2, 2}};
ml::mlp_forward<relu2>(relu_w, x, y, ml::mlp_activations<float>{saved_up});
const std::array<float, 2> dy{1.0f, 0.0f}; // the gradient in output 0 only
std::array<float, 2> dx{};
std::array<float, 4> dup{}, ddown{};
ml::mlp_backward<relu2>(relu_w, x, ml::mlp_activations<float>{saved_up}, dy, dx, ml::mlp_gradients<float>{dup, {}, ddown});
// A mixture of experts: route to the 2 best of 4, then take a gradient in the weights back to the router
const std::array<float, 4> router{0.5f, 2.0f, -1.0f, 1.0f};
const auto route = ml::moe_gate<2>(router);
std::array<float, 4> drouter{};
ml::moe_gate_backward(route, std::array<float, 2>{1.0f, 0.0f}, drouter); // more weight on the best expert
// A sequence of tokens at once: the products through a linalg backend, the hidden rows saved for the backward
const std::array<float, 4> xs{2.0f, -1.0f, 2.0f, -1.0f}; // the same token twice
std::array<float, 4> ys{}, sup{}, shidden{}, dxs{}, dup2{}, ddown2{}, scratch{};
const ml::mlp_activations<float> save{sup, {}, shidden};
ml::mlp_forward_sequence<relu2>(snicholls::linalg::reference, relu_w, xs, ys, save);
const std::array<float, 4> dys{1.0f, 0.0f, 1.0f, 0.0f};
ml::mlp_backward_sequence<relu2>(snicholls::linalg::reference, relu_w, xs, save, dys, dxs,
ml::mlp_gradients<float>{dup2, {}, ddown2, {}, {}, {}, scratch});

Relationships. ml/transformer_config.hpp, ml/linear.hpp, ml/activations.hpp, ml/transformer_block.hpp (the user). Group: snicholls-core.

Implementations. One, by mlp_kind.

Guarantees. constexpr, no allocation (the hidden row is a std::array of d_ff), linear in the weights. moe_gate is O(experts · K); on ties the lower-numbered expert is chosen first.

Errors. Preconditions, asserted: the matrices have the configuration's shapes (up and gate are d_ff x d_model, down is d_model x d_ff), biases are empty or of the output's size, x and y have d_model. An invalid configuration is a compile error.

Performance. Benchmarked through ml/transformer_block.hpp: its decode step, and its training passes, where mlp_backward runs inside the block's backward, within 3% of the same loops by hand.

Tests and demos. tests/ml/mlp_test.cpp, demos/ml/mlp_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <span>, <type_traits>, linalg/backend.hpp, ml/activations.hpp, ml/linear.hpp, ml/row.hpp, ml/sampling.hpp (top_k), ml/transformer_config.hpp.

Known issues. None known.

Status. Experimental, new in 0.8.0; the gated kinds other than SwiGLU, mlp_glu_kind, mlp_glu and mlp_glu_backward new in 0.17.0.

The backward pass of moe_gate: the gradient in the router logits from the gradient in the route's weights.

The weights are a softmax over the chosen experts' logits, so a chosen expert's logit gets w_i (dw_i - sum_k w_k dw_k) and every other expert's 0 (the choice itself has no gradient).

Parameters

dweightThe gradient in route.weight, K (the first route.count are read).
dlogitsThe gradient in the router logits, one per expert: written.
