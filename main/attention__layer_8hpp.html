Detailed Description

snicholls::ml::attention_forward, attention_forward_sequence and attention_backward: a transformer's attention for one token at one position, or over a sequence for training, and its backward pass: the Q, K and V projections, QK norm, RoPE, the KV cache, grouped-query attention, the soft cap and the output projection, as the configuration says.

Overview. The generic multi-head attention layer. For a token x at position pos:

  1. q = Wq x, k = Wk x, v = Wv x (plus biases), from one prepared input;
  2. per head, an RMS norm of q and k before or after the rotation (qk_norm) and RoPE at pos (rope);
  3. k and v appended to the kv_cache at pos;
  4. each query head h attends to key-value head h / group() over the visible positions (attention_window(pos, window)), each score scale · q·k capped by attention_softcap · tanh(s / cap) if set;
  5. out = Wo y (plus its bias) over the heads' outputs.

Prefill is this for each token of a run in order, so a prompt and a decode step are one code path. Attention never forms the scores of a sequence: each head folds its keys in one pass (attention_accumulator), and a sliding window's two runs are folded in position order, so a ring cache gives the flat cache's bits.

attention_head is one head on its own: the unit to run on threads or devices.

For training, attention_forward_sequence runs a whole sequence and saves attention_activations (each token's output is attention_forward's, to the bit), and attention_backward takes the gradient in the outputs back to every weight, bias, QK-norm weight and input (attention_gradients): Wo's backward, each head's (attention_head_backward, the soft cap included; grouped-query heads add into the key-value head they share), then QK norm and RoPE undone in the configuration's order, then the projections'. No n x n probabilities are formed. Only dense weights train.

Both have a batched overload taking a linalg backend first: the projections are matrix products over the whole sequence (Q, each key-value head's K and V, Wo; a BLAS or a GPU backend from another library, the same call), and QK norm, RoPE and the heads are the per-token path's own code. Its backward needs attention_gradients::y, the heads' output gradients. Both take a number of sequences (default one): a batch of sequences laid end to end, every projection one product over all their rows, attention within each sequence, the activations each sequence's own side by side (attention_activations).

Masks and padding (TRAINING.md T11). Over a sequence, a token sees the keys attention_keys(C.mask, t, length, C.window, C.mask_block) allows: causal by default, bidirectional for a ViT or a JEPA encoder or predictor, block-causal for a frame-causal predictor. attention_activations::lengths is the key-padding mask, one count of valid tokens per sequence: the tokens from it on are seen by no query, and their own heads' outputs are zero (their log-sum-exp -infinity) and pass no gradient. A rope source with a member sequence(s) (gathered_rope, ml/patch.hpp) gives each sequence of a batch its own positions; any other source is shared by every sequence.

// A batch of two sequences in one call: the three tokens, then the same three again, end to end. Every projection
// is one product over all six rows; attention stays within each sequence (positions restart at 0), and the
// activations are each sequence's own side by side
constexpr std::size_t batch = 2;
std::vector<float> xs2(xs);
xs2.insert(xs2.end(), xs.begin(), xs.end());
std::vector<float> q2(batch * sq.size()), k2(batch * sk.size()), v2(batch * sv.size()), y2(batch * sy.size()),
lse2(batch * slse.size()), out2(batch * seq.size());
const ml::attention_activations<float> act2{q2, k2, v2, {}, {}, y2, lse2};
ml::attention_forward_sequence<c>(snicholls::linalg::reference, w, xs2, rope, act2, out2, batch);
// Two query heads share one key-value head of 4 channels; RoPE in the half layout
constexpr ml::transformer_config c{.d_model = 8, .n_heads = 2, .n_kv_heads = 1, .head_dim = 4, .d_ff = 8, .rope = ml::rope_kind::half};
std::vector<float> wq(8 * 8), wkv(4 * 8), wo(8 * 8);
for (std::size_t i = 0; i < 8; ++i)
wq[i * 8 + i] = wo[i * 8 + i] = 1.0f; // identity projections, so the arithmetic is visible
for (std::size_t i = 0; i < 4; ++i)
wkv[i * 8 + i] = 1.0f;
const ml::attention_weights<W> w{W{wq, 8, 8}, W{wkv, 4, 8}, W{wkv, 4, 8}, W{wo, 8, 8}};
static const ml::rope_table<float, 16, 4> rope{}; // cosines and sines for positions 0 to 15
std::vector<float> keys(ml::kv_cache_view<c>::required_size(1, 16)), values(keys.size());
const ml::kv_cache_view<c> cache(keys, values, 1, 16);
std::array<std::array<float, 8>, 3> out{};
for (std::size_t pos = 0; pos < 3; ++pos) {
const std::array<float, 8> x{1, float(pos), 0, 0, 0.5f, 0.5f, 0.5f, 0.5f};
ml::attention_forward<c>(w, x, pos, cache, 0, rope, out[pos]); // appends this token, attends to all so far
}
// One head alone over what the cache holds: the unit to spread over threads
std::array<float, 4> head{};
const std::array<float, 4> q{1, 0, 0, 0};
const float lse = ml::attention_head<c, float>(q, cache.visible(0, 0, ml::attention_window(2)), head);
// Training: the same three tokens as one sequence, saving what the backward pass reads
constexpr std::size_t n = 3;
std::vector<float> xs;
for (std::size_t pos = 0; pos < n; ++pos)
for (float e : {1.0f, float(pos), 0.0f, 0.0f, 0.5f, 0.5f, 0.5f, 0.5f})
xs.push_back(e);
std::vector<float> sq(n * c.q_size()), sk(n * c.kv_size()), sv(sk.size()), sy(sq.size()), slse(n * c.n_heads), seq(n * 8);
const ml::attention_activations<float> act{sq, sk, sv, {}, {}, sy, slse}; // no QK norm: no raw projections
ml::attention_forward_sequence<c>(w, xs, rope, act, seq);
// A gradient in the last token's first output channel, back to every weight and every input
std::vector<float> dout(n * 8);
dout[2 * 8 + 0] = 1.0f;
std::vector<float> dq(sq.size()), dk(sk.size()), dv(sv.size()), dwq(wq.size()), dwk(wkv.size()), dwv(wkv.size()),
dwo(wo.size()), dx(xs.size());
ml::attention_backward<c>(w, xs, rope, act, dout, dx, ml::attention_gradients<float>{dq, dk, dv, dwq, dwk, dwv, dwo});
// One head's backward, soft cap or not, over the keys it saw
std::array<float, 4> dhead_q{};
std::vector<float> dhead_k(sk.size()), dhead_v(sv.size());
ml::attention_head_backward<c, float>(std::span<const float>(sq).subspan(2 * 8, 4), sk, sv,
std::span<const float>(sy).subspan(2 * 8, 4), std::array<float, 4>{1, 0, 0, 0},
slse[2 * 2], dhead_q, dhead_k, dhead_v);
// The same sequence with its projections as matrix products through a linalg backend (a BLAS or a GPU backend
// from another library the same way); the backward needs one more working buffer, the heads' output gradients
std::vector<float> bq(sq.size()), bk(sk.size()), bv(sv.size()), by(sy.size()), blse(slse.size()), bout(seq.size());
const ml::attention_activations<float> bact{bq, bk, bv, {}, {}, by, blse};
ml::attention_forward_sequence<c>(snicholls::linalg::reference, w, xs, rope, bact, bout);
std::vector<float> gq(sq.size()), gk(sk.size()), gv(sv.size()), gwq(wq.size()), gwk(wkv.size()), gwv(wkv.size()),
gwo(wo.size()), gx(xs.size()), gy(sq.size());
ml::attention_backward<c>(snicholls::linalg::reference, w, xs, rope, bact, dout, gx,
ml::attention_gradients<float>{gq, gk, gv, gwq, gwk, gwv, gwo, {}, {}, {}, {}, {}, {}, gy});

Relationships. ml/transformer_config.hpp, ml/linear.hpp, ml/kv_cache.hpp, ml/attention.hpp, ml/rope.hpp (rope_table is a rope source), ml/norm.hpp, ml/activations.hpp (softcap), ml/transformer_block.hpp (the user). Group: snicholls-core.

Implementations. One, configured at compile time.

Guarantees. constexpr, no allocation (the projections are std::arrays of the configuration's sizes), O(d_model · (q_size + 2 kv_size) + n_heads · visible · head_dim + q_size · d_model) per token.

Errors. Preconditions, asserted: the matrices have the configuration's shapes (q is q_size x d_model, k and v kv_size x d_model, o d_model x q_size), biases and QK-norm weights are empty or of their row's size, the rope source covers pos, the cache's capacity covers the visible range. An invalid configuration is a compile error.

Performance. Benchmarked through ml/transformer_block.hpp: its decode step, and its training passes, where attention_forward_sequence and attention_backward run inside a layer within 5% and 3% of the same loops by hand.

Tests and demos. tests/ml/attention_layer_test.cpp, demos/ml/attention_layer_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <concepts>, <cstddef>, <limits>, <span>, <type_traits>, linalg/backend.hpp, and the ml/ headers above.

Known issues. The score scale is 1 / sqrt(head_dim), rounded once to T.

Status. Experimental, new in 0.8.0; the masks, lengths and per-sequence rope sources new in 0.16.0.

The backward pass of attention_forward_sequence, from what it saved.

Token by token, Wo's backward gives the heads' output gradients. Each query head's backward (attention_head_backward) writes its query gradient and adds into the key and value gradients of the key-value head it shares, so grouped-query heads sum. QK norm and RoPE are undone in the configuration's order (rope_inverse, rms_norm_backward, the norm weights' gradients summed over heads and positions), and linear_backward takes the gradients through Wq, Wk and Wv. Only dense weights train.

Wo's backward over the whole sequence (into grads.y, the heads' output gradients), the heads' backward and the undoing of QK norm and RoPE token by token (the per-token path's code), then Wq's, each key-value head's Wk and Wv's, each one pair of gemms (linear_sequence_backward).

Attention over a whole sequence with its projections as matrix products through a linalg backend, saving what attention_backward needs.

The batched form of the overload above, for dense weights in the sequence's type: Q = X Wqᵀ, each key-value head's K and V straight into the activations' layout, and X_out = Y Woᵀ, each one gemm (a BLAS or a device does them); QK norm, RoPE and the heads are the same code as the per-token path. The projections are the backend's (linear_sequence), so a result can differ from the per-token path's in the last bits.

A batch of sequences. With sequences > 1, xs holds that many sequences of n tokens end to end, and attention stays within each: positions restart at 0 and no token sees another sequence's. Every projection is one product over all sequences · n rows; the activations are each sequence's own laid end to end (see attention_activations). The result is that of calling this once per sequence, to the bit.

The backward pass of attention_head over one contiguous run of keys, soft cap included.

With r_j = scale · q·k_j, s_j = cap(r_j) and p_j = e^(s_j - lse): dv_j += p_j · dout, ds_j = p_j · (dout·v_j - dout·out) · cap'(r_j), dq = scale · sum ds_j · k_j, dk_j += scale · ds_j · q. Without a soft cap it is attend_backward, to the bit.
