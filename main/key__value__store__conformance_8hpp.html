Detailed Description

The conformance kit of the key-value contract: plain functions that drive any store and report which check failed.

Overview. One kit for every implementation of key_value_store (concepts/key_value_store.hpp), in either form: a model of the concept, or a key_value_store_interface (interfaces/key_value_store.hpp). run_kv_conformance(make) calls make() once per check for a fresh, empty store (a store by value, or a pointer-like handle such as std::unique_ptr<key_value_store_interface>), runs the check, and records every expectation that failed with the check's name. No test framework is included: a test asserts report.ok() and prints report.failures.

// Any implementation, either form: make() returns a fresh, empty store (by value, or a handle to one).
const auto by_concept = run_kv_conformance([] { return reference_key_value_store{}; });
const auto by_interface = run_kv_conformance([]() -> std::unique_ptr<key_value_store_interface> {
return std::make_unique<key_value_store_adapter<reference_key_value_store>>(reference_key_value_store{});
});

The checks, by name: starts_empty, put_then_read_round_trips, missing_key_is_not_an_error, put_overwrites, empty_key_and_value_exist, embedded_nul_round_trips, arbitrary_bytes_round_trip, insert_only_when_absent, ledger_entry_is_written_once, erase_reports_whether_the_key_existed, scan_is_in_unsigned_bytewise_order, ranges_are_half_open, scan_prefix_is_a_true_prefix, prefix_ending_in_ff_is_bounded, scan_stops_when_the_visitor_says_so, chunked_scan_equals_one_scan, erase_range_removes_exactly_the_range, apply_runs_writes_in_order, batch_insert_conflict_changes_nothing, visitor_exceptions_propagate_and_the_store_stays_usable, many_keys_scan_in_order, sequence_rules, snapshot_is_isolated, digest_v1_matches_its_golden_vector, no_exception_crosses_the_interface.

Two checks need a way to make the store fail, which only its owner has; they take the store and a callable that arms the failure: kv_check_failure_changes_nothing (a write that fails, alone or mid-batch, is a typed error and changes nothing) and kv_check_no_exception_escapes (every operation, run under whatever failure the caller arranged, returns rather than throws). run_kv_health_conformance and run_kv_backup_conformance cover the other capabilities.

Relationships. Drives key_value_store, kv_health and kv_backup implementations; run on reference_key_value_store in both forms by tests/interfaces/key_value_store_test.cpp. Group: snicholls-core.

Implementations / variants. One kit for both forms; kv_conformance_options::binary_safe = false skips the two checks with bytes that a text-only backend cannot store.

Guarantees. A check never lets an exception out: one that escapes a check is recorded as a failure of no exception crosses the interface. The kit allocates (it builds expected values); the contract does not. Not thread-safe: no check uses threads (core has none); contention and durability are checked by the implementations' own suites.

Errors. Failures are data (kv_conformance_failure), never thrown.

Examples. See the overview.

Performance. Not benchmarked: a test kit.

Tests and demos. tests/interfaces/key_value_store_conformance_test.cpp (the kit catches broken stores), demos/interfaces/key_value_store_conformance_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <optional>, <stdexcept>, <string>, <string_view>, <utility>, <vector>, and the three capability concepts.

Known issues. The kit checks what one thread can observe; atomicity under contention is the implementation's to prove.

Status. New in 0.22.0. Experimental.
