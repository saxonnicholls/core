Detailed Description

snicholls::ml::muon_step: the Muon optimiser for a weight matrix, Newton-Schulz orthogonalisation of its momentum through a linalg backend.

Overview. Muon (Jordan et al., 2024; nanochat's optimiser for the matrices of its blocks) replaces a matrix parameter's update by its nearest semi-orthogonal matrix, approximately: the momentum M is divided by its Frobenius norm and iterated X ← a X + (b A + c A²) X with A = X Xᵀ, the quintic of muon_newton_schulz (ml/optim.hpp), which moves every singular value toward 1: five steps carry any singular value of at least 1.55e-3 (of the normalised matrix) into about [0.682, 1.2024], and a smaller one s only to about a⁵ s ≈ 488 s, below 0.7. The products run on any linalg::blas_backend: linalg::reference here and in tests, a BLAS or device backend for speed.

  • muon_orthogonalise(backend, g, rows, cols, out, work): the iteration on an rows x cols matrix, on its transpose when it has more rows than columns, so A is the smaller square.
  • muon_step(backend, w, g, momentum, rows, cols, config, work): one update. momentum ← μ momentum + g, then g + μ momentum (Nesterov) or momentum is orthogonalised and w ← w − lr · sqrt(max(1, rows / cols)) · X, nanochat's scaling.
  • muon_work_size(rows, cols): the working space both need, so nothing is allocated.

Every step is a call on the backend (TRAINING.md T9): the products are its gemm, and the rest are ml/linear.hpp's elementwise steps (copy_rows, scale_rows, add_rows, and sum_squares for the norm), whose host overloads take any backend. A device library overloads them for its own backend (snicholls-gpu's cuda_training_backend), so a Muon step runs on the device over device memory, as adamw_rows does; through core's reference backend the result is the elementwise loops' to the bit.

// Every step of muon_step is a call on its backend: the products (gemm) and the elementwise steps (copy_rows,
// scale_rows, add_rows, sum_squares). Core's reference runs them on the host; with snicholls-gpu's
// cuda_training_backend and the four spans in device memory, the same call runs on the GPU, as adamw_rows does

A tiny GPT-2 trained end to end with both: token and position embeddings, two blocks (block_forward_sequence, block_backward), the final norm, a tied head (lm_head_loss), Muon on the blocks' matrices and AdamW on the rest. It learns a 17-token sequence (loss 2.81, a uniform guess, to 0.01 in 30 steps), with the same bits on a second run:

// GPT-2 in miniature: 32 channels, 2 heads of 16, an MLP of 128, layer norm, tanh GELU, biases
constexpr ml::transformer_config tiny{.d_model = 32, .n_heads = 2, .n_kv_heads = 2, .head_dim = 16, .d_ff = 128,
.norm = ml::norm_kind::layer, .norm_eps = 1e-5, .mlp = ml::mlp_kind::gelu_tanh, .bias = true};

// One parameter tensor with its gradient and its optimiser's state: Muon's momentum, or AdamW's two moments
struct tensor {
std::size_t rows, cols;
bool muon; // a matrix inside a block
std::vector<float> w, g, m, v;
tensor(std::size_t r, std::size_t c, bool matrix, float scale, float offset, snicholls::stats::wyrand& rng)
: rows(r), cols(c), muon(matrix), w(r * c), g(r * c), m(r * c), v(r * c)
{
for (float& e : w)
e = offset + scale * static_cast<float>(2 * snicholls::stats::uniform_real(rng) - 1);
}
ml::dense_weights<float> dense() const { return {w, rows, cols}; }
};
struct block {
tensor n1w, n1b, wq, wk, wv, wo, bq, bk, bv, bo, n2w, n2b, up, bup, down, bdown;
explicit block(snicholls::stats::wyrand& r)
: n1w(1, d, false, 0, 1, r), n1b(1, d, false, 0, 0, r), wq(d, d, true, 0.3f, 0, r), wk(d, d, true, 0.3f, 0, r),
wv(d, d, true, 0.3f, 0, r), wo(d, d, true, 0.1f, 0, r), bq(1, d, false, 0, 0, r), bk(1, d, false, 0, 0, r),
bv(1, d, false, 0, 0, r), bo(1, d, false, 0, 0, r), n2w(1, d, false, 0, 1, r), n2b(1, d, false, 0, 0, r),
up(f, d, true, 0.3f, 0, r), bup(1, f, false, 0, 0, r), down(d, f, true, 0.05f, 0, r), bdown(1, d, false, 0, 0, r)
{
}

// What one block's forward pass saves, and the working space of its backward pass (shared by the blocks)
struct saved {
std::vector<float> x0 = std::vector<float>(n * d), h1 = x0, x1 = x0, h2 = x0, q = x0, k = x0, v = x0, y = x0,
lse = std::vector<float>(n * tiny.n_heads), up = std::vector<float>(n * f);
ml::block_activations<float> act() { return {x0, h1, x1, h2, {q, k, v, {}, {}, y, lse}, up, {}}; }
};
struct model {
snicholls::stats::wyrand rng{2026};
tensor wte{vocab, d, false, 0.05f, 0, rng}, wpe{n, d, false, 0.1f, 0, rng}, lnfw{1, d, false, 0, 1, rng}, lnfb{1, d, false, 0, 0, rng};
std::vector<block> blocks = [this] {
std::vector<block> b;
for (std::size_t l = 0; l < layers; ++l)
b.emplace_back(rng); // each block its own draws
return b;
}();
std::vector<saved> acts = std::vector<saved>(layers);
std::vector<float> dq = std::vector<float>(n * d), dk = dq, dv = dq, scratch = dq, work = std::vector<float>(ml::muon_work_size(f, d));
// One training step on a sequence: forward, loss, backward, then every tensor's update. Returns the loss.
float step(const std::vector<std::size_t>& text, std::uint64_t t)
{
const std::span<const std::size_t> in(text.data(), n), next(text.data() + 1, n);
std::vector<float> x(n * d), xf(n * d), h(n * d), dh(n * d), logits(vocab);
std::vector<ml::norm_stats<float>> stats(n);
for (std::size_t p = 0; p < n; ++p)
ml::embed_with_position(wte.w, in[p], wpe.w, p, std::span<float>(x).subspan(p * d, d));
for (std::size_t l = 0; l < layers; ++l)
ml::block_forward_sequence<tiny>(blocks[l].weights(), x, ml::no_rope, acts[l].act());
xf = x; // the final norm's input
for (std::size_t p = 0; p < n; ++p)
stats[p] = ml::layer_norm(std::span<const float>(xf).subspan(p * d, d), lnfw.w, lnfb.w, std::span<float>(h).subspan(p * d, d));
const float loss = ml::lm_head_loss(wte.dense(), h, next, logits, dh, wte.g); // the head is wte, tied
for (std::size_t p = 0; p < n; ++p)
ml::layer_norm_backward(std::span<const float>(dh).subspan(p * d, d), std::span<const float>(xf).subspan(p * d, d), lnfw.w,
stats[p], std::span<float>(x).subspan(p * d, d), lnfw.g, lnfb.g);
for (std::size_t l = layers; l-- > 0;) {
block& b = blocks[l];
const ml::block_gradients<float> grads{
b.n1w.g, b.n1b.g, b.n2w.g, b.n2b.g,
{dq, dk, dv, b.wq.g, b.wk.g, b.wv.g, b.wo.g, b.bq.g, b.bk.g, b.bv.g, b.bo.g, {}, {}},
{b.up.g, {}, b.down.g, b.bup.g, {}, b.bdown.g},
scratch};
ml::block_backward<tiny>(b.weights(), ml::no_rope, acts[l].act(), x, grads);
}
for (std::size_t p = 0; p < n; ++p) {
ml::embedding_backward(std::span<const float>(x).subspan(p * d, d), in[p], wte.g);
ml::embedding_backward(std::span<const float>(x).subspan(p * d, d), p, wpe.g);
}
std::vector<tensor*> all{&wte, &wpe, &lnfw, &lnfb};
for (block& b : blocks)
for (tensor* e : b.all())
all.push_back(e);
for (tensor* e : all) {
if (e->muon)
ml::muon_step(la::reference, std::span<float>(e->w), std::span<const float>(e->g), std::span<float>(e->m), e->rows,
e->cols, ml::muon_config<float>{.lr = 0.02f}, std::span<float>(work));
else
ml::adamw_step(e->w, e->g, e->m, e->v, t, ml::adamw_config<float>{.learning_rate = 0.01f, .beta2 = 0.95f});
std::fill(e->g.begin(), e->g.end(), 0.0f); // gradients accumulate: clear them for the next step
}
return loss;
}
};
std::vector<float> train(const std::vector<std::size_t>& text, int steps)
{
model m;
std::vector<float> losses;
for (int t = 1; t <= steps; ++t)
losses.push_back(m.step(text, static_cast<std::uint64_t>(t)));
return losses;
}

Relationships. ml/optim.hpp (muon_newton_schulz, adamw_step, adamw_rows), ml/linear.hpp (the elementwise steps on the backend), linalg/backend.hpp (the backend concept), linalg/reference.hpp (the reference backend). Group: snicholls-core.

Implementations. One, over the backend's gemm and elementwise steps. A tall matrix is iterated with A = Xᵀ X and X ← a X + X B rather than transposed, the same arithmetic term for term.

Guarantees. constexpr with a constexpr backend, no allocation (the caller's muon_work_size elements), steps · (2 r² s + r³) multiply-adds for r = min(rows, cols), s = max(rows, cols). A zero gradient gives a zero update. The norm is one sum_squares, so on a device the norm's value comes back to the host once per orthogonalisation (a synchronisation).

Errors. Preconditions, asserted: g, out, w and momentum have rows · cols; work has muon_work_size(rows, cols).

Performance. Not benchmarked here: three gemms and two copies per iteration, the backend's. On a GPU see snicholls-gpu's cuda_ops_benchmark.cpp (a GPT-2-small Muon step against AdamW on the same matrices).

Tests and demos. tests/ml/muon_test.cpp, demos/ml/muon_demo.cpp.

Dependencies. <algorithm>, <cassert>, <cstddef>, <span>, snicholls/core/math/constexpr_math.hpp, <utility>, linalg/backend.hpp, ml/linear.hpp, ml/optim.hpp.

Known issues. nanochat runs the iteration in bfloat16; here it runs in T, or in whatever the backend's products use (snicholls-gpu's cuda_math::bf16 rounds their operands to bfloat16).

Status. Experimental, new in 0.9.0.

Muon's approximate orthogonalisation of a matrix: steps Newton-Schulz iterations from g / |g|_F.

Every step is a call on the backend (TRAINING.md T9): sum_squares for the norm, copy_rows and scale_rows for X = g / |g|, three gemms per iteration with the b A and a X terms as the products' beta, and copy_rows for the result, so a device library's overloads keep the matrix on the device. A tall matrix is iterated as it is, with A = Xᵀ X and X ← a X + X B, which is the transpose's iteration term for term (A and B are symmetric to the bit), so nothing is transposed.

One Muon update of a weight matrix, every step on the backend.

momentum ← μ momentum + g and Nesterov's g + μ momentum are scale_rows, add_rows and copy_rows; the orthogonalisation is muon_orthogonalise; w ← w − lr · sqrt(max(1, rows / cols)) · X is scale_rows and add_rows.
