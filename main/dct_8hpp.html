Detailed Description

snicholls::signal discrete cosine and sine transforms of types II, III and IV through the FFT, with scipy's definitions and its orthonormal option, and the backward pass of the DCT-II.

Overview. With scipy.fft's definitions (norm=None), for n points:

Transform y_k
dct2 2 sum_j x_j cos(pi k (2j + 1) / 2n)
dct3 x_0 + 2 sum_{j>=1} x_j cos(pi j (2k + 1) / 2n)
dct4 2 sum_j x_j cos(pi (2j + 1)(2k + 1) / 4n)
dst2 2 sum_j x_j sin(pi (k + 1)(2j + 1) / 2n)
dst3 (-1)^k x_{n-1} + 2 sum_{j<n-1} x_j sin(pi (j + 1)(2k + 1) / 2n)
dst4 2 sum_j x_j sin(pi (2j + 1)(2k + 1) / 4n)

dct_norm::ortho scales each to an orthonormal matrix, as scipy's norm="ortho": the DCT-II's y_0 by sqrt(1 / 4n) and the rest by sqrt(1 / 2n), the DCT-III by the inverse of that, the type IV by sqrt(1 / 2n); then the DCT-III inverts the DCT-II exactly and the type IV is its own inverse. Unnormalised, dct3(dct2(x)) = 2n x. The DCT-II with ortho is the MFCC's transform (signal/mel.hpp), and it may return only its first coefficients.

Types II and III run Makhoul's permutation through one complex transform of length n (an fft_plan of n); type IV a pre-twiddled complex transform of length 2n (an fft_plan of 2n). The DSTs are DCTs of the reversed or alternated sequence, so every transform is O(n log n) for every n.

// A smooth ramp of 32 values: its orthonormal DCT-II puts nearly all of its energy in the first few coefficients.
const std::size_t n = 32;
std::vector<double> x(n), y(n), back(n), first(4);
for (std::size_t i = 0; i < n; ++i)
x[i] = static_cast<double>(i) / static_cast<double>(n);
std::vector<cd> storage(s::fft_plan<double>::storage_size(n));
const s::fft_plan<double> plan(n, storage); // types II and III: a plan of n
std::vector<cd> work(s::dct_work_size(plan));
s::dct2(plan, std::span<const double>(x), std::span<double>(y), std::span<cd>(work), s::dct_norm::ortho);
s::dct2(plan, std::span<const double>(x), std::span<double>(first), std::span<cd>(work), s::dct_norm::ortho); // only the first 4
s::dct3(plan, std::span<const double>(y), std::span<double>(back), std::span<cd>(work), s::dct_norm::ortho); // the inverse
// Type IV runs on a plan of 2n.
std::vector<cd> st4(s::fft_plan<double>::storage_size(2 * n));
const s::fft_plan<double> plan4(2 * n, st4);
std::vector<cd> work4(s::dct_work_size(plan4));
std::vector<double> y4(n), y4back(n);
s::dct4(plan4, std::span<const double>(x), std::span<double>(y4), std::span<cd>(work4), s::dct_norm::ortho);
s::dct4(plan4, std::span<const double>(y4), std::span<double>(y4back), std::span<cd>(work4), s::dct_norm::ortho); // its own inverse

Relationships. signal/fft.hpp (the plans); signal/mel.hpp (mfcc). Group: snicholls-core.

Implementations. One per type, with scipy.fft's conventions; types I are not provided.

Guarantees. constexpr; no allocation (work: dct_work_size(plan) complex elements). Complexity: one transform of the plan's length and O(n) twiddles computed as they are used (a sine and a cosine each).

Errors. Preconditions, asserted: the plan's length is n (2n for type IV); the output has n elements (dct2 may have fewer); the work buffer is large enough.

Performance. Not benchmarked separately: one complex transform (signal/fft.hpp's benchmark) and O(n) trigonometry.

Tests and demos. tests/signal/dct_test.cpp (against the definitions in long double and scipy's values, inverses, orthonormality, the backward pass by central differences), demos/signal/dct_demo.cpp.

Dependencies. <cassert>, <cstddef>, <span>, <type_traits>, signal/fft.hpp.

Known issues. A real-input transform of half the length would halve the cost of types II and III; the complex transform keeps the code short.

Status. Experimental, new in 0.17.0.
