Detailed Description

snicholls::metric::set_metric_solver with ospa and gospa, and hausdorff: distances between two sets of points under any metric.

Overview. Comparing a set of estimates with a set of truths (a multi-target tracker's output against ground truth, a detector's boxes against labels, two point clouds) needs a distance between sets of possibly different sizes. Each of these takes the sets as any random-access ranges of any point type, and the base metric as a value (euclidean by default; mahalanobis, haversine, angular or the caller's own plug in unchanged):

  • OSPA (Schuhmacher, Vo and Vo 2008), cut-off c, order p: for m ≤ n points, ((1/n) (min_π Σ min(d, c)^p + c^p (n - m)))^(1/p), in [0, c], normalised per target.
  • GOSPA (Rahmathullah, García-Fernández and Svensson 2017): (min_π Σ min(d, c)^p + (c^p / α) |n - m|)^(1/p). With α = 2 (the default) it splits into localisation error, missed targets and false tracks, which gospa reports separately.
  • Hausdorff: max(sup_x inf_y d(x, y), sup_y inf_x d(x, y)), the worst nearest-neighbour distance either way. No assignment; O(m n) distances.

OSPA and GOSPA solve an optimal assignment (combinatorics/assignment.hpp) over the points. set_metric_solver<T, MaxTruths, MaxEstimates> holds the cost matrix and the solver's arrays, sized at compile time; construct it once (on the heap if large) and reuse it.

// Three targets; the tracker has two of them, slightly off, one missed, and one false track
const std::array<pt, 3> truths{pt{{0, 0}}, pt{{20, 0}}, pt{{40, 0}}};
const std::array<pt, 3> estimates{pt{{19, 0}}, pt{{0, 2}}, pt{{70, 10}}};
const double c = 10, p = 2; // an error over 10 counts as a miss; order 2
me::set_metric_solver<double, 8, 8> solver; // sized at compile time: up to 8 points each side
const auto ospa = solver.ospa(truths, estimates, c, p).unwrap();
const auto gospa = solver.gospa(truths, estimates, c, p).unwrap(); // α = 2
const double worst = me::hausdorff(truths, estimates); // the worst nearest-neighbour distance
// Any base metric, any random-access range of any point type
const std::vector<std::array<double, 2>> plain{{0, 0}, {20, 0}, {40, 0}};
const auto ospa_l1 = solver.ospa(plain, estimates, c, p, me::manhattan{}).unwrap();

Relationships. metric/concepts.hpp and the metrics, combinatorics/assignment.hpp. Stone Soup's OSPAMetric and GOSPAMetric, whose generators over a whole scenario live in the framework above core. Group: snicholls-core.

Guarantees. constexpr, no allocation; ospa and gospa are noexcept when the metric and T's arithmetic are. With a true_metric base, OSPA, GOSPA and Hausdorff are metrics on sets. Complexity: one assignment, O(m² n), for OSPA and GOSPA.

Errors. set_metric_error::too_large: more points than the solver holds. set_metric_error::invalid_parameters: c ≤ 0, p < 1, or α outside (0, 2]. hausdorff of an empty set and a non-empty one is infinity; of two empty sets, zero.

Performance. Not benchmarked: the assignment dominates (see its benchmark).

Tests and demos. tests/metric/sets_test.cpp, demos/metric/sets_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <iterator>, <limits>, <ranges>, <span>, <utility>, combinatorics/assignment.hpp, math/constexpr_math.hpp, metric/concepts.hpp, metric/minkowski.hpp, result.hpp.

Known issues. None known.

Status. Experimental, new in 0.19.0 as tracking/metrics.hpp (Euclidean only); generic over the metric and moved to metric/ in 0.20.0.
