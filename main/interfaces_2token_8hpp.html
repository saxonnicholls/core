Detailed Description

snicholls::token_interface: the virtual twin of token_like, and the adapters between them.

Overview. For code that chooses a token at run time without templates: a wallet's list of balances, a deposit monitor fed from a registry, a plug-in. The adapters go both ways:

  • token_model<T> puts any token_like type behind the interface;
  • the interface models token_like, so an object behind it goes wherever a template over the concept is expected, check_token and to_asset among them.

chain() returns the chain behind chain_interface (a chain_model held by the adapter), so its kind and identifier are there at run time too.

std::vector<std::unique_ptr<token_interface>> watched;
watched.push_back(std::make_unique<token_model<token::ethereum::USDT>>());
watched.push_back(std::make_unique<token_model<token::tron::USDT>>());
for (const auto& t : watched)
std::printf(" watch %.*s on chain %llu\n", static_cast<int>(t->contract().size()), t->contract().data(),
static_cast<unsigned long long>(*t->chain().chain_id()));

Relationships. concepts/token.hpp, interfaces/asset.hpp (the base), interfaces/chain.hpp, interfaces/token_conformance.hpp, token/basic_token.hpp, token/tokens.hpp. Group: snicholls-core.

Implementations. token_model<T>. A run-time registry (servers') implements the interface over its rows.

Guarantees. Every member is noexcept; the adapter is usable in constant expressions when T is. Single inheritance (token_interface derives only from asset_interface), so no constexpr virtual needs a thunk.

Errors. None.

Performance. One virtual call per member; not benchmarked.

Tests and demos. tests/interfaces/token_test.cpp, demos/interfaces/token_demo.cpp.

Dependencies. <cstdint>, <string_view>, concepts/token.hpp, interfaces/asset.hpp, interfaces/chain.hpp.

Known issues. token_model<T> default-constructs T and its chain type, as the curated types allow.

Status. New in 0.23.0.
