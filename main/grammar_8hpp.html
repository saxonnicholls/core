Detailed Description

snicholls::ml grammar-constrained decoding: a GBNF compiler (at run time from a string, at compile time from a fixed_string into fixed-size tables), the pushdown matcher and the token mask over a vocabulary.

Overview. GBNF is llama.cpp's grammar language (grammars/README.md): rules name ::= ..., alternatives |, sequences, literals "..." with the escapes \n \t \r \\ \" \\‍[ \\‍] \\- \\xHH \\uHHHH \\UHHHHHHHH</tt>, character classes <tt>[a-z0-9_]</tt> and <tt>[^...]</tt>, <tt>.</tt> (any character), grouping <tt>( )</tt>, the repetitions <tt>*</tt>, <tt>+</tt>, <tt>?</tt>, <tt>{m}</tt>, <tt>{m,}</tt> and <tt>{m,n}</tt>, comments <tt>\#</tt>, and token terminals <tt>\<[id]\></tt> / <tt>!\<[id]\></tt>. A grammar constrains generation: before each token is sampled, the tokens that cannot continue a sentence of the grammar are masked out. - <tt>parse_grammar(text, root)</tt>: parses GBNF into a <tt>grammar</tt>, a flat table of <tt>grammar_element</tt>s (llama.cpp's <tt>llama_gretype</tt> encoding, value for value) and each rule's first element, or returns a <tt>grammar_error</tt> with the byte position and a message. Repetitions are rewritten into helper rules exactly as llama.cpp's <tt>handle_repetitions</tt> does, so the rules, their numbering and their names (<tt>root_1</tt>, ...) are llama.cpp's. Undefined rules, a missing root and left recursion are errors. - <tt>compile_grammar\<\"...\">(): the same parse in a consteval function, run twice (once to size, once to fill), into a fixed_grammar<Elements, Rules> of std::arrays: a grammar written in the program is a compile-time automaton table, and a malformed one is a compile error.

  • grammar_matcher: the set of pushdown stacks over a grammar_view (either form), each a list of element indices whose top is a terminal (llama.cpp's llama_grammar_advance_stack). accept_code_point, accept_string and accept_token advance it (UTF-8 decoded with a partial sequence carried across tokens, as llama.cpp's decode_utf8 / llama_partial_utf8); complete() says whether the text so far is a sentence.
  • The token mask: allows(token, piece) for one token, token_mask over a vocabulary into bools, and token_bitmask into 32-bit words (bit t % 32 of word t / 32), which apply_token_bitmask turns into -infinity logits. An end-of-generation token is allowed exactly when some stack is empty (the grammar is complete); an empty piece never is.
  • grammar_accepts(g, text): whether a whole string is a sentence; constexpr, so a small grammar can be checked in a static_assert.

When not to use it: for JSON that must follow a schema, write the schema and convert it (ml/json_schema.hpp).

// A yes/no answer with an optional reason, as GBNF (llama.cpp's grammar language)
constexpr std::string_view text = R"(root ::= answer (" because " reason)?
answer ::= "yes" | "no"
reason ::= [a-z ]+
)";
const auto parsed = ml::parse_grammar(text); // at run time: a result
const ml::grammar& g = *parsed;
// The same grammar at compile time, into std::array tables; a malformed one would not compile
constexpr auto fixed = ml::compile_grammar<R"(root ::= answer (" because " reason)?
answer ::= "yes" | "no"
reason ::= [a-z ]+
)">();
static_assert(ml::grammar_accepts(fixed, "yes"));
const bool yes = ml::grammar_accepts(g, "no because it rains");
const bool shout = ml::grammar_accepts(fixed, "YES");
// A malformed grammar: where and why
const auto bad = ml::parse_grammar(R"(root ::= "yes" | [a-z)");
// A vocabulary in which é (0xc3 0xa9) can come whole or split over two tokens; token 5 ends generation
const auto cafe = ml::parse_grammar(R"(root ::= "caf" ("é" | "e"))");
const std::array<std::string_view, 6> vocab{"caf", "\xc3\xa9", "\xc3", "\xa9", "e", "</s>"};
const std::array<std::uint32_t, 1> end{5};
ml::grammar_matcher m(*cafe);
m.accept_token(0, vocab[0]); // "caf"
std::array<bool, 6> allowed{};
m.token_mask(vocab, end, allowed); // é whole, its first byte, or e; not a lone continuation byte, not the end
m.accept_token(2, vocab[2]); // the first byte of é: the matcher carries the unfinished sequence
std::array<std::uint32_t, 1> bits{};
m.token_bitmask(vocab, end, bits); // only the continuation byte may follow
std::array<float, 6> logits{0.5f, 1.0f, 2.0f, 0.1f, 3.0f, 0.0f};
ml::apply_token_bitmask(std::span<const std::uint32_t>(bits), std::span<float>(logits));
m.accept_token(3, vocab[3]);
const bool done = m.accept_end(); // the sentence is complete: the end token is allowed

Relationships. ml/json_schema.hpp writes GBNF from a JSON schema; ml/sampling.hpp samples from the masked logits; result.hpp carries the parse error; fixed_string.hpp carries a compile-time grammar. Group: snicholls-core.

Implementations. One parser for both forms; the matcher reads either through grammar_view. Semantics follow llama.cpp at commit 39039aa: src/llama-grammar.cpp (llama_grammar_parser::parse_sequence, parse_alternates, parse_rule, parse, parse_char, parse_space, decode_utf8, llama_grammar_match_char, llama_grammar_match_partial_char, llama_grammar_advance_stack, llama_grammar_detect_left_recursion, llama_grammar_accept_token, llama_grammar_accept_str, llama_grammar_apply_impl, llama_grammar_reject_candidates), checked against tests/test-grammar-parser.cpp and tests/test-grammar-integration.cpp (tests/ml/grammar_test.cpp).

Guarantees. Everything is constexpr; compile_grammar is consteval. A grammar_matcher holds spans into the grammar, which must outlive it. The token mask agrees with accept_token: a token the mask allows can be accepted. Complexity: parsing is linear in the text plus the rules the repetitions generate (at most 2,000 per repetition, as llama.cpp); the mask is O(vocabulary · piece length · stacks).

Errors. parse_grammar returns grammar_error{position, message}: a syntax error at the byte where it was found; an undefined rule at its first reference; a missing root at the end of the text; left recursion at the first mention of the rule found to recurse. compile_grammar fails to compile on any of them. Preconditions, asserted: mask spans of the vocabulary's size.

Performance. Not benchmarked: the mask is a per-token simulation of the stacks, which a serving stack runs once per generated token on the CPU while the device computes the next logits; llama.cpp's own reject pass groups the candidates by code point instead, which is faster on large vocabularies but gives the same mask.

Tests and demos. tests/ml/grammar_test.cpp, demos/ml/grammar_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <concepts>, <cstddef>, <cstdint>, <limits>, <span>, <string>, <string_view>, <type_traits>, <utility>, <vector>, snicholls/core/fixed_string.hpp, snicholls/core/result.hpp (which includes <format>: heavier than it looks).

Known issues. Named token terminals (<think>) need a tokenizer and are an error: write <[id]>. llama.cpp left-factors rules after parsing (fewer parallel stacks, the same language); this header does not, so its stacks can be more numerous on grammars with many alternatives sharing a prefix. {m,n} with n < m is an error here (llama.cpp loops). At a token terminal reached in the middle of a piece, llama.cpp's reject pass compares the token's id while its accept_token drops the stack; the mask here follows accept_token, so the two never disagree. Compile-time grammars are limited by the compiler's evaluation steps, and the count depends on the standard library: under Clang a grammar the size of json.gbnf exceeds the default limit with Xcode 26's libc++ and with libstdc++ 15 (whose assertions run in constant evaluation), so raise it with -fconstexpr-steps=16777216 as core's tests do. GCC's default compiles it. Matching long strings in a static_assert may still not fit.

Status. Experimental, new in 0.17.0.
