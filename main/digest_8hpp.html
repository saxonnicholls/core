Detailed Description

digest<N>, the value every hash in core returns, and the concepts the hashes share.

Overview. A digest is N bytes and nothing else: digest<32> is what sha256::hash, keccak256::hash and blake3::hash return. It is an aggregate over std::array<std::byte, N>, trivially copyable and structural (so a digest can be a template argument), compared with == and <=>, written as lowercase hexadecimal by hex() without allocating, and read back by from_hex. Every operation is constexpr, so a digest computed by the compiler can be checked in a static_assert against its published hexadecimal:

// The compiler computes the digest and checks it against the published value
constexpr snicholls::digest<32> empty_sha256 = snicholls::sha256::hash("");
static_assert(empty_sha256 == snicholls::digest<32>::from_hex("e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"));
static_assert(empty_sha256.hex().view().starts_with("e3b0c442"));
// Any one-byte sequence is an input, and a digest is one too
const std::vector<std::uint8_t> bytes{'a', 'b', 'c'};
const auto once = snicholls::sha256::hash(bytes);
const auto twice = snicholls::sha256::hash(once); // Bitcoin's double SHA-256

The concepts are the hashes' vocabulary. hash_input<S> is any sequence of one-byte code units under core's string rules (reflect/string_traits.hpp): std::string, std::string_view, a string literal (its length is N - 1, never strlen), a const char* (a null pointer is empty), std::span<const std::byte>, std::vector<std::uint8_t>, std::array<std::byte, N>, char8_t text. Wider text (char16_t, wchar_t) is not an input: its bytes depend on the host's byte order. A digest<N> is accepted too, so a digest can be hashed or used as a key directly. hash_function<H> is the interface every fixed-length hash meets (update, finish, hash, block_size, digest_size), which hmac<H>, hkdf_* and pbkdf2_hmac are written against. md_hash<Policy> is the class behind SHA-1, every SHA-2 and RIPEMD-160; use it through those names.

Relationships. Returned by hash/sha1.hpp, hash/sha2.hpp, hash/sha3.hpp, hash/ripemd160.hpp, hash/blake2.hpp and hash/blake3.hpp; consumed by hash/hmac.hpp and hash/kdf.hpp. Compare digests that authenticate (a MAC, a password hash) with constant_time_equal (hash/secure.hpp), not ==, which stops at the first difference. The CRCs (hash/crc.hpp) return integers, as zlib does. Group: snicholls-core.

Guarantees. digest<N> is trivially copyable, standard layout, exactly N bytes with alignment 1 (static assertions in the tests). Every member is constexpr and noexcept. hex() writes 2N lowercase digits and a terminating '\0' into a value of its own; nothing allocates.

Errors. from_hex returns std::nullopt for text that is not exactly 2N hexadecimal digits (after an optional 0x / 0X); nothing throws.

Performance. Not benchmarked: a digest is an array of bytes, and hex() is a table lookup per nibble.

Tests and demos. tests/hash/digest_test.cpp, demos/hash/digest_demo.cpp.

Dependencies. <array>, <compare>, <concepts>, <cstddef>, <cstdint>, <optional>, <ostream>, <span>, <string_view>, <type_traits>, and reflect/string_access.hpp, reflect/string_traits.hpp, detail/hash_engine.hpp (the Merkle-Damgard engine behind md_hash).

Known issues. == on digests is not constant-time; see Relationships.

Status. New in 0.17.0. Experimental.
