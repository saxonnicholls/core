Detailed Description

snicholls::signer: anything that signs with a key it holds by id and never hands out, and publishes each key version's public key.

Overview. A signer signs on request (JWT access tokens, SIWE challenges, EVM transactions over a prehashed digest) with keys it holds by id, and never returns private key material. It publishes the public key of every version not destroyed, for a JWKS and for anyone who verifies. This is the concept half of a pair; the pure virtual half is signer_interface (interfaces/signer.hpp), with signer_adapter<S> and signer_ref. Keys are created, rotated and retired through the separate key_store capability (concepts/key_store.hpp), because a product may sign through a KMS it does not administer.

The contract (interfaces/signer_conformance.hpp checks it):

  • sign uses the key's current version and names that version in the signature.
  • An unknown key is capability_errc::not_found; a retired or destroyed key is capability_errc::conflict: it may no longer sign.
  • payload_kind::digest requires exactly 32 bytes (invalid_argument otherwise) and is refused with unsupported by algorithms that hash for themselves (EdDSA, HS256).
  • public_key_of answers for every version not destroyed, retired ones included (tokens they signed still verify); a symmetric algorithm (HS256) has no public key: unsupported.
  • The signature verifies under the published key with the named algorithm.
  • Errors follow the redaction rule of capability_error.hpp: no key material, payload or provider response in them.
memory_signer keys = memory_signer::deterministic(); // HS256, for tests only
const auto key = keys.create({signature_algorithm::hs256, "jwt-access"});
const auto sig = sign_token(keys, key->key_id.view(), "eyJhbGciOiJIUzI1NiJ9.e30");

Relationships. capability_error.hpp, capability_ids.hpp, concepts/key_store.hpp; the twin interfaces/signer.hpp, the reference interfaces/signer_reference.hpp, the kit interfaces/signer_conformance.hpp. Group: snicholls-core.

Implementations. memory_signer (interfaces/signer_reference.hpp, which is memory_key_store: HS256 over core's hmac<sha256>, for tests only). Above core, through constant-time elliptic-curve code: a device signer, a KMS server, AWS KMS. Core signs with no secret-bearing key of its own (CLAUDE.md "Never").

Guarantees. jose_name and is_asymmetric are constexpr and noexcept. Thread safety is the implementation's.

Errors. capability_error, as the contract says.

Performance. benchmarks/interfaces/key_store_reference_benchmark.cpp (the reference's sign).

Tests and demos. tests/concepts/signer_test.cpp, demos/concepts/signer_demo.cpp.

Dependencies. <concepts>, <cstddef>, <cstdint>, <span>, <string_view>, <vector>, capability_error.hpp, capability_ids.hpp.

Known issues. HS256 is in the enumeration for tests and the reference only; RS256 for verifying third-party OIDC tokens only (no signer of ours signs it).

Status. New in 0.23.0. Experimental until two real implementations pass the kit.
