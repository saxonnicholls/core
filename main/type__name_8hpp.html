Detailed Description

snicholls::type_name<T>(): a type's name as a compile-time string, for messages and printed type lists.

Overview. type_name<int>() is "int", type_name<std::vector<int>>() is the compiler's spelling of that type, as a std::string_view that is a constant expression: usable in a static_assert message, a log line, or acout's printing of a meta::type_list. There is no typeid, no RTTI and no demangler: the name is cut out of the compiler's own pretty-printed signature of this function.

// A type's name, as a constant: in a static_assert, or printed.
static_assert(snicholls::type_name<trading::order>() == "trading::order");
constexpr std::string_view side_name = snicholls::type_name<trading::side>();
std::printf(" %s, %s, %s\n", snicholls::type_name<int>().data(), side_name.data(),
std::string(snicholls::type_name<std::vector<trading::order>>()).c_str());

Relationships. acout.hpp prints a type_list with it; basic_type_registry binds names chosen by hand, which is what to use where the spelling must be the same on every compiler. Group: snicholls-core.

Guarantees. constexpr and noexcept; the view refers to static storage and is valid for the program. Fundamental types and types declared in a user namespace spell the same on GCC, Clang and MSVC (the class-keys MSVC writes, struct, class and enum, and the standard libraries' inline namespaces are stripped, as whole words only). Standard templates spell as the compiler writes them and differ: std::string is std::basic_string<char> on GCC and Clang and shows its traits and allocator on MSVC.

Errors. None. A compiler that provides neither __PRETTY_FUNCTION__ nor __FUNCSIG__ gets "?".

Performance. Compile time only.

Tests and demos. tests/meta/type_name_test.cpp, demos/meta/type_name_demo.cpp.

Dependencies. <array>, <cstddef>, <string_view>.

Known issues. The spelling of a template specialisation is the compiler's, with the library's inline namespaces removed but default template arguments shown where the compiler shows them (std::vector<int, std::allocator<int>> on GCC and MSVC, std::vector<int> on Clang). Compare against a fixed string only for the portable cases above.

Status. New in 0.5.0.
