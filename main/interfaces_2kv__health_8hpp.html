Detailed Description

The health capability, virtual form: kv_health_interface and kv_health_adapter.

Overview. ping() and diagnostics() as pure virtual functions, for a store chosen at run time. The interface models the concept kv_health (concepts/kv_health.hpp); kv_health_adapter<S> puts any model of the concept behind the interface, owning it or referring to it (S&).

// The supervisor sees only the interface; adapters put any model of kv_health behind it.
const kv_health_adapter<reference_key_value_store&> primary_health{primary};
const kv_health_adapter<reference_key_value_store&> replica_health{replica};
const kv_health_adapter driver_health{throwing_probe{}};
const std::vector<std::reference_wrapper<const kv_health_interface>> watched{primary_health, replica_health, driver_health};
std::size_t up = 0;
for (const kv_health_interface& store : watched) {
const auto ping = store.ping();
const auto d = store.diagnostics();
std::printf(" %s, %llu keys\n", ping.is_ok() ? "up" : "down",
static_cast<unsigned long long>(d.is_ok() ? d->keys.value_or(0) : 0));
up += ping.is_ok();
}

Relationships. The concept and kv_diagnostics: concepts/kv_health.hpp. The store contract: key_value_store_interface (interfaces/key_value_store.hpp); a backend derives from both, and a caller holding the store asks for health with dynamic_cast<const kv_health_interface*>. Group: snicholls-core.

Implementations / variants. kv_health_adapter<S>; backends above core derive directly.

Guarantees. Those of the concept. The adapter lets no exception of the model through: std::bad_alloc becomes kv_errc::out_of_memory, anything else kv_errc::backend.

Errors. As the concept.

Examples. See the overview.

Performance. Not benchmarked: one call per probe.

Tests and demos. tests/interfaces/kv_health_test.cpp, demos/interfaces/kv_health_demo.cpp.

Dependencies. <type_traits>, <utility>, and concepts/kv_health.hpp, interfaces/key_value_store.hpp (for the exception translation).

Known issues. None known.

Status. New in 0.22.0. Experimental.
