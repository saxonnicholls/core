Detailed Description

snicholls::signal window functions - rectangular, Hann, Hamming, Blackman, Blackman-Harris, Kaiser, Gaussian, Tukey - periodic or symmetric, as constexpr values, filled spans and compile-time tables; and the COLA and NOLA conditions of an overlap-add.

Overview. Each window is a small type whose at<T>(i, m) is the value at sample i with denominator m: the formulas of scipy.signal.windows (which PyTorch's *_window share), with x = i / m:

Window w(i)
rectangular 1
hann 0.5 - 0.5 cos 2 pi x
hamming 0.54 - 0.46 cos 2 pi x
blackman 0.42 - 0.5 cos 2 pi x + 0.08 cos 4 pi x
blackman_harris 0.35875 - 0.48829 cos 2 pi x + 0.14128 cos 4 pi x - 0.01168 cos 6 pi x (four terms, minimum sidelobe)
kaiser{beta} I0(beta sqrt(1 - (2x - 1)^2)) / I0(beta)
gaussian{sigma} exp(-(i - m / 2)^2 / (2 sigma^2)), sigma in samples
tukey{alpha} a cosine taper over alpha / 2 of each end, flat between (scipy's index arithmetic)

A symmetric window of length n has m = n - 1 and is the one FIR design uses; a periodic window has m = n (a symmetric window of n + 1 points without its last), the one spectral analysis uses, so that overlap-adding it at a hop of n / 2 (Hann) is constant. window_symmetry::periodic is the default, as in PyTorch and scipy.signal.get_window. A window of length 1 is {1} either way.

fill_window(out, w, symmetry) fills a span; make_window<T, N>(w, symmetry) returns a std::array, so constexpr auto hann400 = make_window<float, 400>(hann{}); is computed by the compiler. is_cola and is_nola check that a window and hop overlap-add to a constant (constant overlap-add, for reconstruction without dividing) or to something non-zero everywhere (nonzero overlap-add, which istft needs), as scipy.signal.check_COLA and check_NOLA do.

// Whisper's window, written by the compiler: torch.hann_window(400), periodic.
constexpr auto hann400 = s::make_window<float, 400>(s::hann{});
static_assert(hann400[0] == 0.0f && hann400[200] == 1.0f);
// A symmetric Kaiser window for filter design, and the other windows, at run time into any span.
constexpr auto kaiser31 = s::make_window<double, 31>(s::kaiser{8.6}, s::window_symmetry::symmetric);
std::vector<double> w(9);
s::fill_window(std::span<double>(w), s::blackman_harris{}, s::window_symmetry::symmetric);
const double tukey_mid = s::window_value<double>(s::tukey{0.5}, 4, 9, s::window_symmetry::symmetric);
// Reconstruction conditions for an overlap-add at a hop.
const bool cola = s::is_cola<float>(hann400, 200); // Hann at half overlap sums to a constant
const bool nola = s::is_nola<float>(hann400, 160); // Whisper's hop is not COLA, but invertible

Relationships. signal/stft.hpp, signal/fir.hpp and signal/resample.hpp take these windows; math::bessel_i0 is Kaiser's. Group: snicholls-core.

Implementations. One formula per window, in compute_t<T> (double for float) and rounded once.

Guarantees. Every function is constexpr and noexcept; the window types are trivially copyable and structural. The cosine sums, Kaiser and Gaussian are symmetric to the bit in their symmetric form (w(i) is computed from min(i, m - i)); Tukey follows scipy's index arithmetic. Values agree with scipy's to a few units in the last place (scipy sums the cosines in another order). Complexity: linear in the length; is_cola and is_nola are linear in the window.

Errors. None; a Kaiser beta beyond about 700 overflows I0 to infinity and gives NaN.

Performance. Not benchmarked: a window is built once, usually at compile time.

Tests and demos. tests/signal/window_test.cpp (scipy's values, the symmetries, compile-time tables, COLA and NOLA), demos/signal/window_demo.cpp.

Dependencies. <array>, <cstddef>, <span>, snicholls/core/math/constexpr_math.hpp, signal/complex.hpp (for compute_t).

Known issues. scipy's Tukey window computes its taper's width with floor, so two lengths that differ by one can have tapers of the same width; this is copied, not corrected.

Status. Experimental, new in 0.17.0.
