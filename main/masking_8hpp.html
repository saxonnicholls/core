Detailed Description

snicholls::ml masks for joint embedding predictive architectures: I-JEPA's multi-block sampler, V-JEPA's spatio-temporal tubes, random masks, and the collation of index lists across a batch, deterministic from (seed, step, sample).

Overview. A JEPA hides part of each sample and predicts the representations of the hidden part from the rest (TRAINING.md T11). Which tokens are hidden is the mask; this header samples them on a grid of tokens (token_grid: frame groups, rows, columns, raster order, as ml/patch.hpp numbers them) and writes, for each sample, the sorted index lists of its context tokens (what the context encoder sees) and target tokens (what the predictor predicts).

  • ijepa_masks(config, seed, step, sample, context, targets, target_counts): I-JEPA's multi-block mask (Assran et al., 2023, and its code's MaskCollator, read 2026-11-19): M target blocks (4 by default) of a scale of the grid in [0.15, 0.2] and an aspect ratio in [0.75, 1.5], then one context block of scale [0.85, 1.0], square, with every target removed from it. A block is accepted only with more than min_keep (10) tokens; if the context fails 20 times in a row one target stops constraining it (the code's tries). The block sizes are drawn once per step, shared by the batch, as the code does; the positions per sample.
  • vjepa_masks(config, seed, step, sample, context, targets): V-JEPA's multi-block mask in space and time (Bardes et al., 2024, and its code's multiblock3d, read 2026-11-19): blocks boxes of a spatial scale, an aspect ratio and a temporal scale (1 by default: each box spans every frame group, a tube), their union the targets and its complement the context, resampled if the context is empty. V-JEPA trains with two such masks at once, 8 blocks of scale 0.15 ("short range") and 2 of scale 0.7 ("long range"): vjepa_short_range and vjepa_long_range.
  • random_masks(tokens, ratio, seed, step, sample, context, targets): a uniformly random fraction ratio of the tokens hidden (MAE's random masking, len_keep = int(tokens · (1 - ratio))).
  • common_count(counts) and collate_indices(lists, stride, counts, width, out, lengths): the counts differ from sample to sample, and a batch needs one shape. The papers keep the first common_count (the smallest count) of each sorted list, so every sample has the same number of tokens (width = common_count(counts)); or pass a wider width and the lists are padded (with their last index) and lengths says how many are real, for the attention layer's key-padding mask (attention_activations::lengths) and the losses.

Determinism. Every draw comes from core's stats::wyrand streams: key = wyrand::stream(seed, step)(), the step's block sizes from wyrand::stream(key, 0) and sample s's positions from wyrand::stream(key, s + 1), with stats::uniform_real for the scales and stats::uniform_index for the positions. The same (seed, step, sample) gives the same mask on every machine, whichever worker samples it and in whatever order.

A block's size, from one uniform draw u shared by its ranges as I-JEPA's _sample_block_size does: the scale s = s_min + u (s_max - s_min), the aspect ratio a and temporal scale likewise; keep = int(rows · columns · s), h = round(sqrt(keep · a)), w = round(sqrt(keep / a)) (rounding halves to even, as Python's round), and frames = max(1, int(frame groups · temporal)). Under block_rule::ijepa h and w are lowered until they are below the grid's rows and columns and a block's top-left corner is drawn from [0, rows - h) (the code's randint(0, height - h)); under block_rule::vjepa they are at most the grid's and the corner is drawn from [0, rows - h], the first frame from [0, frame groups - frames]. Neither paper lets a block be empty; this header keeps h, w and frames at least 1.

// I-JEPA's mask for sample 0 of step 5 (the paper's settings): 4 target blocks and a context without them
const ml::ijepa_mask_config config{};
std::vector<std::uint32_t> context(196), targets(4 * 196);
std::array<std::size_t, 4> target_counts{};
const ml::mask_counts counts = ml::ijepa_masks(config, 2026, 5, 0, context, targets, target_counts);
// The size every target block of step 5 has, from the step's draw
const ml::block_extent extent = ml::sample_block_extent(config.grid, config.targets, 0.5, ml::block_rule::ijepa);
// A batch of four: the context counts differ, so cut every list to the smallest (the papers' rule) ...
std::vector<std::uint32_t> lists(4 * 196);
std::array<std::size_t, 4> context_counts{}, unused{};
std::vector<std::uint32_t> scratch(4 * 196);
for (std::size_t s = 0; s < 4; ++s)
context_counts[s] = ml::ijepa_masks(config, 2026, 5, s, std::span<std::uint32_t>(lists).subspan(s * 196, 196), scratch, unused).context;
const std::size_t width = ml::common_count(context_counts);
std::vector<std::uint32_t> equal(4 * width);
ml::collate_indices(lists, 196, context_counts, width, equal, {});
// ... or pad them to the longest and mask the padding (attention_activations::lengths, the losses' lengths)
const std::size_t longest = std::max(std::max(context_counts[0], context_counts[1]), std::max(context_counts[2], context_counts[3]));
std::vector<std::uint32_t> padded(4 * longest);
std::array<std::size_t, 4> lengths{};
ml::collate_indices(lists, 196, context_counts, longest, padded, lengths);

Relationships. stats/random.hpp (the streams), ml/gather.hpp (the lists select rows), ml/patch.hpp (the token grid), ml/jepa.hpp, ml/attention_layer.hpp (lengths). TRAINING.md T11. Group: snicholls-core.

Implementations. One each, on the host: masks are drawn by the data loader, before the batch moves to a device.

Guarantees. constexpr, no allocation. Lists are sorted ascending without repeats; a sample's context and targets are disjoint (I-JEPA's unless allow_overlap); each I-JEPA target block has its sampled size (so its scale and aspect ratio within their ranges, up to rounding); the union of the lists is the grid for vjepa_masks and random_masks. O(blocks · tokens) per sample.

Errors. Preconditions, asserted: context holds at least the grid's tokens, targets (ijepa_masks) blocks · tokens; at most max_mask_blocks blocks; under I-JEPA a target block's size above min_keep (else no block could be accepted, as in the paper's code); a ratio in [0, 1].

Performance. Not benchmarked: once per sample in the data loader, O(tokens · blocks).

Tests and demos. tests/ml/masking_test.cpp, demos/ml/masking_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <cstddef>, <cstdint>, <span>, snicholls/core/math/constexpr_math.hpp, stats/random.hpp (which includes <random> for its concept).

Known issues. The draws are core's, not PyTorch's: the same configuration gives masks of the papers' distribution, not their exact masks. V-JEPA's use of one draw for all three ranges is assumed from I-JEPA's code; with V-JEPA's ranges (a fixed scale, a fixed temporal scale) only the aspect ratio varies, so it does not matter.

Status. Experimental, new in 0.16.0.
