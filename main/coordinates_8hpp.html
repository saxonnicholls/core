Detailed Description

snicholls::geometry::cart_to_polar, cart_to_sphere, rotation_z and friends: Cartesian, polar and spherical coordinates, and rotations, in Stone Soup's conventions.

Overview. Sensors measure range and angles; targets move in Cartesian space. These convert between the two, each returning a fixed_vector:

  • cart_to_polar(x, y) → (range, bearing), bearing atan2(y, x); polar_to_cart(range, bearing) → (x, y).
  • cart_to_sphere(x, y, z) → (range, bearing, elevation), elevation asin(z / range) from the x-y plane; sphere_to_cart(range, bearing, elevation); cart_to_angles(x, y, z) → (bearing, elevation).
  • cart_to_az_el_range(x, y, z) → (azimuth, elevation, range), the radar-face convention in which the boresight is z: azimuth asin(x / r), elevation asin(y / r); az_el_range_to_cart.
  • rotation_x, rotation_y, rotation_z(θ): the 3 x 3 rotations about each axis; rotation_2d(θ); sensor_rotation(roll, pitch, yaw) = R_z(-yaw) R_y(pitch) R_x(-roll), the map from the world into a sensor's frame (Stone Soup's build_rotation_matrix).

At the origin, range is 0 and the angles are 0 (not NaN).

// A sensor yawed 30° and pitched 5°; a target 1 km north-east and 100 m up, in the world frame
const auto to_sensor = geo::sensor_rotation(0.0, 5 * pi / 180, 30 * pi / 180);
const auto target = la::make_vector(707.0, 707.0, 100.0);
const auto local = to_sensor * target;
// What the sensor measures: (range, bearing, elevation)
const auto rbe = geo::cart_to_sphere(local[0], local[1], local[2]);
// ... and back, through the transpose of the rotation
const auto back = la::transpose(to_sensor) * geo::sphere_to_cart(rbe[0], rbe[1], rbe[2]);

Relationships. linalg/fixed.hpp, math/constexpr_math.hpp; geometry/angle.hpp for wrapping; tracking/measurement.hpp builds its sensor models on these. Group: snicholls-core.

Guarantees. constexpr, noexcept for the standard floating-point types, no allocation. The rotations are orthogonal with determinant 1 to rounding.

Errors. None. A point exactly at the origin has zero angles; az_el_range_to_cart takes the square root of max(0, 1 - sin² az - sin² el), so an impossible pair of angles maps onto the face's edge rather than to NaN.

Performance. Not benchmarked: a square root and one or two trigonometric functions each.

Tests and demos. tests/geometry/coordinates_test.cpp, demos/geometry/coordinates_demo.cpp.

Dependencies. linalg/fixed.hpp, math/constexpr_math.hpp.

Known issues. None known.

Status. Experimental, new in 0.19.0.
