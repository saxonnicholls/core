Detailed Description

snicholls::ml::transformer_config: the architecture of a transformer layer as one compile-time value, from which every size is a constant.

Overview. Transformers differ in a handful of choices: the widths, how many key-value heads the query heads share, the normalisation, the MLP's activation, the positional encoding, a sliding window, a soft cap on the scores, biases. transformer_config holds them as one structural aggregate, passed as a template parameter to attention_forward, mlp_forward and block_forward, so every size is a constant: scratch is fixed-size, loops are bounded, nothing is allocated, and one layer of code serves GPT-2, Llama and nanochat. Multi-head, grouped-query and multi-query attention are one code path with n_kv_heads equal to n_heads, a divisor of it, or 1.

// Grouped-query attention: 8 query heads share 2 key-value heads; RMS norm, SwiGLU, RoPE, a sliding window of 512
constexpr ml::transformer_config mine{.d_model = 512, .n_heads = 8, .n_kv_heads = 2, .head_dim = 64, .d_ff = 1536,
.norm = ml::norm_kind::rms, .norm_eps = 1e-6, .mlp = ml::mlp_kind::swiglu,
.rope = ml::rope_kind::half, .rope_base = 10000, .window = 512};
static_assert(ml::valid(mine)); // every template taking a configuration checks this too
// Read a floating-point member through its reader, which evaluates it at compile time
constexpr float eps = ml::norm_eps_v<mine, float>;

Relationships. ml/linear.hpp, ml/mlp.hpp, ml/kv_cache.hpp, ml/attention_layer.hpp, ml/transformer_block.hpp; the plan is INFERENCE.md. Group: snicholls-core.

Implementations. One. The presets (gpt2_small, llama3_8b, nanochat_d20) are the shapes of those models.

Guarantees. constexpr, trivially copyable, structural (usable as a template argument). valid(c) checks the invariants below; every class and function templated on a configuration rejects an invalid one at compile time.

Errors. None at run time. A configuration whose n_heads is not a multiple of n_kv_heads, with an odd head_dim under RoPE, or with a zero width is a compile error (static_assert with a snicholls::ml:: message).

Performance. Not applicable: a value read by the compiler.

Tests and demos. tests/ml/transformer_config_test.cpp, demos/ml/transformer_config_demo.cpp.

Dependencies. <cstddef>, snicholls/core/math/constexpr_math.hpp, snicholls/core/ml/rope.hpp (rope_layout).

Known issues. Clang (Apple clang 17, Clang 18) miscompiles a run-time read of a double member of a class-type template argument: it loads garbage (C.norm_eps reads as 6e-314), while the same read in a constant expression is right, and GCC is right in both. Read the floating-point members through norm_eps_v, rope_base_v and attention_softcap_v, which evaluate them at compile time, never as C.norm_eps in code that runs; every header here does. Wrapping the value in a class (its bits as an integer) is worse: Clang 18 crashes.

Status. Experimental, new in 0.8.0.
