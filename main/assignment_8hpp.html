Detailed Description

snicholls::combinatorics::linear_assignment and assignment_solver: the minimum-cost matching of rows to columns of a cost matrix (the "Hungarian" problem), with forbidden pairs.

Overview. Given an R x C matrix of costs, choose one column for each row (or one row for each column if there are fewer columns), no column twice, minimising the total. That is global nearest-neighbour data association (tracks x detections, costs from Mahalanobis distances or negative log-likelihoods), sensor-to-target tasking and the matching inside OSPA and GOSPA. An entry of +∞ forbids the pair (outside the gate).

  • linear_assignment(cost) for a fixed_matrix<T, R, C>: everything on the stack, sized at compile time.
  • assignment_solver<T, MaxRows, MaxCols>: a reusable solver whose working arrays are sized at compile time, for matrices known only at run time (row-major span, rows and cols up to the maxima). Construct it once (on the heap if it is large) and call solve every scan.
  • objective::maximise turns it into a maximum-weight matching (costs are negated inside).

The result assigns every row when R ≤ C (and every column when R > C); the other side has unassigned entries, -1. To let a row stay unassigned at a price (a missed detection), append one dummy column per row with that price on its own row and +∞ elsewhere, the standard construction.

// Three tracks (rows) against two detections (columns 0, 1), costs from the gating distance. Columns 2..4 are
// one dummy per track: the price of a missed detection on its own row, +inf (forbidden) elsewhere
constexpr double miss = 4.0;
const la::fixed_matrix<double, 3, 5> cost{{1.0, 6.0, miss, inf, inf,
inf, 2.5, inf, miss, inf, // track 1 is outside detection 0's gate
2.0, 3.0, inf, inf, miss}};
const auto a = cb::linear_assignment(cost);
// Track 0 takes detection 0, track 1 detection 1, track 2 is missed: 1 + 2.5 + 4

Relationships. linalg/fixed.hpp (fixed_matrix), result.hpp. Used by metric/sets.hpp (OSPA, GOSPA) and by global-nearest-neighbour association. Group: snicholls-core.

Implementations. Shortest augmenting paths with dual variables (Jonker-Volgenant style), as in Crouse, "On implementing 2D rectangular assignment algorithms", IEEE TAES 2016, the algorithm of SciPy's linear_sum_assignment. One Dijkstra-like pass per row of the smaller side; ties prefer an unassigned column. A matrix with more rows than columns is solved through its transpose, read in place.

Guarantees. constexpr, noexcept for the standard floating-point types, no allocation, no recursion. The result is optimal. Complexity O(n² m) for n = min(R, C), m = max(R, C); working storage O(R + C).

Errors. assignment_error::infeasible: no complete matching with finite total cost exists (some row's allowed columns are all taken). assignment_error::invalid_cost: a NaN or -∞. assignment_error::too_large: rows or cols beyond the solver's maxima, or a span shorter than rows * cols. On error, row_to_col is unspecified.

Performance. Uniform costs (benchmarks/combinatorics/assignment_benchmark.cpp; Release, Apple clang 17, Xeon W-3245, 2026-11-23): 64 x 64 in 100 µs, 256 x 256 in 1.66 ms, and 256 x 256 with 90% of the pairs forbidden in 1.36 ms. Each solution is checked first (complete, and no pair of rows gains by swapping columns).

Tests and demos. tests/combinatorics/assignment_test.cpp, demos/combinatorics/assignment_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <limits>, <span>, linalg/fixed.hpp, result.hpp.

Known issues. None known.

Status. Experimental, new in 0.19.0.
