Detailed Description

snicholls::utc<Duration>: a UTC instant.

snicholls::utc<Duration> - a UTC instant: exactly one std::chrono::sys_time<Duration>, nothing else.

auto t = snicholls::utc<>::now(); // nanoseconds on every platform
auto q = snicholls::utc<>::from_unix_millis(1714486985123); // market data (Massive: Unix ms)
snicholls::utc<> d = std::chrono::sys_days{2025y / April / 30} + 14h; // lossless std::chrono converts implicitly
q.unix_millis(); q.date(); q.time_of_day(); q.weekday(); q.floor<std::chrono::days>();
q + 5ms; q - t; q < t; std::hash<snicholls::utc<>>{}(q);

Text (RFC 3339) is in time/rfc3339.hpp, std::format in time/utc_format.hpp.

Semantics:

  • POSIX / Unix time, i.e. std::chrono::system_clock's epoch and std::chrono::sys_time: every day has 86 400 s. Leap seconds are not representable (as in sys_time, time_t and every Unix-ms feed); a difference across a leap second is one SI second short. This is NOT std::chrono::utc_time, which counts leap seconds.
  • The default Duration is nanoseconds on every platform (never system_clock::duration, which is us on macOS
    and ns on Linux). utc<> spans 1677-09-21T00:12:43.145224192Z .. 2262-04-11T23:47:16.854775807Z;
    utc_us spans +-292 277 years.
  • Default construction is the epoch (1970-01-01T00:00:00Z), like std::chrono::time_point. Never "now".
  • Conversions to whole units floor (round toward the past), so instants before 1970 are correct.
  • sizeof == sizeof(Duration::rep), trivially copyable, standard layout. Everything is constexpr and noexcept except now().

Portability. Identical on macOS (libc++), Linux (libstdc++, GCC and Clang, x86-64 and ARM64) and Windows (MSVC), and checked by the same tests on each against committed fixtures generated from Python's datetime and exact integer arithmetic (tests/fixtures/time/, scripts/generate_time_fixtures.py), never from core's own output:

  • the ticks of every instant, at every resolution; every from_unix_* / unix_* conversion, flooring negative values toward the past;
  • the RFC 3339 text written by to_chars / to_text / to_string / operator<< / std::format("{}"), at the resolution's own digits and at every precision 0..9; and what parse_utc / parse_unix / parse_date accept, reject (with which std::errc) and return, strict and lenient. No text form reads the locale (tested with an odd global and stream locale) or goes through double;
  • the calendar: civil.hpp and business_days.hpp for every day of years 0001..9999;
  • to_timespec / from_timespec (a 64-bit time_t is required and asserted; tv_nsec, a long that is 32-bit on Windows, only holds [0, 1e9)).

Not identical, by nature:

  • now() reads std::chrono::system_clock, whose tick is 1 us on libc++, 1 ns on libstdc++ and 100 ns on MSVC. utc<>::now() is always nanoseconds, so on macOS its last three digits are zero; coarser resolutions floor. The value is the clock's own tick, never interpolated (tested).
  • std::hash<utc<D>> is the standard library's hash of the tick count: never persist or compare it across builds.
  • std::format with a chrono spec ({:F T}) is forwarded to the standard library's formatter. Without the L flag it uses the C locale and is identical (tested); with L it follows the locale, as the standard says.
  • solar.hpp uses the platform's <cmath>, so its results agree to the published accuracy (0.01 degree), not bit for bit.
