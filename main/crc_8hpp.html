Detailed Description

CRC-32 (zlib's), CRC-32C (Castagnoli) and CRC-64/XZ, with their tables built by the compiler.

Overview. Cyclic redundancy checks detect accidental corruption: a flipped bit on a wire or a disk, a truncated file. They are not hashes against an adversary, who can forge any CRC. Three are provided, each the parameterisation its users mean:

Name Polynomial (reflected) Check value of "123456789" Used by
crc32 0xEDB88320 0xCBF43926 zlib, gzip, PNG, ZIP, Ethernet, SATA
crc32c 0x82F63B78 0xE3069283 iSCSI, SCTP, ext4, Btrfs, LevelDB, RocksDB, Kafka, gRPC
crc64_xz 0xC96C5795D7870F42 0x995DC9BBDF1939FA xz, 7-Zip (CRC-64/ECMA-182 reflected)

Each is a class with the incremental interface of the hashes (update, finish) and a one-shot hash, returning the integer as zlib does rather than a digest. resume(crc) continues from a finished value, which is zlib's crc32(crc, buf, len): crc32::resume(crc32::hash(a)).update(b).finish() == crc32::hash(a + b).

// Each CRC's catalogue check value, computed by the compiler
static_assert(snicholls::crc32::hash("123456789") == 0xCBF43926u);
static_assert(snicholls::crc32c::hash("123456789") == 0xE3069283u);
static_assert(snicholls::crc64_xz::hash("123456789") == 0x995DC9BBDF1939FAull);
// zlib's crc32(crc, buf, len): continue from a finished value
std::uint32_t running_crc(std::uint32_t crc_so_far, const std::string& more)
{
return snicholls::crc32::resume(crc_so_far).update(more).finish();
}

The tables (eight of 256 entries each, for slicing-by-8) are constexpr values the compiler builds from the polynomial; every function is constexpr, so a CRC of a literal is a constant.

Relationships. hash_input (hash/digest.hpp); fnv1a_64 and wyhash (hash/fnv.hpp, hash/wyhash.hpp) for hash tables; sha256 or blake3 where tampering must be detected. Group: snicholls-core.

Implementations / variants. reflected_crc<T, Poly, Init, XorOut> is the one class (a reflected CRC with equal input and output reflection, which all three are); the names above are its aliases.

Guarantees. Every member is constexpr and noexcept; no allocation; a CRC object is one integer. Complexity: eight table lookups per eight bytes, one per remaining byte.

Errors. None.

Examples. Above; demos/hash/crc_demo.cpp.

Performance. benchmarks/hash/crc_benchmark.cpp: against the same slicing-by-8 written by hand and the byte-at-a-time loop, after a fairness check. Release, Apple clang 17, Xeon W-3245 (a shared machine), 2026-11-20, 16 KiB / 64-byte messages: CRC-32 core 2.11 / 2.76 GB/s, hand 2.14 / 2.84, byte at a time 0.49 / 0.57; CRC-32C and CRC-64/XZ alike. Hardware CRC-32C (SSE4.2 crc32, ARMv8 crc32c) and zlib's PCLMUL / PMULL folding are several times faster; core has no platform headers, so a library above core may add them, checked against these definitions.

Tests and demos. tests/hash/crc_test.cpp (the catalogue's check values, Python's zlib.crc32 and crcmod on random lengths, every split, resume), demos/hash/crc_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, hash/digest.hpp.

Known issues. CRC-64 has several incompatible parameterisations (ECMA-182 unreflected as in CRC-64/ECMA-182, CRC-64/GO-ISO, CRC-64/NVME); only CRC-64/XZ is provided.

Status. New in 0.17.0. Experimental.
