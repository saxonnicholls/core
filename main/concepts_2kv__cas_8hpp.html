Detailed Description

The compare-and-swap capability of a store, static form: kv_cas<S>.

Overview. s.compare_and_swap(key, expected, desired) replaces the value of key with desired only when it is exactly expected, atomically: what a lease, a lock with a fencing token, an idempotency record or an optimistic update needs, and what insert (absent only) and apply (no conditions) cannot express. Either side may be std::nullopt: expected absent means "only if the key is absent", desired absent means "erase it". It returns true when it swapped and false when the value was something else, in which case nothing changed. kv_compare_and_swap(store, key, expected, desired) takes any one-byte sequences.

reference_key_value_store store;
const bool a = take(store, "worker-a"); // free: taken
const bool b_took = take(store, "worker-b"); // held: refused, nothing changed
const auto released = store.compare_and_swap(b("lease/settlement"), b("worker-a"), std::nullopt); // only its owner releases it

Relationships. concepts/key_value_store.hpp (kv_bytes, kv_errc); the virtual twin kv_cas_interface and the kit check_kv_cas (interfaces/kv_cas.hpp); reference_key_value_store implements it. Group: snicholls-core.

Implementations / variants. reference_key_value_store; above core, a SQL store (UPDATE ... WHERE v = ?), RocksDB (a transaction) or Redis (WATCH/MULTI).

Guarantees. Atomic with respect to every other write of the store; a swap that changes the store advances its sequence(), a refused one does not.

Errors. The store's kv_errc (unavailable, io, read_only, ...); a mismatch is false, not an error.

Performance. Not benchmarked: one map lookup in the reference.
