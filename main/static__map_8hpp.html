Detailed Description

containers::static_map and static_set: tables sorted at compile time, looked up in O(log n), duplicates refused.

Overview. A table known when the program is written (instrument codes to tick sizes, venue identifiers to names, currency codes to minor units) should cost nothing to build and little to search. static_map takes its entries in any order, sorts them at compile time, and finds a key by binary search; two entries with one key are a compile error when the map is a constant. static_set is the same for keys alone. The constructors are consteval: a map is always sorted and checked by the compiler. constexpr_map is the linear, two-way table for tens of entries; this is for hundreds or thousands, or when the order of declaration should not matter.

// Written in any order, sorted and checked for duplicates by the compiler, found by binary search.
constexpr snicholls::containers::static_map<std::string_view, int, 4> minor_units{
std::array<std::pair<std::string_view, int>, 4>{{{"usd", 2}, {"jpy", 0}, {"bhd", 3}, {"eur", 2}}}};
static_assert(minor_units.at("jpy"sv) == 0);

Relationships. constexpr_map.hpp; meta/enums.hpp for enumeration names. Group: snicholls-core.

Guarantees. constexpr throughout; find is O(log n) and noexcept when comparing keys is; iteration is in key order; no allocation.

Errors. at throws std::out_of_range for a missing key; a duplicate key is a compile error.

Performance. benchmarks/containers/perfect_map_benchmark.cpp: 32,768 lookups of 512 four-letter codes, Release, Apple clang 17, Xeon W-3245, 2026-11-08: 2.81 ms, against 2.90 ms for a binary search written by hand; perfect_map takes 211 us for the same lookups and is the choice when order is not needed.

Tests and demos. tests/containers/static_map_test.cpp, demos/containers/static_map_demo.cpp.

Dependencies. <algorithm>, <array>, <cstddef>, <functional>, <stdexcept>, <utility>.

Known issues. Keys and values must be default-constructible and copyable (the entries live in a std::array). The comparison is std::less<> by default.

Status. New in 0.5.0.
