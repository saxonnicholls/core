Detailed Description

snicholls::ml spatial operations of vision and audio encoders: max and average pooling of rank 1 to 3 with backward, upscaling (nearest, bilinear, bicubic) with its adjoint, zero and reflect padding, roll, SAM's window partition and decomposed relative-position bias, all constexpr over the caller's spans.

Overview. The data movement and resampling around the convolutions of ml/conv.hpp, as ggml computes them, for one sample of [channels][spatial...] (row-major, the last dimension fastest):

  • pool_shape<Rank> and pool_forward(s, kind, x, y) / pool_backward(s, kind, x, dy, dx): max or average over windows of kernel taps every stride, padding on both sides; output (in + 2p - k) / s + 1. The maximum ignores the padding (a window entirely in it gives the lowest finite value, ggml's -FLT_MAX); its gradient goes to the first maximal tap. The average divides by the window's taps inside the input (count_padding = false, ggml's pool_1d) or by every tap (true, ggml's pool_2d): pool_1d_shape and pool_2d_shape make each ggml's way.
  • upscale(mode, align_corners, x, in_h, in_w, y, out_h, out_w) resizes each [h][w] plane: nearest (floor(i / scale)), bilinear and bicubic (Keys' kernel with a = -0.75, PyTorch's) at pixel offset 0.5, or with corners aligned (offset 0, scale (out - 1) / (in - 1)), borders clamped: ggml's ggml_interpolate modes. upscale_backward is the adjoint (every output's gradient spread back with the same weights).
  • pad(extents, left, right, x, y) adds zeros on each side of each dimension (ggml's ggml_pad_ext); pad_backward crops (its adjoint). pad_reflect_1d(rows, width, left, right, x, y) mirrors each row without repeating its edge (ggml's ggml_pad_reflect_1d, PyTorch's reflect); pad_reflect_1d_backward folds the mirrored gradients back.
  • roll(extents, shifts, x, y): y[i] = x[(i - shift) mod n] per dimension (ggml's ggml_roll, torch.roll); its adjoint is the roll by -shift.
  • window_partition(h, w, c, window, x, windows) cuts [h][w][c] into ceil(h / window) · ceil(w / window) windows [window][window][c], zero-padded at the bottom and right (SAM, ggml's ggml_win_part); window_unpartition (ggml_win_unpart) crops them back and is the partition's adjoint, and the other way round.
  • SAM's decomposed relative positions: rel_pos_gather(rel, size, out) gives out[q][k] = rel[q - k + size - 1] (ggml's ggml_get_rel_pos, query and key sizes equal); rel_pos_scores(q, rh, rw, h, w, c, rel_h, rel_w) the einsums rel_h[qh][qw][kh] = q · Rh[qh][kh] and rel_w[qh][qw][kw] = q · Rw[qw][kw]; add_rel_pos(attn, rel_h, rel_w, h, w) adds them to the (h w) x (h w) scores (ggml's ggml_add_rel_pos), and add_rel_pos_backward sums the scores' gradient back into them.
// A 4x4 plane, 2x2 pools at stride 2 (ggml's pool_2d: the average counts every tap).
std::array<float, 16> x{};
for (std::size_t i = 0; i < 16; ++i)
x[i] = static_cast<float>(i);
constexpr auto pool = ml::pool_2d_shape(1, 4, 4, 2, 2, 2, 2);
std::array<float, pool.y_size()> mx{}, avg{};
ml::pool_forward(pool, ml::pool_kind::max, x, mx);
ml::pool_forward(pool, ml::pool_kind::avg, x, avg);
std::array<float, 16> dx{};
ml::pool_backward(pool, ml::pool_kind::max, x, std::array<float, 4>{1, 1, 1, 1}, dx); // to each window's maximum
// Upscale a 2x2 plane to 4x4: nearest, bilinear at half-pixel centres, bicubic with corners aligned.
const std::array<float, 4> small{0, 1, 2, 3};
std::array<float, 16> nearest{}, bilinear{}, bicubic{};
ml::upscale(ml::upscale_mode::nearest, false, small, 2, 2, nearest, 4, 4);
ml::upscale(ml::upscale_mode::bilinear, false, small, 2, 2, bilinear, 4, 4);
ml::upscale(ml::upscale_mode::bicubic, true, small, 2, 2, bicubic, 4, 4);
// Zero padding of a 1x3 row by one on each side; reflect padding; a roll by one.
std::array<float, 15> padded{};
ml::pad<2>({1, 3}, {1, 1}, {1, 1}, std::array<float, 3>{1, 2, 3}, padded);
std::array<float, 7> reflected{};
ml::pad_reflect_1d(1, 3, 2, 2, std::array<float, 3>{1, 2, 3}, reflected);
std::array<float, 3> rolled{};
ml::roll<1>({3}, {1}, std::array<float, 3>{1, 2, 3}, rolled);
// SAM: a 3x3 grid of one channel into windows of 2 (four windows, zero-padded), and back.
std::array<float, 9> grid{1, 2, 3, 4, 5, 6, 7, 8, 9};
std::array<float, ml::window_count(3, 3, 2) * 4> windows{};
ml::window_partition(3, 3, 1, 2, grid, windows);
std::array<float, 9> back{};
ml::window_unpartition(3, 3, 1, 2, windows, back);
// SAM's relative positions for a 2x2 window of one channel: tables gathered, scores added.
std::array<float, 4> rh{}, rw{};
ml::rel_pos_gather(std::array<float, 3>{-1, 0, 1}, 2, rh); // rh[q][k] = table[q - k + 1]
ml::rel_pos_gather(std::array<float, 3>{-2, 0, 2}, 2, rw);
std::array<float, 8> rel_h{}, rel_w{};
ml::rel_pos_scores(std::array<float, 4>{1, 1, 1, 1}, rh, rw, 2, 2, 1, rel_h, rel_w);
std::array<float, 16> attn{};
ml::add_rel_pos(attn, rel_h, rel_w, 2, 2);

Relationships. ml/conv.hpp (the convolutions these surround), ml/patch.hpp, ml/row.hpp. Group: snicholls-core.

Implementations. One each.

Guarantees. constexpr, no allocation, no exceptions; outputs are written, never accumulated, except add_rel_pos (in place on the scores) and the documented gradients. Linear in the output for every operation but the relative-position einsums (h w (h + w) c). pool_shape is a structural aggregate.

Errors. Preconditions, asserted: spans of the sizes the arguments imply; a valid pool shape (kernel within the padded input, positive strides); reflection shorter than the row; a window and sizes above 0.

Performance. Not benchmarked: data movement, or a few multiply-adds per output.

Tests and demos. tests/ml/spatial_test.cpp, demos/ml/spatial_demo.cpp.

Dependencies. <array>, <cassert>, <concepts>, <cstddef>, <cstdint>, <limits>, <span>, snicholls/core/math/constexpr_math.hpp, ml/conv.hpp (its shape helpers), ml/row.hpp.

Known issues. ggml's average pool counts the padding in 2-D and not in 1-D: the defaults of pool_1d_shape and pool_2d_shape follow it, so a 2-D average near a padded border is smaller than PyTorch's with count_include_pad = False. ggml's antialiased bilinear mode is not built in. ggml's maximum starts from -FLT_MAX, so a window of -infinities gives -FLT_MAX there and -infinity here. ggml's add_rel_pos adds the two terms in an order that depends on the position; here (attn + rel_h) + rel_w, SAM's, so a score may differ from ggml's in its last bit.

Status. Experimental, new in 0.17.0.
