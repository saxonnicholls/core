Detailed Description

snicholls::metric::dot, norm, cosine_similarity, and the metrics cosine_distance, angular, angle and inner_product: distances between directions, for embeddings and normalised features.

Overview. Embeddings (text, image, appearance) are compared by direction, not position. These work on any two points point_traits reads, in their common floating type:

  • dot(a, b), squared_norm(a), norm(a): the inner product and length of any point, the one generic form (linalg::dot and linalg::norm are the same on fixed_vectors).
  • cosine_similarity(a, b) = a·b / (|a| |b|), in [-1, 1]; 0 when either is the zero vector.
Metric m(a, b) is_metric Note
cosine_distance 1 - cos θ, in [0, 2] no the usual embedding distance
angular √(2 - 2 cos θ), in [0, 2] yes Annoy's "angular": the Euclidean distance between the unit vectors
angle θ = acos(cos θ), in [0, π] yes the great-circle distance on the unit sphere
inner_product -a·b no maximum inner product search as a nearest-neighbour search (Annoy's "dot")

All four order points the same way when the vectors are normalised; inner_product also counts length.

// Two embeddings of different kinds: a float array and a fixed_vector of doubles
const std::array<float, 3> x{1, 2, 3};
const auto y = la::fixed_vector<double, 3>{{4, 5, 6}};
std::puts("Inner products and lengths of (1, 2, 3) and (4, 5, 6)");
check(mt::dot(x, y) == 32.0, "dot = 4 + 10 + 18", mt::dot(x, y));
check(mt::squared_norm(x) == 14.0f, "squared_norm(x) = 14", mt::squared_norm(x));
check(near(mt::norm(y), 8.774964387392123), "norm(y) = sqrt(77) (python3)", mt::norm(y));
check(near(mt::cosine_similarity(x, y), 0.9746318461970762), "cosine_similarity (numpy)", mt::cosine_similarity(x, y));
std::puts("The four direction metrics (python3 values)");
check(near(mt::cosine_distance{}(x, y), 0.025368153802923787), "cosine_distance = 1 - cos", mt::cosine_distance{}(x, y));
check(near(mt::angular{}(x, y), 0.225247214424169), "angular = sqrt(2 - 2 cos)", mt::angular{}(x, y));
check(near(mt::angle{}(x, y), 0.2257261285527342), "angle = acos(cos), radians", mt::angle{}(x, y));
check(mt::inner_product{}(x, y) == -32.0, "inner_product = -dot", mt::inner_product{}(x, y));
// Nearest embedding to a query: the direction metrics agree; inner_product also rewards length
const std::vector<std::array<double, 3>> docs{{1, 0, 0}, {0.9, 0.1, 0}, {0, 10, 10}};
const std::array<double, 3> query{1, 0.2, 0};
const std::size_t by_cos = nearest(mt::cosine_distance{}, query, docs);
check(by_cos == 1 && nearest(mt::angular{}, query, docs) == 1 && nearest(mt::angle{}, query, docs) == 1, "cosine, angular, angle: doc 1", double(by_cos));
check(nearest(mt::inner_product{}, query, docs) == 2, "inner_product: doc 2, the longest", 2.0);

Relationships. metric/concepts.hpp, metric/minkowski.hpp (euclidean on normalised vectors equals angular), containers/ann_forest.hpp (its angular and dot splits), math/constexpr_math.hpp. Group: snicholls-core.

Guarantees. constexpr, noexcept when the points' coordinate reads are, no allocation. The cosine is clamped to [-1, 1] before acos and √(2 - 2 cos), so rounding never yields NaN.

Errors. None. A zero vector has cosine similarity 0 with everything (so cosine_distance 1, angular √2, angle π/2).

Performance. Not benchmarked on their own: one pass over the coordinates for the dot product and both norms.

Tests and demos. tests/metric/angular_test.cpp, demos/metric/angular_demo.cpp.

Dependencies. <cstddef>, math/constexpr_math.hpp, metric/concepts.hpp.

Known issues. None known.

Status. Experimental, new in 0.20.0.
