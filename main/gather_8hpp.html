Detailed Description

snicholls::ml rows by index lists, on the backend: gather_rows, its backward scatter_add_rows, scatter_rows, concat_rows and slice_rows, over a batch of sequences, deterministic.

Overview. A joint embedding predictive architecture (TRAINING.md T11) moves token rows by index: the context encoder reads only the context tokens of each sample, the target tokens are picked out of the target encoder's output, and the predictor reads the context encoder's rows followed by one mask token per target. Each of those moves is one of these calls, made with the pass's backend (TRAINING.md T9), so a device library runs it where the rows live.

A batch is sequences sequences laid end to end. src holds sequences · n rows of width; indices holds sequences · k positions, sequence s's k of them relative to its own first row (in [0, n)), as ml/masking.hpp writes them. Row (s, j) of the result is row s · n + indices[s · k + j] of src.

  • gather_rows(b, src, indices, out, width, sequences): out(s, j) = src(s, indices(s, j)).
  • scatter_add_rows(b, dout, indices, dsrc, width, sequences): its backward, dsrc(s, indices(s, j)) += dout(s, j) for j from 0 up, sequence after sequence: a fixed order, so a repeated index sums the same way on every run (no atomics). Untouched rows keep their values.
  • scatter_rows(b, rows, indices, dst, width, sequences): dst(s, indices(s, j)) = rows(s, j), the last write winning for a repeated index; its backward is gather_rows of the gradient (the overwritten rows of dst pass none). The way to lay rows out in any order, such as V-JEPA 2-AC's action, state and patch tokens frame by frame.
  • concat_rows(b, first, second, out, width, sequences): each sequence's rows of first, then of second (the predictor's input: context rows, then the targets' mask tokens). Its backward is two slice_rows.
  • slice_rows(b, rows, first, count, out, width, sequences): rows [first, first + count) of each sequence (the predictor's outputs at the targets). Its backward is slice_rows_backward, added into those rows.
// Two sequences of four rows of two values: row r of sequence s is (10 s + r, -(10 s + r))
std::array<float, 2 * 4 * 2> tokens{};
for (std::size_t s = 0; s < 2; ++s)
for (std::size_t r = 0; r < 4; ++r) {
tokens[(s * 4 + r) * 2] = float(10 * s + r);
tokens[(s * 4 + r) * 2 + 1] = -float(10 * s + r);
}
// Each sequence's context: positions within the sequence, sorted
const std::array<std::uint32_t, 4> context{0, 3, 1, 2};
std::array<float, 4 * 2> rows{};
ml::gather_rows(backend, std::span<const float>(tokens), context, std::span<float>(rows), 2, 2); // rows 0, 3 | 11, 12
// The backward: each gathered row's gradient added back to its position, in a fixed order
const std::array<float, 4 * 2> drows{1, 1, 2, 2, 3, 3, 4, 4};
std::array<float, 2 * 4 * 2> dtokens{};
ml::scatter_add_rows(backend, std::span<const float>(drows), context, std::span<float>(dtokens), 2, 2);

Relationships. ml/masking.hpp (the index lists), ml/jepa.hpp (the predictor's input), ml/patch.hpp, ml/linear.hpp (the other elementwise steps of the batched passes). The mixture of experts' gather and combine (ml/moe.hpp, TRAINING.md T10) are a different operation, a permutation of every row by its experts with weights; these are plain index lists per sequence. Group: snicholls-core.

Implementations. One each, on the host for any backend; a device library overloads them for its own backend type, found by argument-dependent lookup (TRAINING.md T9).

Guarantees. constexpr, no allocation, O(rows · width); copies are exact, so every result but scatter_add_rows' sums is bit-exact, and those sums run in the stated order. noexcept for the standard floating-point types.

Errors. Preconditions, asserted: the sizes divide as stated, every index is below n, no output overlaps an input.

Performance. gather_rows and scatter_add_rows against the loops by hand (benchmarks/ml/gather_benchmark.cpp), 64 sequences gathering 49 of 196 rows of 768 floats: level, 5 to 7 GiB/s for the gather and 5.4 GiB/s for the scatter-add, memory bound (Xeon W-3245, Release, Apple clang 17, 2026-11-19, one thread, a machine at load average 60 to 80: differences within about 15% are noise).

Tests and demos. tests/ml/gather_test.cpp, demos/ml/gather_demo.cpp.

Dependencies. <algorithm>, <cassert>, <cstddef>, <cstdint>, <span>, <type_traits>, snicholls/core/math/constexpr_math.hpp (the math_number concept).

Known issues. Indices are std::uint32_t, as the mixture of experts' are: four billion rows per sequence.

Status. Experimental, new in 0.16.0.
