Detailed Description

snicholls::https_client: one request out to a provider's API, one response back, held as data.

Overview. Every provider adapter (Stripe, Wise, OKX, Xero) talks to its API through an https_client, so the adapter's logic is tested against a fixture server or a recorded day with no network, and the transport (TLS, timeouts, retries) is written once. The request and the response are values: a method (http_method, shared with concepts/http_handler.hpp), a URL, headers (http_header.hpp), a body, timeouts and a reference to a client certificate. Core does no I/O: the transport is ts-moveables' and servers'. This is the concept half of a pair; the pure virtual half is https_client_interface (interfaces/https_client.hpp), with https_client_adapter<C> and https_client_ref.

The contract (interfaces/https_client_conformance.hpp checks it):

  • send returns the provider's answer whatever its status: a 4xx or a 5xx is a response, not an error. An error is a transport failure only: capability_errc::unavailable (no connection, TLS refused, the connection dropped), capability_errc::timeout (no complete answer in time; the outcome is unknown), capability_errc::invalid_argument (a URL that parse_https_url refuses, or a header is_sendable refuses: no request is sent).
  • Credentials travel only in authorization (a snicholls::secret, sent as the Authorization header). A body that carries a secret (a signed challenge, a token exchange) sets sensitive_body. An implementation never logs or records authorization or a sensitive body, and neither ever reaches an error.
  • idempotency_key, when set, is sent as the Idempotency-Key header; a retry layer retries a request that changes state (is_idempotent false) only when it carries one.
  • client_certificate, when set, names a client certificate the transport holds (mutual TLS, a bank's API); the request never carries the certificate or its key. An implementation without that certificate is unsupported.
  • connect_timeout and timeout of zero mean the implementation's defaults; timeout bounds the whole exchange.
  • Errors follow the redaction rule of capability_error.hpp: no response, URL or credential in them.
// A provider adapter's call: any client, a POST that changes state, so it carries an idempotency key.
template <https_client C>
capability_result<https_response> refund(C& client, std::string_view payment, std::string_view key)
{
https_request r;
r.method = http_method::post;
r.url = "https://api.stripe.test/v1/refunds";
r.headers = {{"Content-Type", "application/x-www-form-urlencoded"}};
r.authorization = secret<std::string>{"Bearer sk_test_demo"};
r.body = "payment_intent=" + std::string(payment);
r.idempotency_key = *client_id::make(key);
r.timeout = std::chrono::seconds{30};
return client.send(r);
}

Relationships. concepts/http_handler.hpp (http_method), http_header.hpp, secret.hpp, capability_error.hpp, capability_ids.hpp; the twin interfaces/https_client.hpp, the reference interfaces/https_client_reference.hpp, the kit interfaces/https_client_conformance.hpp. Group: snicholls-core.

Implementations.

  • memory_https_client (interfaces/https_client_reference.hpp): an in-memory router, by host, to handlers or to any http_handler; with cassette, recording_https_client and replay_https_client for recorded days. Standard library only.
  • Above core: servers' tls_https_client (TLS through ts-moveables and OpenSSL) and retrying_https_client (back-off honouring Retry-After, over any model).

Guarantees. is_idempotent, is_sendable and parse_https_url are constexpr, noexcept and allocation-free. https_url views the URL it was parsed from. Thread safety is the implementation's.

Errors. capability_error, as the contract says; parse_https_url returns invalid_argument.

Performance. Dominated by the network; the reference by its handler.

Tests and demos. tests/concepts/https_client_test.cpp, demos/concepts/https_client_demo.cpp.

Dependencies. <chrono>, <concepts>, <cstdint>, <string>, <string_view>, <vector>, capability_error.hpp, capability_ids.hpp, concepts/http_handler.hpp, http_header.hpp, secret.hpp.

Known issues. Bodies are whole strings: no streaming. IPv6 literal hosts ([::1]) are refused.

Status. New in 0.27.0, lifted from servers. Experimental until two real implementations pass the kit.
