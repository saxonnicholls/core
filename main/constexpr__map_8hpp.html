Detailed Description

snicholls::constexpr_map: a fixed table of key-value pairs, looked up at compile time or run time.

Overview. A map whose contents are known when the program is written: an enumeration's names, a protocol's codes, a unit's scale factors. It is an aggregate over a std::array of pairs, so it is a literal type: declare it constexpr, look it up in a static_assert or a case label, and nothing is built at run time:

// One table, written once, a constant.
constexpr auto method_names = snicholls::make_constexpr_map(
std::pair{http_method::get, std::string_view{"GET"}},
std::pair{http_method::post, std::string_view{"POST"}},
std::pair{http_method::put, std::string_view{"PUT"}},
std::pair{http_method::del, std::string_view{"DELETE"}});
static_assert(method_names.keys_unique());
// Enumeration to name, and name to enumeration, both at compile time ...
static_assert(method_names.at(http_method::put) == "PUT");
static_assert(*method_names.find_key(std::string_view{"DELETE"}) == http_method::del);
// ... and at run time, where an unknown name is a null pointer, not an exception.
const http_method* parse_method(std::string_view text) { return method_names.find_key(text); }

Lookups are linear, which for the tables this is for (tens of entries) beats a hash or a tree at compile time and at run time. find returns a pointer or null; at throws, which in a constant expression is a compile error; find_key looks the other way, for the enumeration-to-name-and-back pair of tables that would otherwise be two.

Relationships. snicholls::fixed_string makes a compile-time key; basic_type_registry binds names to types where the value is a type rather than a value. Group: snicholls-core.

Guarantees. An aggregate and a literal type: constexpr construction and every lookup when Key and Value are literal types with a constexpr operator==. find, find_key, contains and keys_unique are noexcept. No allocation, no run-time initialisation. Keys need not be unique; find returns the first match, and keys_unique() says whether that matters.

Errors. at throws std::out_of_range when the key is absent, at run time; in a constant expression the throw makes the expression not constant, so the program does not compile.

Performance. O(N) comparisons per lookup. Not benchmarked: a table of tens of entries compared by == is a handful of instructions, and a constant-expression lookup is none.

Tests and demos. tests/constexpr_map_test.cpp, demos/constexpr_map_demo.cpp.

Dependencies. <array>, <cstddef>, <stdexcept>, <utility>.

Known issues. A key type with no constexpr operator== (a std::string) still works at run time but not in a constant expression; use std::string_view or snicholls::fixed_string for text keys.

Status. New in 0.5.0.
