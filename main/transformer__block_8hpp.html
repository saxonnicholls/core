Detailed Description

snicholls::ml::block_forward: one pre-norm transformer block, x += attention(norm(x)); x += mlp(norm(x)), for a token or a run of tokens; and for training, over a sequence with its backward pass.

Overview. The layer every decoder-only transformer stacks. block_forward updates one token's residual stream in place at its position, appending its keys and values to the cache; block_prefill does the same for a run of consecutive tokens, which is the same thing token by token, so prefill and decode cannot disagree. The normalisation (layer norm with weight and bias, or RMS norm with or without a weight), the attention and the MLP are the configuration's. A whole model, the stack of blocks between an embedding and an LM head, belongs above core (INFERENCE.md I9).

For training, block_forward_sequence runs a whole sequence in place and saves block_activations (each token's result is block_prefill's, to the bit); block_backward turns the gradient in the block's output into the gradient in its input, in place, and adds every weight's gradient into block_gradients: the MLP's and second norm's per token, the attention's over the sequence, the first norm's, each through its residual.

Both have a batched overload taking a linalg backend first, every projection a matrix product over the sequence (attention_forward_sequence, mlp_forward_sequence and their backward passes, a BLAS or a GPU backend from another library, the same call); it saves block_activations::mlp_hidden too, and its backward uses mlp_gradients::scratch and attention_gradients::y.

// The same block with every projection a matrix product through a linalg backend (a BLAS or a GPU backend from
// another library the same way). It also saves the MLP's hidden rows, and its backward has two more working
// buffers: the MLP's hidden gradients (twice d_ff for SwiGLU) and the heads' output gradients
std::vector<float> hidden(3 * 16), mlp_scratch(2 * 3 * 16), dy(3 * 8);
ml::block_activations<float> bact = act;
bact.mlp_hidden = hidden;
auto one_step = [&](bool batched, std::vector<float>& out, std::vector<float>& dout, std::vector<float>& gq) {
std::vector<float> gkv(t.kv.size()), gv(t.kv.size()), go(t.o.size()), gup(t.up.size()), ggate(t.gate.size()),
gdown(t.down.size()), dq(sq.size()), dk(sk.size()), dv(sv.size());
const ml::block_gradients<float> grads{
{}, {}, {}, {}, {dq, dk, dv, gq, gkv, gv, go, {}, {}, {}, {}, {}, {}, dy}, {gup, ggate, gdown, {}, {}, {}, mlp_scratch}, scratch};
if (batched) {
ml::block_forward_sequence<c>(snicholls::linalg::reference, t.weights(), out, rope, bact);
ml::block_backward<c>(snicholls::linalg::reference, t.weights(), rope, bact, dout, grads);
} else {
ml::block_forward_sequence<c>(t.weights(), out, rope, act);
ml::block_backward<c>(t.weights(), rope, act, dout, grads);
}
};
std::vector<float> out_p = x, out_b = x, dout_p = target, dout_b = target, gq_p(t.q.size()), gq_b(t.q.size());
one_step(false, out_p, dout_p, gq_p);
one_step(true, out_b, dout_b, gq_b);

A batch of sequences. Both batched passes take a number of sequences (default one): xs is that many sequences of n tokens end to end, every row-wise step (the norms, each projection, the MLP, the residual adds, the bias sums) runs once over all their rows, and attention runs within each sequence, positions restarting at 0. The activations are the sequences' own side by side (attention_activations), so one call per layer replaces one per sequence per layer and the products are sequences times taller. On core's reference backend the result is the per-sequence calls': the outputs, the input's gradient, every bias's and norm's gradient and Wk's and Wv's to the bit; the gradients of Wq, Wo and the MLP's matrices are each one product over all the rows, where per-sequence calls add one sequence's sum at a time, so they agree within rounding.

// A batch: two sequences of 3 tokens end to end, one call per layer instead of one per sequence. The activations and
// the working spaces cover all six rows; attention stays within each sequence, positions restarting at 0
constexpr std::size_t batch = 2, rows = batch * 3;
std::vector<float> xb = x;
xb.insert(xb.end(), target.begin(), target.end()); // sequence 0 is x, sequence 1 is target
std::vector<float> bx0(rows * 8), bh1(rows * 8), bx1(rows * 8), bh2(rows * 8), bq(rows * 8), bk(rows * 4), bv(rows * 4), by(rows * 8),
blse(rows * 2), bup(rows * 16), bgate(rows * 16), bhidden(rows * 16);
const ml::block_activations<float> batch_act{bx0, bh1, bx1, bh2, {bq, bk, bv, {}, {}, by, blse}, bup, bgate, bhidden};
ml::block_forward_sequence<c>(snicholls::linalg::reference, t.weights(), xb, rope, batch_act, batch);
// ... and its backward: ml::block_backward<c>(backend, weights, rope, batch_act, dxb, grads, batch)

Every step of the batched passes that is not a matrix product is a call made with the backend (TRAINING.md T9): copy_rows, fill_rows, add_rows, add_bias_rows, sum_rows (ml/linear.hpp), mlp_activate_rows and its backward (ml/mlp.hpp), the four attention steps (ml/attention_layer.hpp), block_norm_rows and block_norm_rows_backward_add (here). Each has an overload for any backend that runs on the host; a device library overloads them for its own backend type, in its own namespace, and the whole pass runs where its data lives:

// A device library's backend runs the batched passes' steps itself: it overloads core's operations for its type, in
// its namespace, and the passes call those (argument-dependent lookup). Here one step, counted, on the host.
namespace my_device {
struct backend : snicholls::linalg::reference_backend {
inline static int norms = 0;
};
template <snicholls::ml::transformer_config C, typename T>
void block_norm_rows(const backend& b, std::type_identity_t<std::span<const T>> x, std::type_identity_t<std::span<const T>> weight,
std::type_identity_t<std::span<const T>> bias, std::span<T> out)
{
++backend::norms; // a device would launch its kernel here, on data it already holds
snicholls::ml::block_norm_rows<C>(static_cast<const snicholls::linalg::reference_backend&>(b), x, weight, bias, out);
}
} // namespace my_device
// Training one block: 1/2 |block(x) - target|^2 over 3 tokens, by plain gradient descent on every weight
layer t(1); // a copy of layer 0's weights, to train
const std::vector<float> x = pattern(3 * 8, 2.0f, 20), target = pattern(3 * 8, 1.0f, 40);
std::vector<float> x0(x.size()), h1(x.size()), x1(x.size()), h2(x.size()), sq(3 * 8), sk(3 * 4), sv(3 * 4), sy(3 * 8),
slse(3 * 2), sup(3 * 16), sgate(3 * 16), scratch(x.size());
const ml::block_activations<float> act{x0, h1, x1, h2, {sq, sk, sv, {}, {}, sy, slse}, sup, sgate};
std::vector<float> losses;
for (int step = 0; step < 5; ++step) {
std::vector<float> out = x;
ml::block_forward_sequence<c>(t.weights(), out, rope, act);
std::vector<float> dout(out.size());
float loss = 0.0f;
for (std::size_t i = 0; i < out.size(); ++i) {
dout[i] = out[i] - target[i];
loss += 0.5f * dout[i] * dout[i];
}
losses.push_back(loss);
// Gradients have the weights' shapes; the backward pass adds into them
std::vector<float> gq(t.q.size()), gkv(t.kv.size()), gv(t.kv.size()), go(t.o.size()), gup(t.up.size()),
ggate(t.gate.size()), gdown(t.down.size()), dq(sq.size()), dk(sk.size()), dv(sv.size());
const ml::block_gradients<float> grads{{}, {}, {}, {}, {dq, dk, dv, gq, gkv, gv, go}, {gup, ggate, gdown}, scratch};
ml::block_backward<c>(t.weights(), rope, act, dout, grads); // dout becomes the gradient in x
// K and V share one matrix in this layer, so its gradient is the sum of both uses
auto descend = [](std::vector<float>& w, const std::vector<float>& g) {
for (std::size_t i = 0; i < w.size(); ++i)
w[i] -= 0.02f * g[i];
};
for (std::size_t i = 0; i < gkv.size(); ++i)
gkv[i] += gv[i];
descend(t.q, gq), descend(t.kv, gkv), descend(t.o, go), descend(t.up, gup), descend(t.gate, ggate), descend(t.down, gdown);
}
// Two layers sharing one cache, 16 positions each; a prompt of 3 tokens' residual streams, then a fourth
static const ml::rope_table<float, 16, 4> rope{};
std::vector<float> keys(ml::kv_cache_view<c>::required_size(2, 16)), values(keys.size());
const ml::kv_cache_view<c> cache(keys, values, 2, 16);
const std::array<ml::block_weights<W>, 2> layers{l0.weights(), l1.weights()};
std::vector<float> prompt = pattern(3 * 8, 2.0f, 20);
for (std::size_t i = 0; i < layers.size(); ++i)
ml::block_prefill<c>(layers[i], prompt, 0, cache, i, rope); // the whole prompt through layer i
std::vector<float> next = pattern(8, 2.0f, 30);
for (std::size_t i = 0; i < layers.size(); ++i)
ml::block_forward<c>(layers[i], next, 3, cache, i, rope); // one decode step at position 3

Relationships. ml/attention_layer.hpp, ml/mlp.hpp, ml/norm.hpp, ml/kv_cache.hpp, ml/transformer_config.hpp; the plans INFERENCE.md and TRAINING.md. Group: snicholls-core.

Implementations. One, configured at compile time.

Guarantees. constexpr, no allocation (the normalised row and each half's output are std::arrays of d_model), the cost of attention_forward plus mlp_forward per token.

Errors. Preconditions, asserted, as attention_forward and mlp_forward; the norm weights and biases are empty or have d_model; a prefill's rows are d_model each.

Performance. One decode step of a GPT-2-small layer (768 wide, 12 heads, MLP of 3072) at position 256, against the same layer written as loops over raw pointers with every operation in the same order, after a bit-for-bit fairness check (benchmarks/ml/transformer_block_benchmark.cpp; Release, Apple clang 17, Xeon W-3245, macOS 26, 2026-11-12, medians of five, on a shared machine with load average 45 to 120):

Weights Core By hand
float 8.45 ms 8.31 ms
Q8_0 3.07 ms 3.00 ms

Level within the machine's noise. A decode step reads every weight once, so it is bound by memory: Q8_0's quarter of the bytes makes it 2.8x faster than float.

Training, a GPT-2-shaped float layer (256 wide, 4 heads of 64, MLP of 1024, layer norm, tanh GELU, biases) over 64 tokens, against the same passes by hand with the same bit-for-bit check on every activation and gradient (same file and machine, 2026-11-15, medians of five, load average about 6):

Pass Core By hand
block_forward_sequence 50.4 ms 48.2 ms
block_backward 20.0 ms 19.4 ms

Within 5% and 3%. The backward, attention_backward, mlp_backward and linear_backward inside it, is faster than the forward: its products accumulate into rows (+= across a row, which vectorises) where the forward's are dot products, whose sums keep their order.

Tests and demos. tests/ml/transformer_block_test.cpp, demos/ml/transformer_block_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <cstddef>, <span>, <type_traits>, linalg/backend.hpp, ml/attention_layer.hpp, ml/mlp.hpp, ml/norm.hpp.

Known issues. Post-norm and sandwich-norm blocks (Gemma's extra norms) are not configurable.

Status. Experimental, new in 0.8.0.

The backward pass of the batched block_forward_sequence, in place, its products through the backend.

The MLP's backward over the sequence (mlp_backward_sequence), each token's second norm and the residual, the attention's (attention_backward with the backend), each token's first norm and the residual. The working spaces are grads.scratch (n · d_model), grads.mlp.scratch (n · d_ff, twice for SwiGLU) and grads.attention.y (n · q_size).
