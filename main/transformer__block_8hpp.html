Detailed Description

snicholls::ml::block_forward: one pre-norm transformer block, x += attention(norm(x)); x += mlp(norm(x)), for a token or a run of tokens.

Overview. The layer every decoder-only transformer stacks. block_forward updates one token's residual stream in place at its position, appending its keys and values to the cache; block_prefill does the same for a run of consecutive tokens, which is the same thing token by token, so prefill and decode cannot disagree. The normalisation (layer norm with weight and bias, or RMS norm with or without a weight), the attention and the MLP are the configuration's. A whole model, the stack of blocks between an embedding and an LM head, belongs above core (INFERENCE.md I9).

// Two layers sharing one cache, 16 positions each; a prompt of 3 tokens' residual streams, then a fourth
static const ml::rope_table<float, 16, 4> rope{};
std::vector<float> keys(ml::kv_cache_view<c>::required_size(2, 16)), values(keys.size());
const ml::kv_cache_view<c> cache(keys, values, 2, 16);
const std::array<ml::block_weights<W>, 2> layers{l0.weights(), l1.weights()};
std::vector<float> prompt = pattern(3 * 8, 2.0f, 20);
for (std::size_t i = 0; i < layers.size(); ++i)
ml::block_prefill<c>(layers[i], prompt, 0, cache, i, rope); // the whole prompt through layer i
std::vector<float> next = pattern(8, 2.0f, 30);
for (std::size_t i = 0; i < layers.size(); ++i)
ml::block_forward<c>(layers[i], next, 3, cache, i, rope); // one decode step at position 3

Relationships. ml/attention_layer.hpp, ml/mlp.hpp, ml/norm.hpp, ml/kv_cache.hpp, ml/transformer_config.hpp; the plans INFERENCE.md and TRAINING.md. Group: snicholls-core.

Implementations. One, configured at compile time.

Guarantees. constexpr, no allocation (the normalised row and each half's output are std::arrays of d_model), the cost of attention_forward plus mlp_forward per token.

Errors. Preconditions, asserted, as attention_forward and mlp_forward; the norm weights and biases are empty or have d_model; a prefill's rows are d_model each.

Performance. One decode step of a GPT-2-small layer (768 wide, 12 heads, MLP of 3072) at position 256, against the same layer written as loops over raw pointers with every operation in the same order, after a bit-for-bit fairness check (benchmarks/ml/transformer_block_benchmark.cpp; Release, Apple clang 17, Xeon W-3245, macOS 26, 2026-11-12, medians of five, on a shared machine with load average 45 to 120):

Weights Core By hand
float 8.45 ms 8.31 ms
Q8_0 3.07 ms 3.00 ms

Level within the machine's noise. A decode step reads every weight once, so it is bound by memory: Q8_0's quarter of the bytes makes it 2.8x faster than float.

Tests and demos. tests/ml/transformer_block_test.cpp, demos/ml/transformer_block_demo.cpp.

Dependencies. <array>, <cassert>, <cstddef>, <span>, ml/attention_layer.hpp, ml/mlp.hpp, ml/norm.hpp.

Known issues. Post-norm and sandwich-norm blocks (Gemma's extra norms) are not configurable.

Status. Experimental, new in 0.8.0.
