Detailed Description

wyhash final version 4.3: a fast 64-bit hash, usable at compile time and the same on every machine.

Overview. The hash for a hash table, a fingerprint or a bloom filter: 48 bytes a round through 64 x 64 -> 128-bit multiplies, passes SMHasher, a handful of instructions for the short keys that dominate (a symbol, a token, a quantised state). It is constexpr, so a closed alphabet's fingerprint or a dispatch table's keys are compile-time constants, and it reads its input in little-endian order whatever the host, so the value is the same on a big-endian machine as on this one, which the reference's memcpy reads are not.

using namespace snicholls::literals;
// A closed alphabet's fingerprint, computed by the compiler from its definition: two machines
// that derive the same 64 bits from the same text agree on what they are talking about.
constexpr std::string_view alphabet_definition = "ACGT v1";
constexpr std::uint64_t alphabet_fingerprint = snicholls::wyhash(alphabet_definition);
// A switch on a string: the labels are constants, the subject is hashed at run time.
int route(std::string_view method)
{
switch (snicholls::wyhash(method)) {
case "GET"_wyhash: return 1;
case "POST"_wyhash: return 2;
case "DELETE"_wyhash: return 3;
default: return 0;
}
}

wymix is the 64-bit mixer the hash is built from, for folding two words into one; splitmix64 is a cheap integer mixer for seeds and ids. Neither is cryptographic, and neither is fnv1a_64: use FNV where a tiny, specified-by-the-byte hash is wanted, wyhash where speed over long keys or avalanche in the low bits matters.

Relationships. hash/fnv.hpp, the other machine-independent hash; hash_combine, for std::hash values that need not cross a process; endian.hpp, whose byteswap keeps the run-time reads little-endian; containers/bloom_filter.hpp, which hashes with it. Group: snicholls-core.

Guarantees. Every function is constexpr and noexcept. The values are those of the upstream test_vector.cpp for final version 4.3 (pinned in the tests), on every host and in constant and run-time evaluation alike, and never change between versions. The default secret is upstream's; a different secret is a different hash function. In a constant expression, and for input that is not contiguous, the bytes are read one at a time through b[i]; at run time, contiguous single-byte input (std::string_view, a span of bytes, a std::array<char, N>) is read a word at a time with memcpy, byte-swapped on a big-endian host, so the two paths agree bit for bit.

Errors. None.

Performance. Benchmarked in benchmarks/hash/wyhash_benchmark.cpp against the reference written out with memcpy reads and the compiler's 128-bit multiply, on 4,096 keys of 1 to 96 bytes, after a fairness check that every value agrees; fnv1a_64 runs beside them for scale. Release, Apple clang 17, Xeon W-3245, 2026-11-06: 8.9 ns per key through wyhash, 7.9 ns through the reference, 38.6 ns through FNV-1a. The nanosecond is the call into the outlined hash body, which the reference, one function in the benchmark's own translation unit, does not pay; the arithmetic and the reads are the same.

Tests and demos. tests/hash/wyhash_test.cpp, demos/hash/wyhash_demo.cpp.

Dependencies. <bit>, <concepts>, <cstddef>, <cstdint>, <cstring>, <span>, <string_view>, <type_traits>, detail/wide_mul.hpp and endian.hpp (for byteswap).

Known issues. Final version 4.3 is not the same function as final 4.0 or 4.1 (a different secret and final mix): Zig's standard library and abseil carry older versions, so their values differ from these. The literal _wyhash is in snicholls::literals.

Status. New in 0.5.0.
