Detailed Description

snicholls::tracking::predict, update, predict_measurement and friends: the Kalman and extended Kalman filter steps, the information form, the Rauch-Tung-Striebel smoothing step, the alpha-beta filter and Fisher information.

Overview. The filter's two steps, as functions of fixed-size values:

  • predict(prior, model, dt): x ← f(x), P ← F P Fᵀ + Q. A linear_transition uses F = matrix(dt); any other transition_model is linearised at the prior mean (the extended Kalman filter). predict(prior, F, Q) takes the matrices already formed, for many targets stepped over the same dt. predict(prior, model, dt, B, u) adds a known control input B u (a current that carries a swimmer, an engine command).
  • predict_measurement(prediction, sensor): the predicted measurement ẑ, its covariance S = H P Hᵀ + R, and the cross-covariance P Hᵀ, linear or linearised in the same way.
  • update(prediction, z, sensor): the posterior, with the innovation ν = z ⊖ ẑ (wrapped as the sensor's kinds say), S, the gain K, the squared Mahalanobis distance νᵀ S⁻¹ ν and the log-likelihood log N(ν; 0, S), everything a gate and an associator need, from one Cholesky of S. covariance_form::joseph uses (I - K H) P (I - K H)ᵀ + K R Kᵀ, which stays positive definite under rounding; the default is P - K S Kᵀ (Stone Soup's default).
  • update(prediction, z, measurement_prediction, kinds): the same from a measurement prediction made any other way (the unscented transform, cubature).
  • Information form: to_information, from_information, information_update (Y ← Y + Hᵀ R⁻¹ H, y ← y + Hᵀ R⁻¹ z: sensors add), fisher_information(H, R) and gdop(J), the geometric dilution of precision √tr(J⁻¹) that a placement optimiser minimises.
  • rts_smooth(filtered, predicted, smoothed_next, F): one backward step of the Rauch-Tung-Striebel smoother, also the retrodiction step for an out-of-sequence measurement.
  • numerical_jacobian(f, x): central differences, for a model without an analytic Jacobian.
  • alpha_beta_update<Pos, Vel>(x, z, α, β, dt): the fixed-gain filter (Stone Soup's AlphaBetaUpdater).
// The target moves at (3, -1) m/s from (0, 100); a sensor reports its position every second with 5 m of noise
const auto model = tr::combine(cv{0.01}, cv{0.01}); // state (x, vx, y, vy)
const tr::linear_gaussian<double, 4, xy> sensor{{{25, 0, 0, 25}}};
const double gate = tr::gate_threshold(0.999, 2);
tr::gaussian<double, 4> track{{{0, 0, 100, 0}}, la::fixed_matrix<double, 4, 4>::identity() * 100};
std::array<tr::gaussian<double, 4>, steps> filtered{}, predicted{};
std::array<state, steps> truth{};
int gated_out = 0;
for (int k = 0; k < steps; ++k) {
truth[static_cast<std::size_t>(k)] = {{3.0 * (k + 1), 3, 100 - 1.0 * (k + 1), -1}};
const la::fixed_vector<double, 2> z{{truth[static_cast<std::size_t>(k)][0] + 5 * normal(g), truth[static_cast<std::size_t>(k)][2] + 5 * normal(g)}};
const auto prediction = tr::predict(track, model, 1.0); // F x, F P F^T + Q
const auto u = tr::update(prediction, z, sensor); // posterior, innovation, gain, d^2, log-likelihood
if (!u)
return 1; // S was not positive definite: cannot happen with R > 0
gated_out += tr::in_gate(u->distance2, gate) ? 0 : 1;
track = u->posterior;
predicted[static_cast<std::size_t>(k)] = prediction;
filtered[static_cast<std::size_t>(k)] = track;
}
// Smoothing backwards: each step refined by everything that came after it
std::array<tr::gaussian<double, 4>, steps> smoothed{};
smoothed[steps - 1] = filtered[steps - 1];
for (std::size_t k = steps - 1; k-- > 0;)
smoothed[k] = *tr::rts_smooth(filtered[k], predicted[k + 1], smoothed[k + 1], model.matrix(1.0));

Group: snicholls-core.

Implementations. The gain is K = P Hᵀ S⁻¹ by one Cholesky factorisation of S, reused for the distance and the log-likelihood. Posterior covariances are made exactly symmetric.

Guarantees. constexpr, noexcept for the standard floating-point types, no allocation, no virtual call. A predict on a 4-state constant-velocity target is a few hundred multiply-adds.

Errors. update, to_information, from_information, information_update, fisher_information, gdop and rts_smooth return linalg::error::not_positive_definite when a matrix they must factorise is not.

Performance. A 2-D constant-velocity predict and position update, the whole kalman_update record written, against the same arithmetic in the same order written by hand over raw arrays, after a bit-for-bit check, 4096 tracks (benchmarks/tracking/kalman_benchmark.cpp; Release, Apple clang 17, Xeon W-3245, 2026-11-23): 7.9 million tracks a second (by hand 11.0). The predict is at parity; the update is slower by the copies of its 36-double record through result and of the intermediate measurement prediction. See Known issues.

Tests and demos. tests/tracking/kalman_test.cpp, demos/tracking/kalman_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <limits>, linalg/fixed.hpp, geometry/angle.hpp, tracking/gaussian.hpp, tracking/measurement.hpp, tracking/transition.hpp, result.hpp.

Known issues. Stone Soup's extended filters differentiate numerically; ours use each model's analytic Jacobian, so results agree to the numerical derivative's accuracy (about 1e-7 relative), not to rounding. The update runs at 0.72 of the hand-written loop's speed (Performance): closing the gap needs a form that writes into the caller's storage, planned with the batched device forms.

Status. Experimental, new in 0.19.0.
