Detailed Description

Facts about a pack of values at compile time: distinct, increasing, decreasing.

Overview. Tables written by hand into a program (enumeration codes, tenor buckets, the breakpoints of a schedule) carry rules: no code twice, buckets in order. These state the rule where the table is, as a static_assert, for any values usable as template arguments.

// Tenor buckets in days and the codes that name them: in order, and no code twice.
static_assert(snicholls::strictly_increasing_v<7, 30, 91, 182, 365, 730>, "tenor buckets out of order");
static_assert(snicholls::all_distinct_v<'W', 'M', 'Q', 'H', 'Y', 'B'>, "a bucket code is used twice");

Relationships. meta/concepts.hpp (distinct_static_names_v for names); constexpr_map.hpp. Group: snicholls-core.

Guarantees. Compile time only. An empty pack or a single value is distinct and monotone.

Errors. None.

Performance. Compile time only.

Tests and demos. tests/meta/values_test.cpp, demos/meta/values_demo.cpp.

Dependencies. <array>, <cstddef>, <type_traits>.

Known issues. The values must share a type once std::common_type has had its say.

Status. New in 0.5.0.
