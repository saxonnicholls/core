Detailed Description

snicholls::fn combinators: functions that take functions and return functions, all constexpr.

Overview. The classic combinators, each a function that takes callables and returns a new callable, built and called at compile time or at run time alike:

here what it returns Haskell / maths
identity its argument id
constant(x) a function that ignores its arguments and returns x const x (K)
flip(f) f with its first two arguments swapped flip f
compose(f, g, h) x -> f(g(h(x))), right to left f . g . h
pipe(f, g, h) x -> h(g(f(x))), left to right h . g . f
x \| then(f) \| then(g) g(f(x)): a value through a pipe x & f & g
on(f, p) (a, b) -> f(p(a), p(b)) f `on` p
apply(f) tuple -> f(elements...) uncurry on tuples
juxt(f, g) x -> tuple{f(x), g(x)} f &&& g
fix(f) x -> f(self, x): recursion for lambdas fix (Y)
tap(f) x -> (f(x), x): look, pass it on traceShowId
when(p, f), unless(p, f) x -> p(x) ? f(x) : x, and the converse bool-guarded f
call(f, x...) f(x...) as a value f $ x, OCaml f @@ x
until(p, f) x -> f(f(...x)) until p holds until p f
apply_when(b, f) x -> b ? f(x) : x applyWhen b f
bool_(f, t, b) b ? t : f bool f t b
rotate_args(f), swap_args(f) (a, b, c) -> f(b, c, a); flip(f) argument reordering
constexpr auto to_bp = [](double r) { return r * 10'000.0; };
constexpr auto spread = [](double bid, double ask) { return ask - bid; };
// compose runs right to left, as in maths; pipe left to right, in the order the steps run.
constexpr auto spread_bp = fn::compose(to_bp, spread);
constexpr auto spread_bp_too = fn::pipe(spread, to_bp);
static_assert(spread_bp(1.0850, 1.0852) == spread_bp_too(1.0850, 1.0852));
// constant, flip, identity, juxt: small pieces that complete a composition.
static_assert(fn::constant(42)("ignored", 1, 2.0) == 42);
static_assert(fn::flip(std::minus<>{})(1, 10) == 9);
static_assert(fn::identity(7) == 7);
constexpr auto stats = fn::juxt([](int a, int b) { return a < b ? a : b; }, [](int a, int b) { return a < b ? b : a; });
static_assert(stats(3, 9) == std::tuple{3, 9});

Every entry point without an explicit template argument is itself a constexpr function object, so it can be passed, composed and curried like any other function: fn::curry<2>(fn::compose), fn::juxt(fn::identity, f). Use these when the function is the value being built (a pricing step assembled from pieces, a projection passed to an algorithm, a recursive lambda); write the plain lambda when it is used once and reads better that way.

Relationships. The rest of functional/: curry.hpp (currying, partial application, sections), bind.hpp (placeholders), typeclasses.hpp and instances.hpp (Functor, Monad, Monoid, ...), state.hpp (Reader, Writer, State), monad.hpp (Maybe / Either helpers), fold.hpp and list.hpp (folds, Data.List), lazy.hpp (thunks, streams), match.hpp (pattern matching), recursion.hpp, tabulate.hpp (compile-time memoisation), types.hpp, ocaml.hpp. snicholls::overloaded / first_match join callables into one overload set; snicholls::function_ref refers to one without owning it; snicholls::pipeline stages are observer chains that push values to a sink, where then pulls one value through. std::identity and std::not_fn are the standard library's. Group: snicholls-core.

Implementations / variants. One. Every returned callable is one class template, fn::detail::closure<Op, Parts...>: the parts stored by value, and an empty policy Op saying what a call does. It has the four operator() overloads (&, const&, &&, const&&), so a call through an rvalue closure moves its parts into the call (C++23's std::forward_like without C++23), and a call through a const closure calls the parts as const.

Guarantees.

  • constexpr: every combinator and every call, usable in static_assert.
  • noexcept exactly when the wrapped calls and the copies made are: a closure's call is noexcept(noexcept(...)) of what it does, and building one is noexcept when decaying the arguments into it is.
  • SFINAE-friendly: std::is_invocable_v of a closure is false, not a hard error, when the wrapped call is ill-formed (except when / unless / tap, which are constrained instead).
  • Ownership: the parts are decayed copies (or moves of rvalues); nothing refers to its arguments, so a closure can outlive them. Pass std::ref(x) to refer instead.
  • Layout: a closure holds its parts and nothing else. It is trivially copyable when they are, an aggregate, and an empty part (a captureless lambda, a standard function object) takes no space: it is an empty base, not a member. No allocation, no virtual call, no type erasure.
  • Results are values: identity, tap and when return an lvalue argument as the same lvalue and an rvalue argument as a new value moved from it, never a reference to a temporary; constant returns a copy (or, from an rvalue closure, a move) of its value.

Errors. None at run time. A call the parts cannot make is a compile error at the call site, or std::is_invocable_v false.

Performance. A composed or curried pipeline compiles to the same code as the hand-written lambda. benchmarks/functional/combinators_benchmark.cpp, pipe of three curried pieces against the lambda over 4096 prices, fairness-checked (identical sums): medians 4347 ns and 4326 ns, equal within noise (CV under 1%; macOS x86-64 Xeon W-3245, Apple Clang 17, Release, 2026-11-26, 5 repetitions). At -O2 the two functions compile to identical instructions (Apple Clang 17 and Clang 23, arm64; x86-64 identical but for constant-pool label names).

Tests and demos. tests/functional/combinators_test.cpp, demos/functional/combinators_demo.cpp.

Dependencies. <cstddef>, <functional> (for std::invoke), <tuple>, <type_traits>, <utility>, and snicholls/core/overloaded.hpp (for SNICHOLLS_EMPTY_BASES).

Known issues and gotchas.

  • fix(f): f takes the recursive function as its first parameter and must state its return type ([](auto& self, int n) -> int { ... }): a deduced return type would need itself.
  • A function pointer to an overload set or a function template has no single address: wrap it in a lambda ([](auto x) { return std::abs(x); }), as for any standard algorithm.
  • then is spelled x | fn::then(f), not x | f: a bare callable on the right would capture every | in the program. snicholls::pipeline's | composes stage specs and is unaffected.
  • Two parts of the same empty type (compose(f, g, f)) cannot share an address, so each takes a byte. [[no_unique_address]] is not used: GCC 13 rejects reading such parts in a constant expression and Clang 18 crashes on them, so empty parts are empty bases instead. A final empty class is stored as a member and takes a byte.

Status. Experimental, new in 0.27.0.
