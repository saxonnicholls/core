Detailed Description

snicholls::function_ref<R(Args...)>: a non-owning, non-allocating reference to a callable.

Overview. function_ref<R(Args...)> is the shape of C++26 std::function_ref: a type-erased reference to any callable invocable as R(Args...), built from two pointers. It is what a function takes when it wants "something callable" without becoming a template and without the allocation and copy of std::function:

// Not a template: one definition, whatever callable the caller passes.
int count_if(const std::vector<int>& values, snicholls::function_ref<bool(int)> keep)
{
int n = 0;
for (int v : values)
if (keep(v))
++n;
return n;
}

Use it for parameters - a visitor passed down a call, a callback invoked before the call returns. Do not use it for storage: it refers to the callable it was built from and does not keep it alive.

Relationships. Replaces a template <typename F> parameter where code size or compile time matters, and std::function where the callable does not need to be owned. snicholls::overloaded builds a callable it can refer to.

Guarantees. Two pointers, trivially copyable; copying a function_ref copies the reference, never the callable, so every copy calls the same object and sees the same state. Construction is noexcept and allocates nothing. The call is one indirect call, which throws nothing of its own and lets whatever the callable throws propagate. A result convertible to R is converted; with R = void any result is discarded.

Errors. None of its own. A callable not invocable as R(Args...) does not convert (the constructor is constrained), so the mistake is a compile error.

Performance. Not benchmarked.

Tests and demos. tests/function_ref_test.cpp, demos/function_ref_demo.cpp.

Dependencies. <memory> (for std::addressof), <type_traits>, <utility>.

Known issues. The referenced callable must outlive the function_ref. Built from a temporary (a lambda written in the argument list) it is valid for that call only, which is exactly the parameter case; stored past the full expression it dangles. A function pointer is referred to by the address of the pointer object, so the same applies to a pointer temporary. A plain function name (a function type, not a pointer) is not accepted.

Status. Stable.
