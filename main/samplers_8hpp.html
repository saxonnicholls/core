Detailed Description

snicholls::ml samplers over a candidate array, as llama.cpp chains them: greedy, dist, temperature, top-k, top-p, min-p, penalties, locally typical, dynamic temperature, XTC, top-n-sigma, mirostat v1 and v2, DRY and logit bias, composed at compile time (sampler_chain) or at run time (runtime_sampler_chain).

Overview. ml/sampling.hpp samples straight from a row of logits. Serving stacks instead pass a candidate array through a chain of samplers, each of which rescales, masks, reorders or truncates it, and the last of which selects a token. This header is that model, as llama.cpp's llama_token_data_array (src/llama-sampler.cpp):

  • token_data<T> is {id, logit, p}; token_candidates<T> is a view over the caller's span of them with sorted (descending logit) and selected (the chosen index, -1 before a selecting sampler ran). make_candidates(logits, storage) fills one from a row of logits, token i at index i.
  • Each sampler is a small struct with apply(candidates, g), where g is a stats::wyrand; the stateful ones (penalties, dry, mirostat, mirostat_v2) also have accept(token) and reset().
    • selecting: greedy_sampler (the first largest logit), dist_sampler (softmax, then the inverse CDF at one stats::uniform_real draw), mirostat_sampler (Basu et al., 2021, algorithm 1: Zipf's exponent estimated from the top m, a top-k from it, mu moved by the observed surprise) and mirostat_v2_sampler (truncate where the surprise exceeds mu).
    • rescaling: temperature_sampler (0 keeps only the largest), temp_ext_sampler (dynamic temperature: the temperature in [temp - delta, temp + delta] set by the normalised entropy raised to exponent).
    • truncating: top_k_sampler, top_p_sampler, min_p_sampler, typical_sampler (Meister et al., 2023: the tokens whose surprise is closest to the entropy, up to mass p), xtc_sampler (exclude top choices: with probability probability, drop every token at or above threshold but the least probable of them), top_n_sigma_sampler (Tang et al., 2024: mask logits below max - n · σ).
    • adjusting logits: penalties_sampler (repetition, frequency and presence over the last last_n accepted tokens: the same rule as apply_penalties in ml/sampling.hpp), dry_sampler (DRY, "don't repeat yourself": a token that would extend a repeat of allowed_length or more of the recent context is penalised multiplier · base^(length - allowed_length), with sequence breakers that reset the match), logit_bias_sampler.
  • sampler_chain<S...>: the chain as a tuple, fixed at compile time; runtime_sampler_chain<T, History>: a std::vector of any_sampler<T, History>, a std::variant over every sampler here, built at run time. Both sample(...) the selected token and forward accept and reset to the samplers that have them.
// A vocabulary of eight tokens and one step's logits.
const std::vector<float> logits{1.0f, 3.0f, 0.5f, 2.5f, -1.0f, 2.0f, 0.0f, 1.5f};
std::vector<ml::token_data<float>> storage(logits.size());
// The chain fixed at compile time: penalties over the history, top-k, top-p, temperature, then a draw.
ml::sampler_chain chain{ml::penalties_sampler<float, 32>{.last_n = 32, .repeat = 1.3f}, ml::top_k_sampler{5},
ml::top_p_sampler<float>{0.9f}, ml::temperature_sampler<float>{0.8f}, ml::dist_sampler{}};
// The same chain built at run time, from a request, say.
ml::runtime_sampler_chain<float, 32> dynamic;
dynamic.add(ml::penalties_sampler<float, 32>{.last_n = 32, .repeat = 1.3f})
.add(ml::top_k_sampler{5})
.add(ml::top_p_sampler<float>{0.9f})
.add(ml::temperature_sampler<float>{0.8f})
.add(ml::dist_sampler{});
// A generation: each step samples, then tells the chain which token was accepted.
wyrand g1(2026), g2(2026);
std::vector<ml::token_id> text;
for (int step = 0; step < 12; ++step) {
const ml::token_id a = chain.sample(logits, std::span(storage), g1);
const ml::token_id b = dynamic.sample(logits, std::span(storage), g2);
ok &= a == b; // the same seed, the same chain: the same token
chain.accept(a);
dynamic.accept(b);
text.push_back(a);
}

Relationships. ml/sampling.hpp (the row samplers, whose apply_penalties rule penalties_sampler follows), stats/random.hpp (wyrand, uniform_real), overloaded.hpp (first_match, overloaded), constexpr_for.hpp, ml/speculative.hpp (verification with the same probabilities). Group: snicholls-core.

Implementations. One each. The semantics are llama.cpp's at commit 39039aa (src/llama-sampler.cpp), read function by function: llama_sampler_temp_impl, llama_sampler_softmax_impl, llama_sampler_top_k_impl, llama_sampler_dist_apply, llama_sampler_top_p_apply, llama_sampler_min_p_apply (its unsorted path first), llama_sampler_typical_apply, llama_sampler_temp_ext_apply (the renormalisation in double), llama_sample_xtc_apply, llama_sampler_top_n_sigma_apply, llama_sampler_mirostat_apply, llama_sampler_mirostat_v2_apply, llama_sampler_penalties_apply, llama_sampler_dry_apply (the restart sequences, the reverse Z-algorithm, the exponent clamp at 88.7228391 / ln base) and llama_sampler_logit_bias_apply. Differences, all deliberate:

  • Randomness is stats::wyrand, never std::mt19937 with a standard distribution (whose output differs between standard libraries), so a seed gives the same tokens everywhere. Every random choice is one uniform_real draw.
  • Sorting orders equal logits by the lower id, so that the order is the same on every standard library (llama.cpp's std::partial_sort leaves ties unspecified). typical_sampler breaks ties of its score the same way.
  • dist_sampler selects the first token whose cumulative probability exceeds u · sum (llama.cpp: reaches it), so a token of probability 0 is never chosen, even at u = 0.
  • typical_sampler skips tokens of probability 0 in the entropy (llama.cpp's -p log p is then NaN).
  • mirostat_sampler clamps the computed k to [1, size] (llama.cpp converts a non-finite or huge float to int, which is undefined).
  • Surprise in bits is -log(p) / ln 2 (llama.cpp: log2f), which can differ in the last bit.
  • DRY's sequence breakers are token sequences the caller has tokenised, head first in reading order. llama.cpp derives them from strings with the vocabulary (get_overlapping_token_sequences, every token that contains a breaker or begins one, the tail capped at 20 tokens); that needs the tokenizer and is the caller's.

Infill (llama_sampler_infill_apply) is not here: it sums the probabilities of end-of-generation tokens against text tokens (choosing only EOG tokens when 3 · p_eog · n > p_text), and merges candidates whose pieces share a prefix, so it needs the vocabulary's EOG classification and the token pieces, which belong to the tokenizer layer above core. A caller can apply it between this chain's truncation and its selection with the same candidates.

Guarantees. constexpr (a whole chain runs in a static_assert), no allocation except runtime_sampler_chain's vector, no I/O. Deterministic: the same candidates, state and generator give the same token. Each sampler is trivially copyable apart from the spans it views (dry_sampler's breakers, logit_bias_sampler's biases), which must outlive it. Complexity: O(n) for the masks, rescalings and dist; O(n log n) where the candidates are sorted; penalties O(h² + h · n) for h history tokens (O(h²) when the candidates are in id order); dry O(h · b) for b breakers plus O(h · n) at worst.

Errors. Preconditions, asserted: a selecting sampler has at least one candidate; top_p and min_p thresholds in their documented ranges; last_n, penalty_last_n not beyond the compile-time history; a repetition penalty greater than 0. A chain whose samplers selected nothing returns the greedy choice.

Performance. Not benchmarked: one pass over the candidates, dominated by the exponentials, or a sort.

Tests and demos. tests/ml/samplers_test.cpp, demos/ml/samplers_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <concepts>, <cstddef>, <cstdint>, <limits>, <span>, <tuple>, <type_traits>, <utility>, <variant>, <vector>, snicholls/core/constexpr_for.hpp, snicholls/core/math/constexpr_math.hpp, snicholls/core/overloaded.hpp, snicholls/core/stats/random.hpp, ml/row.hpp.

Known issues. NaN logits are not ordered. Mirostat's estimate needs at least two candidates and m >= 2; otherwise its k is 1 (greedy). The run-time chain's std::variant makes it as large as its largest sampler (the history buffers of penalties and dry).

Status. Experimental, new in 0.17.0.
