Detailed Description

snicholls::signer_interface: the pure virtual twin of signer, and the adapters both ways.

Overview. When the keys live in a KMS chosen by configuration, code holds a signer_interface&. Its pure virtual functions (sign, public_key_of) are the operations of the concept signer (concepts/signer.hpp, where the contract and its value types are documented), so the interface models the concept itself. signer_adapter<S> puts any model behind the interface, owning it (S) or referring to it (S&); signer_ref is a copyable, non-owning handle on the interface that models the concept.

signer_adapter<memory_signer&> adapter{keys}; // borrows
signer_interface& chosen = adapter;
signer_ref handle{chosen};
const std::array<std::byte, 3> payload{std::byte{1}, std::byte{2}, std::byte{3}};
const auto sig = handle.sign({key->key_id.view(), payload, payload_kind::message});

Relationships. concepts/signer.hpp, interfaces/signer_reference.hpp, interfaces/signer_conformance.hpp. Group: snicholls-core.

Implementations / variants. signer_adapter<S> over any model; an implementation above core may derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else; thread safety and exception safety are the wrapped implementation's.

Errors. As the contract.

Performance. One virtual call; the signer's own cost dominates (benchmarks/interfaces/key_store_reference_benchmark.cpp).

Tests and demos. tests/interfaces/signer_test.cpp (the kit through every form, the adapters forward), demos/interfaces/signer_demo.cpp.

Dependencies. <type_traits>, <utility>, concepts/signer.hpp.

Known issues. None.

Status. New in 0.23.0. Experimental until two real implementations pass the kit.
