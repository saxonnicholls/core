Detailed Description

snicholls::overloaded and snicholls::first_match: several callables as one, resolved at compile time.

Overview. Two ways to make one callable out of several. They differ only in which callable a call picks:

  • overloaded{f, g, h} is an overload set. A call is resolved by ordinary overload resolution: the best match wins and an ambiguity is a compile error. It is the usual companion to std::visit, one handler per alternative:

    using message = std::variant<int, double, std::string>;
    const std::vector<message> inbox{42, 2.5, std::string{"hello"}};
    const auto describe = snicholls::overloaded{
    [](int n) { return "int " + std::to_string(n); },
    [](const std::string& s) { return "string " + s; },
    [](const auto&) { return std::string{"something else"}; }, // catch-all
    };
    for (const auto& m : inbox)
    std::printf(" %s\n", std::visit(describe, m).c_str());

  • first_match{f, g, h} is an if constexpr chain without the if constexpr. A call goes to the first callable, in the order written, that accepts the arguments; the rest are not considered, so overlapping conditions are settled by order and nothing is ever ambiguous. With concept-constrained lambdas every callable states its condition and the chain reads top to bottom, like the chain it replaces:

    // The conditions of the chain are core's concepts (snicholls/core/meta/concepts.hpp).
    std::string text(const auto& value); // the chain calls itself for the elements of a range
    // A to_string written as one generic lambda has an if constexpr / else if constexpr
    // chain inside it. Here every branch is its own callable and the order of the list is the
    // chain: the first that accepts the value runs, and nothing is ambiguous. No if constexpr.
    const auto text_chain = snicholls::first_match{
    [](std::string_view s) { return std::string{s}; }, // std::string, const char*, string_view
    [](std::same_as<bool> auto b) { return std::string{b ? "true" : "false"}; },
    [](snicholls::character auto c) { return std::string(1, static_cast<char>(c)); },
    [](snicholls::integer auto n) { return std::to_string(n); }, // not bool, not a character
    [](std::floating_point auto x) { return std::format("{}", x); },
    [](snicholls::enumeration auto e) { return std::to_string(static_cast<std::underlying_type_t<decltype(e)>>(e)); },
    [](const snicholls::map_like auto& m) {
    std::string out{"{"};
    for (const auto& [key, value] : m)
    out += (out.size() > 1 ? ", " : "") + text(key) + ": " + text(value);
    return out + "}";
    },
    [](const std::ranges::input_range auto& r) { // after map_like: a map is a range too
    std::string out{"["};
    for (const auto& element : r)
    out += (out.size() > 1 ? ", " : "") + text(element);
    return out + "]";
    },
    [](const snicholls::streamable auto& x) { std::ostringstream os; os << x; return os.str(); },
    [](const auto&) { return std::string{"?"}; }, // the else
    };
    std::string text(const auto& value) { return text_chain(value); }

Which one: overloaded when every argument type has exactly one handler (a variant's alternatives, a type registry's types); first_match when the handlers are conditions that can overlap (integral, enumeration, range, streamable, anything) and the order is the rule. A first_match can be an element of an overloaded and the other way round.

Both accept lambdas, function objects and function pointers; a pointer is wrapped in snicholls::fn_ptr, which calls it with its exact signature. Both are resolved at compile time and cost nothing at run time. For a dispatch decided at run time, over std::any arguments, see snicholls::invoke_any in snicholls/core/invoke_with.hpp.

Relationships. std::visit; base-encode-decode's type registry dispatch; snicholls::invoke_any, the run-time counterpart; snicholls::function_ref refers to either. Group: snicholls-core.

Guarantees. Both are aggregates that derive from each callable: no storage beyond the callables, no indirection, and std::is_empty_v when every callable is empty. Copyable and movable exactly when every callable is. constexpr whenever the chosen callable is. A first_match call is noexcept exactly when the chosen callable's call is, and is SFINAE-friendly: std::is_invocable_v is false, not an error, when no callable accepts the arguments. A first_match considers a callable through the same constness as itself, so a mutable lambda is skipped when the first_match is const.

Errors. None of their own. An ambiguous or missing overloaded overload, or a first_match that no callable accepts, is a compile error at the call site.

Performance. No run-time footprint: a call is the chosen callable's call, inlined. Not benchmarked. benchmarks/invoke_with_benchmark.cpp measures the run-time path against a direct call through an overloaded.

Tests and demos. tests/overloaded_test.cpp, demos/overloaded_demo.cpp.

Dependencies. <cstddef>, <type_traits>, <utility> and snicholls/core/meta/type_list.hpp (for first_match's choice).

Known issues.

  • first_match asks "does this callable accept these arguments?" (std::is_invocable), and implicit conversions count: [](bool) accepts an int, [](double) accepts an int, [](const std::string&) accepts a string literal. Put the exact cases first, or constrain them: [](std::same_as<bool> auto).
  • overloaded has the opposite trap: an exactly matching generic lambda beats a converting concrete one, so overloaded{[](int) {...}, [](const auto&) {...}} called with a short takes the generic lambda. first_match takes the int one.
  • To decide whether a generic lambda accepts the arguments, the compiler instantiates its body (the return type is deduced from it), for every callable, whichever one is chosen. So each body must be well-formed for everything its constraint admits: a [](std::integral auto n) { std::from_chars(..., n); } fails to compile when called with a bool, even behind a [](std::same_as<bool> auto) that would take it, because bool is integral and std::from_chars has no bool overload. Constrain each branch to what its body can take, or state the return type (-> std::string) so the body is not needed.
  • A callable must be a class type or a function pointer. A C-variadic function pointer and a final class cannot be bases: wrap them in a lambda. Two callables of the same type (the same function pointer type twice) cannot both be bases either.

Status. overloaded stable. first_match and fn_ptr new in 0.5.0.
