Detailed Description

The native assets of the major chains as types: snicholls::native::ETH, BTC, SOL, TRX, ...

Overview. A chain's native asset is what its fees are paid in. Its symbol and decimals are fixed by the chain's protocol and never change, so like ISO 4217 codes they are compile-time types. Each answers:

  • code(), name() and scale(), the decimals of its smallest unit (wei, satoshi, lamport, sun);
  • slip44(), its SLIP-44 coin type, the number BIP-44 derivation paths use.

They model asset_like and has_name, so asset_v<native::ETH> and money_of<native::ETH> work. Tokens (ERC-20, TRC-20, SPL) are not here: they are deployed contracts, not protocol constants, and they live in the application's token registry, which gives each a unique code (USDC:56). A product declares its own tokens as types of the same shape.

constexpr asset eth = asset_v<native::ETH>;
static_assert(native::ETH::slip44() == 60 && native::BTC::scale() == 8);

Relationships. money/asset.hpp, chain/chains.hpp (each chain names its native asset), money/money.hpp. Group: snicholls-core.

Implementations. One type per asset.

Guarantees. constexpr, noexcept, no state.

Errors. None.

Performance. Not applicable.

Tests and demos. tests/money/native_test.cpp: the decimals are checked against each protocol's specification, and the coin types against the SLIP-44 registry. Demo: demos/money/native_demo.cpp.

Dependencies. <cstdint>, <string_view>.

Known issues.

  • SLIP-44 numbers BNB 714 (its original Beacon chain); BNB Smart Chain wallets derive with Ethereum's 60. The type gives 714, the registered value.
  • POL keeps MATIC's coin type, 966.

Status. New in 0.22.0.
