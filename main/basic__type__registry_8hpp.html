Detailed Description

snicholls::basic_type_registry and snicholls::named: construct-and-dispatch by name, with no codec.

Overview

The codec-independent core of the type registry: construct-and-dispatch by name with no std::variant, no common base class and no switch statement. Each type is bound to a compile-time string; a run-time name is matched against those names with a short-circuiting fold expression, and on the first match the payload is deserialised with a caller-supplied deserialiser and handed to a generic callable. It depends only on fixed_string.hpp - no encoder, no SIMD - so it can be used with any format (JSON, protobuf, your own bytes).

Relationships
  • snicholls::basic_fixed_string names the bindings; snicholls::overloaded makes a per-type handler.
  • base-encode-decode's TypeRegistry (utils/type_registry.hpp) extends this one with the Base64 defaults (Registry::serialize(obj), Registry::dispatch(name, base64, handler)); that part stays there because it is a codec.
  • Module: snicholls-core.
Implementations and variants

None: a single implementation. The set of bindings is closed and fixed at compile time.

Guarantees and contracts
  • Every member is static; the registry is never instantiated. count, names, contains and name_of are compile-time (contains also works at run time).
  • dispatch tries the bindings in declaration order and stops at the first name that matches: at most one deserialisation and one handler call. On no match neither is called.
  • Lookup is a linear chain of string comparisons, O(bindings x name length).
  • Thread safety: no state, so as safe as the handler and deserialiser passed in.
Errors

name_of<T>() for an unregistered T is a compile error. dispatch returns false for an unknown name and lets whatever the deserialiser or handler throws propagate.

Examples
using Registry = snicholls::basic_type_registry<
snicholls::named<"celsius", Celsius>,
snicholls::named<"label", Label>>;
static_assert(Registry::name_of<Label>() == "label"); // an unregistered type would not compile
int degrees = 0;
std::string text;
const auto handler = snicholls::overloaded{
[&](Celsius&& c) { degrees = c.value; },
[&](Label&& l) { text = std::move(l.text); },
};
const std::vector<std::pair<std::string, std::string>> inbox{
{"celsius", "21"}, {"label", "hello"}, {"kelvin", "294"}};
int handled = 0;
for (const auto& [name, payload] : inbox)
if (Registry::dispatch(name, payload, handler, TextFormat{}))
++handled;

Dependencies

Known issues and gotchas
  • snicholls::named is a name-to-type binding, not a concept for types that declare their own name().
  • Two bindings with the same name are not rejected: the first one wins in dispatch and name_of.
