Detailed Description

Classification of every string and byte-sequence type: code units, ownership, termination, length.

String / byte-sequence classification: separate, composable compile-time properties of every "string-ish" type the snicholls libraries meet (field names, keys, values and serialisation), plus concepts built from them. Zero-copy access (to_string_view, as_bytes_view, length_of, c_str_of) is in <snicholls/core/reflect/string_access.hpp>.

A code-unit sequence is a contiguous run of code units carried by one of these types (any cv, any reference):

carrier owning NUL-terminated length units
C* no by contract O(n) (strlen; null -> 0) text only
C[N] (text: a string literal) yes by contract N-1, compile time text
B[N] (bytes) yes no N, compile time bytes
std::basic_string<C, T, A> (incl. pmr) yes guaranteed O(1) text only
std::basic_string_view<C, T> no no O(1) text only
std::vector<U, A> (incl. pmr) yes no O(1) text or bytes
std::array<U, N> yes no N, compile time text or bytes
std::span<U, dynamic_extent> no no O(1) text or bytes
std::span<U, N> no no N, compile time text or bytes
basic_fixed_string<C, N> (and the yes guaranteed N, compile time text only
fixed_string<N>, u8/u16/u32/w wrappers)

Classification rules (see CLAUDE.md "Strings"):

  • Text code units are the character types char, wchar_t, char8_t, char16_t, char32_t. Byte code units are std::byte and unsigned char (std::uint8_t is unsigned char on every supported platform). signed char / std::int8_t is neither: it is a small number (canonical int8), not a character type distinct from char, and not one of the types the standard lets inspect object representation. So std::vector<std::uint8_t> is a byte sequence here (same object representation as std::vector<std::byte>, viewing it as bytes is lossless); this says nothing about how a consumer maps it to its own types.
  • A character array is a string literal: its length is N-1 (every element but the last, embedded NULs included, never strlen), and its last element must be NUL (checked by the access functions). For a fixed-width, possibly unterminated buffer use std::array or std::span (length N, not NUL-terminated).
  • A byte array has no terminator: its length is N.
  • Ownership describes the type as given: a reference never owns (std::string& is a view of someone else's string; a string literal is a const char(&)[N]). Owning containers propagate top-level const to their code units; views (span, pointer, string_view) do not.
  • Volatile carriers or code units, unbounded arrays, pointers to bytes (no length) and non-contiguous containers (std::deque, std::list) are not code-unit sequences.
