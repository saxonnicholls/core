Detailed Description

The game of a model at one row of a dataset: a feature's absence is its value in background rows.

Overview. To explain why a model gave f(x) for one row x, each feature is a player. A coalition keeps its features at x's values and replaces the others by their values in a background row, and its worth is the model's average over the background. That is the interventional game SHAP's permutation explainer samples; give it to shapley (exact, up to about 20 features) or shapley_sampled.

// Any model over rows of features: here a score from leverage, coverage, and their interaction.
const auto model = [](std::span<const double> x) { return 2.0 * x[0] - 1.0 * x[1] + 0.5 * x[0] * x[1]; };
const std::array<double, 2> borrower{3.0, 1.0};
const std::vector<std::array<double, 2>> others{{1.0, 2.0}, {2.0, 2.0}, {1.0, 3.0}};
// Why did this borrower score what it did, compared with the others?
const auto explained = game::shapley<2>(game::interventional(model, borrower, others));

Any model, any dataset: the instance is a random-access range of feature values; the background is any range of rows like it; the model is called with a std::span<const F> of one hybrid row. The features may be anything a row holds (double, an enum, a struct) and the result any game_value.

Relationships. game/shapley.hpp; game/change.hpp for one point moving to another, the special case of a single background row. Group: snicholls-core.

Guarantees. constexpr. One evaluation is one model call per background row. The game refers to the model, instance and background: they must outlive it. It keeps one row buffer, so it is not thread-safe; give each thread its own.

Errors. None of its own; the background must not be empty and each row must have as many features as the instance (asserted).

Performance. Not benchmarked: the model calls are the cost.

Tests and demos. tests/game/tabular_test.cpp, demos/game/tabular_demo.cpp.

Dependencies. <cassert>, <cstddef>, <functional>, <ranges>, <span>, <type_traits>, <vector>, game/coalition.hpp.

Known issues. The interventional game breaks correlations between features: a feature is replaced independently of the others, as in SHAP's default. Conditional expectations need a model of the data, which is the caller's to build.

Status. New in 0.5.0, experimental.
