Detailed Description

snicholls::http_handler_interface: the pure virtual twin of http_handler, and the adapters both ways.

Overview. When routes are assembled at run time, code holds a http_handler_interface&. Its pure virtual functions (handle) are the operations of the concept http_handler (concepts/http_handler.hpp, where the contract and its value types are documented), so the interface models the concept itself. http_handler_adapter<H> puts any model behind the interface, owning it (H) or referring to it (H&); http_handler_ref is a copyable, non-owning handle on the interface that models the concept.

std::unique_ptr<http_handler_interface> app = std::make_unique<http_handler_adapter<route_table>>(std::move(routes));
http_handler_ref handle{*app};
http_request r;
r.path = "/health";
const http_response answer = handle.handle(r);

Relationships. concepts/http_handler.hpp, interfaces/http_handler_reference.hpp, interfaces/http_handler_conformance.hpp. Group: snicholls-core.

Implementations / variants. http_handler_adapter<H> over any model; an implementation above core may derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else; thread safety and exception safety are the wrapped implementation's.

Errors. As the contract.

Performance. One virtual call, measured against the concept and a hand-written dispatch in benchmarks/interfaces/http_handler_benchmark.cpp.

Tests and demos. tests/interfaces/http_handler_test.cpp (the kit through every form, the adapters forward), demos/interfaces/http_handler_demo.cpp.

Dependencies. <type_traits>, <utility>, concepts/http_handler.hpp.

Known issues. None.

Status. New in 0.23.0. Experimental until two real implementations pass the kit.
