Detailed Description

snicholls::ml K-quants: ggml's super-block formats Q2_K, Q3_K, Q4_K, Q5_K and Q6_K, byte for byte, with their reference and importance-weighted quantisation, dequantisation and the dot products with Q8_K, all constexpr.

Overview. A K-quant block holds 256 numbers in sub-blocks of 16 or 32, each sub-block with its own scale (and minimum), the sub-block scales themselves quantised against one or two float16 super-block scales. These are llama.cpp's "Q4_K_M"-style formats, so a GGUF tensor of one of them is an array of these structs, read in place:

Block Sub-blocks Weight Sub-block scales Bytes Bits per weight
block_q2_k 16 of 16 2-bit, x ≈ d·s·q - dmin·m 4-bit scale and min, in scales 84 2.625
block_q3_k 16 of 16 3-bit (2 in qs, the third in hmask), x ≈ d·(s - 32)·(q - 4) 6-bit, packed in 12 bytes 110 3.4375
block_q4_k 8 of 32 4-bit, x ≈ d·s·q - dmin·m 6-bit scale and min, packed in 12 bytes 144 4.5
block_q5_k 8 of 32 5-bit (the fifth in qh) as Q4_K 176 5.5
block_q6_k 16 of 16 6-bit (4 in ql, 2 in qh), x ≈ d·s·(q - 32) int8 210 6.5625

The activations are block_q8_k (ml/quantize.hpp). The functions follow ml/quantize.hpp's contract: quantize_row(x, importance, blocks) is ggml's quantize_q<n>_K for one row (an empty importance is the reference quantize_row_q<n>_K_ref; a non-empty one the importance-matrix path, quantize_row_q<n>_K_impl), dequantize_row is dequantize_row_q<n>_K, and dot is ggml_vec_dot_q<n>_K_q8_K_generic, with its summation order (eight lanes of integer sums for Q3_K to Q6_K), so the result is ggml's to the bit.

// The weights as K-quant blocks: the reference quantisation, and the importance-weighted one llama-quantize
// runs with an imatrix (one weight per column: how much each input matters)
std::vector<B> q(w.size() / B::elements), qi(w.size() / B::elements);
ml::quantize(w, std::span<B>(q));
ml::quantize(w, importance, std::span<B>(qi));
// The activations as Q8_K, then the integer dot product ggml runs
std::vector<ml::block_q8_k> a8(a.size() / 256);
ml::quantize(a, std::span<ml::block_q8_k>(a8));
const float d = ml::dot(std::span<const B>(q), std::span<const ml::block_q8_k>(a8));

Relationships. ml/quantize.hpp (the type ids, block_traits, Q8_K, and the scale searches make_qx_quants, make_qkx_quants, make_qp_quants this header shares with Q4_0 to Q5_1 and the IQ formats); ml/quant_iq.hpp, ml/quant_ternary.hpp, the other super-block formats. Group: snicholls-core.

Implementations. One per block. The quantisers search scales as ggml's do (make_qkx2_quants for the reference Q2_K, Q4_K and Q5_K, make_q3_quants for Q3_K, make_qx_quants for Q6_K and the weighted Q3_K; make_qkx3_quants and make_qp_quants for the weighted Q2_K, Q4_K and Q5_K), so they cost tens of operations per weight; dequantisation and the dot products are the scalar reference a SIMD or GPU kernel reorders.

Guarantees. constexpr, no allocation, linear in the row. The blocks are trivially copyable, have ggml's sizes and no padding (static_asserted against ggml_type_traits). Bytes, dequantised numbers, Q8_K activations and dot products equal ggml's on every row of the committed fixture (tests/fixtures/ml/quant_formats_fixture.txt, from scripts/generate_quant_formats_fixture.cpp built against ggml, llama.cpp 39039aa), with and without an importance row. Each multiplication and addition is its own statement, so no compiler fuses them.

Errors. Preconditions, asserted: the row has 256 · blocks.size() numbers; importance is empty or as long as the row; the rows of a dot product have the same number of blocks. NaN and infinity are not representable; the result is ggml's (deterministic, not meaningful).

Performance. Against ggml's scalar loops written out by hand (benchmarks/ml/quant_k_benchmark.cpp), rows of 4,096, medians of five: Q6_K dot 2.1 against 2.2 billion weights per second; Q4_K dot 2.2 against 2.8 (core unpacks the nibbles in element order, ggml in two passes); Q4_K dequantisation 3.9 against 1.4 (Xeon W-3245, Release, Apple clang 17, 2026-11-20, one thread, scalar code). Quantisation is a conversion step, tens of operations per weight (the scale searches), not benchmarked.

Tests and demos. tests/ml/quant_k_test.cpp, demos/ml/quant_k_demo.cpp.

Dependencies. <array>, <cassert>, <cstddef>, <cstdint>, <span>, ml/quantize.hpp.

Known issues. As ml/quantize.hpp: build with -ffp-contract=off on GCC for ggml's last bit, and a float converted out of an integer's range gives x86's result, where the fixture was made. Whole-block quantisation is thousands of operations per block, so compile-time use is for a block or two within the compiler's limits.

Status. Experimental, new in 0.17.0.
