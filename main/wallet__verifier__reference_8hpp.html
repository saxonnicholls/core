Detailed Description

snicholls::memory_wallet_verifier: the standard-library reference wallet_verifier, test wallets with a deterministic keyed "signature", for tests only.

Overview. add_wallet(address, key) registers a test wallet, sign(address, message) makes its 65-byte test signature, and verify checks one in constant time. The scheme is not ECDSA: with h = personal_sign_hash(message), the signature is r = HMAC-SHA256(key, h), s = HMAC-SHA256(key, r) and v = 27 (0x1b), so it has an EOA signature's length and shape and binds the wallet, the message and its EIP-191 framing, but proves nothing about a real wallet. A real one needs secp256k1, which is crypto's (servers' crypto_wallet_verifier). fail_next(code, response) makes the next verify fail as though a node had answered response. Never configure it in production.

constexpr std::string_view alice = "0x52908400098527886e0f7030069857d2e4169ee7";
constexpr std::string_view bob = "0x8617e340b3d01fa5f11f306f4090fd50e238070d";
memory_wallet_verifier wallets; // not ECDSA: a keyed test scheme, for tests only
static_cast<void>(wallets.add_wallet(alice, "alice's test key"));
static_cast<void>(wallets.add_wallet(bob, "bob's test key"));
const auto sig = wallets.sign(alice, "sign in"); // 65 bytes, r||s||v
const auto as_alice = wallets.verify({1, alice, "sign in", sig});
const auto as_bob = wallets.verify({1, bob, "sign in", sig});

Relationships. Models wallet_verifier (concepts/wallet_verifier.hpp); passes its kit in every form. Group: snicholls-core.

Implementations / variants. One.

Guarantees. verify is const; it is safe to call concurrently once the wallets are added and no failure is armed. Keys are held as snicholls::secret, and no operation returns them. Errors carry fixed messages only.

Errors. invalid_argument (an address not in the contract's form), signature_invalid (an unknown wallet, a signature not 65 bytes, a wrong one), and whatever fail_next armed.

Performance. One Keccak-256 and two HMAC-SHA256.

Tests and demos. tests/interfaces/wallet_verifier_reference_test.cpp, demos/interfaces/wallet_verifier_reference_demo.cpp.

Dependencies. <array>, <cstddef>, <functional>, <map>, <optional>, <span>, <string>, <string_view>, <vector>, hash/hmac.hpp, hash/secure.hpp, hash/sha2.hpp, secret.hpp, interfaces/wallet_verifier.hpp.

Known issues. ERC-1271 and ERC-6492 are not modelled: every wallet is an EOA.

Status. New in 0.27.0.
