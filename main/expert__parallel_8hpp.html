Detailed Description

snicholls::ml expert parallelism, the arithmetic: which rank holds which experts, the dispatch and combine layouts, and a reference all-to-all over in-process ranks that fixes the order of every received row.

Overview. With expert parallelism (GShard, Lepikhin et al., 2020; DeepSeek-V3) each of P ranks holds E / P of a mixture of experts' routed experts, and each rank's tokens travel to the ranks of the experts they chose and back. This header is that arithmetic, and nothing of the transport (sockets, NCCL, a library above core):

  • Placement: rank r holds the contiguous experts [r · E/P, (r + 1) · E/P) (first_expert, expert_rank, experts_per_rank). Since a rank's permuted rows (moe_permutation) are in expert order, the rows for one destination are one contiguous run: moe_send_offsets.
  • The exchange: the ranks first exchange their counts (E numbers each), then the rows. moe_all_to_all is the reference: destination r receives, in source order s = 0, 1, ..., source s's run for r. So a received buffer is ordered by (source, expert, row, slot).
  • The receiving rank's layout: its grouped products want (expert, source, row, slot), which is the single-process permuted order restricted to its experts, since global rows are numbered source by source. moe_receive_layout gives that order and the local experts' offsets; moe_permute_rows applies it, moe_unpermute_rows undoes it.
  • The way back: each rank sends every source its rows back, in the order received, with moe_receive_offsets as the send offsets; the same moe_all_to_all delivers them in rank order, which is the source's own permuted order.

One forward step on rank r, the backward passes the same layouts in reverse:

// Each rank routes and permutes its own tokens, and cuts its permuted rows by destination
for (std::size_t r = 0; r < P; ++r) {
auto& s = ranks[r];
s.xs.assign(xs.begin() + std::ptrdiff_t(r * rows * d), xs.begin() + std::ptrdiff_t((r + 1) * rows * d));
s.logits.resize(rows * C.experts), s.weights.resize(n), s.experts.resize(n), s.order.resize(n), s.inverse.resize(n);
s.xp.resize(n * d), s.yp.resize(n * d), s.ys.resize(rows * d);
ml::linear_sequence(backend, w.router, s.xs, s.logits);
ml::moe_route_rows<C>(backend, s.logits, {}, s.experts, std::span<float>(s.weights));
ml::moe_count_rows<C>(backend, s.experts, s.counts);
ml::moe_offsets<C>(backend, s.counts, s.offsets);
ml::moe_permutation<C>(backend, s.experts, s.offsets, s.order, s.inverse);
ml::moe_gather_rows<C>(backend, s.xs, s.order, std::span<float>(s.xp));
ml::moe_send_offsets<C>(backend, s.offsets, P, s.send);
}
// The ranks exchange their counts; each learns what it receives and the order its experts read it in
const std::array<std::span<const u32>, P> counts{ranks[0].counts, ranks[1].counts};
for (std::size_t r = 0; r < P; ++r) {
auto& s = ranks[r];
ml::moe_receive_offsets<C>(backend, counts, r, s.receive);
const std::size_t m = s.receive[P];
s.recv.resize(m * d), s.xe.resize(m * d), s.ye.resize(m * d), s.back.resize(m * d), s.layout.resize(m);
s.up.resize(m * f), s.gate.resize(m * f), s.hidden.resize(m * f);
ml::moe_receive_layout<C>(backend, counts, r, s.expert_offsets, s.layout);
}
// Rows out, each rank's experts, rows back, and each rank combines its own tokens
exchange(ranks, &rank::xp, &rank::recv, &rank::send, bf16);
for (std::size_t r = 0; r < P; ++r) {
auto& s = ranks[r];
ml::moe_permute_rows(backend, std::span<const float>(s.recv), s.layout, std::span<float>(s.xe), d);
ml::moe_experts_forward<C>(backend, ml::moe_expert_range(w.experts, ml::first_expert(r, C.experts, P), local), s.expert_offsets, s.xe,
s.ye, {s.up, s.gate, s.hidden});
ml::moe_unpermute_rows(backend, std::span<const float>(s.ye), s.layout, std::span<float>(s.back), d);
}
exchange(ranks, &rank::back, &rank::yp, &rank::receive, bf16);
for (auto& s : ranks)
ml::moe_combine_rows<C>(backend, s.yp, s.weights, s.inverse, std::span<float>(s.ys));

Exactness. An expert multiplies the same rows in the same order as in one process holding every rank's tokens, so the outputs, the input gradients and each expert's weight gradients are the single-process layer's to the bit (tested with 1, 2 and 4 ranks on core's reference backend). The router's and the shared experts' weight gradients are each rank's own part (data parallel), summed across ranks in rank order by ordered_sum (ml/diloco.hpp); they agree with one process within rounding, since one process sums all the rows in one product. The balance loss and z-loss are exact when each rank passes the whole batch's denominator (moe_balance_loss, moe_z_loss).

The payload may travel in bfloat16 (to_bfloat16_rows, to_float_rows in ml/minifloat.hpp) and be combined in float; that halves the bytes and is no longer bit-for-bit the float layer.

Relationships. ml/moe.hpp (the layer's steps), ml/diloco.hpp (ordered_sum), ml/minifloat.hpp; the plan is TRAINING.md T10. A transport of a library above core moves the bytes; a device library overloads these ops for its backend. Group: snicholls-core.

Implementations. One, for any backend, on the host: copies in a fixed order.

Guarantees. constexpr, no allocation; the placement functions noexcept. Every op is linear in what it copies.

Errors. Preconditions, asserted: P divides E, every span has its documented size, the received buffers are large enough.

Performance. Not benchmarked: copies, each row once, dominated in practice by the transport.

Tests and demos. tests/ml/expert_parallel_test.cpp, demos/ml/expert_parallel_demo.cpp.

Dependencies. <cassert>, <cstddef>, <cstdint>, <span>, <type_traits>, ml/transformer_config.hpp.

Known issues. Only the contiguous placement; an uneven split of experts over ranks is not supported.

Status. Experimental, new in 0.16.0.

The reference all-to-all over in-process ranks: destination r receives, in source order, each source's rows [send_offsets[s][r], send_offsets[s][r + 1]).

It defines the order of every received row, which a transport must reproduce for a distributed run to match one process. Any trivially copyable payload: float rows, or bfloat16 rows.
