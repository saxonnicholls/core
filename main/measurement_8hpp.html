Detailed Description

snicholls::tracking::linear_gaussian, bearing_range, elevation_bearing_range and the other sensor models: what a sensor measures of a state, its Jacobian, its noise, and which components are angles.

Overview. A measurement model maps a state to what a sensor reports. Every model here satisfies measurement_model:

  • state_dim, measurement_dim, value_type, and kinds, an angle_kinds<measurement_dim> saying which components are bearings or elevations (so residuals wrap);
  • measure(x): the noise-free measurement h(x);
  • jacobian(x): ∂h/∂x, analytic;
  • covariance(): the measurement noise R.

Which state components are the position (and velocity) is a template argument, a std::array of indices (Stone Soup's mapping), so the gather is resolved at compile time. A sensor's pose is a translation and a rotation (geometry::sensor_rotation, identity by default) applied as R (x - t).

Model Measures Kinds Reversible
linear_gaussian<T, N, Map> the mapped components linear (matrix() is H)
bearing<T, N, Map> (2-D) φ bearing no
bearing_range<T, N, Map> (2-D) (φ, ρ) bearing, linear yes
elevation_bearing<T, N, Map> (3-D) (θ, φ) elevation, bearing no
elevation_bearing_range<T, N, Map> (3-D) (θ, φ, ρ) elevation, bearing, linear yes
bearing_range_rate<T, N, Map, VelMap> (2-D or 3-D) (φ, ρ, ρ̇) bearing, linear, linear no

The functions and component order are Stone Soup's (LinearGaussian, Cartesian2DToBearing, CartesianToBearingRange, CartesianToElevationBearing, CartesianToElevationBearingRange, CartesianToBearingRangeRate, CartesianToBearingRangeRate2D). Where Stone Soup differentiates numerically, these differentiate exactly.

// A radar at (1000, 500) on a platform heading 30 degrees left of east: bearing and range in its own frame
tr::bearing_range<double, 4, xy> radar{};
radar.translation = {{1000, 500}};
radar.rotation = ge::sensor_rotation(0.0, 0.0, 30 * deg);
radar.noise = {{0.5 * deg * 0.5 * deg, 0, 0, 25}}; // 0.5 degree and 5 m
const la::fixed_vector<double, 4> target{{2000, 10, 1500, -3}}; // 45 degrees and 1414 m from the radar
const auto z = radar.measure(target); // (15 degrees, 1414.2 m)
const auto h = radar.jacobian(target); // exact, 2 x 4: zero in the velocity columns
const auto where = radar.inverse(z); // back to (2000, 0, 1500, 0)
std::printf(" radar: bearing %.2f deg, range %.1f m -> position (%.1f, %.1f)\n", z[0] / deg, z[1], where[0], where[2]);
static_assert(tr::reversible_measurement_model<decltype(radar)>);

Relationships. linalg/fixed.hpp, geometry/angle.hpp (angle_kinds), geometry/coordinates.hpp; tracking/kalman.hpp and tracking/unscented.hpp update with them. Group: snicholls-core.

Guarantees. constexpr, noexcept for the standard floating-point types, no allocation. Every model is an aggregate, trivially copyable. At the sensor's own position (zero range) the angles are 0 and the Jacobian's angle rows are zero, not NaN.

Errors. None.

Performance. Not benchmarked on their own: a gather (linear) or a rotation, a square root and an atan2.

Tests and demos. tests/tracking/measurement_test.cpp, demos/tracking/measurement_demo.cpp.

Dependencies. <array>, <concepts>, <cstddef>, linalg/fixed.hpp, geometry/angle.hpp, geometry/coordinates.hpp, math/constexpr_math.hpp.

Known issues. The 2-D models use the upper-left 2 x 2 block of the rotation, as Stone Soup does (a roll or pitch is ignored in the plane).

Status. Experimental, new in 0.19.0.
