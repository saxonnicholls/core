Detailed Description

snicholls::ml::minifloat<E, M, Kind>: the low-precision floating-point formats of machine learning (bfloat16, float16, FP8 E4M3 and E5M2, the MX FP6 and FP4) as one template, with exact decoding, round-to-nearest-even and stochastic rounding, all constexpr.

Overview. A minifloat is the bits of a narrow float in a trivially copyable 8- or 16-bit word. It converts to float and double exactly, and from them with round-to-nearest-even or with stochastic rounding from random bits the caller supplies (so a GPU kernel draws them by thread index). A format is three numbers: exponent bits, mantissa bits, and what the all-ones exponent means.

Alias E M Kind Largest finite Use
bfloat16 8 7 ieee 3.39e38 training: float's range, 3 digits
float16 5 10 ieee 65504 inference, gradients with loss scaling
float8_e5m2 5 2 ieee 57344 FP8 gradients (OCP OFP8)
float8_e4m3 4 3 finite_nan 448 FP8 weights and activations (OCP OFP8 "E4M3FN")
float6_e3m2, float6_e2m3 3/2 2/3 finite 28, 7.5 MX FP6 (OCP MX v1.0)
float4_e2m1 2 1 finite 6 MX FP4, NVFP4 elements
  • ieee: the all-ones exponent is infinity (mantissa 0) or NaN, as IEEE 754.
  • finite_nan: no infinity; only all-ones exponent and mantissa is NaN, so E4M3 reaches 448.
  • finite: no infinity and no NaN; every code is a number.

Overflow on conversion follows overflow_policy: infinity (the default for ieee: infinity; for finite_nan: NaN, OCP's non-saturating mode) or saturate (the default otherwise: the largest finite value, which is what FP8 training uses). An 8-bit or narrower format also has decode_table<F>, all its values in a table the compiler builds.

// pi in each format: the bits, and the value they hold. Conversions are constexpr.
constexpr double pi = 3.14159265358979;
constexpr ml::bfloat16 b = ml::to_minifloat<ml::bfloat16>(pi);
constexpr ml::float16 h = ml::to_minifloat<ml::float16>(pi);
constexpr ml::float8_e4m3 e4 = ml::to_minifloat<ml::float8_e4m3>(pi);
constexpr ml::float8_e5m2 e5 = ml::to_minifloat<ml::float8_e5m2>(pi);
constexpr ml::float4_e2m1 f4 = ml::to_minifloat<ml::float4_e2m1>(pi);
static_assert(ml::to_double(e4) == 3.25 && ml::to_double(f4) == 3.0);
// FP8 E4M3 has no infinity: an activation of 1000 saturates to 448 by default (as FP8 training wants), or
// becomes NaN under the non-saturating policy. The MX FP6 formats saturate too.
constexpr ml::float8_e4m3 big = ml::to_minifloat<ml::float8_e4m3>(1000.0);
constexpr ml::float8_e4m3 big_nan = ml::to_minifloat<ml::float8_e4m3>(1000.0, ml::overflow_policy::infinity);
constexpr double e3m2 = ml::to_double(ml::to_minifloat<ml::float6_e3m2>(pi)), e2m3 = ml::to_double(ml::to_minifloat<ml::float6_e2m3>(pi));
// Decoding an 8-bit format is one load from a table the compiler built.
constexpr float one = ml::decode_table<ml::float8_e4m3>[0x38];
// A weight of 1 in bfloat16 updated 1,000 times by 1e-4: rounding to nearest loses every update, because
// 1e-4 is below half of bfloat16's last place at 1 (2^-8); stochastic rounding keeps them on average (each
// step rounds up with probability 1e-4 / 2^-7, so the total is within about 0.03 of 1.1).
float nearest = 1.0f, stochastic = 1.0f;
std::uint32_t r = 2463534242u;
for (int i = 0; i < 1000; ++i) {
nearest = ml::to_float(ml::to_bfloat16(nearest + 1e-4f));
r ^= r << 13; r ^= r >> 17; r ^= r << 5; // the caller's random bits
stochastic = ml::to_float(ml::to_minifloat_stochastic<ml::bfloat16>(stochastic + 1e-4f, r));
}

Relationships. ml/quantize.hpp stores block scales in float16 and MX elements in these formats. Group: snicholls-core.

Implementations. One generic conversion; bfloat16 from float takes the usual integer fast path, which gives the same bits.

Guarantees. constexpr (through std::bit_cast), noexcept, trivially copyable, sizeof 1 or 2. Decoding is exact. Encoding rounds once from double, so a float or a double converts correctly rounded. Stochastic rounding rounds up with probability equal to the discarded fraction, to 2^-32.

Errors. None. A NaN converts to NaN where the format has one, and to the largest magnitude, with its sign, where it does not. A value below half the smallest subnormal converts to zero, keeping its sign.

Performance. Benchmarked against hand-written bfloat16 conversion (benchmarks/ml/minifloat_benchmark.cpp).

Tests and demos. tests/ml/minifloat_test.cpp (every code of every 8-bit format, round trips, ties, overflow, stochastic rounding's mean), demos/ml/minifloat_demo.cpp.

Dependencies. <array>, <bit>, <cstddef>, <cstdint>, <limits>, <type_traits>.

Known issues. No arithmetic: convert to float, compute, convert back, as hardware without native support does. C++23's std::bfloat16_t and std::float16_t are arithmetic types; these are storage formats that also work in C++20 and on a device.

Status. Experimental, new in 0.6.0.
