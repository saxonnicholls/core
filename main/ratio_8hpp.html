Detailed Description

finance::ratio: an exact ratio of two 64-bit integers, normalised; the one rational of finance/, behind year_fraction, split and rights ratios, cost apportionments, repo rates and exact returns.

Overview. Finance meets many exact fractions: a day count's 91 / 360, a 3-for-2 split, a 1-for-5 rights issue, a demerger's 13.24% of the cost base, a repo at 4.35% a year, a period's return of 1,250 / 100,000. ratio keeps each one as numerator / denominator, always in lowest terms with a positive denominator, so equal values have equal members, == is member-wise and two sources' ratios compare exactly. It is the only rational in finance/: finance::year_fraction is this type (finance/year_fraction.hpp), so a day-count fraction, a split ratio and a return combine without conversion.

  • ratio{n, d} normalises; its preconditions (d != 0, neither part INT64_MIN) are asserted. ratio::make checks them and returns ratio_errc instead, for data.
  • ratio::parse reads "3/2", "7", "-1.25" and "13.24%" exactly.
  • add, subtract and multiply are exact and checked: std::nullopt when the result does not fit in 64 bits. multiply cancels across before it multiplies, so a chain of returns or ratios stays small as long as it can.
  • <=> is exact for every pair: cross-multiplied while the products fit in 64 bits, and compared by continued fractions (only divisions) when they would not.
  • to_double() is for display and for code that wants a double anyway.

It is a pure rational, tied to no asset: finance/money_ratio.hpp multiplies and divides money by it exactly (a fund's units are amount / NAV per unit), to a ratio or to money at a stated scale and rounding mode.

Use it where an exact fraction is the answer; use snicholls::rate (money/rate.hpp) to convert an amount from one asset to another, and money for amounts.

constexpr ratio split{3, 2}; // 3 new for 2 old
constexpr ratio apportioned = *ratio::parse("13.24%"); // the demerged entity's share of the cost base
static_assert(apportioned == ratio{331, 2500});
const ratio repo_rate = *ratio::parse("4.35%"); // a year
const year_fraction days = act_365_fixed::year_fraction(sys_days{2026y / November / 2d}, sys_days{2026y / December / 2d});
const auto accrual = multiply(repo_rate, days); // the interest per unit of cash lent, exactly

Relationships. finance/year_fraction.hpp (the alias), finance/money_ratio.hpp (with money), finance/day_count.hpp, finance/returns.hpp, concepts/security_provider.hpp (split ratios, apportionments, repo rates), checked.hpp, result.hpp. Group: snicholls-core.

Implementations / variants. One, over std::int64_t. The securities library's entitlement arithmetic works in uint256 and widens a ratio into it.

Guarantees. constexpr and noexcept throughout; trivially copyable; 16 bytes; always normalised (gcd(numerator, denominator) == 1, denominator > 0, zero is 0/1). INT64_MIN is never a member, so negation never overflows.

Errors. ratio::make and ratio::parse return ratio_errc: zero_denominator, out_of_range (a part that is INT64_MIN or does not fit), malformed (text that is not a ratio). The arithmetic returns std::nullopt on overflow.

Performance. One std::gcd on construction. benchmarks/finance/ratio_benchmark.cpp, 4,096 pairs of day-count fractions, Release, Apple clang 17, macOS x86-64, 2026-11-26, CPU time on a loaded machine (load 200, so a record, not a quote): <=> 10.0 us against 7.4 us for the bare 64-bit cross-multiplication (the overflow checks); multiply 648 us against 358 us for the same cancel-then-multiply unchecked and unnormalised.

Tests and demos. tests/finance/ratio_test.cpp, demos/finance/ratio_demo.cpp.

Dependencies. <cassert>, <compare>, <cstdint>, <limits>, <numeric>, <optional>, <string_view>, checked.hpp (which brings <charconv> and <algorithm>), result.hpp.

Known issues. 64 bits: a long chain of unrelated ratios overflows (the arithmetic says so with std::nullopt), and finance/returns.hpp falls back to double there. Not a general arithmetic type: no operators but negation.

Status. New in 0.27.0. year_fraction became an alias of it, source-compatible.
