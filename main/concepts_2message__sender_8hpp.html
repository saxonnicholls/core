Detailed Description

snicholls::message_sender: anything that delivers one email or SMS and returns the provider's receipt.

Overview. A message sender delivers one message over one channel and returns a send_receipt with the provider's message id. Sign-in codes, notifications and alerts send through it; templates, codes and rate limits sit above it, and a sender only delivers. This is the concept half of a pair; the pure virtual half is message_sender_interface (interfaces/message_sender.hpp), with the adapter message_sender_adapter<S> and the handle message_sender_ref.

The contract (every implementation; interfaces/message_sender_conformance.hpp checks it):

  • validate(m) passes before anything is sent; an invalid message is capability_errc::invalid_argument and sends nothing. An SMS goes to an E.164 number in its canonical form (phone_number.hpp), an email to a conservative RFC 5321 address; a subject has no CR or LF; an idempotency key is at most 64 characters (client_id).
  • A channel the sender does not support is capability_errc::unsupported, and supports(channel) says so in advance.
  • The same non-empty idempotency_key with the same message returns the same receipt and sends once; with a different message it is capability_errc::conflict.
  • Nothing logged or returned contains the body of a message (it may hold a one-time code), the recipient or the provider's response: errors follow the redaction rule of capability_error.hpp.
memory_message_sender sender;
const auto receipt = send_code(sender, "+61412345678");
const auto refused = send_code(sender, "0412 345 678"); // not E.164: refused before anything is sent

Relationships. capability_error.hpp, capability_ids.hpp, phone_number.hpp; the twin interfaces/message_sender.hpp, the reference interfaces/message_sender_reference.hpp, the kit interfaces/message_sender_conformance.hpp. Group: snicholls-core.

Implementations. memory_message_sender (interfaces/message_sender_reference.hpp, standard library only, records an outbox; for tests). Above core: SMTP and SES email, Twilio SMS.

Guarantees. The validators are constexpr, noexcept and allocation-free. Thread safety is the implementation's.

Errors. capability_error, as the contract says.

Performance. Not benchmarked: a sender is I/O bound.

Tests and demos. tests/concepts/message_sender_test.cpp, demos/concepts/message_sender_demo.cpp.

Dependencies. <concepts>, <cstddef>, <cstdint>, <string_view>, capability_error.hpp, capability_ids.hpp, phone_number.hpp.

Known issues. The email check is deliberately conservative: quoted local parts and address literals are refused.

Status. New in 0.23.0. Experimental until two real implementations pass the kit.
