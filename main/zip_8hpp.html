Detailed Description

snicholls::zip(a, b, ...): walk several ranges together, stopping at the shortest.

Overview. zip is std::views::zip for C++20: each element is a std::tuple of references, one per range, so a structured binding reads and writes the originals.

// A structured binding, one name per range; the walk stops at the shortest.
const std::vector<double> prices{189.25, 420.50, 15.75};
const std::vector<int> sizes{100, 10};
double notional = 0;
for (auto [price, size] : snicholls::zip(prices, sizes))
notional += price * size;
// The names are references: writing changes the original.
std::vector<int> filled{0, 0};
for (auto [fill, size] : snicholls::zip(filled, sizes))
fill = size / 2;
// A range with itself, one along: adjacent pairs.
int rises = 0;
for (auto [before, after] : snicholls::zip(prices, prices | std::views::drop(1)))
rises += after > before ? 1 : 0;

Use it for ranges whose length is known at run time. To walk tuples, whose element types differ, use thread_apply. To zip types, use meta::zip_t.

Relationships. thread_apply.hpp for tuples, meta/type_list.hpp for types, and acout.hpp prints a zip as it prints any range. Group: snicholls-core.

Guarantees. constexpr and allocation-free. A range passed as an lvalue is referred to and must outlive the view; one passed as an rvalue is moved into it (std::views::all). The view is a forward_range when every range is and an input_range otherwise, except as noted under known issues. It has size() when every range has, the smallest of them. Iterators are invalidated as the underlying ranges' are. Zipping views costs their sizes, nothing more: see the static_asserts in tests/zip_test.cpp.

Errors. None of its own; whatever the ranges' iterators do.

Performance. benchmarks/zip_benchmark.cpp, a dot product of two std::vector<double> of 4,096 elements, against the index loop, after a fairness check. Release, Apple clang 17, Xeon W-3245, 2026-11-07: 4.11 us through zip against 4.04 us for the index loop, identical sums.

Tests and demos. tests/zip_test.cpp, demos/zip_demo.cpp.

Dependencies. <algorithm>, <concepts>, <cstddef>, <iterator>, <ranges>, <tuple>, <type_traits>, <utility>. It specialises std::tuple_size, std::tuple_element and std::basic_common_reference for zip_value, its own type, as the standard permits. <ranges> is heavier than it looks.

Known issues. It has no reverse iteration, random access or pipe form (a | zip(b)), which std::views::zip has no pipe form for either. Its end is a sentinel, so it works with range-for and std::ranges algorithms, not classic iterator-pair algorithms. Its value type is snicholls::zip_value, a std::tuple underneath, which declares the common reference C++20's std::tuple lacks; compare a value with a tuple through std::get, not ==.

Status. New in 0.5.0.
