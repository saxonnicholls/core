Detailed Description

The health capability of a store, static form: kv_health<S> (ping, diagnostics) and kv_diagnostics.

Overview. A supervisor, a readiness probe or an operator's console asks a store two things: can it serve requests now (ping()), and what does it hold (diagnostics(), a kv_diagnostics struct). This is separate from the store contract, so a store that cannot answer cheaply need not pretend to, and a caller that needs health asks for exactly that capability.

// A probe for any store that offers health: ready, and what it holds, as plain data to print or export.
template <kv_health S>
bool probe(const S& store)
{
if (const auto up = store.ping(); up.is_err()) {
std::printf(" not ready: error %d\n", static_cast<int>(up.unwrap_err_unchecked()));
return false;
}
const auto d = store.diagnostics();
if (d.is_err())
return false;
std::printf(" ready: %.*s, sequence %llu, %llu keys, %llu bytes, %s\n", static_cast<int>(d->backend.size()),
d->backend.data(), static_cast<unsigned long long>(d->sequence),
static_cast<unsigned long long>(d->keys.value_or(0)), static_cast<unsigned long long>(d->bytes.value_or(0)),
d->persistent ? "persistent" : "in memory");
return true;
}

Relationships. The virtual twin is kv_health_interface (interfaces/kv_health.hpp), with adapters both ways; the reference implementation is reference_key_value_store; the kit is run_kv_health_conformance (interfaces/key_value_store_conformance.hpp). Errors are kv_errc (concepts/key_value_store.hpp). A diagnostics struct is turned into JSON, a log line or a dashboard by the layer above, never here. Group: snicholls-core.

Implementations / variants. reference_key_value_store; the backends above core.

Guarantees. ping() succeeds exactly when the store can serve requests; it never changes the store. diagnostics().sequence is the store's sequence() at the time of the call; keys and bytes, when present, are exact for that moment, and absent when the backend cannot count them cheaply. No exception crosses either.

Errors. ping() and diagnostics() return the kv_errc that stops the store serving (unavailable, io, ...).

Examples. See the overview.

Performance. Not benchmarked: one call per probe.

Tests and demos. tests/concepts/kv_health_test.cpp, demos/concepts/kv_health_demo.cpp.

Dependencies. <concepts>, <cstdint>, <optional>, <string_view>, and concepts/key_value_store.hpp.

Known issues. backend is a view of a static string (the implementation's name), never of a buffer.

Status. New in 0.22.0. Experimental.
