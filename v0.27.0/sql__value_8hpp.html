Detailed Description

SQL values: parameters, rows, column types, errors, and the mappings of core's types.

Overview. What crosses the SQL contract (concepts/sql_dialect.hpp, concepts/sql_connection.hpp):

  • sql_param: a parameter, one of the six storage classes every engine shares: sql_null, bool, std::int64_t, double, text (std::string_view) and blob (std::span<const std::byte>). Text and blob are views of the caller's bytes, valid for the call that receives them: values cross as typed parameters, never as SQL text, so there is no quoting and no injection. sql_text(s) and sql_blob(b) make them explicitly; sql_value is the owning twin, and view_of / to_value convert.
  • sql_row: one result row, seen by a query's visitor (valid during the call), with typed getters that convert exactly or return type_mismatch / out_of_range, never a silent truncation.
  • sql_type: a column's logical type, which a dialect names (INTEGER, BIGINT, BYTEA, ...).
  • sql_errc and sql_error: database-neutral codes, the SQLSTATE when the engine has one, a fixed message (capability_message: a literal, so no parameter value, password or row can reach an error), and may_retry(code, policy).

Core's types map onto the storage classes exactly: utc<D> is int64 ticks of D (8 bytes, sortable, before 1970 too); uuid is a 16-byte blob (bytewise order is RFC order, so version 7 sorts by time); decimal is its canonical text; money is its exact text at all of its asset's digits, the asset (and so the scale) being the column's. to_sql encodes, and utc_from_sql, uuid_from_sql, decimal_from_sql and money_from_sql decode.

const utc_ms at = utc_ms::from_unix_millis(1'800'000'000'000);
const uuid id = *parse_uuid("0190a5c4-7e1b-7c3a-9f12-3b4c5d6e7f80");
const sql_money_text price = money_text(*parse_money(checked_asset("AUD", 2), "12.5"));
const std::array<sql_param, 4> params{to_sql(id), to_sql(at), to_sql(price), sql_null}; // views: no copies
const std::array<std::string_view, 4> names{"id", "at", "price", "note"};
const sql_row row{names, params}; // as a visitor sees it
const auto back = utc_from_sql<std::chrono::milliseconds>(*row.cell(1));

Relationships. concepts/sql_dialect.hpp, concepts/sql_connection.hpp; time/utc.hpp, uuid.hpp, decimal.hpp, money/money.hpp. Group: snicholls-core.

Implementations / variants. None: values.

Guarantees. kind_of, the error helpers and the integer and time mappings are constexpr; nothing here allocates except to_value (owning copies). A sql_param is trivially copyable.

Errors. The decoders: type_mismatch for the wrong storage class or text that does not parse, out_of_range for a value the target cannot hold. sql_row's getters: the same, and misuse for a column index past the row.

Performance. Not benchmarked: views and integer copies.

Tests and demos. tests/sql_value_test.cpp, demos/sql_value_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <limits>, <span>, <string>, <string_view>, <variant>, <vector>, capability_error.hpp (capability_message), containers/inplace_string.hpp, decimal.hpp, money/money.hpp, result.hpp, time/utc.hpp, uuid.hpp.

Known issues. A uuid's blob view points into the uuid: keep it alive for the call. C++ types of the libraries above core (crtp's objects, enumerations, durations) map through their own column traits, not here (type support, LIBRARIES section 5).

Status. New in 0.27.0. Experimental, with the SQL contract.
