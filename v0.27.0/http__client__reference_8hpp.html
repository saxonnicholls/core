Detailed Description

snicholls::loopback_http_client: the standard-library reference http_client, which sends to a handler in memory.

Overview. Code that calls an API through http_client is tested against a fake of that API written as an http_handler (a route_table, say): loopback_http_client<H> validates the request as a transport would, hands it to the handler and returns its response, HEAD without a body; nothing touches the network. fail_next(code, response) makes the next send fail as though the transport had failed after receiving response, which is dropped (its first word is kept as the provider code when it is one), to test a caller's retry path. sent() counts the requests that reached the handler.

loopback_http_client api{price_api()};
api.fail_next(capability_errc::timeout, "upstream_timeout <html>...</html>");
const auto first = http_get(api, "/prices/BHP"); // the transport fails once
const auto second = http_get(api, "/prices/BHP"); // then the fake answers

Relationships. Models http_client (concepts/http_client.hpp); passes interfaces/http_client_conformance.hpp directly and through interfaces/http_client.hpp; any http_handler, such as route_table (interfaces/http_handler_reference.hpp). Group: snicholls-core.

Implementations / variants. loopback_http_client<H>, owning (H) or borrowing (H&) the handler.

Guarantees. Not thread-safe unless the handler is. Errors follow the redaction rule.

Errors. invalid_argument from validate_request; whatever fail_next armed.

Performance. Not benchmarked: a test double (one request copy).

Tests and demos. tests/interfaces/http_client_reference_test.cpp, demos/interfaces/http_client_reference_demo.cpp.

Dependencies. <cstddef>, <optional>, <string_view>, <type_traits>, <utility>, interfaces/http_client.hpp.

Known issues. None.

Status. New in 0.27.0.
