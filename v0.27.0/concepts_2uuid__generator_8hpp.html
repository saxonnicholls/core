Detailed Description

snicholls::uuid_generator: anything that makes version 4 and version 7 UUIDs.

Overview. Core composes UUIDs from bits it is given (make_uuid_v4, make_uuid_v7 in uuid.hpp); a generator is where those bits come from: a random source and a clock. Production generators draw from the operating system through a random_source_like source (concepts/random_source.hpp; getrandom, arc4random_buf, BCryptGenRandom in ts-moveables) and read the system clock; tests and replays use basic_uuid_generator (interfaces/uuid_generator_reference.hpp) over stats::wyrand and manual_utc_clock, so every run makes the same identifiers. Code that makes identifiers takes a uuid_generator, never std::random_device or std::mt19937.

The contract (interfaces/uuid_generator_conformance.hpp checks it):

  • v4() is version 4 with the RFC 9562 variant, from 122 random bits;
  • v7() is version 7 with the RFC 9562 variant, its 48-bit timestamp the clock's Unix millisecond (or, to stay monotonic, a later one: RFC 9562 section 6.2), and strictly increasing within one generator, even when many are made in one millisecond and when the clock steps back;
  • a random source that fails is capability_errc::unavailable, and nothing is returned; a clock outside v7's range (before 1970, after the year 10889) is capability_errc::invalid_argument.
auto ids = make_reference_uuid_generator(2026, utc_ms::from_unix_millis(1'800'000'000'000));
const auto first = new_order_id(ids);
const auto second = new_order_id(ids);

Relationships. uuid.hpp (the value and the composers), capability_error.hpp; the twin interfaces/uuid_generator.hpp, the reference interfaces/uuid_generator_reference.hpp, the kit interfaces/uuid_generator_conformance.hpp; the clock is anything with now().unix_millis(). Group: snicholls-core.

Implementations. basic_uuid_generator<Random, Clock> (standard library only, deterministic for a seeded source). Above core: the operating system's generator in crtp (make_uuid) and ts-moveables.

Guarantees. A concept: no code. Thread safety is the implementation's (one generator per thread, or a lock).

Errors. capability_error, as the contract says.

Performance. Not benchmarked here: the reference costs two or three wyrand draws per identifier.

Tests and demos. tests/concepts/uuid_generator_test.cpp, demos/concepts/uuid_generator_demo.cpp.

Dependencies. <concepts>, capability_error.hpp, uuid.hpp.

Known issues. A deterministic generator makes predictable identifiers: never let one reach production, where an identifier may be guessed.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
