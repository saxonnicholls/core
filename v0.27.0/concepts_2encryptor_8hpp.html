Detailed Description

snicholls::encryptor: authenticated encryption with associated data, behind key ids.

Overview. An encryptor seals bytes under a named key and opens what it sealed: encrypt(key_id, plaintext, associated_data) returns a self-contained sealed envelope, and decrypt(sealed, associated_data) returns the plaintext only when the envelope is authentic and the associated data is the same. The associated data is authenticated, not encrypted: bind a ciphertext to its context (a row's key, a user id, a field name) so it cannot be moved to another. Code that stores secrets (a key-value store's values, a column, a file) holds an encryptor and never names an algorithm; serialise, encrypt, encode and store, and the reverse, without any layer knowing the cipher (base-encode-decode's design).

The envelope is the contract's, so any implementation reads a key id written by another: byte 0 the format (sealed_format_v1, 1), byte 1 the key id's length n (1 to 64), then the key id, then the implementation's own nonce, ciphertext and tag. sealed_key_id(sealed) reads the key id without a key, to route an envelope to the encryptor that holds it. A key id is 1 to 64 characters of A-Z a-z 0-9 _ - . : (is_key_id): never a secret.

The contract (interfaces/encryptor_conformance.hpp checks it):

  • decrypt(encrypt(k, p, a), a) == p, for any p (the empty one included) and a;
  • two encryptions of the same plaintext differ (a fresh nonce every time; the caller never manages nonces);
  • any change to the envelope, or other associated data, is capability_errc::signature_invalid, and no plaintext is returned: never unauthenticated data;
  • an unknown key id is capability_errc::not_found; an envelope too short to read, or a key id that is not one, is capability_errc::invalid_argument;
  • an envelope sealed under an older key opens while that key is held (rotation adds keys);
  • errors carry no key material and no plaintext (capability_error.hpp's redaction rule: the message is a literal, and a provider code is the library's short code at most).
insecure_test_encryptor e = with_keys();
const auto sealed = seal_card(e, "users/42", "4111 1111 1111 1111");
const auto opened = e.decrypt(*sealed, bytes_of("users/42"));
const auto moved = e.decrypt(*sealed, bytes_of("users/43")); // pasted into another row: refused

Relationships. capability_error.hpp; the twin interfaces/encryptor.hpp, the test double interfaces/encryptor_reference.hpp, the kit interfaces/encryptor_conformance.hpp. Group: snicholls-core.

Implementations. insecure_test_encryptor (not encryption: a test double that exercises the contract and protects nothing). Above core, in crypto: ChaCha20-Poly1305 and AES-256-GCM over vetted libraries.

Guarantees. is_key_id is constexpr; it and sealed_key_id are noexcept and allocation-free. Thread safety is the implementation's.

Errors. capability_error, as the contract says.

Performance. Not benchmarked: the cost is the cipher's.

Tests and demos. tests/concepts/encryptor_test.cpp, demos/concepts/encryptor_demo.cpp.

Dependencies. <concepts>, <cstddef>, <span>, <string_view>, <vector>, capability_error.hpp.

Known issues. The plaintext comes back in a std::vector<std::byte>: wipe it with secure_wipe (hash/secure.hpp) when it held a secret.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
