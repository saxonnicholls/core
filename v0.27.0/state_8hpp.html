Detailed Description

The Identity, Const, Reader, Writer and State monads as constexpr value types, with their Functor, Applicative and Monad instances.

Overview.

type holds run operations
identity_of<A> a value .value (the trivial monad)
const_of<C> a value; fmap leaves it alone .value Applicative when C is a monoid
reader<F> F: env -> a run_reader(m, env) ask, asks(f), local(f, m)
writer<W, A> a value and a log W (a monoid) run_writer(m), exec_writer(m) tell(w)
state<F> F: s -> std::pair<a, s> run_state, eval_state, exec_state get_state, put_state(s), modify(f), gets(f)
// A fill costs cash; it reports whether the cash covered it. The state is the cash balance.
constexpr auto fill = [](double cost) {
return fn::mbind(fn::get_state, [cost](double cash) {
return fn::mthen(fn::put_state(cash - cost), fn::pure<fn::state<>>(cash >= cost));
});
};
// A day: two fills, then a sweep that adds interest; the value is whether every fill was covered.
constexpr auto day = fn::mbind(fill(40.0), [fill](bool a) {
return fn::mbind(fill(50.0), [a](bool b) {
return fn::mthen(fn::modify([](double cash) { return cash * 1.01; }), fn::pure<fn::state<>>(a && b));
});
});
static_assert(fn::eval_state(day, 100.0)); // covered
static_assert(!fn::eval_state(day, 60.0)); // the second fill was not
static_assert(fn::exec_state(day, 100.0) == 10.0 * 1.01);

Each is a value: a state is a function from a state to a result and the next state, built by mbind and the operations, and run when given the initial state, by the compiler in a static_assert or at run time. Nothing is mutated and nothing is allocated. The carrier keys for pure / mreturn are the types with their defaults: pure<state<>>(x), pure<reader<>>(x), pure<writer<W>>(x), pure<identity_of<>>(x), pure<const_of<C>>(x).

Use State for a calculation that threads a value through many steps (a cash balance through a day's fills, a random generator's seed); Reader for configuration passed down a call tree; Writer for an audit trail combined with a monoid. Write the loop when it is one loop.

Relationships. functional/typeclasses.hpp (fmap, ap, mbind, mthen), functional/monad.hpp (fold_m, replicate_m), functional/combinators.hpp. Group: snicholls-core.

Implementations / variants. One each. reader and state hold one function; every operation returns a new one wrapping the old (the types grow with the program, as lambdas do).

Guarantees. constexpr. The functions are held by value; mbind(m, k) holds copies of m and k. Trivially copyable when the functions are. Running is noexcept when the functions are.

Errors. None of their own.

Examples.

// Writer: every step adds to a log; here the log is a count of trades (a sum monoid).
using trades = fn::sum_of<int>;
constexpr auto trade = [](double px) {
return fn::mthen(fn::tell(trades{1}), fn::pure<fn::writer<trades>>(px));
};
constexpr auto book = fn::mbind(trade(1.08), [trade](double a) { return fn::fmap([a](double b) { return a + b; }, trade(1.09)); });
static_assert(fn::exec_writer(book).value == 2);

Performance. After inlining, a state program is the code it describes. benchmarks/functional/lazy_benchmark.cpp, a day of three fills as a State program against the hand-written loop, fairness-checked: 1.82 ns each (macOS x86-64 Xeon W-3245, Apple Clang 17, Release, 2026-11-26, 5 repetitions).

Tests and demos. tests/functional/state_test.cpp, tests/functional/state_laws_test.cpp, tests/functional/typeclasses_laws_test.cpp, demos/functional/state_demo.cpp, demos/functional/state_rpn_demo.cpp (fresh ids, a stack machine, Reader and Writer).

Dependencies. <cstddef>, <functional>, <type_traits>, <utility>, <variant> (for std::monostate, the unit value) and functional/typeclasses.hpp.

Known issues and gotchas. A long chain of mbinds nests one closure per step, which the compiler instantiates; for thousands of steps, use fold_m over a range instead of a written chain. The unit value is std::monostate.

Status. Experimental, new in 0.27.0.
