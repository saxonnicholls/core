Detailed Description

snicholls::loop_clock_interface: the virtual twin of loop_clock_like, and the adapters both ways.

Overview. An event loop holds its clock by pointer (std::shared_ptr<loop_clock_interface>), chosen at run time: real time, manual, replay. The interface is ts-moveables' loop_clock exactly: now() and block_for() are pure virtual; set_waker() is virtual with a default that keeps the waker, and the protected wake() calls it, so a clock that moves on command (a manual or a scaled one) wakes the loop with one call. It satisfies the concept and the trait (asserted below). The adapters:

  • loop_clock_adapter<Impl>: the interface implemented by forwarding to a model, held by value, or bound to one when Impl is a reference (a view); set_waker is forwarded, so the model wakes the loop itself;
  • any_loop_clock: a value owning a std::unique_ptr<loop_clock_interface>, which models the concept.
auto adapted = std::make_shared<loop_clock_adapter<manual_loop_clock>>();
std::shared_ptr<loop_clock_interface> clock = adapted; // what a loop holds
int woken = 0;
clock->set_waker([&woken] { ++woken; }); // the loop installs its waker
adapted->implementation().advance(250ms); // the test moves time; the loop is woken

Relationships. concepts/loop_clock.hpp, interfaces/loop_clock_reference.hpp, interfaces/loop_clock_conformance.hpp. Group: snicholls-core.

Implementations / variants. loop_clock_adapter<Impl> over any model; ts-moveables' clocks derive from the interface directly.

Guarantees. The adapters add one virtual call. set_waker is not synchronised: the loop installs the waker before the clock is shared, as in ts-moveables.

Errors. None.

Performance. One virtual call; not benchmarked.

Tests and demos. tests/interfaces/loop_clock_test.cpp (the kit through every form), demos/interfaces/loop_clock_demo.cpp.

Dependencies. <chrono>, <functional>, <memory>, <type_traits>, <utility>, concepts/loop_clock.hpp.

Known issues. C++17-clean by rule (snicholls_core_cpp17_check).

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
