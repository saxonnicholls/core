Detailed Description

snicholls::check_task_pool: the conformance kit of the task pool contract, C++17-clean.

Overview. Drives any pool with task_pool_like's members (a pool, a task_pool_interface&, an any_task_pool) through the contract of concepts/task_pool.hpp and returns the failures as strings, ts-moveables' kit style, so any test framework (or none) reports them: an empty vector is a pass. C++17-clean, so ts-moveables runs it on its threaded pools under its own build. The checks: worker_count is at least 1, wait_idle on an idle pool returns, every task runs exactly once, tasks submitted by tasks run before wait_idle returns, a lambda is a task, wait_idle can be called again. Counters are atomic, so a threaded pool is checked as it is.

deferred_task_pool good;
leaky_pool bad;
const auto good_failures = check_task_pool(good); // std::vector<std::string>: empty is a pass
const auto bad_failures = check_task_pool(bad);

Relationships. concepts/task_pool.hpp, interfaces/task_pool.hpp; run on deferred_task_pool in every form by tests/interfaces/task_pool_test.cpp. Group: snicholls-core.

Implementations / variants. One kit for every form.

Guarantees. The pool is left idle. Exceptions from the pool propagate (the kit catches none).

Errors. Failures are data.

Performance. Not benchmarked: a test kit (about 300 tasks).

Tests and demos. tests/interfaces/task_pool_conformance_test.cpp (the kit catches broken pools), demos/interfaces/task_pool_conformance_demo.cpp.

Dependencies. <atomic>, <cstddef>, <memory>, <string>, <vector>, concepts/task_pool.hpp.

Known issues. A pool that never runs anything hangs in wait_idle rather than failing; run the kit under a test timeout.

Status. New in 0.27.0.
