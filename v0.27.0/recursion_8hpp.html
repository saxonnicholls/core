Detailed Description

Recursion schemes over list-shaped data, cata, ana, hylo and para, and a trampoline for deep recursion without the stack, all constexpr.

Overview. A recursion scheme separates what a recursion computes from how it walks:

here what it is Haskell (recursion-schemes)
cata(alg, nil, xs) a list torn down: alg(x0, alg(x1, ... nil)) cata on ListF
ana<N>(coalg, seed) a list built: coalg(seed) gives {x, next seed} or stops ana
hylo(alg, nil, coalg, seed) built and torn down in one pass, no list in between (left-nested) hylo (fused)
para(alg, nil, xs) cata where alg also sees the rest of the list para
trampoline(step, state) step returns more(next) or done(result); a loop, not a stack Trampoline
// ana: a bond's cash flows from a state (periods left): coupons, then the redemption.
constexpr auto flows = [](int left) {
return left == 0 ? std::nullopt : std::optional{std::pair{left == 1 ? 1025.0 : 25.0, left - 1}};
};
constexpr auto schedule = fn::ana<16>(flows, 4);
static_assert(schedule.size() == 4 && schedule[3] == 1025.0);
// cata: priced from the last flow back, each discounted one period.
constexpr double price = fn::cata([](double cf, double later) { return (cf + later) / 1.025; }, 0.0, schedule);
static_assert(price > 999.99 && price < 1000.01);
// hylo: the undiscounted total, unfolded and folded in one pass, with no schedule in between.
static_assert(fn::hylo([](double acc, double cf) { return acc + cf; }, 0.0, flows, 4) == 1100.0);

The schemes here are over the list functor (one element and the rest), which is the shape most recursions in core's domain take: a cash-flow schedule built from a state (ana) and priced back (cata), a convergence loop (hylo, trampoline). Recursion over trees in constant expressions needs a fixed-point type with indirection, which C++ gives only through allocation or an index arena; it is left out (see the report in the CHANGELOG), and fix (functional/combinators.hpp) gives recursion over any shape for a function.

Relationships. fn::foldr_of (cata is it), fn::unfold (ana with a fixed count), functional/lazy.hpp (infinite unfolds), fn::fix, snicholls::nest_while. Group: snicholls-core.

Implementations / variants. hylo is fused: it never materialises the list, so it needs no bound and folds left (alg(acc, x)). ana collects into a containers::inplace_vector<T, N> and stops at N.

Guarantees. constexpr, allocation-free, and none of them recurse at run time: cata and para walk backwards in a loop, hylo and trampoline are loops. So depth is limited by nothing but time (and the compiler's step limit at compile time).

Errors. None of their own. hylo and trampoline do not terminate if the coalgebra or the step never stops.

Examples.

// Steps to reach 1 under Collatz's rule, at any depth, in constant stack.
constexpr auto collatz = [](std::pair<long, int> s) -> fn::bounce<std::pair<long, int>, int> {
if (s.first == 1) return fn::done(s.second);
return fn::more(std::pair{s.first % 2 != 0 ? 3 * s.first + 1 : s.first / 2, s.second + 1});
};
static_assert(fn::trampoline(collatz, std::pair{27L, 0}) == 111);

Performance. The loops; not benchmarked.

Tests and demos. tests/functional/recursion_test.cpp, demos/functional/recursion_demo.cpp.

Dependencies. <cstddef>, <functional>, <optional>, <ranges>, <type_traits>, <utility>, <variant>, containers/inplace_vector.hpp and functional/fold.hpp.

Known issues and gotchas. para gives alg the rest of the list as a std::span-like pair of iterators over a contiguous range; it needs a contiguous range.

Status. Experimental, new in 0.27.0.
