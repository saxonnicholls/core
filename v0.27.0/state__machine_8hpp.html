Detailed Description

snicholls::fsm: state machines written as sml writes them (*state<A> + event<E> [guard] / action = state<B>), with states that are values: an enumerator per state, current() and restore(), no exceptions across the boundary.

Overview
A transition table is a list of rows, each read left to right as "in this state, on this event, if this guard holds, run this action and go to that state":
struct release {};
struct ack {};
struct fin {};
struct timeout {};
const auto is_ack_valid = [](const ack&) { return true; };
const auto is_fin_valid = [](const fin&) { return true; };
const auto send_fin = [] { trace += "send_fin "; };
const auto send_ack = [] { trace += "send_ack "; };
struct hello_world {
auto operator()() const
{
using namespace snicholls::fsm;
return make_transition_table(
*"established"_s + event<release> / send_fin = "fin wait 1"_s,
"fin wait 1"_s + event<ack> [is_ack_valid] = "fin wait 2"_s,
"fin wait 2"_s + event<fin> [is_fin_valid] / send_ack = "timed wait"_s,
"timed wait"_s + event<timeout> / send_ack = X);
}
};

sm<Def> is the machine: Def is a class whose operator() returns the table, built once when the machine is constructed. process_event(e) runs the first row that leaves the current state on e and whose guard holds, and says whether one did. The notation, the dispatch rules and the order of entry, exit and actions are boost-ext/sml's; see "Implementations and variants" for what is reproduced and what is not.

The difference from sml, and the reason this exists in core: every state can be a value. A state is state<T> (a type, as sml), "name"_s (a string, as sml), or enum_state<E::pending> (an enumerator). A machine whose states are the enumerators of one enumeration, or which declares using state_enum = E;, has current() returning that enumerator and restore(e) setting it, refusing a value that is not a state of the table. So the state lives as one byte on the object it describes (a transaction is pending, then confirmed), and a machine is rebuilt from that byte after a restart; fsm/persist.hpp saves and loads it through any key_value_store.

enum class order_state : std::uint8_t { placed, paid, shipped, delivered, cancelled };
struct pay {
long cents = 0;
};
struct ship {};
struct deliver {};
struct cancel {};
struct order {
constexpr auto operator()() const // constexpr: the machine can then run at compile time
{
using namespace snicholls::fsm;
constexpr auto placed = enum_state<order_state::placed>;
constexpr auto paid = enum_state<order_state::paid>;
constexpr auto shipped = enum_state<order_state::shipped>;
constexpr auto delivered = enum_state<order_state::delivered>;
constexpr auto cancelled = enum_state<order_state::cancelled>;
const auto paid_in_full = [](const pay& p) { return p.cents >= 1999; };
return make_transition_table(
*placed + event<pay> [paid_in_full] = paid,
placed + event<cancel> = cancelled,
paid + event<ship> = shipped,
paid + event<cancel> = cancelled,
shipped + event<deliver> = delivered);
}
};

Use it for any lifecycle (a payment, an order, a connection, a protocol handshake): the table is the specification, checked by the compiler, drawn by fsm/diagram.hpp. Do not use it for a two-state flag (a bool is clearer), nor for a machine whose states and transitions are only known at run time (this table is a type).

Implementations and variants
API and semantics modelled on boost-ext/sml (https://github.com/boost-ext/sml), BSL-1.0; this is an independent C++20 implementation (concepts, class-type template arguments, fold expressions), not a copy. Reproduced from sml:
  • the table DSL: * (initial state, one per orthogonal region), state<T>, "x"_s, event<E>, "e"_e, [guard], / action, = target, the reversed form target <= source + event, guard algebra (&&, ||, !), action sequences (a, b), wrap(f) for function pointers, eval [g] / a inside a sequence;
  • anonymous (eventless) transitions, internal transitions (no target), self transitions (exit and entry run), on_entry<_> / on_exit<_> (and on_entry<E> for one triggering event, on_entry<initial> for the start), X (terminate);
  • defer and process(e) (the queues are built in, fixed capacity, no allocation: sml needs defer_queue and process_queue policies), with sml's draining order: anonymous transitions, then deferred events after each state change, then queued events one at a time;
  • composite machines (a state<Sub> whose Sub returns a table), orthogonal regions, history ((H));
  • unexpected_event<E> / unexpected_event<_> rows, and exception<E> / exception<_> rows (when exceptions are enabled);
  • dependency injection: objects passed to the constructor are matched by type to the parameters of guards and actions; the event is matched by its type or by a deduced (auto) parameter; the definition object itself is available to member-function-pointer guards and actions;
  • process_event, is(...) (one state, or one per region), is<Sub>(...), visit_current_states, set_current_states (with the testing policy), the logger<L> hook (log_process_event, log_guard, log_action, log_state_change), make_dispatch_table (run-time ids to event types), and two dispatch strategies (fold_expr, the default, and jump_table).

Not reproduced: sml::thread_safe (core has no threads by rule; lock around the machine in the caller, as ts-moveables does); dont_instantiate_statemachine_class and passing sub-machine objects to the constructor (a sub-machine definition is default-constructed); event<_> and state<_> wildcard rows other than the on_entry, on_exit, unexpected_event and exception forms; sml's sm.process_event returning through back::process handles and flush_queue (queued events are drained before process_event returns). The examples that need other libraries are not replicated: arduino and sdl2 (hardware and SDL), dependency_injection (Boost.DI) and euml_emulation (Boost.MSM's eUML notation).

Guarantees and contracts
  • State is one small integer per region: std::uint8_t up to 255 states, else std::uint16_t. A machine whose guards and actions hold no data and that has no dependencies, queues or sub-machines is exactly that array: sizeof(sm<hello_world>) == 1, trivially copyable (static_asserts in the test).
  • No exception crosses process_event: it is noexcept. An exception from a guard or an action goes to the table's exception<E> rows; one no row takes is caught and reported (try_process_event answers fsm_errc::action_failed). The state is then as sml leaves it: the target state is current, its entry has not run.
  • Order of a transition (sml's): guard; the source's exit (a sub-machine's current states first, then the composite's own on_exit); the state changes; the action; the target's entry (the composite's own on_entry, then its sub-machine's current states). An internal transition runs only its action.
  • Regions: an event goes to every region in turn; process_event is true if any region took it. Within a region the rows are tried in table order and the first whose guard holds runs.
  • Composite states: the sub-machine sees the event first; if it took it and has not terminated, the parent's rows are not tried. Entering a composite resets its regions to their initial states, except a region whose initial state is marked (H), which resumes where it was.
  • Compile-time checks (static_asserts, messages start snicholls::fsm:): an initial state exists; no row leaves a state on an event after an unguarded row that already does; every state is reached from an initial state; no row leaves X; with a state enumeration, every state has an enumerator. table_diagnostics<Def> reports the same facts as values, for a test.
  • Everything is constexpr: a machine can run in a constant expression. Copying a machine rebuilds its table from the copied definition, so a guard that captured the definition's this refers to the copy's.
  • Not synchronised: one machine, one thread at a time.
Errors
fsm_errc. process_event returns bool as sml does; try_process_event returns result<void, fsm_errc>: no_transition (no row leaves the current state on the event), guard_rejected (rows exist and every guard refused), action_failed (a guard or action threw and no exception row took it), queue_full (a defer or process found its fixed queue full; the event is dropped), anonymous_loop (anonymous transitions ran more than max_anonymous_steps times in a row), queued_event_unhandled (an event the action queued with process was not taken). restore returns not_a_state for an enumerator that is not a state of the table. Nothing throws.

struct e1 {};
struct e2 {};
struct e3 {};
struct e4 {};
struct e5 {};
bool guard2_impl(int i);
struct actions_guards {
using self = actions_guards;
auto operator()()
{
using namespace snicholls::fsm;
auto guard1 = [] { note("guard1"); return true; };
auto guard2 = wrap(&guard2_impl);
auto action1 = [](const auto& e) { note(event<std::remove_cvref_t<decltype(e)>>.name().data()); };
struct action2 {
void operator()(int i) { note(i == 42 ? "action2" : "action2-wrong"); }
};
return make_transition_table(
*"idle"_s + event<e1> = "s1"_s,
"s1"_s + event<e2> [guard1] / action1 = "s2"_s,
"s2"_s + event<e3> [guard1 && ![] { return false; }] / (action1, action2{}) = "s3"_s,
"s3"_s + event<e4> [!guard1 || guard2] / (action1, [] { note("action3"); }) = "s4"_s,
"s3"_s + event<e4> [guard1] / ([] { note("action4"); }, [this] { action4(); }) = "s5"_s,
"s5"_s + event<e5> [&self::guard3] / (wrap(&self::action4), &self::action5) = X);
}
bool guard3(int i) const noexcept
{
note(i == 42 ? "guard3" : "guard3-wrong");
return true;
}
void action4() const { note("action4"); }
void action5(int i, const e5&) { note(i == 42 ? "action5" : "action5-wrong"); }
};
bool guard2_impl(int i)
{
note(i == 42 ? "guard2" : "guard2-wrong");
return false;
}

Performance
benchmarks/fsm/state_machine_benchmark.cpp: 4,096 random events, valid and invalid, against the same machine written by hand (an enumeration, one function per event, a switch over the state), with a fairness check. macOS x86-64 (32 cores, load 9), Apple Clang 17, Release, 2026-11-24, medians of 10 interleaved runs: hello_world 5.39 ns per event (by hand 5.33); the payment lifecycle 7.56 ns (by hand 7.49). The loops compile to the same instructions: a transition is a compare (or a bit test over the source states) and a store, and a machine with a dense state enumeration numbers its states by their enumerators, so current() is the stored byte.

Known issues and gotchas
  • state<T> takes a type and enum_state<V> a value: one template cannot take both, so an enumerator is written enum_state<E::pending> (or named once: constexpr auto pending = enum_state<E::pending>;).
  • The operators &&, ||, ! and , are overloaded for callables in namespace snicholls::fsm; a table is written after using namespace snicholls::fsm;. Two function pointers cannot be combined by an operator (the language needs a class operand): wrap the first, as in sml.
  • A generic (auto) guard or action is instantiated with the row's event to learn its parameters; on an on_entry<_> / on_exit<_> row the event is only known when it runs, so such a callable may ask only for dependencies that another row (or a non-generic callable) also asks for.
  • glibc declares a function ::on_exit, so after using namespace snicholls::fsm; the name on_exit is ambiguous on Linux: write snicholls::fsm::on_exit<_> (sml's examples write sml::on_exit for the same reason), or add using snicholls::fsm::on_exit; where the table is written.
  • Anonymous transitions stop after max_anonymous_steps (1024) in a row and report anonymous_loop, where sml would loop for ever.
  • The constructor runs the initial states' entry actions; an exception there that no exception row takes is discarded.
  • MSVC ignores the standard [[no_unique_address]]; core spells [[msvc::no_unique_address]] there.
  • Clang 18 and older (LLVM's numbering, not Apple clang's) crash compiling an action sequence that holds an eval of the same empty action, (a, eval [g] / a) (sml's eval example), when the sequence's members are [[no_unique_address]]; on those compilers the sequence's members are plain, a byte per empty action in a sequence. Every other layout, and every other compiler, is unchanged.
  • sml's examples arduino, sdl2, dependency_injection and euml_emulation are not replicated (see above).
