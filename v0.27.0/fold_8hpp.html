Detailed Description

snicholls::fn::foldl, foldr, scan, foldl_of, foldr_of, unfold and iterate_n: folds over parameter packs and sequences, and unfolds into arrays, all constexpr.

Overview.

here what it computes Haskell
foldl(f, z, a, b, c) f(f(f(z, a), b), c) foldl f z [a,b,c]
foldr(f, z, a, b, c) f(a, f(b, f(c, z))) foldr f z [a,b,c]
scan(f, z, a, b, c) std::array{z, f(z, a), f(f(z, a), b), ...} scanl f z [a,b,c]
foldl_of(f, z, seq) foldl over a range or a tuple foldl
foldr_of(f, z, seq) foldr over a bidirectional range or a tuple foldr
unfold<N>(seed, step) N values from step(state) -> {value, next state} unfoldr
iterate_n(f, n) the function x -> f(f(...f(x))), n times (!! n) . iterate f
constexpr auto plus = [](auto a, auto b) { return a + b; };
constexpr auto minus = [](auto a, auto b) { return a - b; };
// Over a pack: left and right, and the accumulator may change type (int, then double).
static_assert(fn::foldl(minus, 100, 10, 20) == 70); // (100 - 10) - 20
static_assert(fn::foldr(minus, 100, 10, 20) == 90); // 10 - (20 - 100)
static_assert(fn::foldl(plus, 0, 1, 2.5) == 3.5);
// A running P&L: every partial sum.
static_assert(fn::scan(plus, 0, 120, -40, 15) == std::array{0, 120, 80, 95});
// Over a range or a tuple.
static_assert(fn::foldl_of(plus, 0, std::array{1, 2, 3}) == 6);
static_assert(fn::foldl_of(plus, 0.0, std::tuple{1, 0.5f, 2.0}) == 3.5);

Over a pack the accumulator may change type at every step (foldl of an int, then a double); scan and the range forms keep one accumulator type, z's. A tuple is folded as the pack of its elements, so its elements may differ in type too. Use these when the elements are known at compile time or are a heterogeneous pack; std::accumulate (already constexpr) is the fold over an iterator range when that reads better.

Relationships. snicholls::nest (iterate_n(f, x, n) is it), snicholls::nest_list and snicholls::fold_list (scan over a std::array) in snicholls/core/iterate.hpp; snicholls::constexpr_for for a loop over indices; meta::fold_t for types; functional/combinators.hpp. Group: snicholls-core.

Implementations / variants. A range and a tuple are distinct overloads of foldl_of / foldr_of: a std::array, which is both, is folded as a range (the same result).

Guarantees. constexpr, allocation-free, no recursion at run time (the pack forms recurse at compile time, one instantiation per element). noexcept exactly when f and the accumulator's moves are (and, for a range, iterating it). The accumulator is moved from step to step; scan copies each step into the result. unfold calls step exactly N times, in order.

Errors. None of their own.

Examples.

// unfold: a schedule from a state. Each step returns {value, next state}: a coupon, then the next period.
constexpr auto coupons = fn::unfold<4>(std::pair{1, 1000.0}, [](const std::pair<int, double>& s) {
return std::pair{s.second * 0.05 / 2, std::pair{s.first + 1, s.second}};
});
static_assert(coupons == std::array{25.0, 25.0, 25.0, 25.0});
// iterate_n: a function applied n times, as a function.
constexpr auto compound_5y = fn::iterate_n([](double b) { return b * 1.05; }, 5);
static_assert(compound_5y(1000.0) > 1276.28 && compound_5y(1000.0) < 1276.29);

Performance. The calls to f; not benchmarked.

Tests and demos. tests/functional/fold_test.cpp, demos/functional/fold_demo.cpp.

Dependencies. <array>, <cstddef>, <functional>, <iterator>, <ranges>, <tuple>, <type_traits>, <utility>, snicholls/core/iterate.hpp and snicholls/core/functional/combinators.hpp.

Known issues and gotchas. foldr over a pack of n elements nests n calls; at a few hundred elements the compiler's template depth limit is reached. Fold a std::array with foldr_of instead.

Status. Experimental, new in 0.27.0.
