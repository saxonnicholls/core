Detailed Description

snicholls::memory_https_client, the standard-library reference https_client: an in-memory router by host; and recorded days (cassette, recording_https_client, replay_https_client).

Overview. Three models of https_client, none of which touches a network:

  • memory_https_client: routes each request by its URL's host to a handler (https_request in, a response or a transport error out) set with route, or to any http_handler (concepts/http_handler.hpp, such as core's route_table) set with serve; a host with no route is unavailable, as an unreachable one is. It makes the checks a real client makes first (parse_https_url, is_sendable) and keeps what it sent, already redacted as a cassette records it, so a test can check the requests. A provider's fixture server is such a handler; it may answer with a transport error to script a dropped connection or a timeout. fail_next(code, response) makes the next send fail as though the TLS layer had answered response.
  • recording_https_client<C>: forwards to any model and appends each answered exchange to a cassette.
  • replay_https_client: answers from a cassette, in order: each request takes the first unused exchange with the same method, URL, idempotency key and body; nothing matching is capability_errc::not_found.

A cassette is a recorded day. save writes it as text and load reads it back, never with the Authorization value (it is not recorded at all, only that one was sent) and never with a sensitive body (recorded as cassette::redacted, which replay matches against any body). Response Set-Cookie headers are dropped. The text, one exchange after another, bodies length-prefixed so any bytes survive: 

> POST https://api.stripe.com/v1/refunds
> a
> h Idempotency-Key: r-1
> b 23
payment_intent=pi_1&...
< 200
< h Request-Id: req_1
< b 42
{...}
route_table routes; // a product's own routes, as an http_handler
static_cast<void>(routes.add(http_method::get, "/health", [](const http_request&) { return respond(200, "ok"); }));
memory_https_client network;
network.serve("api.example.test", routes);
network.route("down.example.test", [](const https_request&) -> capability_result<https_response> {
return fail(capability_errc::timeout); // a scripted outage
});
recording_https_client<memory_https_client&> recorder{network};
https_request health;
health.url = "https://api.example.test/health";
health.authorization = secret<std::string>{"Bearer never-recorded"};
const auto live = recorder.send(health);
const auto text = recorder.tape().save(); // the recorded day: no credential in it
replay_https_client replay{*cassette::load(text)};
const auto replayed = replay.send(health);

Relationships. Models https_client (concepts/https_client.hpp); passes its kit in every form; serve bridges to http_handler (concepts/http_handler.hpp), so a product's routes can be driven through a client. Group: snicholls-core.

Implementations / variants. The router, the recorder and the replay.

Guarantees. Not thread-safe. Deterministic. Nothing recorded carries a credential or a sensitive body; errors carry fixed messages only.

Errors. As the contract; load returns invalid_argument on malformed text.

Performance. Not benchmarked: linear in the routes and in the cassette.

Tests and demos. tests/interfaces/https_client_reference_test.cpp, demos/interfaces/https_client_reference_demo.cpp.

Dependencies. <charconv>, <cstddef>, <functional>, <optional>, <string>, <string_view>, <system_error>, <type_traits>, <utility>, <vector>, concepts/http_handler.hpp, interfaces/https_client.hpp.

Known issues. A path handed to an http_handler by serve is not percent-decoded. The client certificate is not recorded.

Status. New in 0.27.0, lifted from servers.
