Detailed Description

snicholls::uuid_generator_interface: the pure virtual twin of uuid_generator, and the adapters both ways.

Overview. When the generator is chosen at run time (the operating system's in production, a seeded one in a replay), code holds a uuid_generator_interface&. Its pure virtual functions are the operations of the concept uuid_generator (concepts/uuid_generator.hpp, where the contract is documented), so the interface models the concept. uuid_generator_adapter<G> puts any model behind the interface, owning it (G) or referring to it (G&); uuid_generator_ref is a copyable, non-owning handle on the interface that models the concept.

std::unique_ptr<uuid_generator_interface> chosen = std::make_unique<uuid_generator_adapter<reference_uuid_generator>>(
make_reference_uuid_generator(1, utc_ms::from_unix_millis(1'800'000'000'000)));
uuid_generator_ref ids{*chosen}; // copyable, models the concept
const auto session = ids.v4();

Relationships. concepts/uuid_generator.hpp, interfaces/uuid_generator_reference.hpp, interfaces/uuid_generator_conformance.hpp. Group: snicholls-core.

Implementations / variants. uuid_generator_adapter<G> over any model; a generator above core may derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else; thread safety is the wrapped generator's.

Errors. As the contract.

Performance. One virtual call; not benchmarked.

Tests and demos. tests/interfaces/uuid_generator_test.cpp (the kit through every form), demos/interfaces/uuid_generator_demo.cpp.

Dependencies. <type_traits>, <utility>, concepts/uuid_generator.hpp.

Known issues. None.

Status. New in 0.27.0. Experimental until two real implementations pass the kit.
