Detailed Description

snicholls::ml::tokenize and detokenize: a whole tokenizer (added tokens, normalisation, pre-tokenisation, model, byte fallback) over a tokenizer_vocab, the non-owning view a GGUF or tokenizer.json loader fills.

Overview. The building blocks of ml/pretokenize.hpp, ml/bpe_merges.hpp, ml/sentencepiece.hpp, ml/unigram.hpp, ml/wordpiece.hpp and ml/rwkv_tokenizer.hpp assembled the way llama.cpp's llama_tokenize assembles them, for the five model types a tokenizer file can name:

tokenizer_model GGUF tokenizer.ggml.model pipeline
sentencepiece_bpe llama escape spaces ("▁", dummy prefix), merge by score, <0xNN> fallback
bpe gpt2, gemma4 pre-tokenise, GPT-2's byte alphabet (or escaped spaces), merge by rank, byte fallback
unigram t5 charsmap and whitespace normaliser, Viterbi, one unknown per run
wordpiece bert BERT's basic tokenisation, greedy longest match
rwkv rwkv greedy longest match over raw bytes

Before any of them, added tokens (user-defined tokens always, special tokens when the caller puts them in added) are cut out of the raw text (split_added_tokens) and emitted as themselves. A sentencepiece_bpe text fragment gets the dummy prefix when it opens the text or follows an added token, as llama.cpp does.

The seam. tokenizer_vocab is what a loader fills from a tokenizer file, all views into memory it owns: the pieces (as stored: GPT-2's alphabet for byte-level BPE, "▁" for SentencePiece, "▁" word starts for GGUF's WordPiece, unescaped bytes for RWKV), scores and kinds by id, the tries (build_token_index), the merge index (split_merge, build_merge_index), the pre-tokenizer (pretokenizer_for(tokenizer.ggml.pre)), the flags, the charsmap blob, the unknown token, and the byte fallback (make_byte_fallback, make_byte_level_fallback). Nothing here reads a file.

// What a loader reads from a file: pieces by id ("Ġ" is a space), merges as strings, the pre-tokenizer's name
constexpr std::array<std::string_view, 8> pieces{"h", "i", "\xC4\xA0", "hi", "\xC4\xA0hi", "!", "<|end|>", "\xC4\xA0h"};
constexpr std::array<std::string_view, 3> merge_lines{"h i", "\xC4\xA0 hi", "\xC4\xA0 h"};
constexpr std::array<ml::token_kind, 8> kinds{ml::token_kind::normal, ml::token_kind::normal, ml::token_kind::normal,
ml::token_kind::normal, ml::token_kind::normal, ml::token_kind::normal,
ml::token_kind::user_defined, ml::token_kind::normal};
struct loaded
{
std::array<std::pair<std::string_view, std::string_view>, 3> merges{};
std::array<std::uint32_t, 8> order{}, added_order{};
std::array<std::uint32_t, 3> merge_order{};
std::size_t added = 0;
constexpr loaded()
{
for (std::size_t i = 0; i < merges.size(); ++i)
merges[i] = ml::split_merge(merge_lines[i]);
ml::build_merge_index(merges, merge_order);
ml::build_token_index(pieces, order);
added = ml::build_token_index(pieces, added_order, [](std::uint32_t id) { return kinds[id] == ml::token_kind::user_defined; });
}
constexpr ml::tokenizer_vocab vocab() const
{
ml::tokenizer_vocab v;
v.model = ml::tokenizer_model::bpe;
v.pieces = pieces;
v.kinds = kinds;
v.vocab = {pieces, order};
v.added = {pieces, std::span<const std::uint32_t>(added_order).first(added)};
v.merges = {merges, merge_order};
v.pre = ml::pretokenizer_for("llama-bpe").unwrap();
v.bytes = ml::make_byte_level_fallback(v.vocab);
return v;
}
};
constexpr std::size_t count(std::string_view text)
{
const loaded l;
const ml::tokenizer_vocab v = l.vocab();
std::array<char, 256> t{};
std::array<ml::merge_entry<std::uint32_t>, 1024> r{};
std::array<std::uint32_t, 64> out{};
return ml::tokenize(v, text, out, {t, r, {}, {}}).unwrap();
}
static_assert(count("hi hi!<|end|>") == 4); // "hi", "Ġhi", "!", "<|end|>"

Relationships. Every tokenizer header above. Group: snicholls-core.

Implementations. One per model type, each the corresponding header's algorithm.

Guarantees. No allocation: the caller's output and tokenizer_scratch (tokenizer_scratch_need sizes it for a text length). tokenize is constexpr when the vocabulary is. Complexity: that of the model (O(n log n) for the merges, O(n · L log V) for the tries).

Errors. tokenizer_error::output_too_small (out short; 3n + 3 slots suffice for n bytes of text), scratch_too_small, unknown_bytes (a byte with no token), bad_charsmap.

Performance. The models' own benchmarks; the pipeline adds one pass over the text per stage.

Tests and demos. tests/ml/tokenizer_test.cpp: token for token llama.cpp's test vectors (models/ggml-vocab-*.gguf.inp/.out, plus edge cases: empty text, whitespace runs, emoji, CJK, combining marks, invalid UTF-8) for Llama (SentencePiece), Phi-3, GPT-2, Llama 3, Qwen 2, Qwen 3.5, DeepSeek LLM and Coder, Falcon, StarCoder, Refact, Command R, MPT, Gemma 4, BGE (WordPiece) and nomic-embed (Unigram, XLM-R's vocabulary and charsmap), on committed subsets of those vocabularies (tests/fixtures/ml/tokenizers/, written by scripts/generate_tokenizer_fixtures.cpp from llama.cpp itself); and every detokenisation back to the text. demos/ml/tokenizer_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <span>, <string_view>, and the tokenizer headers.

Known issues. A BPE model sees invalid UTF-8 as U+FFFD, as llama.cpp's does (and as Hugging Face sees text decoded lossily), so its tokens decode to the repaired text; the SentencePiece models keep the bytes (byte fallback). Where core and llama.cpp differ (llama.cpp's SentencePiece path cuts an invalid sequence by its lead byte; it treats Phi-3's user-defined "</s>" as a control token; it strips BERT's Hangul to its first jamo), the fixtures record both and the tests check core's. Special tokens' lstrip/rstrip, Metaspace's prepend_scheme, BERT's [CLS]/[SEP] and BOS/EOS are the caller's.

Status. Experimental, new in 0.17.0.
