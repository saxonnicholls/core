Detailed Description

A bitset of n bits with summary words, so the next or previous set bit is found in O(log64 n).

Overview

Level 0 holds the bits; each higher level holds one bit per non-zero word of the level below, up to a single top word. Finding the next set bit at or after i scans at most one word per level up and one per level down (three levels cover 262,144 bits, four 16.7 million). A price ladder uses it to find the next non-empty price level after the best one empties, in constant time for any realistic span, instead of walking the ladder.

Use it to track occupancy of a dense index range. Not for sparse huge ranges (memory is n / 8 bytes plus ~1/63 of that for the summaries).

Relationships
  • Used by ladder order books (one bit per price level).
  • Module: snicholls-core.
Implementations and variants

None: a single implementation.

Guarantees and contracts
  • Thread safety: none internal.
  • Exception safety: resize may throw std::bad_alloc (strong); every other operation is noexcept.
  • Complexity: set/reset/test O(levels); find_next/find_prev O(levels); levels = ceil(log64 n).
  • Invariants: a summary bit is set exactly when the word below is non-zero.
    Precondition
    Indices passed to set/reset/test are < size().
    Errors
    None besides std::bad_alloc from resize.
Examples
hierarchical_bitset occupied(1'000'000);
occupied.set(10);
occupied.set(500'000);
occupied.set(999'999);
const auto next_ask = occupied.find_next(11); // 500000: skips empty words via the summaries
const auto next_bid = occupied.find_prev(499'999); // 10
Performance

Measured inside a ladder order book. In core, benchmarks/containers/hierarchical_bitset_benchmark.cpp compares it like for like with std::vector<bool>, after a fairness check; not yet measured in Release.
