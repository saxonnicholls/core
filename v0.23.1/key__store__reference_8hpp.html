Detailed Description

snicholls::memory_key_store: the standard-library reference key_store and signer in one, HS256 keys in memory, for tests only.

Overview. Holds HMAC-SHA256 keys (core's hmac<sha256>), so a product's tests can create, rotate, retire and destroy keys and sign with them without a KMS. HS256 is the only algorithm the standard library can give: ES256, EdDSA and ES256K need constant-time elliptic-curve code above core, so create refuses them with unsupported. Never use it for production tokens.

Key material comes from the caller's random_source (the operating system's in a program, a fixed pattern in a test: deterministic()), so the reference reads nothing from the system. Keys are held as snicholls::secret, and no operation returns them. verify is the test-side check of a signature (a constant-time compare). fail_next(code, response) makes the next mutating call fail as though the KMS had answered response.

memory_key_store store{[](std::span<std::byte> out) { std::fill(out.begin(), out.end(), std::byte{0x5a}); }, // the OS's, in a program
[] { return utc_s::from_unix_seconds(1'800'000'000); }};
const auto made = store.create({signature_algorithm::hs256, "webhooks"});
const auto refused = store.create({signature_algorithm::eddsa, "jwt"}); // needs elliptic curves: above core

Relationships. Models key_store (concepts/key_store.hpp) and signer (concepts/signer.hpp); passes both kits in every form; interfaces/signer_reference.hpp names it memory_signer. Group: snicholls-core.

Implementations / variants. One.

Guarantees. Not thread-safe. Signing is deterministic. Key ids are key-1, key-2, ... and never reused. Errors follow the redaction rule: no key material, payload or response in them.

Errors. As the two contracts, and whatever fail_next armed.

Performance. benchmarks/interfaces/key_store_reference_benchmark.cpp: sign against hmac<sha256>::mac written by hand. Not yet quoted from a quiet machine: make benchmarks records them in BENCHMARKS.md.

Tests and demos. tests/interfaces/key_store_reference_test.cpp, demos/interfaces/key_store_reference_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <functional>, <map>, <memory>, <optional>, <span>, <string>, <string_view>, <utility>, <vector>, hash/hmac.hpp, hash/secure.hpp, hash/sha2.hpp, secret.hpp, interfaces/key_store.hpp, interfaces/signer.hpp.

Known issues. HS256 only, by design.

Status. New in 0.23.0.
