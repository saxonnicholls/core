Detailed Description

snicholls::message_sender_interface: the pure virtual twin of message_sender, and the adapters both ways.

Overview. When the sender is chosen at run time (configuration names SES or SMTP), code holds a message_sender_interface&. Its pure virtual functions are the operations of the concept message_sender (concepts/message_sender.hpp, where the contract and its value types are documented), so the interface models the concept itself. message_sender_adapter<S> puts any model behind the interface, owning it (S) or referring to it (S&); message_sender_ref is a copyable, non-owning handle on the interface that models the concept.

std::unique_ptr<message_sender_interface> chosen = std::make_unique<message_sender_adapter<memory_message_sender>>(memory_message_sender{true, false});
message_sender_ref handle{*chosen}; // copyable, models the concept
const auto r = handle.send({channel::email, "ops@example.test", "Alert", "disk full", "", ""});

Relationships. concepts/message_sender.hpp, interfaces/message_sender_reference.hpp, interfaces/message_sender_conformance.hpp. Group: snicholls-core.

Implementations / variants. message_sender_adapter<S> over any model; a sender above core may derive from the interface directly.

Guarantees. The adapters add one virtual call and nothing else; thread safety is the wrapped implementation's.

Errors. As the contract.

Performance. One virtual call; not benchmarked (a sender is I/O bound).

Tests and demos. tests/interfaces/message_sender_test.cpp (the kit through every form), demos/interfaces/message_sender_demo.cpp.

Dependencies. <type_traits>, <utility>, concepts/message_sender.hpp.

Known issues. None.

Status. New in 0.23.0. Experimental until two real implementations pass the kit.
