Detailed Description

snicholls::inplace_string<N>: a string of at most N characters stored in place, trivially copyable and structural, refused rather than truncated when too long.

Overview. Identifiers that cross a wire or sit in a record have a bounded length set by a contract: an order id, a contract name, a venue symbol. inplace_string<N> holds up to N characters inside itself, so a record that holds one is trivially copyable, can be written as bytes and compared without following a pointer, and is a structural type, usable as a template argument. Run-time text becomes one only through make, which returns result and refuses a text longer than N with inplace_string_errc::too_long: an identifier cut short is a different identifier, so it is never truncated. A string literal known to fit is checked by the compiler (inplace_string<8>{"ETH-PERP"}, a compile error when it does not fit).

struct order { // a record that can be copied as bytes
snicholls::inplace_string<64> contract;
double quantity;
};
static_assert(std::is_trivially_copyable_v<order> && sizeof(snicholls::inplace_string<64>) == 65);
template <snicholls::inplace_string<16> Venue> // a string as a template argument
constexpr std::string_view venue() { return Venue.view(); }
static_assert(venue<"XNYS">() == "XNYS");

Relationships. containers/inplace_vector.hpp (the same idea for elements), fixed_string.hpp (a string whose length is part of its type, for template arguments of exactly one text), hash/fnv.hpp (the hash). Group: snicholls-core.

Implementations. One, for char.

Guarantees.

  • constexpr and noexcept throughout; no allocation, ever.
  • Layout: N characters then the length, in the smallest unsigned type that holds N (one byte up to 255): sizeof(inplace_string<255>) == 256, sizeof(inplace_string<64>) == 65; alignment 1 up to 255.
  • Trivially copyable, standard layout and structural. The characters past the length are always zero, so two equal strings have equal members (and, up to 255, no padding: they are equal byte for byte), and the member-wise equivalence of template arguments agrees with ==.
  • == and <=> compare the text (as std::string_view does), also across capacities and against a std::string_view; hash() is FNV-1a 64 of the text, the same on every machine, and std::hash is specialised.

Errors. make returns inplace_string_errc::too_long when the text has more than N characters.

Performance. benchmarks/containers/inplace_string_benchmark.cpp: 4,096 contract ids of 8 to 40 characters, Release, Xeon W-3245, 2026-11-23. inplace_string<64>::make: 50.9 us against 42.4 us for the same check and copy written by hand with Apple clang 17 (macOS), 22.5 us against 23.8 us with GCC 13 (Ubuntu 24.04 in Docker). == of neighbours: 3.95 us against 3.96 us (Apple clang).

Tests and demos. tests/containers/inplace_string_test.cpp, demos/containers/inplace_string_demo.cpp.

Dependencies. <algorithm>, <compare>, <concepts>, <cstddef>, <cstdint>, <functional>, <string_view>, <type_traits>, <utility>, hash/fnv.hpp, result.hpp.

Known issues. No c_str(): the characters are not followed by a terminator (that byte is the length's). Text only, char; for bytes use containers::inplace_vector<std::byte, N>.

Status. New in 0.23.0.
