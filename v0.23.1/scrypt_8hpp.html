Detailed Description

scrypt (RFC 7914), the memory-hard password KDF, in working memory the caller supplies.

Overview. scrypt makes each password guess cost memory as well as time: ROMix fills N blocks of 128 r bytes and then reads them back in an order that depends on their contents, so an attacker who keeps less memory pays in recomputation. Use it for a new password store or a wallet key (Ethereum's keystore v3, Litecoin's proof of work, many vaults use it); N = 2^17, r = 8, p = 1 (128 MiB) is the setting OWASP's password storage cheat sheet gives, N = 2^20 for a file encrypted once.

Core never allocates, so the 128 r (N + p + 1) bytes of working memory are the caller's: ask scrypt_work_words(params) for the size, provide that many std::uint32_t (a std::vector, a buffer reused between calls, an mmap), and scrypt fills out:

// The caller owns the working memory: ask for its size, provide it, reuse it between calls
snicholls::result<snicholls::digest<32>, snicholls::kdf_error> password_key(const std::string& password, const std::string& salt,
std::vector<std::uint32_t>& work)
{
const snicholls::scrypt_params params{1u << 14, 8, 1}; // 16 MiB
SNICHOLLS_TRY_ASSIGN(const std::size_t words, snicholls::scrypt_work_words(params));
work.resize(words);
snicholls::digest<32> key{};
SNICHOLLS_TRY_VOID(snicholls::scrypt(password, salt, params, work, key.bytes));
return snicholls::ok(key);
}

Relationships. pbkdf2_hmac<sha256> and kdf_error (hash/kdf.hpp), which scrypt calls at its start and end; secure_wipe (hash/secure.hpp), which clears the working memory before returning; result (result.hpp). Group: snicholls-core.

Guarantees. constexpr and noexcept; no allocation. The working memory is wiped (secure_wipe) before scrypt returns, on success; on an error nothing is written to out or work. Complexity: 2 N p BlockMix operations of 2 r Salsa20/8 cores each, and N blocks of memory; the parameters are the caller's to choose for the time and memory they can afford.

Precondition
work and out do not overlap.

Errors. kdf_error::invalid_cost unless N is a power of two, greater than 1 and below 2^(16 r) (RFC 7914 2), or when the working memory's size overflows std::size_t; kdf_error::invalid_block_parameters when r or p is 0 or r * p >= 2^30; kdf_error::insufficient_work_memory when work is shorter than scrypt_work_words(params); kdf_error::empty_output / output_too_long as PBKDF2's.

Examples. Above; demos/hash/scrypt_demo.cpp.

Performance. benchmarks/hash/scrypt_benchmark.cpp: against a hand-written loop over the same working memory and OpenSSL's EVP_PBE_scrypt (when installed), after a fairness check. Release, Apple clang 17, Xeon W-3245, 2026-11-20, N = 16384, r = 8, p = 1 (16 MiB): ROMix core 26.2 ms, hand 27.0 ms; the whole scrypt core 30.6 ms, OpenSSL 39.3 ms.

Tests and demos. tests/hash/scrypt_test.cpp (RFC 7914's Salsa20/8, BlockMix, ROMix and scrypt vectors, the N = 2^20 one only in Release; Python's hashlib.scrypt on random inputs; every error; the wipe; a compile-time derivation), demos/hash/scrypt_demo.cpp.

Dependencies. <array>, <cstddef>, <cstdint>, <span>, hash/kdf.hpp, hash/sha2.hpp, result.hpp.

Known issues. p lanes run one after another: scrypt's p is meant for parallelism, which core leaves to the caller (run p = 1 derivations on several threads, or a library above core). The working memory holds password-derived data until it is wiped; memory that is swapped out before then can reach a disk.

Status. New in 0.17.0. Experimental.
