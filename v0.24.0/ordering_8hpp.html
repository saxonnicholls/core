Detailed Description

snicholls::sparse::amd and reverse_cuthill_mckee: fill-reducing and bandwidth-reducing orderings of a symmetric sparse matrix, with the permutation helpers, all constexpr over the caller's storage.

Overview. Factorising a sparse symmetric matrix A = L D Lᵀ fills in: L has non-zeros where A has none, and how many depends on the order of the rows. A good order costs a fraction of the factorisation and can cut nnz(L) (and the flops, which go as the sum of the squares of the column counts) by orders of magnitude. Every sparse direct solver for optimisation (OSQP's QDLDL, Clarabel, MOSEK, CHOLMOD) orders its KKT system once, by approximate minimum degree, and reuses the order for every refactorisation.

  • amd(a, perm, work): approximate minimum degree (Amestoy, Davis and Duff, 1996) for the symmetric matrix whose upper triangle is a. Writes perm[new] = old. Use it before ldl_symbolic (sparse/ldl.hpp).
  • reverse_cuthill_mckee(a, perm, work): the bandwidth-reducing order (George and Liu, 1981). Fill is usually worse than AMD's; use it for banded or profile solvers, or as a comparison.
  • inverse_permutation, is_permutation, permute (y[k] = x[perm[k]]), inverse_permute (y[perm[k]] = x[k]): moving vectors between the original and the permuted numbering.

The permuted matrix itself is symmetric_permute_upper of sparse/csc.hpp.

// nnz(L) of the matrix whose upper triangle is a, in the order perm (perm[new] = old)
std::size_t fill(sp::csc_view<const double, const I> a, std::span<const I> perm)
{
const std::size_t n = a.cols, nnz = a.nnz();
std::vector<I> cp(n + 1), ri(nnz), work(2 * n), parent(n), counts(n), lp(n + 1);
std::vector<double> vx(nnz);
sp::csc_view<double, I> b{0, 0, cp, ri, vx};
if (!sp::symmetric_permute_upper(a, perm, b, std::span<I>(work)))
return 0;
const auto s = sp::ldl_symbolic(b, std::span<I>(parent), std::span<I>(counts), std::span<I>(lp), std::span<I>(work).first(n));
return s ? s->nnz : 0;
}
struct fills {
std::size_t natural, rcm, amd;
};
fills compare(sp::csc_view<const double, const I> a)
{
const std::size_t n = a.cols;
std::vector<I> natural(n), rcm(n), amd(n);
for (std::size_t i = 0; i < n; ++i)
natural[i] = static_cast<I>(i);
std::vector<I> rcm_work(sp::rcm_workspace_size(n, a.nnz())), amd_work(sp::amd_workspace_size(n, a.nnz()));
const bool ok = sp::reverse_cuthill_mckee(a, std::span<I>(rcm), std::span<I>(rcm_work)).is_ok() && sp::amd(a, std::span<I>(amd), std::span<I>(amd_work)).is_ok();
if (!ok || !sp::is_permutation(std::span<const I>(amd)) || !sp::is_permutation(std::span<const I>(rcm)))
return {};
return {fill(a, natural), fill(a, rcm), fill(a, amd)};
}

Relationships. sparse/csc.hpp (csc_view, symmetric_permute_upper), sparse/ldl.hpp (the factorisation that the order is for), result.hpp. Group: snicholls-core.

Implementations. amd works on the quotient graph: eliminated variables become elements (cliques stored as their variable lists), so the graph never grows beyond the storage of A + Aᵀ. On each step it takes a variable of least approximate degree, forms its element Lme from the variable's own list and the elements it touches (absorbing them), and updates the degrees of Lme's variables by the bound of Amestoy, Davis and Duff, d̄ᵢ = min(n - k, d̄ᵢ' + |Lme \ i|, |Aᵢ \ i| + |Lme \ i| + Σ_{e ∈ Eᵢ \ me} |Le \ Lme|), with |Le \ Lme| for every element at once in one pass over Lme. It also does

  • aggressive absorption: an element whose variables all lie in Lme is absorbed into it;
  • mass elimination: a variable adjacent to nothing but Lme is eliminated with the pivot;
  • supervariables: variables of Lme with the same adjacency (found by a hash of their lists, then compared) are merged and eliminated together, so degree updates cost per supervariable;
  • dense rows: a row with more than max(16, amd_options::dense · √n) off-diagonal entries (dense = 10 by default, as AMD's) is removed before the ordering starts and ordered last, so a budget constraint or an arrow head does not make every degree large. The quotient graph is compacted in place when its free space runs out. Ties go to the variable whose degree last changed, the lowest index first at the start. reverse_cuthill_mckee takes, for each connected component, a pseudo-peripheral start node (repeated breadth-first search from a node of least degree in the last level, until the eccentricity stops growing), orders breadth-first with neighbours in ascending degree, and reverses the whole.

Guarantees. constexpr, noexcept, no allocation, no recursion. Every valid input gives a permutation (is_permutation(perm) holds afterwards). amd is O(nnz) storage and, in practice, close to O(nnz(A) · α) time; reverse_cuthill_mckee is O(nnz + n) storage and O(nnz · d) time for the largest degree d (neighbours are sorted by insertion). Fill: on the matrices of tests/sparse/ordering_test.cpp (grids, arrows, random SPD and KKT matrices) amd's nnz(L) is within a factor 1.25 of an exact minimum degree ordering's (one with true external degrees on the explicit elimination graph), and below natural order's and reverse Cuthill-McKee's on all but the matrices already in their best order.

Errors. sparse_error::dimension_mismatch: a is not square. sparse_error::invalid_index: a is not a valid CSC matrix (is_valid), or perm is not a permutation (the permutation helpers). sparse_error::insufficient_capacity: perm or work is shorter than documented (for amd, shorter than the least it accepts).

Performance. Not benchmarked by a Google Benchmark group of its own. Timed by hand (-O3, Apple clang 17, Xeon W-3245, 2026-11-23) on the 100 x 100 grid Laplacian: amd 2.6 ms, reverse_cuthill_mckee 0.31 ms. benchmarks/sparse/ldl_benchmark.cpp times the factorisation in natural and in AMD order (on that grid AMD cuts nnz(L) from 990,099 to 186,098 and the numeric factorisation from 52 ms to 7.7 ms).

Tests and demos. tests/sparse/ordering_test.cpp, demos/sparse/ordering_demo.cpp.

Dependencies. <cstddef>, <cstdint>, <limits>, <span>, <type_traits>, sparse/csc.hpp, result.hpp.

Known issues. Entries below the diagonal of a are ignored, and so is the diagonal: the orderings see the pattern of the strict upper triangle, mirrored. The order is not postordered (the elimination tree's postorder has the same fill; a supernodal code would want it). The constant evaluator's step limit bounds a compile-time amd to small problems (a few hundred entries).

Status. Experimental, new in 0.21.0.
