Detailed Description

snicholls::memory_message_sender: the standard-library reference message_sender; it validates, deduplicates and records an outbox, and sends nothing.

Overview. What a product's tests send email and SMS through: it applies the contract exactly (validate, idempotency, channel support) and keeps every accepted message in an outbox the test reads, so no network, mail server or SMS provider is needed. fail_next(code, response) makes the next send that would be accepted fail as though the provider had answered response, to test a caller's retry path; the error keeps the response's first word as the provider code when it is one (provider_error) and nothing else of it.

memory_message_sender sender;
const message m{channel::email, "ops@example.test", "Alert", "disk full", "", "alert-7"};
const auto first = sender.send(m);
const auto again = sender.send(m); // the same key: the same receipt, sent once
sender.fail_next(capability_errc::unavailable, "503 upstream says no");
const auto failed = sender.send({channel::sms, "+61412345678", "", "hi", "", ""});

Relationships. Models message_sender (concepts/message_sender.hpp); passes interfaces/message_sender_conformance.hpp directly and through interfaces/message_sender.hpp. Group: snicholls-core.

Implementations / variants. One; email and SMS can each be switched off.

Guarantees. Not thread-safe (one per test). Strong exception safety: a throwing allocation leaves the outbox unchanged. Message ids are deterministic (memory-email-1, memory-sms-2). Errors follow the redaction rule.

Errors. As the contract, and whatever fail_next armed.

Performance. Not benchmarked: a test double.

Tests and demos. tests/interfaces/message_sender_reference_test.cpp, demos/interfaces/message_sender_reference_demo.cpp.

Dependencies. <cstddef>, <functional>, <map>, <optional>, <string>, <string_view>, <vector>, interfaces/message_sender.hpp.

Known issues. None.

Status. New in 0.23.0.
