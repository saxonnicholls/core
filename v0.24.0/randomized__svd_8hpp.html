Detailed Description

snicholls::linalg::truncated_svd: the leading k singular values and vectors of a matrix by randomised range finding (Halko, Martinsson and Tropp), on any linalg backend.

Overview. A factor model, a PCA of returns or a low-rank compression wants the largest k singular triplets of an m x n matrix, not all of them. The exact SVD (linalg::svd, one-sided Jacobi) costs about 6 m n^2 per sweep; this costs a few matrix products with l = k + oversample columns, (2q + 2) m n l for q power iterations, plus a QR of m x l and the exact SVD of n x l:

  1. Y = A Ω for an n x l random test matrix Ω, filled by the sketch (Gaussian by default, from its seed: the same seed, the same bits);
  2. q times: Y = A (Aᵀ Q(Y)), each product re-orthonormalised by QR, so the leading directions dominate;
  3. Q = Q(Y), an orthonormal basis of (nearly) A's leading range;
  4. the exact SVD of the small Aᵀ Q = U_b S V_bᵀ (n x l), so A ≈ Q Qᵀ A = (Q V_b) S U_bᵀ;
  5. U = Q V_b, V = U_b, the first k columns, s descending.

The error is close to the best rank-k error σ_{k+1} when the spectrum decays; with a flat spectrum, more power iterations help. When l reaches min(m, n) the result is the exact SVD's, to rounding.

  • truncated_svd(backend, a, s, u, v, work, options, sketch): s (k), u (m x k), v (n x k); A is not changed.
  • truncated_svd_work_size(m, n, k, options): the working space, in elements, so nothing is allocated.
  • The randomness is a seam: a sketch is anything callable as sketch(omega, rows, cols) that fills the rows x cols test matrix (row-major, in the caller's T). gaussian_sketch<Normal>{seed} is the default (the analysis's choice), its Gaussian sampler itself interchangeable (stats/normal.hpp); rademacher_sketch{seed} draws ±1 (cheaper, as accurate in practice). A sketch of the caller's own (another generator, quasi-random points, a device's generator, a structured transform) drops in without touching the algorithm.
// The leading k = 4 singular triplets of the 500 x 120 panel: the factors' directions (V, by asset) and their
// scores (U diag(s), by day). The working space is the caller's; nothing is allocated.
constexpr std::size_t k = factors;
std::vector<double> s(k), u(days * k), v(assets * k), work(la::truncated_svd_work_size(days, assets, k));
const la::matrix_view<const double, right> r(returns.data(), {days, assets});
const auto done = la::truncated_svd(la::reference, r, std::span<double>(s), la::matrix_view<double, right>(u.data(), {days, k}),
la::matrix_view<double, right>(v.data(), {assets, k}), std::span<double>(work));
// The randomness is a seam: another sketch (Rademacher ±1), or the Gaussian one with another sampler (Box-Muller)
std::vector<double> s2(k), s3(k);
const auto r2 = la::truncated_svd(la::reference, r, std::span<double>(s2), la::matrix_view<double, right>(u.data(), {days, k}),
la::matrix_view<double, right>(v.data(), {assets, k}), std::span<double>(work), {},
la::rademacher_sketch{1});
const auto r3 = la::truncated_svd(la::reference, r, std::span<double>(s3), la::matrix_view<double, right>(u.data(), {days, k}),
la::matrix_view<double, right>(v.data(), {assets, k}), std::span<double>(work),
{.oversample = 10, .power_iterations = 2}, la::gaussian_sketch<st::normal_box_muller>{2});

Relationships. linalg/backend.hpp (gemm, qr_factor, qr_q, svd: the operations it is written in), linalg/reference.hpp (core's backend), stats/normal.hpp (the Gaussian samplers), stats/random.hpp (wyrand). Group: snicholls-core.

Implementations. One algorithm, over the backend: a backend with fast products (a BLAS, a GPU) makes it fast; it needs blas_backend, factorisation_backend and decomposition_backend. Two sketches: gaussian_sketch (any stats::normal_sampler over wyrand: the inverse CDF by default, Box-Muller) and rademacher_sketch (one bit of wyrand per entry).

Guarantees. constexpr with a constexpr backend, no allocation (the caller's truncated_svd_work_size elements), deterministic for a given seed and backend. U and V have orthonormal columns; s is descending and non-negative. A zero matrix gives zero singular values.

Errors. error::dimension_mismatch when k > min(m, n), s is not k, u is not m x k, v is not n x k, or work is short. When A holds a NaN or an infinity, the backend's QR or SVD reports it: core's reference reports error::singular (the first QR's pivot) or error::did_not_converge (the small SVD). k = 0 succeeds and writes nothing.

Performance. Against the exact svd of the same matrix through the reference backend, k = 10, a decaying spectrum (benchmarks/linalg/randomized_svd_benchmark.cpp; a different algorithm, so the fairness check is that the leading 10 singular values agree to 1e-9 relative; Release, Apple clang 17, Xeon W-3245, macOS 26, 2026-11-16):

Matrix truncated_svd svd
500 x 100 7.7 ms 145 ms
2000 x 200 55 ms 3.56 s

19 and 64 times faster; the gap grows with n. Nearly all of the time is in gemm, so a faster backend (a BLAS, snicholls-gpu's OpenCL backend once it carries the factorisations) speeds it in proportion.

Tests and demos. tests/linalg/randomized_svd_test.cpp, demos/linalg/randomized_svd_demo.cpp.

Dependencies. <algorithm>, <cstddef>, <cstdint>, <span>, <type_traits>, result.hpp, linalg/backend.hpp, stats/normal.hpp, stats/random.hpp.

Known issues. A slowly decaying spectrum needs more power iterations (or more oversampling) for the trailing directions of the k; the leading ones are accurate first. Sums accumulate in T.

Status. Experimental, new in 0.9.0.
