Detailed Description

snicholls::http_handler: anything that answers an HTTP request with a response, with no transport in sight.

Overview. Everything a server answers (routes, middleware, webhooks, health) is a function of an http_request to an http_response. The transport (sockets, TLS, HTTP/1.1 and HTTP/2 framing) is the server's, above core, and is not in this contract, so handlers are tested without a network and composed freely: a router is a handler of handlers, a middleware wraps one. This is the concept half of a pair; the pure virtual half is http_handler_interface (interfaces/http_handler.hpp), with http_handler_adapter<H> and http_handler_ref.

The contract (interfaces/http_handler_conformance.hpp checks it): handle always returns a response with a status from 100 to 599; failure is a response (4xx, 5xx), not an exception; a handler that throws anyway is answered 500 with no detail (the redaction rule of capability_error.hpp for HTTP: nothing of the exception reaches the response). HEAD is answered as GET without a body. A request's body is the raw bytes, so a webhook's signature can be checked over exactly what was sent.

health h;
http_request r;
r.path = "/health";
const http_response answer = h.handle(r);

Relationships. http_header.hpp; the twin interfaces/http_handler.hpp, the reference interfaces/http_handler_reference.hpp, the kit interfaces/http_handler_conformance.hpp. Group: snicholls-core.

Implementations. route_table (interfaces/http_handler_reference.hpp, an exact-path router). Above core: the servers' HTTP server.

Guarantees. to_string(http_method) and parse_http_method are constexpr and noexcept. A handler shared across connections must be safe to call concurrently; that is the implementation's.

Errors. None: errors are responses.

Performance. benchmarks/interfaces/http_handler_benchmark.cpp (concept, virtual and hand-written dispatch); not yet quoted from a quiet machine: make benchmarks records them in BENCHMARKS.md.

Tests and demos. tests/concepts/http_handler_test.cpp, demos/concepts/http_handler_demo.cpp.

Dependencies. <concepts>, <cstdint>, <optional>, <string>, <string_view>, <utility>, <vector>, http_header.hpp.

Known issues. The request and response own their strings: an HTTP message is a payload, not an identifier, and routers above core build on owned requests. Streaming bodies and WebSocket upgrades are not in the contract.

Status. New in 0.23.0. Experimental until two real implementations pass the kit.
