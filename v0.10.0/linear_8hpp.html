Detailed Description

snicholls::ml::linear: y = W x + b over any weight storage: dense rows of float, double or bfloat16, or ggml's quantised blocks.

Overview. The projections of a transformer are matrix-vector products whose weights may be stored densely or quantised. Each storage is a small view (dense_weights<S>, quantized_weights<Block>) over the caller's memory, laid out as PyTorch's nn.Linear.weight: rows outputs, each a row of cols inputs. A product is two calls:

  • prepare_input<N>(w, x): the input as that storage reads it. A dense matrix reads x as it is; a quantised one reads it quantised to Q8_0, once, as ggml does. Projections sharing an input (Q, K and V) share one prepared input.
  • linear(w, input, y, bias): each output starts at its bias (or 0) and adds the products in input order, as llm.c's matmul_forward does, so a dense float product is llm.c's to the bit.
  • linear_backward(w, x, dy, dx, dw, db): for dense (trainable) storage, adds Wᵀ dy, dy xᵀ and dy into the gradients, as llm.c's matmul_backward.
  • linear_sequence(backend, w, xs, ys, bias) and linear_sequence_backward(backend, w, xs, dys, dxs, dw, db): the same over a sequence of n rows, as one matrix product (and two for the backward) through a linalg backend: core's reference, or a BLAS or a GPU backend from another library, the same call. Dense weights in the sequence's type. The result is the backend's: the reference sums each output in input order and adds the bias after, so it can differ from linear in the last bit.

A storage of the caller's own joins by overloading prepare_input and linear in its namespace (found by ADL); that is the seam for a BLAS or device backend.

// 2 outputs from 32 inputs, laid out as nn.Linear.weight: row i is output i's weights
std::array<float, 2 * 32> w{};
std::array<float, 32> x{};
for (std::size_t j = 0; j < 32; ++j) {
w[j] = 0.5f; // output 0 sums the inputs, halved
w[32 + j] = j % 2 ? -1.0f : 0.5f; // output 1 alternates
x[j] = static_cast<float>(j) / 8.0f;
}
const std::array<float, 2> bias{1.0f, 0.0f};
const ml::dense_weights<float> dense{w, 2, 32};
std::array<float, 2> y{};
ml::linear(dense, ml::prepare_input<32>(dense, x), y, bias);
// The same matrix in bfloat16, and quantised to Q4_0: the input is quantised once, for every product sharing it
std::array<ml::bfloat16, 2 * 32> wb{};
for (std::size_t i = 0; i < w.size(); ++i)
wb[i] = ml::to_minifloat<ml::bfloat16>(w[i]);
std::array<ml::block_q4_0, 2> wq{};
ml::quantize(w, std::span<ml::block_q4_0>(wq));
const ml::dense_weights<ml::bfloat16> half{wb, 2, 32};
const ml::quantized_weights<ml::block_q4_0> q4{wq, 2, 32};
std::array<float, 2> yb{}, yq{};
ml::linear(half, ml::prepare_input<32>(half, x), yb, bias);
ml::linear(q4, ml::prepare_input<32>(q4, x), yq, bias);
// Training: the backward pass of the float product adds W^T dy, dy x^T and dy into the gradients
const std::array<float, 2> dy{1.0f, 0.0f}; // the gradient in output 0 only
std::array<float, 32> dx{};
std::array<float, 2 * 32> dw{};
std::array<float, 2> db{};
ml::linear_backward(dense, x, dy, dx, dw, db);
// Training and prefill: a sequence of rows at once, Y = X Wᵀ + b, as one matrix product through a linalg backend
// (core's reference here; a BLAS or a GPU backend from another library the same way)
const std::array<float, 6> m{1, 2, 3, 4, 5, 6}; // 2 x 3
const std::array<float, 6> rows{1, 0, -1, 0, 1, 0}; // two inputs
const std::array<float, 2> row_bias{10, 20};
std::array<float, 4> outs{};
ml::linear_sequence(snicholls::linalg::reference, ml::dense_weights<float>{m, 2, 3}, rows, outs, row_bias);
const std::array<float, 4> douts{1, 0, 0, 1}; // the gradient in output 0 of row 0 and output 1 of row 1
std::array<float, 6> drows{}, dm{};
std::array<float, 2> dbias{};
ml::linear_sequence_backward(snicholls::linalg::reference, ml::dense_weights<float>{m, 2, 3}, rows, douts, drows, dm, dbias);

sum_values, sum_squares and scale_rows are the batched passes' reductions and gradient clipping's rescale, on the backend like the other steps:

// The batched passes' reductions on a backend: a loss summed over rows, a gradient's squared norm, its rescale
std::array<float, 3> g{3.0f, 4.0f, 0.0f};
const float total = ml::sum_values(snicholls::linalg::reference, std::span<const float>(g));
const float norm2 = ml::sum_squares(snicholls::linalg::reference, std::span<const float>(g));
ml::scale_rows(snicholls::linalg::reference, std::span<float>(g), 1.0f / std::sqrt(norm2)); // clipped to norm 1

Relationships. ml/quantize.hpp (the blocks and their dot products), ml/minifloat.hpp (bfloat16), ml/attention_layer.hpp and ml/mlp.hpp (the users). Group: snicholls-core.

Implementations. Dense: one multiply and one add per weight, in the input's type. Quantised: one block dot product per output row against the Q8_0 input (ml::dot), plus the bias.

Guarantees. constexpr, no allocation (a prepared quantised input is a std::array of N / 32 blocks), linear in rows · cols. Each multiply and add is its own statement, so no compiler fuses them under its default contraction; GCC needs -ffp-contract=off (see ml/quantize.hpp).

Errors. Preconditions, asserted: the input has cols elements, y has rows, a bias is empty or has rows, a quantised matrix has cols a multiple of 32 and rows · cols / 32 blocks.

Performance. Benchmarked through ml/transformer_block.hpp's decode step and training passes (see there), and linear_backward through ml/self_attention.hpp's backward; level with llm.c's matmul_backward loops.

linear_sequence through linalg::reference against the same products as loops over raw pointers, after a bit-for-bit check: 64 tokens of 256 inputs (benchmarks/ml/linear_benchmark.cpp; Release, Apple clang 17, Xeon W-3245, macOS 26, 2026-11-16, medians of five, load average about 16):

Product Core By hand
forward, 256 outputs 3.96 ms 3.98 ms
forward, 1024 outputs 15.9 ms 16.1 ms
backward, 256 outputs 8.43 ms 8.58 ms
backward, 1024 outputs 42.9 ms 43.9 ms

Level: the views, the extent checks and the backend's dispatch cost nothing measurable. The reference backend is no faster than linear token by token (3.96 ms and 16.1 ms the same rows); the batched path is for a backend that is (a BLAS, a device).

Tests and demos. tests/ml/linear_test.cpp, demos/ml/linear_demo.cpp.

Dependencies. <array>, <cassert>, <concepts>, <cstddef>, <span>, <type_traits>, linalg/backend.hpp, ml/minifloat.hpp, ml/quantize.hpp, ml/row.hpp.

Known issues. A quantised product is in float only, as ggml's are.

Status. Experimental, new in 0.8.0.

The backward pass of a dense linear: adds Wᵀ dy into dx, dy xᵀ into dw and dy into db.

Every gradient is accumulated, so an input shared by several products (Q, K and V) and the positions of a sequence add into one buffer; zero them first. The loops are llm.c's matmul_backward: for each output i, dx_j += w_ij · dy_i and dw_ij += dy_i · x_j for j in order, then db_i += dy_i. Only dense storage has a backward: training quantised weights is a compile error.

Parameters
wThe matrix, rows x cols.
xThe input the forward pass read, cols.
dyThe gradient in the output, rows.
dxAdded into, cols; or empty to skip it (a first layer's input).
dwAdded into, rows · cols, row by row as w.
dbAdded into, rows; or empty for a matrix without a bias.
