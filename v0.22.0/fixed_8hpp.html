Detailed Description

snicholls::linalg::fixed_matrix<T, R, C>: a matrix whose size is part of its type, with the arithmetic and factorisations of state estimation, all constexpr.

Overview. Tracking and estimation work on small matrices whose sizes are known when the program is written: a 4-state target, a 2-component measurement, a 4 x 2 gain. fixed_matrix<T, R, C> is one std::array of R * C elements, row-major, an aggregate, trivially copyable when T is. Its operations are free functions on values, each a loop of compile-time length that the compiler unrolls: no allocation, no views, no error codes for shapes (a mismatched product does not compile). The factorisations that can fail on a value (Cholesky of an indefinite matrix, the inverse of a singular one) return result<V, linalg::error>.

  • Construction: aggregate, fixed_matrix<double, 2, 2>{{1, 2, 3, 4}} (row by row); fixed_vector<T, N> is fixed_matrix<T, N, 1>; make_vector(1.0, 2.0); zero(), identity(), diagonal_matrix(v).
  • Arithmetic: +, -, * (matrix product, and by a scalar), / by a scalar, transpose, trace, dot, squared_norm, norm, outer, sandwich(A, P) = A P Aᵀ, symmetrise.
  • Blocks: block<I, J, BR, BC>(a), set_block<I, J>(a, b), block_diagonal(a, b), stack(x, y), diagonal_of(a).
  • Factorisations: cholesky (lower, L Lᵀ = A), lower_solve, lower_transpose_solve, cholesky_solve, cholesky_log_det, spd_inverse; solve, inverse and determinant by LU with partial pivoting; symmetric_eigen (cyclic Jacobi, ascending); tria (the lower square-root factor of A Aᵀ, by Householder QR).
  • Interoperation: view(m) is a matrix_view over the same storage, for the run-time-sized functions of linalg/backend.hpp.

Use it for anything whose size is fixed and small (up to a few tens). For sizes known only at run time, or large ones, use linalg/backend.hpp over md_span.

// A target (x, vx, y, vy) after one second of constant velocity, measured in position only
using m4 = la::fixed_matrix<double, 4, 4>;
using m2 = la::fixed_matrix<double, 2, 2>;
const la::fixed_matrix<double, 2, 2> cv{{1, 1, 0, 1}};
const m4 f = la::block_diagonal(cv, cv); // the transition
const la::fixed_matrix<double, 2, 4> h{{1, 0, 0, 0, 0, 0, 1, 0}}; // the measurement model
const auto x0 = la::make_vector(0.0, 1.0, 0.0, 2.0);
const m4 p0 = la::diagonal_matrix(la::make_vector(4.0, 1.0, 4.0, 1.0));
const m4 q = m4::identity() * 0.01;
const m2 r = m2::identity() * 0.25;
const auto x = f * x0; // predict
const m4 p = la::sandwich(f, p0) + q; // F P Fᵀ + Q, exactly symmetric
const auto z = la::make_vector(1.2, 1.9);
const auto s = la::sandwich(h, p) + r; // the innovation covariance
const auto ls = la::cholesky(s); // a result: S might not be positive definite
if (!ls)
return 1;
// K = P Hᵀ S⁻¹, by two triangular solves rather than an inverse
const auto k = la::transpose(la::cholesky_solve(*ls, h * p));
const auto xu = x + k * (z - h * x);
const m4 pu = la::symmetrise(p - k * s * la::transpose(k));
const double log_det_s = la::cholesky_log_det(*ls);

Relationships. linalg/types.hpp (scalar, error, pivot_tolerance, matrix_view), math/constexpr_math.hpp (sqrt, log), result.hpp. The tracking primitives (tracking/gaussian.hpp, tracking/kalman.hpp and the rest) are written on it. Group: snicholls-core.

Implementations. Plain loops, row-major. The product accumulates a(i, k) * b(k, j) in k order. Cholesky is the column (Cholesky-Banachiewicz) form; LU is Doolittle with partial pivoting; the eigen decomposition is cyclic Jacobi, at most 64 sweeps; tria is Householder QR of Aᵀ, with the signs of the factor's columns made positive.

Guarantees. Every function is constexpr, and noexcept exactly when T's arithmetic and copies are (they are for float and double). No allocation, no recursion. fixed_matrix<T, R, C> has the size and alignment of std::array<T, R * C> and is trivially copyable when T is. The factorisations judge a pivot against pivot_tolerance(n, scale) (relative, as linalg/backend.hpp does), so a matrix and its multiple by 1e-30 are judged alike. Complexity: products and solves O(n³) for n x n, Jacobi O(n³) per sweep.

Errors. cholesky and spd_inverse: error::not_positive_definite when a pivot is at or below the tolerance, or not a number. solve and inverse: error::singular. symmetric_eigen: error::did_not_converge after 64 sweeps (not seen for a finite symmetric input). Nothing throws unless T's arithmetic does.

Performance. Against the same loops written by hand over raw arrays, after a bit-for-bit check, 4096 matrices (benchmarks/linalg/fixed_benchmark.cpp; Release, Apple clang 17, Xeon W-3245, 2026-11-23): the 4 x 4 product 53.1 million a second (by hand 58.9), the 4 x 4 Cholesky 55.8 million (by hand, reporting failure the same way, 68.2). The factor is built inside the result it returns, so it is not copied; the remaining gap is the result's flag and the caller's copy out of it.

Tests and demos. tests/linalg/fixed_test.cpp, demos/linalg/fixed_demo.cpp.

Dependencies. <array>, <cstddef>, <type_traits>, linalg/types.hpp, math/constexpr_math.hpp, result.hpp.

Known issues. At run time sqrt and log are the standard library's, so results agree with a constant evaluation only to the last bit or so. Elements are read with operator()(i, j); a vector also has operator[].

Status. Experimental, new in 0.19.0.
