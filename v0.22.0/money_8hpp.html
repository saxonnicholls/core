Detailed Description

snicholls::money and snicholls::money_of<T>: an exact amount of one asset, a sign and 256 bits of minor units, with checked arithmetic and exact text.

Overview. An amount is a whole number of minor units of one asset: cents, wei, satoshi. Neither a double, which rounds, nor an int64, which overflows at 9.2 ETH in wei, can hold every amount a ledger meets, so the magnitude is a uint256: every raw on-chain amount is representable exactly. The sign is separate, so debits and credits share one type and the whole uint256 range is available with either sign. Zero is never negative.

Two forms:

  • money: the asset is a run-time value (snicholls::asset), for data such as a ledger row;
  • money_of<T>: the asset is a type (money_of<currency::AUD>, money_of<native::ETH>), for code that knows its currency. Mixing two currencies is a compile error, and the asset is not stored at all.

Arithmetic is exact and checked:

  • add and subtract return result, never wrap, and work within one asset only (for money, a mismatch is an error; for money_of, there is no overload);
  • multiply by an integer is checked too;
  • conversion between assets goes through an explicit rate and a named rounding mode (money/rate.hpp).

Text is exact at the asset's scale, and no double is involved anywhere:

  • parse_money(asset, "1000.5") refuses digits the scale cannot hold unless a rounding mode is given;
  • to_chars writes the minimal form ("1000.5", "-0.000001", "1": viem's formatUnits), or every fractional digit on request.
const asset eth = asset_v<native::ETH>;
const money a = *parse_money(eth, "1000.5"); // 1000500000000000000000 wei, exactly
const money b = *parse_money(eth, "-0.000000000000000001"); // one wei, negative
const auto sum = add(a, b); // result<money, money_errc>
const auto mixed = add(a, *parse_money(asset_v<currency::AUD>, "1")); // a different asset: an error
using aud = money_of<currency::AUD>; // the asset in the type
const auto typed = add(aud::from_units(1025), aud::from_units(330, true));

Relationships. money/asset.hpp, money/rate.hpp, money/iso4217.hpp, money/native.hpp, uint256.hpp, result.hpp.

decimal.hpp remains for bounded values within 18 digits (a price on a wire, a rate in a message); it is not for balances. The two convert:

  • from_decimal(asset, d) is exact, refusing digits beyond the asset's scale unless a rounding mode is named;
  • to_decimal(m) gives std::nullopt when the amount needs more than 18 significant digits. Group: snicholls-core.

Implementations. One representation, { sign, uint256 magnitude }, with the asset beside it (money) or in the type (money_of).

Guarantees.

  • constexpr throughout.
  • Arithmetic and to_chars are noexcept and allocation-free; only to_string allocates.
  • Both forms are trivially copyable.
  • money_of<T> is the size of its sign plus its uint256.
  • Equality compares asset, sign and magnitude; zero is normalised to non-negative, so -0 == 0.

Errors. money_errc, returned through result:

  • asset_mismatch: two different assets;
  • overflow: a magnitude beyond 2^256 - 1;
  • malformed: text that is not a decimal amount;
  • too_many_digits: more fractional digits than the scale, with no rounding mode;
  • buffer_too_small.

Performance. benchmarks/money/money_benchmark.cpp: add against hand-written signed uint256 addition, after a fairness check.

Tests and demos. tests/money/money_test.cpp, with fixtures from Python's decimal (scripts/generate_money_fixtures.py, CTest generated.money_fixtures_up_to_date); demos/money/money_demo.cpp.

Dependencies. <array>, <charconv>, <compare>, <cstddef>, <cstdint>, <optional>, <ostream>, <string>, <string_view>, money/asset.hpp, result.hpp, uint256.hpp.

Known issues. None.
