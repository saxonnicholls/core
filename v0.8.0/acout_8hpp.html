Detailed Description

snicholls::acout, acerr, print, println: thread-safe printing, one write per message, format strings included.

Overview. Several threads printing to one stream interleave their characters, because std::cout << a << b is two calls and another thread's call can land between them. The fix is to assemble the whole message first and hand it to the stream in a single call:

// One message, assembled first, written once: another thread's message cannot land in the
// middle of it. The temporary's destructor does the write at the end of the statement.
snicholls::acout{} << " balance " << std::fixed << std::setprecision(2) << 1234.5 << " in thread " << 0 << '\n';
snicholls::acerr{} << " (to stderr, the same way)\n";
// Four threads, one stream, 100 lines each: counted afterwards, every line is intact.
std::ostringstream shared;
std::vector<std::thread> threads;
for (int t = 1; t <= 4; ++t)
threads.emplace_back([&shared, t] {
for (int i = 0; i < 100; ++i)
snicholls::acout(shared) << "thread " << t << " says hello number " << i << '\n';
});
for (auto& th : threads)
th.join();

acout is a message: stream into it, or print a format string into it, and when it goes out of scope (the end of the statement, for a temporary) the text is written once. Two messages from two threads never interleave: for a std::ostream the one write is made under one program-wide lock; for a FILE* it is one fwrite, which the C library locks. The lock is held for that write alone, never while the message is formatted, so a message may print another (acout{} << f() where f prints) and formatting a slow argument never blocks anyone. Messages under 256 bytes allocate nothing.

print and println are the one-line forms, C++23's std::print shape on C++20:

// The one-line forms: a format string checked at compile time, written in one call.
snicholls::println(" {} of {} orders filled ({:.1f}%)", 7, 8, 87.5);
snicholls::print(stderr, " {}: {}\n", "warning", "stderr through fwrite");
// Into a message, mixed with streaming, emitted when it goes out of scope.
{
snicholls::acout message;
message << " order " << 42 << ": ";
message.print("{} @ {:.2f}", "AAPL", 189.25).println(" {}", "filled");
}

Formatting is std::format, with the format string checked at compile time. The {fmt} library itself cannot enter core (standard library only); its API is this one.

A type that knows how to print itself gives it one member, and that is the whole contract (snicholls::printable): the classic print(std::ostream&) const, or the better print(snicholls::acout&) const, inside which format strings and streaming both work and the whole object is written in one call. acout streams either through the member, print(value) and println(value) write one in one line, and using snicholls::print_operators::operator<<; lends both to any plain stream, the way magic_enum's iostream_operators does for enumerations:

// A type that prints itself: one member, and that is the whole contract. The classic form
// takes a stream ...
struct fill {
const char* symbol;
int quantity;
double price;
void print(std::ostream& os) const { os << symbol << " x" << quantity << " @ " << std::fixed << std::setprecision(2) << price; }
};
// ... and the better form takes the message: format strings inside, and the whole object is
// written in one call wherever it is streamed.
struct quote {
const char* symbol;
double bid;
double ask;
void print(snicholls::acout& out) const { out.print("{} {:.2f}/{:.2f}", symbol, bid, ask); }
};
// Plain streams get the operator by opting in, as with magic_enum's iostream_operators.
using snicholls::print_operators::operator<<;
// Through acout, print() is found by the concept; through a plain stream, by the operator above;
// println(value) is the one-liner.
const fill f{"AAPL", 100, 189.25};
const quote q{"AAPL", 189.20, 189.30};
snicholls::acout{} << " filled: " << f << " at " << q << '\n';
snicholls::println(q);
std::ostringstream plain;
plain << f << "; " << q;

Everything else prints too, through one engine (snicholls::print_to) that acout uses for every << and that print_operators lends to plain streams: sequences as [a, b], sets as {a, b}, maps as {k: v}, pairs and tuples as (a, b), a std::optional as its value or none, a std::variant as what it holds, a snicholls::result as ok(v) or err(e), a snicholls::meta::type_list as type_list<int, double>, recursively, with strings and characters quoted inside a container:

// Containers, pairs, tuples, optionals and type lists print as they are, recursively, through
// the same engine: into an acout always, onto a plain stream with the operator above in scope.
const std::map<std::string, std::vector<int>> book{{"bids", {100, 99}}, {"asks", {101, 102}}};
const std::vector<std::pair<std::string, std::optional<double>>> marks{{"AAPL", 189.25}, {"PRIV", std::nullopt}};
snicholls::acout{} << " book " << book << '\n';
snicholls::println(marks);
snicholls::acout{} << " types " << snicholls::meta::type_list<int, double>{} << '\n';
std::ostringstream shown;
shown << book << " " << std::tuple{1, 'a', "two"};

The engine is a first_match chain, so a std::string is text and not a range of chars, and a type's own operator<< is taken before its shape is looked at. A type nothing in the chain accepts is a compile error with a message, not a silent address.

Colour is part of the message, and ends with it, so one thread's colour cannot tint another thread's line. colours::red in a message holds until colour_reset; styled(colour, value) colours one value, in a container too; print(colour, ...) and println(colour, ...) colour a whole line. Any rgb(0xRRGGBB) works where a named colour does:

// A colour holds until colour_reset, or the end of the message, which always ends it.
using namespace snicholls::colours;
snicholls::acout{} << " " << green << "filled" << snicholls::colour_reset << " 100 AAPL\n";
// One value in a colour, in a container too; the message returns to the colour it was in.
const int up = 3, down = -2;
const std::array moves{snicholls::styled(green, up), snicholls::styled(red, down)};
snicholls::acout{} << " moves " << moves << ' ' << snicholls::styled(snicholls::rgb(0x8250df), "any rgb") << '\n';
// A whole line, as a format string.
snicholls::println(yellow, " {} of {} orders late", 1, 8);
// A string stream gets the plain text; set_colour_mode(always) is how to ask for the codes anyway.
std::ostringstream plain_text;
snicholls::acout(plain_text) << red << "no codes here";

A type that declares display attributes (display.hpp, meta/attributes.hpp) prints in its colour with its label or number format, everywhere and in containers too; a number with sign_colours is green when up and red when down, and by_sign(x) does the same for a bare number. print_displayed prints a value under attributes given.

Escape codes are written only where they mean something (snicholls::colour_mode). By default that is std::cout, std::cerr, std::clog, stdout and stderr, unless NO_COLOR is set or TERM is dumb; a string stream or a file gets the plain text.

Relationships. colour.hpp for the colours; meta/concepts.hpp for printable; meta/type_name.hpp for the names in a type_list; result.hpp, whose error_text is what to print for an error; ts-moveables' logger, for logging with levels, fields and sinks, which this is not; C++20's std::osyncstream, the same idea in the standard, which libc++ ships only as experimental and core therefore does not depend on. Group: snicholls-core.

Guarantees.

  • Atomic per message: the characters of one acout reach the target in one call, under a lock shared by every acout in the program, so two messages from two threads never interleave, whichever thread finishes first. Text written to the same target not through acout can still land between two of ours.
  • The lock is one std::mutex, program-wide, held only for the write; never while formatting, so no user code runs under it and no message can deadlock another. It is the only state this header owns.
  • No allocation for a message of up to 256 bytes; longer messages grow a std::string.
  • The message's formatting state (std::hex, width, precision) is its own, fresh per message, not the target's.
  • flush(), std::endl and std::flush request a flush of the target after the write; otherwise the target's own buffering applies, as for a plain stream.
  • emit() writes now and empties the message, which is then reusable. The destructor calls it and swallows exceptions (there is nowhere to report them); call emit() yourself to see them.
  • Not copyable or movable: a message is a scoped object.

Errors. std::bad_alloc from a message over 256 bytes; std::format_error from a format argument invalid at run time; std::system_error if the lock cannot be taken; whatever a streamed type's operator<< throws. A failed write sets the target's state as the stream would.

Performance. Benchmarked in benchmarks/acout_benchmark.cpp against a plain unsynchronised stream, and against std::osyncstream where the library has it, writing the same 4,096 messages (a label, an integer, a double) to a string stream, after a fairness check that the text is identical. Release, Apple clang 17, Xeon W-3245, 2026-11-06: 432 ns per message through acout, 375 ns through the plain stream, 341 ns through println with a format string. The 57 ns over the plain stream is the lock and the one extra copy; the format form is faster than streaming because std::format of a double is faster than operator<<. Colour, 2026-11-07, same machine: with a coloured label, 554 ns per message against 421 ns for a plain stream given the same codes by hand; the same run's message without colour took 456 ns against 381 ns. The engine on a container, the same day and machine: 4,096 rows of 16 ints through print_to 1.17 us a row against 1.16 us for the loop written by hand, identical text; the branch choice is at compile time and the cost is the stream's.

Tests and demos. tests/acout_test.cpp, demos/acout_demo.cpp.

Dependencies. <atomic>, <concepts>, <cstdint>, <cstdio>, <cstdlib>, <format>, <iostream>, <iterator>, <mutex>, <optional>, <ostream>, <ranges>, <streambuf>, <string>, <string_view>, <tuple>, <type_traits>, <utility>, <variant>, and colour.hpp, meta/concepts.hpp, overloaded.hpp, meta/type_list.hpp, meta/type_name.hpp, result.hpp. Heavier than it looks: the engine prints results, so result.hpp comes along. The one header in core that performs I/O and holds a mutex, admitted by name in CLAUDE.md: it does nothing but hand a finished message to a stream the caller names.

Known issues. std::cout redirected to a file (./app > log.txt) still gets the escape codes of whatever is printed in colour: telling a terminal from a file takes isatty, a platform header, which core does not include. A program that may be redirected makes the check itself and calls set_colour_mode(colour_mode::never). On Windows, colour is on by default only in Windows Terminal or where TERM is set, because a classic console must be switched into escape-code mode by a platform call. Built without RTTI, in automatic mode, a coloured value nested in a container prints without its colour. One lock for every stream target means two threads printing to two different streams wait for each other for the length of a write; a per-stream lock would need a registry, which std::osyncstream provides but libc++ does not ship. A type that is both printable and has its own operator<< is streamed through print by acout; on a plain stream the two are ambiguous only if the print_operators declaration is in scope. A type with both print forms is streamed through the acout one. The engine does not read std::boolalpha for its own words (none, ok(...)) but passes bool elements to the stream as they are. A scoped enumeration prints by name (meta/enums.hpp), or as its integer when its value is not an enumerator; one with its own operator<< uses that, and an unscoped one prints as the stream prints it.

Status. New in 0.5.0.
