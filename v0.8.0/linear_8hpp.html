Detailed Description

snicholls::ml::linear: y = W x + b over any weight storage: dense rows of float, double or bfloat16, or ggml's quantised blocks.

Overview. The projections of a transformer are matrix-vector products whose weights may be stored densely or quantised. Each storage is a small view (dense_weights<S>, quantized_weights<Block>) over the caller's memory, laid out as PyTorch's nn.Linear.weight: rows outputs, each a row of cols inputs. A product is two calls:

  • prepare_input<N>(w, x): the input as that storage reads it. A dense matrix reads x as it is; a quantised one reads it quantised to Q8_0, once, as ggml does. Projections sharing an input (Q, K and V) share one prepared input.
  • linear(w, input, y, bias): each output starts at its bias (or 0) and adds the products in input order, as llm.c's matmul_forward does, so a dense float product is llm.c's to the bit.

A storage of the caller's own joins by overloading prepare_input and linear in its namespace (found by ADL); that is the seam for a BLAS or device backend.

// 2 outputs from 32 inputs, laid out as nn.Linear.weight: row i is output i's weights
std::array<float, 2 * 32> w{};
std::array<float, 32> x{};
for (std::size_t j = 0; j < 32; ++j) {
w[j] = 0.5f; // output 0 sums the inputs, halved
w[32 + j] = j % 2 ? -1.0f : 0.5f; // output 1 alternates
x[j] = static_cast<float>(j) / 8.0f;
}
const std::array<float, 2> bias{1.0f, 0.0f};
const ml::dense_weights<float> dense{w, 2, 32};
std::array<float, 2> y{};
ml::linear(dense, ml::prepare_input<32>(dense, x), y, bias);
// The same matrix in bfloat16, and quantised to Q4_0: the input is quantised once, for every product sharing it
std::array<ml::bfloat16, 2 * 32> wb{};
for (std::size_t i = 0; i < w.size(); ++i)
wb[i] = ml::to_minifloat<ml::bfloat16>(w[i]);
std::array<ml::block_q4_0, 2> wq{};
ml::quantize(w, std::span<ml::block_q4_0>(wq));
const ml::dense_weights<ml::bfloat16> half{wb, 2, 32};
const ml::quantized_weights<ml::block_q4_0> q4{wq, 2, 32};
std::array<float, 2> yb{}, yq{};
ml::linear(half, ml::prepare_input<32>(half, x), yb, bias);
ml::linear(q4, ml::prepare_input<32>(q4, x), yq, bias);

Relationships. ml/quantize.hpp (the blocks and their dot products), ml/minifloat.hpp (bfloat16), ml/attention_layer.hpp and ml/mlp.hpp (the users). Group: snicholls-core.

Implementations. Dense: one multiply and one add per weight, in the input's type. Quantised: one block dot product per output row against the Q8_0 input (ml::dot), plus the bias.

Guarantees. constexpr, no allocation (a prepared quantised input is a std::array of N / 32 blocks), linear in rows · cols. Each multiply and add is its own statement, so no compiler fuses them under its default contraction; GCC needs -ffp-contract=off (see ml/quantize.hpp).

Errors. Preconditions, asserted: the input has cols elements, y has rows, a bias is empty or has rows, a quantised matrix has cols a multiple of 32 and rows · cols / 32 blocks.

Performance. Benchmarked through ml/transformer_block.hpp's decode step (see there).

Tests and demos. tests/ml/linear_test.cpp, demos/ml/linear_demo.cpp.

Dependencies. <array>, <cassert>, <concepts>, <cstddef>, <span>, ml/minifloat.hpp, ml/quantize.hpp, ml/row.hpp.

Known issues. A quantised product is in float only, as ggml's are.

Status. Experimental, new in 0.8.0.
