Detailed Description

Conversions between plain aggregate structs and std::tuples.

Conversions between plain aggregate structs and std::tuples. Everything is constexpr; tie() is unconditionally noexcept, every other conversion is noexcept exactly when the member copies/moves/assignments it performs are (e.g. not for std::string copies, which may throw).

auto refs = snicholls::tie(s); // std::tuple of references (lvalues only)
auto vals = snicholls::to_tuple(s); // std::tuple of values; moves from rvalues
S s = snicholls::from_tuple<S>(tup); // tuple-like -> struct

Structs (plain aggregates, member count detected automatically, see reflect/member_count.hpp): one element per member; nested structs stay as they are.

Strict input: sizes must match exactly, and arithmetic conversions must not narrow - both are compile-time errors with a snicholls:: message.

The rules, as CLAUDE.md "Struct / tuple conversion rules" states them:

  • Everything is constexpr. tie is always noexcept; every other conversion is noexcept exactly when the copies/moves/assignments it performs are (a std::string copy may throw bad_alloc, so copying one is not noexcept; moving it is). Never declare a conversion unconditionally noexcept when it can allocate - that turns bad_alloc into std::terminate.
  • Input is strict: sizes must match exactly and arithmetic conversions must not narrow (brace-init rules, so int -> double and int -> bool are rejected). Errors are compile-time static_asserts with a snicholls:: message.
  • Plain structs: members of any type incl. move-only, const, std::optional/any/variant, nested aggregates, std::array. Not supported: reference members (clear error), C arrays (miscounted - use std::array), bit-fields, base classes, unions. Up to SNICHOLLS_MAX_STRUCT_MEMBERS (256) members.
