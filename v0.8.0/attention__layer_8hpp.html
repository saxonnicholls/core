Detailed Description

snicholls::ml::attention_forward: a transformer's attention for one token at one position: the Q, K and V projections, QK norm, RoPE, the KV cache, grouped-query attention, the soft cap and the output projection, as the configuration says.

Overview. The generic multi-head attention layer. For a token x at position pos:

  1. q = Wq x, k = Wk x, v = Wv x (plus biases), from one prepared input;
  2. per head, an RMS norm of q and k before or after the rotation (qk_norm) and RoPE at pos (rope);
  3. k and v appended to the kv_cache at pos;
  4. each query head h attends to key-value head h / group() over the visible positions (attention_window(pos, window)), each score scale · q·k capped by attention_softcap · tanh(s / cap) if set;
  5. out = Wo y (plus its bias) over the heads' outputs.

Prefill is this for each token of a run in order, so a prompt and a decode step are one code path. Attention never forms the scores of a sequence: each head folds its keys in one pass (attention_accumulator), and a sliding window's two runs are folded in position order, so a ring cache gives the flat cache's bits.

attention_head is one head on its own: the unit to run on threads or devices.

// Two query heads share one key-value head of 4 channels; RoPE in the half layout
constexpr ml::transformer_config c{.d_model = 8, .n_heads = 2, .n_kv_heads = 1, .head_dim = 4, .d_ff = 8, .rope = ml::rope_kind::half};
std::vector<float> wq(8 * 8), wkv(4 * 8), wo(8 * 8);
for (std::size_t i = 0; i < 8; ++i)
wq[i * 8 + i] = wo[i * 8 + i] = 1.0f; // identity projections, so the arithmetic is visible
for (std::size_t i = 0; i < 4; ++i)
wkv[i * 8 + i] = 1.0f;
const ml::attention_weights<W> w{W{wq, 8, 8}, W{wkv, 4, 8}, W{wkv, 4, 8}, W{wo, 8, 8}};
static const ml::rope_table<float, 16, 4> rope{}; // cosines and sines for positions 0 to 15
std::vector<float> keys(ml::kv_cache_view<c>::required_size(1, 16)), values(keys.size());
const ml::kv_cache_view<c> cache(keys, values, 1, 16);
std::array<std::array<float, 8>, 3> out{};
for (std::size_t pos = 0; pos < 3; ++pos) {
const std::array<float, 8> x{1, float(pos), 0, 0, 0.5f, 0.5f, 0.5f, 0.5f};
ml::attention_forward<c>(w, x, pos, cache, 0, rope, out[pos]); // appends this token, attends to all so far
}
// One head alone over what the cache holds: the unit to spread over threads
std::array<float, 4> head{};
const std::array<float, 4> q{1, 0, 0, 0};
const float lse = ml::attention_head<c, float>(q, cache.visible(0, 0, ml::attention_window(2)), head);

Relationships. ml/transformer_config.hpp, ml/linear.hpp, ml/kv_cache.hpp, ml/attention.hpp, ml/rope.hpp (rope_table is a rope source), ml/norm.hpp, ml/activations.hpp (softcap), ml/transformer_block.hpp (the user). Group: snicholls-core.

Implementations. One, configured at compile time.

Guarantees. constexpr, no allocation (the projections are std::arrays of the configuration's sizes), O(d_model · (q_size + 2 kv_size) + n_heads · visible · head_dim + q_size · d_model) per token.

Errors. Preconditions, asserted: the matrices have the configuration's shapes (q is q_size x d_model, k and v kv_size x d_model, o d_model x q_size), biases and QK-norm weights are empty or of their row's size, the rope source covers pos, the cache's capacity covers the visible range. An invalid configuration is a compile error.

Performance. Benchmarked through ml/transformer_block.hpp's decode step.

Tests and demos. tests/ml/attention_layer_test.cpp, demos/ml/attention_layer_demo.cpp.

Dependencies. <array>, <cassert>, <cstddef>, <span>, and the ml/ headers above.

Known issues. The score scale is 1 / sqrt(head_dim), rounded once to T.

Status. Experimental, new in 0.8.0.
