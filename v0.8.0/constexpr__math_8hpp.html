Detailed Description

snicholls::math: exp, log, expm1, log1p, sqrt, pow, the trigonometric and hyperbolic functions, erf, gamma, and the normal and chi-square distributions, all constexpr, for any floating-point type.

Overview. <cmath> is not constexpr in C++20, so a table built at compile time (a normal quantile grid, a discount curve, a Sobol point mapped to a normal draw) cannot call it. These functions can: during constant evaluation they use series and argument-reduction kernels, and at run time they defer to the correctly rounded <cmath> (or, for a type of the caller's, to its own functions, found by argument-dependent lookup), so run-time results are the library's to the bit and compile-time ones agree with them to a few units in the last place.

Every function is a template on its argument's type: float, double, long double, or a type of the caller's (a multiprecision or fixed-point number) for which math_limits is specialised. An integer argument computes in double, as <cmath> does. What a kernel needs to know about a type (its overflow bounds, how far a series runs, its constants) is in math_limits<T>, one specialisation per type, as std::numeric_limits is; compute_type says which type the kernels run in (float runs in double and is rounded once, so it is correctly rounded nearly always).

// Discount factors for 1 to 5 years at 4% continuously compounded, computed by the compiler.
constexpr auto discount = [] {
std::array<double, 5> out{};
for (int y = 1; y <= 5; ++y)
out[static_cast<std::size_t>(y - 1)] = math::exp(-0.04 * y);
return out;
}();
// The quantiles a VaR report needs, as constants.
constexpr double z95 = math::normal_quantile(0.95);
constexpr double z99 = math::normal_quantile(0.99);
static_assert(math::near(z99, 2.3263478740408408, 1e-14));

Relationships. stats/bootstrap.hpp (the normal quantile for BCa intervals), stats/low_discrepancy.hpp (Sobol points to normal draws), finance/attribution.hpp. Group: snicholls-core.

Guarantees. Every function is constexpr. NaN and infinities propagate as in <cmath>. double results are bit-identical to those before the functions were generic.

Errors. None: a domain error is NaN, as in <cmath>.

Performance. At run time, <cmath>'s. normal_quantile costs a logarithm, a square root and an erfc.

Tests and demos. tests/math/constexpr_math_test.cpp, demos/math/constexpr_math_demo.cpp.

Dependencies. <bit>, <cmath>, <cstdint>, <limits>, <type_traits>.

Known issues. At compile time sin and cos reduce arguments with three parts of pi/2, accurate for |x| up to about 1e9; beyond that compile-time results drift. lgamma, gamma_p and chi_square_cdf use Lanczos' coefficients and are good to about 15 digits in every type. long double is double on Apple ARM and MSVC; its limits follow std::numeric_limits, so it is right either way. A type of the caller's needs arithmetic, comparisons, conversion to and from long long and double, std::numeric_limits, and, for run time, exp, log, ... in its own namespace.

Status. New in 0.5.0.
