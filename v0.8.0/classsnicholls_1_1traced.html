Detailed Description

template<class E>
class snicholls::traced< E >

An error E with the source_location where it was created, a chain of context frames, key-value fields and an optional stack trace (anyhow / eyre for snicholls::result).

Overview

Logging an error well needs more than the error: where it happened, what the program was doing at each level on the way up, the identifiers involved, and sometimes a stack. snicholls::traced<E> carries all of it beside the original E, so the function that finally handles the error can log a complete account in one place: snicholls::err(snicholls::traced{e}) records the location; r.context("loading {}", id) adds a frame at the caller; SNICHOLLS_TRY adds a "propagated" frame with the expression text; r.with_field("account", id) adds a field; r.with_stack() captures a stack through the installed hook. format_error_report renders text, error_report_fields a flat field list, and a snicholls::error_sink (a super-log adapter, say) receives the structured snicholls::error_report.

Use it where errors are logged or shown to people. Keep plain error types (an enum, std::error_code) on hot paths whose errors are handled locally.

Relationships
  • snicholls::result<V, snicholls::traced<E>>: context, with_field, with_stack, trace, log_err, SNICHOLLS_TRY.
  • snicholls::error_report, snicholls::make_error_report, snicholls::format_error_report, snicholls::error_report_fields.
  • snicholls::error_sink: the logging interface; snicholls::text_error_sink, or a consumer's super-log adapter.
  • Module: snicholls-core.
Implementations and variants

None: a single implementation.

Guarantees and contracts
  • Cost: sizeof(traced<E>) == sizeof(E) + a source_location (one pointer; three words on MSVC) + one pointer, rounded to alignment. Creating one stores the location and does not allocate (beyond what E's own constructor does). The first add_context / add_field / capture_stack allocates one block holding the frames, fields and stack; each frame or field then allocates its text. A success never constructs a traced at all, so the success path of a result<V, traced<E>> costs what a result<V, E> of the same size costs.
  • Copying is a deep copy (allocates when there are details); moving is noexcept when E's move is.
  • Equality and std::hash use E only: the context is diagnostics, not identity.
  • Not thread-safe beyond the usual value-type rules.
Errors

std::bad_alloc from the adders and from copies. std::format_error from context(fmt, args...) and snicholls::fail(fmt, args...) when an argument is invalid for its format at run time, e.g. a negative dynamic width ("{:{}}" with -1): the format string itself is checked at compile time, its run-time arguments are not.

Examples
enum class io_error
{
not_found = 2,
};
using io_result = snicholls::result<std::string, snicholls::traced<io_error>>;
io_result read_file(std::string_view path)
{
if (path != "positions.csv")
return snicholls::traced_err(io_error::not_found); // records this file and line
return snicholls::ok(std::string("ES,10\nNQ,-4\n"));
}
snicholls::result<std::size_t, snicholls::traced<io_error>> load_positions(std::string_view account, std::string_view path)
{
// context() adds a frame at this line; SNICHOLLS_TRY adds a "propagated" frame with the expression text.
SNICHOLLS_TRY_ASSIGN(const std::string text, read_file(path).context("loading positions for {}", account));
return snicholls::ok(static_cast<std::size_t>(std::count(text.begin(), text.end(), '\n')));
}
auto bad = load_positions("ACC1", "missing.csv")
.context("start of day for desk {}", 7)
.with_field("account", "ACC1")
.with_field("token", api_token{"s3cr3t"});
const snicholls::traced<io_error>& e = bad.unwrap_err();
std::cout << snicholls::to_string(e) << '\n';
Performance

Not benchmarked: the error path allocates by design and is not on a hot path. The success path is benchmarked as part of snicholls::result (benchmarks/result_benchmark.cpp).

Dependencies

CMake target snicholls::core; standard library only (core).

Known issues and gotchas
  • Never put a secret in the context text: format arguments are printed as they are (a snicholls::secret has no std::formatter, so passing one is a compile error). Fields mask secrets.
  • Core masks field values that are secrets (anything with reveal()) and nothing else: there is no masking by key name here. Masking keys that look secret is a sink's own choice; snicholls::text_error_sink sees every key and every non-secret value as given.
  • SNICHOLLS_TRY records the text of the expression it propagates, verbatim, in a "propagated" frame: an expression that spells out a secret (a literal, a variable name that matters) puts it in the log.
  • rethrow() of a traced error throws the inner E; the chain is not in the exception.
  • source_location::function_name() differs between compilers, so the text and the field list carry file:line only (the report keeps the full location).
Status

Experimental, pre-1.0. Design: RESULT_PLAN.md.
