Detailed Description

The vocabulary of snicholls::linalg: matrix and vector views, the error and status codes, triangles, pivots, tolerances.

Overview. Every linear-algebra operation in core speaks these types and nothing else: matrices, vectors and batches are containers::md_span views (row-major, column-major or strided, never owned), a failure is an error inside a snicholls::result, and a batch reports one status per system. A backend from another library (a BLAS, LAPACK, Eigen or GPU binding) sees the same types, so callers never see the backend's.

// A 2 x 3 matrix in the caller's row-major storage; its transpose is the same storage read column-major.
std::array<double, 6> storage{1, 2, 3, 4, 5, 6};
const la::matrix_view<double, la::layout_right> a(storage.data(), {2, 3});
const auto at = la::transposed(a); // matrix_view<double, layout_left>, 3 x 2
const la::matrix_view<const double> strided = a; // every layout converts to the canonical strided view
const auto att = la::transposed(la::transposed(strided));
// A std::span is a vector; a vector is a one-column matrix (a right-hand side).
std::array<double, 3> x{1, 0, -1};
const auto xv = la::as_vector(std::span<double>(x));
const auto xc = la::as_column(xv);

Relationships. containers/md_array.hpp (the views), result.hpp (the error channel), linalg/backend.hpp (the operations), linalg/batched.hpp, linalg/reference.hpp. Group: snicholls-core.

Guarantees. Everything here is constexpr and trivially copyable, and nothing allocates. The views and codes are noexcept; what computes in T (pivot_tolerance, ldlt_growth_limit, signed_log_det::value) is noexcept exactly when T's arithmetic is, so a number type that throws (an allocating multiprecision type) propagates.

Errors. None of its own: error is the value the operations return.

Performance. No run-time cost beyond the views' (see containers/md_array.hpp).

Tests and demos. tests/linalg/types_test.cpp, demos/linalg/types_demo.cpp.

Dependencies. <array>, <concepts>, <cstddef>, <cstdint>, <limits>, <span>, <type_traits>, <utility>, containers/md_array.hpp, math/constexpr_math.hpp.

Known issues. Tolerances are relative to std::numeric_limits<T>::epsilon(), and the kernels' abs, sqrt and log are snicholls::math's; a number type of the caller's (a half-precision or quantised type) takes part by specialising std::numeric_limits and math::math_limits, as for every other numeric header in core.

Status. Experimental, new in 0.6.0.
