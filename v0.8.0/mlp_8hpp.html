Detailed Description

snicholls::ml::mlp_forward: a transformer's MLP for one token, down(act(up x)) or SwiGLU's down(silu(gate x) · up x), as the configuration says.

Overview. The feed-forward half of a transformer block. transformer_config::mlp chooses the form: GELU (exact or tanh, GPT-2), ReLU² (nanochat) or SwiGLU (Llama). The weights are mlp_weights, views over any weight_matrix storage, so the same call runs on float, bfloat16 or quantised weights. The input is prepared once for up and gate.

For a mixture of experts, moe_gate<K>(router_logits) picks the K experts a token goes to and their weights (a softmax over the K largest router logits, as Mixtral); the token's output is the weighted sum of those experts' mlp_forwards, each expert's weights a mlp_weights of its own.

constexpr ml::transformer_config relu2{.d_model = 2, .n_heads = 1, .n_kv_heads = 1, .head_dim = 2, .d_ff = 2, .mlp = ml::mlp_kind::relu_squared};
constexpr ml::transformer_config swiglu{.d_model = 2, .n_heads = 1, .n_kv_heads = 1, .head_dim = 2, .d_ff = 2, .mlp = ml::mlp_kind::swiglu};
const std::array<float, 4> up{1, 0, 0, 1}, gate{1, 1, -1, -1}, down{1, 0, 1, 1}; // 2 x 2 each
const std::array<float, 2> x{2.0f, -1.0f};
std::array<float, 2> a{}, b{};
ml::mlp_forward<relu2>(ml::mlp_weights<W>{W{up, 2, 2}, W{}, W{down, 2, 2}}, x, a); // down(relu(up x)²)
ml::mlp_forward<swiglu>(ml::mlp_weights<W>{W{up, 2, 2}, W{gate, 2, 2}, W{down, 2, 2}}, x, b); // down(silu(gate x) · up x)

Relationships. ml/transformer_config.hpp, ml/linear.hpp, ml/activations.hpp, ml/transformer_block.hpp (the user). Group: snicholls-core.

Implementations. One, by mlp_kind.

Guarantees. constexpr, no allocation (the hidden row is a std::array of d_ff), linear in the weights. moe_gate is O(experts · K); on ties the lower-numbered expert is chosen first.

Errors. Preconditions, asserted: the matrices have the configuration's shapes (up and gate are d_ff x d_model, down is d_model x d_ff), biases are empty or of the output's size, x and y have d_model. An invalid configuration is a compile error.

Performance. Benchmarked through ml/transformer_block.hpp's decode step.

Tests and demos. tests/ml/mlp_test.cpp, demos/ml/mlp_demo.cpp.

Dependencies. <array>, <cassert>, <span>, ml/activations.hpp, ml/linear.hpp, ml/row.hpp, ml/sampling.hpp (top_k), ml/transformer_config.hpp.

Known issues. None known.

Status. Experimental, new in 0.8.0.
