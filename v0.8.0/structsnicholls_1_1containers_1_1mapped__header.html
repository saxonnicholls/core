Detailed Description

The description of a persisted container that leads its file: what the elements are and how many there are.

Overview

A container persisted to a file (ts-moveables' mapped_vector, an index_pool in a mapped file) must refuse a file that is not one of its own, was written for another element type, or was torn by a crash. The header is 64 bytes at offset 0: a magic number and a format version, the element's sizeof and alignof, a type tag the caller chooses, the element count and capacity, one word for the container's own use, and a wyhash checksum of the 56 bytes before it. encode_header writes it, decode_header reads and checks it, and validate_header also checks it against the reader's own element shape.

Encoded layout, every field little-endian whatever the machine:

offset size field
0 8 magic mapped_header_magic
8 4 format version
12 4 header size, 64
16 8 type_tag
24 4 element_size
28 4 element_align
32 8 count
40 8 capacity
48 8 user
56 8 wyhash of bytes 0-55, seeded with the magic

The header itself is portable; the elements after it are in the writer's native layout, which is what the element shape and the type tag guard.

Relationships
  • wyhash (hash/wyhash.hpp), the checksum.
  • index_pool, a region that can follow the header.
  • ts-moveables' mapped_vector, which keeps its size and capacity here.
  • Module: snicholls-core.
Implementations and variants

None.

Guarantees and contracts
  • Thread safety: pure functions.
  • Exception safety: everything is noexcept.
  • Complexity: O(1): 64 bytes and one 56-byte hash.
  • Invariants: a header decode_header accepts has count <= capacity and the recorded checksum.
Errors

header_error, as returned by encode_header (too_short, count_over_capacity), decode_header (every structural error) and validate_header (those plus element_mismatch and type_mismatch).

Examples
constexpr std::uint64_t tag = snicholls::fnv1a_64("tick v1");
std::array<std::byte, mapped_header_size> file_start{};
// Writer: 1000 ticks in a file with room for 4096.
if (encode_header(mapped_header_for<tick>(tag, 1000, 4096), file_start).is_err()) return 1;
// Reader: is this a file of ticks, and how many?
if (auto ok = validate_header(file_start, mapped_header_for<tick>(tag)); ok.is_err()) return 1;
auto h = decode_header(file_start);
Performance

benchmarks/containers/mapped_header_benchmark.cpp measures an encode and a decode against a hand-written memcpy and wyhash, after a fairness check. Release, Apple Clang 17, Intel Xeon W-3245 (macOS 26), 2026-11-12, median of 5: 19.9 ns per round trip against 19.3 ns by hand. The cost is the two wyhashes of 56 bytes; the explicit byte order is close to free.

Dependencies

hash/wyhash.hpp, result.hpp; standard library only. No I/O: reading and writing the file is the caller's.

Known issues and gotchas
  • The checksum makes a torn header detectable, not the data: a container that must survive a crash writes its data, makes it durable, and only then rewrites the header (ts-moveables' mapped_vector::flush does).
  • The type tag is the caller's: a hash of a type name and a schema version (fnv1a_64("order v2")) is usual. Zero is a valid tag, so a reader that does not care passes the tag it finds.
