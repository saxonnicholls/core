Detailed Description

snicholls::ml::kv_cells: which position and which sequences each slot of a KV cache holds, llama.cpp's sequence operations on them (remove a range, copy, keep, add to and divide positions), the K-shift that re-rotates cached keys after a position change, and attention over the cells a query sees.

Overview. kv_cache_view (ml/kv_cache.hpp) stores keys and values by slot. A server holding several sequences in one cache, sharing a prompt between them, or dropping the oldest tokens to keep generating (context shift) needs to know what each slot holds. kv_cells<Capacity> is that table, as llama.cpp's llama_kv_cells keeps it (src/llama-kv-cells.h and src/llama-kv-cache.cpp, llama.cpp 39039aa): per slot a position (-1 when empty), the set of sequences that share it (a 64-bit mask: sequences 0 to 63), and the shift its position has accumulated since its key was rotated.

  • place(slot, pos, seq) records a token written with kv_cache_view::append(layer, slot, k, v); find_free(from) finds a slot; share(slot, seq) adds a sequence to a cell (a shared prompt).
  • The sequence operations, over the positions [p0, p1) (a negative p0 is 0, a negative p1 is unbounded, as llama.cpp's): seq_rm(seq, p0, p1) (seq -1: every sequence), seq_cp(src, dst, p0, p1), seq_keep(seq), seq_add(seq, p0, p1, delta) (cells moved below position 0 are freed), seq_div(seq, p0, p1, d) (self-extend's grouping); seq_pos_min and seq_pos_max.
  • kv_shift_keys<C>(keys, layers, cells): rotates every cached key whose position moved by its shift (RoPE's rotations compose: a key rotated at p and then by δ is the key rotated at p + δ, with the configuration's base, layout and rescaling), then clears the shifts; llama.cpp's build_graph_shift.
  • visible(slot, seq, query_pos, window): the causal mask of a query of seq at query_pos, with a sliding window as llama_hparams::is_masked_swa (standard: a key is outside when query_pos - pos >= window).
  • attend_cells<C>(cache, cells, layer, kv_head, q, out, seq, query_pos, slope): one query head over the cells it sees, in slot order, with the configuration's scale and soft cap and an optional ALiBi slope (ml/alibi.hpp) read from each cell's position.
// One layer, one key-value head of 4 channels, 8 slots, RoPE on
constexpr ml::transformer_config c{.d_model = 4, .n_heads = 1, .n_kv_heads = 1, .head_dim = 4, .d_ff = 4, .rope = ml::rope_kind::half};
std::vector<float> keys(ml::kv_cache_view<c, float>::required_size(1, 8)), values(keys.size());
const ml::kv_cache_view<c, float> cache(keys, values, 1, 8);
ml::kv_cells<8> cells;
// A prompt of three tokens for sequence 0, rotated at their positions, then shared with sequence 1
auto write = [&](std::size_t slot, ml::kv_pos pos, ml::kv_seq seq, float x) {
std::array<float, 4> k{x, 1.0f, -x, 0.5f}, v{x, x, x, x};
std::array<float, 2> cs{}, sn{};
ml::rope_angles(std::size_t(pos), cs, sn);
ml::rope(k, cs, sn);
cache.append(0, slot, k, v); // the slot, not the position: cells say which position it holds
cells.place(slot, pos, seq);
};
for (std::size_t t = 0; t < 3; ++t)
write(t, ml::kv_pos(t), 0, float(t + 1));
cells.seq_cp(0, 1, -1, -1);
write(cells.find_free(), 3, 0, 4.0f); // sequence 0 continues; sequence 1 does not see this token
write(cells.find_free(), 3, 1, 9.0f); // nor does sequence 0 see this one
// A query of sequence 1 at position 3 attends to the shared prompt and its own token
const std::array<float, 4> q{0.2f, 0.1f, -0.3f, 0.4f};
std::array<float, 4> out{};
ml::attend_cells(cache, cells, 0, 0, q, out, 1, 3);
// Context shift for sequence 0: drop position 0, move the rest back by one, re-rotate the keys (a position belongs to
// the cell, so the shared cells move for sequence 1 too, as in llama.cpp)
cells.seq_rm(0, 0, 1);
cells.seq_add(0, 1, -1, -1);
ml::kv_shift_keys<c>(std::span<float>(keys), 1, cells);

Relationships. ml/kv_cache.hpp (the storage, by slot), ml/rope.hpp (the rotation), ml/alibi.hpp, ml/attention.hpp (the recurrence). ml/kv_cache_quant.hpp holds the keys and values as quantised rows. Group: snicholls-core.

Implementations. One, of fixed capacity (arrays: no allocation, synthesisable).

Guarantees. constexpr. Every operation is linear in the capacity; llama.cpp's per-sequence ordered sets of positions are replaced by scans, which cost the same order as the attention that follows. Trivially copyable. A cell is empty exactly when its sequence mask is empty.

Errors. Preconditions, asserted: slots below the capacity; sequences from 0 to 63 (-1 where an operation allows it); place on an empty slot; d > 0 for seq_div; the key storage is kv_cache_view's size.

Performance. Not benchmarked: the table is a few bytes a slot; attend_cells is attend's loop with a test per slot.

Tests and demos. tests/ml/kv_cells_test.cpp, demos/ml/kv_cells_demo.cpp.

Dependencies. <algorithm>, <array>, <cassert>, <cstddef>, <cstdint>, <limits>, <span>, ml/alibi.hpp, ml/activations.hpp, ml/attention.hpp, ml/kv_cache.hpp, ml/rope.hpp, ml/transformer_config.hpp.

Known issues. llama.cpp's pos_div (src/llama-kv-cells.h, 39039aa) accumulates p_old - p_new into the shift, the opposite sign of pos_add's p_new - p_old, and its K-shift rotates by the shift as stored, so a divided key is rotated away from its new position; core records p_new - p_old in both, so the K-shift always moves a key to its new position (tested). A position belongs to the cell, so moving a shared cell moves it for every sequence that shares it, as in llama.cpp. Multiple streams and the per-cell extra data of llama.cpp's two-dimensional positions are not modelled. A latent attention's cache (MLA) is not shifted here (kv_shift_keys rejects it).

Status. Experimental, new in 0.17.0.
